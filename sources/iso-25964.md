# ISO 25964 叙词表标准

阅读笔记。正文收费，本文基于可免费获取的部分：样章（目录、范围、定义 2.1–2.47）、NISO 托管的数据模型与 SKOS 对应表、修订版公开说明。凡本文未覆盖的章节，只有标题，没有内容。

## 这个标准是什么

ISO 25964 是叙词表（thesaurus）的国际标准，由 ISO/TC 46/SC 9 制定，分两部分：

| 部分 | 标题 | 状态 |
|---|---|---|
| [ISO 25964-1:2011](https://www.iso.org/standard/53657.html) | Part 1: Thesauri for information retrieval | 现行，2022 复审确认；修订版 [ISO/FDIS 25964-1](https://www.iso.org/standard/86713.html) 预计 2026 出版 |
| [ISO 25964-2:2013](https://www.iso.org/standard/53658.html) | Part 2: Interoperability with other vocabularies | 现行 |

Part 1 合并并取代了 ISO 2788:1986（单语叙词表）和 ISO 5964:1985（多语叙词表），1–13 章大体对应旧标准，14–18 章（软件要求、数据模型、集成、交换格式、协议）是新增。Part 2 讲叙词表与分类法、名称规范表、本体等其他词表的映射与互操作。

中国国标 [GB/T 13190.1-2015](https://std.samr.gov.cn/gb/search/gbDetailed?id=71F772D7A385D3A7E05397BE0A0AB82A) 和 [GB/T 13190.2-2018](https://std.samr.gov.cn/gb/search/gbDetailed?id=71F772D82DD2D3A7E05397BE0A0AB82A) 等同采用。因 ISO 版权，国家标准全文公开系统不提供全文。

## 适用范围

原文（1 Scope）要点：

- 给出叙词表的开发与维护建议，面向信息检索应用
- 适用于检索任何媒介的信息资源——文本、声音、图像、实物、多媒体，**明确包括知识库和门户**
- 提供数据模型和推荐的导入/导出格式
- 适用于单语和多语叙词表
- 不适用于：书后索引；直接用于检索/标引的数据库或软件本身（但为其需求做了考虑）

引言里有一句对设计者重要的话：叙词表的主要原则是**让标引者和检索者对同一概念选择同一个词**；标准假定通常有人参与选词，但也适用于由计算机选词的场景，并提到对“能让机器推理的词表”的需求。

## 关键定义

选自第 2 章，编号为原文条款号。译文为本文所加。

### 概念与词的分离

| 条 | 术语 | 原文定义 | 译 |
|---|---|---|---|
| 2.11 | concept | unit of thought | 概念：思维单元。注：概念独立于表达它的词而存在 |
| 2.61 | term | （样章未含） | 词 |
| 2.12 | controlled vocabulary | prescribed list of terms, headings or codes, each representing a concept | 受控词表：规定好的词、标题或代码列表，每项代表一个概念 |
| 2.45 | preferred term (descriptor) | term used to represent a concept when indexing | 首选词 / 叙词：标引时用来代表概念的词，通常是名词或名词短语 |
| 2.39 | non-preferred term (non-descriptor) | term that is not assigned to documents but is provided as an entry point | 非首选词 / 非叙词：不用于标引，只作入口 |
| 2.16 | entry term (lead-in term) | term provided ... for the purpose of guiding the user to another term | 入口词：引导用户找到可用词的词 |
| 2.25 | identifier | set of symbols ... designating a concept or a term or another entity for purposes of unique identification | 标识符：概念、词或其他实体的唯一标识 |

这组定义的要点：**概念有自己的标识符，词只是挂在概念上的标签**。一个概念可以有多个词（一个首选、多个非首选），这与知识图谱“实体有 ID，名称是属性”是同一设计。

### 三类关系的定义

| 条 | 术语 | 原文定义 | 译 |
|---|---|---|---|
| 2.18 | equivalence relationship | relationship between two terms in a thesaurus that both represent the same concept | 等价关系：两个词代表同一概念。同语言内一个定为首选词，其余为非首选词 |
| 2.23 | hierarchical relationship | relationship between a pair of concepts of which one has a scope falling completely within the scope of the other | 层级关系：一个概念的范围完全落在另一个之内。注：有几种不同类型，见 10.2 |
| 2.3 / 2.37 | broader term / narrower term | preferred term representing a concept that is broader/narrower than the one in question | 广义词 BT / 狭义词 NT |
| 2.2 | associative relationship | relationship between a pair of concepts that are not related hierarchically but share a strong semantic connection | 相关关系：非层级但语义联系强 |
| 2.41 | paradigmatic relationship (a priori) | relationship between concepts that is inherent in the concepts themselves | 聚合关系：概念固有的关系，与任何具体文档无关。叙词表只收这类关系 |

注意：等价关系是**词与词**之间的，层级和相关关系是**概念与概念**之间的。这是数据模型里 `Equivalence` 挂在 Term 上、`HierarchicalRelationship` 挂在 Concept 上的原因。

### 结构类术语

| 条 | 术语 | 译 |
|---|---|---|
| 2.20 | facet | 分面：同一内在类别的概念分组，如对象、材料、施动者、动作、地点、时间 |
| 2.21 | facet analysis | 分面分析：把学科领域分解为概念并按分面分组，再按划分特征细分 |
| 2.4 | characteristic of division | 划分特征：把一个概念细分为一组狭义概念所依据的属性，如“人 → 按年龄段 → 儿童 / 青年 / 成人” |
| 2.1 | array | 数组：一组同级概念 |
| 2.38 | node label | 节点标签：层级显示中插入的标签，说明分面名或划分特征；本身既非首选词也非非首选词 |
| 2.34 / 2.42 | monohierarchical / polyhierarchical structure | 单层级 / 多层级结构：每个概念只能有一个 / 可以有多个直接上位概念。标准允许多层级 |
| 2.9 | compound term | 复合词：可拆分为多个成分的词，如 copper mines |
| 2.8 | compound equivalence | 复合等价：一个词在另一语境中由两个以上词表示，如 `coal mining USE coal + mining` |
| 2.47 | quasi-synonym | 准同义词：日常意义不同但在词表中视为同一概念，如 diseases / disorders |
| 2.24 | homograph | 同形异义词：如 bank |
| 2.43 / 2.44 | post-coordination / pre-coordination | 后组 / 先组：检索时组合词 vs 建表或标引时组合 |

## 数据模型

第 15 章定义，NISO 公开了 [UML 图](https://www.niso.org/schemas/iso25964/Model_2011-06-02.jpg)和 [XML Schema v1.4](https://www.niso.org/schemas/iso25964/iso25964-1_v1.4.xsd)。

### 数据模型的类

```
Thesaurus                 词表本身。identifier, lang 必填;title, creator, publisher 等 Dublin Core 风格元数据
├─ ThesaurusConcept       概念。identifier 必填;created, modified, status, notation, topConcept
│   ├─ ThesaurusTerm      词(抽象)。lexicalValue, identifier 必填;lang, source, status, created, modified
│   │   ├─ PreferredTerm           首选词,每概念每语言一个
│   │   ├─ SimpleNonPreferredTerm  非首选词,有 hidden 标志(隐藏入口,如拼写错误)
│   │   └─ SplitNonPreferredTerm   需拆分的非首选词(复合等价用)
│   ├─ Note               注释(抽象)。lexicalValue, lang, created, modified
│   │   ├─ ScopeNote      范围注释,挂概念
│   │   ├─ Definition     定义,挂词
│   │   ├─ HistoryNote    历史注释,挂词或概念
│   │   ├─ EditorialNote  编辑注释,挂词
│   │   └─ CustomNote     自定义注释,有 noteType
│   ├─ CustomConceptAttribute  概念的自定义属性:customAttributeType + lexicalValue
│   └─ CustomTermAttribute     词的自定义属性
├─ ThesaurusArray         数组:一组同级概念,ordered 标志,可挂 NodeLabel
├─ ConceptGroup           概念组:conceptGroupType(如 micro-thesaurus),可嵌套(hasSubgroup / hasSupergroup)
└─ VersionHistory         版本:date, versionNote, currentVersion, thisVersion
```

### 数据模型的关系

| 关系类 | 连接 | 属性 | 说明 |
|---|---|---|---|
| Equivalence | PreferredTerm ↔ SimpleNonPreferredTerm | role | USE / UF |
| CompoundEquivalence | PreferredTerm (2..*) ↔ SplitNonPreferredTerm | — | USE+ / UF+ |
| HierarchicalRelationship | Concept ↔ Concept | **role: String[1]** 必填 | BT / NT;role 区分类型 |
| AssociativeRelationship | Concept ↔ Concept | role: String[0..1] | RT;role 可选 |
| TopLevelRelationship | Thesaurus ↔ Concept | — | 顶层概念 |
| hasSuperOrdinateConcept / hasSubordinateArray | Concept ↔ ThesaurusArray | — | 概念与其下数组 |
| hasMemberConcept / hasMemberArray | ThesaurusArray ↔ Concept / Array | ordered | 数组成员 |
| hasAsMember | ConceptGroup ↔ Concept | — | 组成员 |

层级关系的 role 取值，标准 10.2 定义了三种（缩写来自第 3 章 Table 1）：

| 缩写 | 类型 | 含义 | 例 |
|---|---|---|---|
| BTG / NTG | generic | 是一种 (is-a) | `PostgreSQL NTG-of 关系型数据库` |
| BTP / NTP | partitive | 是一部分 (part-of) | `查询规划器 BTP PostgreSQL` |
| BTI / NTI | instantial | 是实例 (instance-of) | `生产库 db-prod-01 BTI PostgreSQL` |

### 对知识图谱设计的含义

这个模型比“三类关系”的叙词表要丰富，已经具备属性图的基本要件：

1. **节点有 ID**:`ThesaurusConcept.identifier` 必填，名称是挂在上面的 Term
2. **边有类型**:`HierarchicalRelationship.role` 必填，`AssociativeRelationship.role` 可选；10.4 允许自定义关系
3. **节点和边可带属性**:`CustomConceptAttribute` / `CustomTermAttribute` 任意扩展
4. **有生命周期**:`status`、`created`、`modified`、`HistoryNote`、`VersionHistory`——支撑废弃、合并、拆分的治理
5. **有分组和分面**:`ConceptGroup`、`ThesaurusArray` + `NodeLabel`

缺的是：关系本身不能带任意属性（只有 role），关系类型没有 schema 约束（role 是自由字符串），没有推理规则。这些是本体 / 图谱层要补的，对应 Part 2 和 OWL。

## 与 SKOS 的对应

NISO 发布了 [ISO 25964 ↔ SKOS / SKOS-XL / MADS 对应表](http://groups.niso.org/higherlogic/ws/public/download/12351/Correspondence%20ISO25964-SKOSXL-MADS-2013-12-11.pdf)(2013-12-11)，并把 SKOS 缺的部分做成扩展本体 `iso-thes`，发布在 [purl.org/iso25964/skos-thes](http://purl.org/iso25964/skos-thes)。

| ISO 25964 | SKOS / SKOS-XL | 备注 |
|---|---|---|
| Thesaurus | `skos:ConceptScheme` | 元数据映射到 Dublin Core |
| ThesaurusConcept | `skos:Concept` | identifier → `dc:identifier`;status → `iso-thes:status`（扩展） |
| isPartOf / contains | `skos:inScheme` / 反向 | |
| topConcept = true | `skos:topConceptOf` / `skos:hasTopConcept` | |
| notation | `skos:notation` | |
| ThesaurusTerm | `skos-xl:Label` | lexicalValue → `skos-xl:literalForm` |
| hasPreferredLabel | `skos:prefLabel` 或 `skos-xl:prefLabel` | 简单场景直接用字面量，需要词级元数据时用 XL |
| hasNonPreferredLabel, hidden=false | `skos:altLabel` / `skos-xl:altLabel` | |
| hasNonPreferredLabel, hidden=true | `skos:hiddenLabel` / `skos-xl:hiddenLabel` | |
| PreferredTerm / SimpleNonPreferredTerm / SplitNonPreferredTerm | `iso-thes:PreferredTerm` 等，`skos-xl:Label` 的子类 | SKOS 本身无此区分 |
| CompoundEquivalence | `iso-thes:CompoundEquivalence` + `plusUF` / `plusUse` | SKOS 无 |
| HierarchicalRelationship | `skos:broader` / `skos:narrower` | role 三种类型 → `iso-thes:broaderGeneric` / `broaderPartitive` / `broaderInstantial` 及 narrower 对应，均为 skos:broader/narrower 的子属性 |
| AssociativeRelationship | `skos:related` | 有 role 时需定义 `skos:related` 的子属性 |
| ThesaurusArray | `iso-thes:ThesaurusArray`,`skos:Collection` 的子类；ordered 时为 `skos:OrderedCollection` | |
| ConceptGroup | `iso-thes:ConceptGroup`,`skos:Collection` 的子类；作微词表时 `iso-thes:microThesaurusOf` | |
| hasSubordinateArray / hasSuperOrdinateConcept | `iso-thes:subordinateArray` / `iso-thes:superOrdinate` | SKOS 无 |
| ScopeNote / Definition / HistoryNote / EditorialNote | `skos:scopeNote` / `skos:definition` / `skos:historyNote` / `skos:editorialNote` | ISO 里部分注释挂词，SKOS 全部挂概念 |
| CustomNote | 定义 `skos:note` 的子属性；可考虑 `skos:changeNote`、`skos:example` | |
| CustomConceptAttribute / CustomTermAttribute | 自定义 RDF 数据属性 | 属性名取决于 customAttributeType |
| NodeLabel, ConceptGroupLabel, VersionHistory, TopLevelRelationship | 无对应 | VersionHistory 有单独提案 |

结论：ISO 25964 模型可以无损落到 RDF——基础部分用 SKOS，差额用 `iso-thes` 扩展。这就是从词表到图谱的标准化通道。

## 2026 修订版

ISO/TC 46 已完成修订，目前处于 FDIS 阶段，预计 2026 年出版。公开信息：

- 标题改为 *Thesauri for information retrieval, **management and use***
- 适用范围明确扩展到 web 导航、人工智能、作者自标引（author tagging）、管理与使用
- 据 Hlava 2024 年的说明，数据模型更新以支持**知识图谱**、聊天机器人、在线购物、AI 等场景
- 数据模型具体改了什么，公开页面没有细节
