# 技术写作规范阅读笔记

读了四份公认的技术写作规范，按「文档类型 → 结构 → 段落 → 句子 → 用词 → 标点」的顺序提炼可用规则，每条标出处。目的是给 `design/writing.md` 提供依据，不是替代它。

本文自身按这些规则写，因此标点用全角，与本库其他文件目前的写法不一致；统一工作在规则定稿后做。

## 文档类型

Diátaxis 把文档分成四类，两条轴：给**做事**还是给**认知**，服务**学习**还是服务**工作**。

| | 学习 | 工作 |
|---|---|---|
| 做事 | 教程 tutorial | 操作指南 how-to |
| 认知 | 解释 explanation | 参考 reference |

核心主张：**四类不能混**。「模糊或跨越这些边界，是大量文档问题的根源。」教程里塞解释、参考里塞观点，都是典型病。

对本库最相关的两类：

| | 解释 | 参考 |
|---|---|---|
| 回答 | 为什么 | 是什么 |
| 语气 | 像讨论：承认观点、给多个角度、举反例 | 克制、中立、一致：陈述事实，不解释不指导 |
| 结构 | 围绕主题绕着讲 | 镜像被描述对象的结构，读者按预期位置找 |
| 典型句式 | 「x 之所以这样，是因为历史上 y」「w 比 z 好，因为」「x 类似于 z 中的 w，但」 | 「必须使用 a」「除非 c，否则不得 b」 |
| 标题 | 隐含「关于」：About authentication | 与对象同名 |
| 禁忌 | 吸收操作步骤和技术细节 | 掺观点、推测、营销 |

对本库的映射：

| 目录 | Diátaxis 类型 | 现状 |
|---|---|---|
| `concepts/` | 解释 | 基本对 |
| `design/` | 参考（规则、字段、取值）| **混了**：「为什么求完整」这类解释和「字段有哪些」这类参考写在一起 |
| `sources/` | 参考（文献事实）+ 少量解释 | 基本对 |

这是本次阅读最有用的发现：`design/topics.md` 的问题不止用词，它同时在做两件事。Diátaxis 的处理是拆开，参考部分保持克制，解释部分链接过去。

## 结构

| 规则 | 出处 |
|---|---|
| 标题分四级；一级下不直接出三级；谨慎用四级，并列内容改用列表 | 阮一峰·标题 |
| 避免孤立编号：同级只有一个标题时，删掉它 | 阮一峰·标题 |
| 下级标题不重复上级标题的名字 | 阮一峰·标题；Google·headings |
| 标题后必须有内容，不得空标题直接接子标题 | Google·headings |
| 概念性标题用名词短语，不以 -ing 动词开头；任务性标题用动词原形开头 | Google·headings |
| 标题不用序号表示顺序、不放代码、不放链接、标点从简 | Google·headings |
| 引用一组小节时说「以下各节」，不说「本节」「这些节」（指代不明） | Google·headings |
| 文件名：小写、半角、连字符，不含空格和中文 | 阮一峰·文档体系 |
| 参考类文档的结构镜像被描述对象的结构 | Diátaxis·reference |

## 段落

| 规则 | 出处 |
|---|---|
| 一段只有一个主题或一个中心句 | 阮一峰·段落 |
| 中心句放段首，后面的句子为它服务 | 阮一峰·段落 |
| 一段不超过七行，最佳四行以内 | 阮一峰·段落 |
| 陈述和肯定语气，不用感叹 | 阮一峰·段落 |
| 条件放在指令前面，不放后面 | Google·highlights |
| 不预告（「后面会讲」「即将支持」） | Google·highlights |

## 列表与表格

| 规则 | 出处 |
|---|---|
| 有顺序用编号列表，无顺序用项目列表 | Google·highlights |
| 每项是一对相关数据（词—解释）用描述列表 | Google·highlights |
| 每项有三个以上相关数据用表格 | Google·tables |
| 只有一行或一列不用表格 | Google·tables |
| 表格前用完整句子说明表格用途 | Google·tables |
| 表头简短、句首大写、不以标点结尾 | Google·tables |
| 不合并单元格；行按逻辑或字母排序 | Google·tables |
| 不在句子中间插表格 | Google·tables |

## 句子

| 规则 | 出处 |
|---|---|
| 主动语态，说清谁在做 | Google·highlights；阮一峰·写作风格 |
| 第二人称「你」，不用「我们」 | Google·highlights |
| 单句或逗号分隔的句段 20 字以内；30–39 字须语义明确；40 字以上不接受 | 阮一峰·句子 |
| 逗号串起的长句不超过 100 字或三行 | 阮一峰·句子 |
| 用简单句和并列句，不用复合句 | 阮一峰·句子 |
| 用肯定句，不用否定句；禁双重否定 | 阮一峰·句子 |
| 代词（其、该、此、这）必须只有一个所指 | 阮一峰·写作风格 |
| 名词前不堆形容词 | 阮一峰·写作风格 |
| 链接文字要描述目标，不写「点这里」 | Google·highlights |

## 用词

| 规则 | 出处 |
|---|---|
| 不使用冷僻、生造或文言词，用现代汉语常用表达 | 阮一峰·写作风格 |
| 英文词首次出现时括号给中文；此后可直接用英文缩写 | 阮一峰·英文处理 |
| 专有名词每词首字母大写，非专有名词不大写 | 阮一峰·英文处理 |
| 查用词表（word list）决定特定词的用法和拼写 | Google·highlights |
| 参考类文档词汇保持一致，不追求变化和文采 | Diátaxis·reference |
| 用对「的、地、得」 | 阮一峰·写作风格 |

四份规范都把用词放在靠后的位置，且都是**查表**（Google 的 word list）加**禁生造**（阮一峰）两条，没有更复杂的机制。这说明用词一致性是写作规范的一个常规部分，靠一份词表和写作时查阅解决，不需要单独的工程。

## 标点与排版

| 规则 | 出处 |
|---|---|
| 中文句子全部用全角标点；整句英文用半角 | 阮一峰·标点 |
| 中文与英文、中文与数字之间留一个半角空格（数字可不留，但全文统一） | 阮一峰·文本 |
| 英文和数字与全角标点之间不留空格 | 阮一峰·文本 |
| 并列词用顿号「、」，即使并列的是英文 | 阮一峰·标点 |
| 引号用全角弯引号「“ ”」，内层用单引号 | 阮一峰·标点 |
| 补充说明用全角圆括号「（）」，前后不加空格 | 阮一峰·标点 |
| 句末括号加注时句号在括号外 | 阮一峰·标点 |
| 点号（句逗顿分冒）不出现在标题末尾 | 阮一峰·标点 |
| 省略号用「⋯⋯」，不用「...」；不与「等」连用 | 阮一峰·标点 |
| 破折号占两个字「——」 | 阮一峰·标点 |
| 数值范围用「～」或「至」 | 阮一峰·标点 |
| 代码相关文字用代码字体；界面元素用粗体 | Google·highlights |
| 日期格式无歧义 | Google·highlights |

GB/T 15834-2011 原文核对：§4.8 引号形式为双引号“ ”、单引号‘ ’，竖排改用﹃﹄﹁﹂；**「」不在国标之内**，是台湾和部分技术社区的习惯。§4.11 省略号“……”六点占两字位；§4.10 破折号“——”占两字位；§4.13 连接号三种：短横线“-”半字位（化合物、号码）、一字线“―”一字位（起止）、浪纹线“～”一字位（数值范围）；§4.9 括号主要形式全角圆括号“（）”。本库此前用「」，与国标不符，需要定。

Microsoft top 10 与 Google 的共识：句首大写（when in doubt, don't capitalize）、标题末不加句号或冒号、序列逗号、简短、口语、去掉 *there is* 之类弱写法、以动词开头。与中文写作直接相关的是后四条。

## 本次犯的错对应哪条

| 错 | 规则 |
|---|---|
| `形式`、`三类关系`作标题 | 标题用描述性名词短语（Google） |
| `0. 一图看懂` | 标题不用序号、不用动词开头（Google） |
| `**不覆盖**：` 充当标题 | 不用格式标签冒充标题层级；并列内容用列表或描述列表（Google·headings、highlights） |
| 「待写……」写在正文 | 不预告（Google）；一段一个主题（阮一峰） |
| 生造「不覆盖」「骨架」「档」 | 不生造词（阮一峰）；查词表（Google） |
| 「见 §4」 | 标题不用序号，引用用标题名（Google） |
| 中文用半角逗号 | 中文全角标点（阮一峰） |
| `design/topics.md` 同时解释和规定 | 四类不混（Diátaxis） |
| 一段里塞三件事、长句 | 一段一主题、句长限制（阮一峰） |

九条错里只有一条是用词。其余是结构、段落、类型混淆。
