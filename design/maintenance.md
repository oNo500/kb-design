# 维护循环

维护是让词表和内容随时间保持可信的全部过程。它在[治理](governance.md)授权之下运行：治理定政策、决策权和阈值的复核，维护按规则执行。它不是几份各管一摊的清单，是一个循环：

```
对象 ──有状态──▶ 指标 ──达到阈值──▶ 触发 ──▶ 动作 ──▶ 留痕
```

本文按这六个要素组织。“指标”“阈值”“监控”的用法按 ISO 15489-1 §6.4 监控与评价。来源怎么复核、候选词怎么转正、判断怎么防腐、剩余怎么监控、什么时候发版，都是这个循环的实例，不另立规则。依据见文末。

## 对象与状态

维护作用于六类对象，每类有自己的状态：

| 对象 | 在哪 | 状态 | 说明 |
|---|---|---|---|
| 来源实体 | `entities.yaml`，`kind` 为 standard / publication | `tier`：de-jure / de-facto / vendor / archival | 分档及其说明见[命名实体词表](entities.md)；de-facto 和 vendor 只作入口和例证，不作定义来源，vendor 的接口类文档不进概念文和设计文档 |
| 概念 | `topics.yaml` | unassigned / candidate / active / deprecated | 见[主题词表设计](topics.md) |
| 命名实体 | `entities.yaml` | candidate / active / deprecated | 见[命名实体词表](entities.md) |
| 断言 | 各词表的判断字段 | `basis`：有依据 / self | 见下节 |
| 内容单元 | 知识库 | draft / active / deprecated | 见[内容模型](content-model.md)；不删，处置决定在那里 |
| 词表版本 | 各词表 `version` 块 | 当前版 | 见[词表版本](versioning.md) |

### 断言

有些字段的值不是从来源抄来的，是人判断的。这些判断如果不记依据，半年后就成了事实，再被当作推断的前提——零自定防的是自造的词，这里防的是自造的断言。判断字段的清单以本表为准，各词表设计只引用：

| 词表 | 判断字段 |
|---|---|
| 主题词表 | 本地概念的 `broader`、`related`、`scope`；借入概念之间的合并（同名归一） |
| 命名实体词表 | `subjects`、`form`（多个 Wikidata 类取一个时）、`scope`、`vendor` |
| 内容单元 | `subject`、`type` |

借入的值（`source` 非 self 的 `broader`、`match`、`label`）不是判断，不记依据。

判断字段旁边记 `basis`：

```yaml
- id: eslint
  subjects: [tools-and-environments]
  basis:
    subjects: cs2023:SE-Tools#3        # 来源 id + 条目 + 位置：SE-Tools 主题 3“静态和动态分析工具”
- id: uv
  subjects: [tools-and-environments]
  basis:
    subjects: self                      # 没核到依据
```

| `basis` 的值 | 含义 |
|---|---|
| `<来源 id>:<条目>[#<位置>]` | 在该来源的该条目里核到了支持这个判断的文字 |
| `<来源 id>:scope` | 该来源自身的范围声明支持这个判断 |
| `wikidata:<Q 号>/P31` | `form` 取自该条目的 instance of；多个值时全部记，不挑 |
| `self` | 本库判断，未核到外部依据 |

有任何 `basis: self` 的记录，`status` 不得为 `active`。把 `self` 转为有依据只能靠核到文字，不能靠“用了很久没出问题”。核到文字后的批准属 AI 可直接做的一级，判断本身属二级，见[治理](governance.md)决策权。

## 指标

指标是脚本能算出、或外部能通知的量。三类：

| 类 | 指标 | 对象 | 来自 |
|---|---|---|---|
| 计数 | 被内容单元引用的次数 | 概念、命名实体 | 内容单元的 `subject`、`entities`（Z39.19 §11.1.3.4 b） |
| 计数 | 未标引节点数及占比 | 概念 | `status: unassigned` |
| 计数 | `self` 断言数及占比 | 断言 | `basis` |
| 计数 | 候选在 `candidate` 状态经过的候选审核次数 | 概念、命名实体 | `added` 与审核日期 |
| 计数 | “其他”类目的下位数 | 概念 | GB/T “其他学科”等剩余类目 |
| 计数 | 未标引的术语：正文里出现、但不在任何词表的名词短语及频次 | 候选词来源 | 脚本抽词（Z39.19 §11.1.3.4 a） |
| 计数 | 未命中的检索：检索记录里没有命中任何概念的词 | 候选词或别名来源 | 执行形态的检索记录（Z39.19 §11.1.3.4 c） |
| 时间 | 距上次复核的月数 | 来源实体 | `checked` |
| 时间 | 距上次候选审核的月数 | 词表 | `signals.yaml` |
| 外部事件 | 来源发布新版 | 来源实体 | `watch` 探测点 |
| 外部事件 | 链接失效 | 来源实体、引用 | 链接检查 |

未标引、`self`、长期候选、“其他”四项对应 Star 与 Bowker 的剩余类目：分类没有安放好的东西，其大小和增长是分类失效的指标；维护不消灭它们，监控它们。每个指标的历次值记在 `signals.yaml`，看增长。

引用次数类的指标要读知识库的内容，由执行形态的映射提供；首个映射落地前这些指标不触发，见[决定记录](decisions/form-independence.md)。

## 阈值

所有数字只在此一处，其他文档和脚本引用本表。**除标明依据的，其余是本库估值，首轮维护循环（第一次候选审核完成）后校准。**

| 指标 | 阈值 | 依据 |
|---|---|---|
| 引用次数，unassigned → active | 1 次，或有下位 | 本库 |
| 引用次数，candidate → active | ≥ 3 次，且有 `scope`，且通过审核四问，且 `basis` 无 `self` | 本库 |
| 候选删除 | 引用为 0 连续两次候选审核 | 本库 |
| 候选审核触发 | 候选攒到 20 个，或距上次审核满 12 个月 | 本库 |
| 某节点下 `self` 断言 | ≥ 5 | 本库 |
| 某节点下候选 | ≥ 5 | 本库 |
| “其他”类目下位 | ≥ 3 | 本库 |
| 某顶层未标引占比 | 连续两次候选审核（约 12 个月）无变化 | 本库 |
| 来源复核，de-jure | 24 个月，或发新版 | 本库 |
| 来源复核，de-facto | 12 个月 | 本库 |
| 来源复核，vendor | 6 个月 | 本库 |
| 来源复核，archival | 不复核内容 | 内容固定 |
| 链接检查 | 3 个月，所有档一样 | 本库 |
| 过度使用的概念 | 单个概念的引用占全部引用 ≥ 10% | Z39.19 §11.3.1.3：过度与过少使用都是修改或删除的候选；数字为本库估值 |

## 触发与动作

指标达到阈值触发动作。动作是有限集合：**批准、废弃、删除、拆分、合并、找依据、复核来源、注明不覆盖、发版**。每个动作属哪一级决策权见[治理](governance.md)。

| 指标达到阈值 | 动作 |
|---|---|
| 候选达到阈值表的批准条件 | 批准：`candidate` → `active`（Z39.19 §11.1.6 approved） |
| 未标引概念被引用 | 批准：`unassigned` → `active` |
| 候选引用为 0 连续两次审核 | 删除（候选词可以删，Z39.19 §11.1.6）；AI 列清单，人批 |
| 某节点下 `self` ≥ 5 或候选 ≥ 5 | 拆分：该节点需要下一级类目；先找文献依据，有依据才建 |
| “其他”类目下位 ≥ 3 | 拆分：给它们找正式类目；找不到的留在“其他”，写明 |
| 某顶层未标引占比长期不变 | 注明不覆盖：在顶层概念的 `scope` 写明原因；或承认未覆盖，不动 |
| 过度使用的概念 | 拆分：拆成更具体的概念，或加下位（Z39.19 §11.3.1.3） |
| 两个概念被发现是同一个 | 合并：留一个，另一个转 `deprecated` 并 `replaced_by` |
| `self` 断言 | 找依据：核来源文字；核到则改 `basis`，状态可转正 |
| 来源复核到期或发新版 | 复核来源，见下 |
| 链接失效 | 找官方新地址，其次 DOI / arXiv，最后 archive.org 快照 |
| 一批批准、废弃、来源改版后的增删改 | 发版，见[词表版本](versioning.md)；只补 `scope`、`alt`、`match` 不触发 |

### 候选词的产生

1. 脚本从内容单元正文抽名词短语，去掉已在三份词表（主题、实体、类型）里的首选词和别名，按出现次数排
2. 人工从中提名。提名的词进主题词表或实体词表，`status: candidate`，`origin` 指向第一次出现它的内容单元
3. 没被提名的留在脚本输出里，下次再出现再看

未命中的检索也是来源，看执行形态能否提供检索记录。

### 候选的审核

批准前按 Z39.19 §11.3.1.1 的四问：

1. 已被现有概念或概念的组合覆盖吗？若是，加一条 `alt` 而不是新概念
2. 需要 `scope` 吗？
3. 词形对吗：`label.zh`、`label.en`、id 规则
4. 和现有概念的 `broader`、`related` 怎么建？

### 来源的复核

1. 打开来源，确认引用的事实仍在且未改
2. 有新版：读变更说明，判断是否影响本库引用的部分；影响则改正文，不影响则只更新实体的 `version` 和 `checked`
3. 来源被撤销或替代：找替代来源，改引用；找不到则把断言标为“来源已失效”，不删
4. `basis` 引用该来源的断言随之复核
5. 更新 `checked`

链接存活与内容有效分开查：前者脚本，所有档一样；后者人工，按 tier。archival 档写入时就用 DOI、arXiv 或带日期的永久链接。

de-jure 来源的新版探测，每个实体在 `watch` 登记一个可脚本化的探测点：

| 发布方 | 探测点 | 看什么 |
|---|---|---|
| ISO | `https://www.iso.org/standard/<id>.html` | 状态字段（Published / Under review / Withdrawn）和“将被替代”提示。iso.org 对脚本返回 403，带浏览器 UA 或改用 iTeh 镜像页 |
| GB/T | `std.samr.gov.cn` 详情页 | 标准状态（现行 / 废止）、替代标准 |
| W3C | `https://www.w3.org/TR/<shortname>/` | "This version" 日期和 "Latest published version" 链接 |
| IETF | `https://www.rfc-editor.org/info/rfc<n>` | Obsoleted by / Updated by |
| NISO | `https://www.niso.org/publications/<id>` | 状态与年份 |

## 留痕

留痕的层次以本表为准，[治理](governance.md)只引用：

| 层 | 记在哪 | 记什么 |
|---|---|---|
| 对象 | 概念和实体的 `history` | 每次状态变化：日期、改了什么、为什么（Z39.19 §11.3.2.2 历史注释） |
| 版本 | `vocab/CHANGELOG.md` | 每版的新增、废弃、改名、来源更新；只追加 |
| 规则 | `design/decisions/` | 治理规则本身的变更，ADR，只追加 |
| 维护动作 | `vocab/CHANGELOG.md` 当前版节 | 每次复核时点执行了哪些动作 |
| 指标快照 | `vocab/signals.yaml` | 历次复核时点的各指标值、候选审核日期、治理年审日期 |

注明不覆盖也是留痕：未安放的东西可以被承认，但要写下来。

## 复核时点

| 时点 | 做什么 |
|---|---|
| 内容或词表任何改动后 | 跑 `check-topics.py`（校验 + 指标表）、`check-links.py` |
| 每月 | de-jure 新版探测脚本 |
| 每 3 个月 | 链接存活脚本 |
| 候选攒到 20 个，或距上次候选审核满 12 个月 | 候选审核；同时读指标表，对照触发表执行动作；用 `--record` 写快照 |
| 按 tier | 来源复核 |
| 动作攒成一批 | 发版 |

人工动作只在复核时点做；脚本随时跑，指标表在复核时点读。链接存活脚本和 de-jure 探测脚本待写，写好前这两行不执行。

## 指标表

`check-topics.py` 在校验之外输出指标表，每个指标一行：当前值、上次值、阈值、是否触发。历次值存在 `vocab/signals.yaml`，复核时点用 `--record` 追加一条快照。每顶层未标引数和每字段 `self` 数是其中两组。脚本目前只算词表内部的指标。

## 形态映射的分工

怎么读内容单元的正文和字段、检索记录从哪取、引用计数怎么算，由各执行形态的映射回答（[内容模型](content-model.md)“形态映射的要求”第 4 问）。本文只定指标、阈值、动作。

## 与收词依据的关系

本文的来源复核讲“事实从哪来、凭什么信”；词表建设里平行的问题是“词从哪来、凭什么收”，即 warrant，见[词表的建设与维护](../concepts/vocabulary-construction.md)。来源分级本身的依据是组织依据——本库获取与信任知识的方式。

## 待定事项

- 阈值表里标“本库”的全部数字，首轮维护循环后校准
- 名词短语抽取用什么方法；中英混排文本的分词
- 内容单元的 `subject`、`type` 是否也记 `basis`，还是由引用计数代替
- `basis` 条目里“#位置”的写法是否统一为来源自己的编号
- 注明不覆盖的节点在 `scope` 里怎么写
- 链接存活脚本、de-jure 探测脚本待写；概念文和内容单元引用的文献登记为实体，引用处改为实体 id
- 计数类指标在首个执行形态的映射落地前不触发
