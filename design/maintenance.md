# 维护

维护让词表和内容随时间保持可信。它在[治理](governance.md)授权之下运行：治理规定政策、决策权和阈值复核，维护按规则执行。维护由一个循环中的六个要素组成。

```
对象 ──有状态──▶ 指标 ──达到阈值──▶ 触发 ──▶ 动作 ──▶ 审计追踪
```

本文按这六个要素组织。“指标”“阈值”“监控”的用法依据 ISO 15489-1 §6.4 的监控与评价。来源复核、`candidate` 概念记录转正、断言复核、剩余监控和发版都是这个循环的实例，不另立规则。指标和观察只触发复核；正式修改始终服从[治理](governance.md)的决策权。

## 对象与状态

现行维护作用于以下六类对象，每类对象有自己的状态。正式旧数据和现行规则继续生效。

| 对象 | 在哪 | 状态 | 说明 |
|---|---|---|---|
| 来源实体 | `vocab/entities.yaml`，`kind` 为 standard／publication | `tier`：de-jure／de-facto／vendor／archival | 分档见[命名实体词表](entities.md)；`tier` 决定现行复核周期，不等于外部状态，也不自动增加用途 |
| 概念记录 | `vocab/topics.yaml` | `unassigned`／`candidate`／`active`／`deprecated` | 见[主题词表设计](topics.md) |
| 命名实体记录 | `vocab/entities.yaml` | `candidate`／`active`／`deprecated` | 见[命名实体词表](entities.md) |
| 断言 | 各词表的人工赋值字段 | `basis`：有依据／`self` | 见下节 |
| 内容单元 | 知识库 | `draft`／`active`／`deprecated` | 见[内容模型](content-model.md)；不删，处置决定在该文档中 |
| 词表版本 | 各词表的 `version` 块 | 当前版 | 见[词表版本](versioning.md) |

来源实体、概念记录和命名实体记录的状态互不继承。`unassigned` 只属于现行主题概念；`candidate` 概念记录只表示概念进入现行审核，不表示其中任一 designation 获得试用资格。

来源用途继续受现行 `tier` 和[来源名称规范表](sources-registry.md)共同限制：de-facto 和 vendor 只作入口和例证，不作定义来源，vendor 的接口文档不进概念文和设计文档；有版本号的 de-facto 只有在正式用途已经登记时才可承担现行结构用途。同步不改变任何现行 `tier`。

### 能力边界

来源实体外部状态、来源用途角色状态、来源复核义务状态、候选术语记录、术语状态转换和术语复核义务已经有模式或操作接口。这些接口尚未接管现行六类对象。

| 接口 | 已实现能力 | 当前边界 |
|---|---|---|
| 来源实体与用途 | 结构化地址、外部状态、字段级依据、复核字段、观察入口、逐角色状态、决定引用和只追加历史 | 正式来源仍为旧形状；真实值和具体角色未获批准 |
| 来源义务与索引 | 开启、解决、再次触发和反向定位接口 | 正式来源义务和正式索引不存在；接口结果不是复核结论 |
| 术语记录与转换 | 候选三层记录、独立状态和转换校验 | 正式术语数据、委托和消费者不存在；不替代主题或实体状态 |
| 术语义务与索引 | 义务转换、决定反查和双向定位接口 | 正式术语义务和正式索引不存在；没有获准周期或阈值 |
| 术语生成与诊断 | 受状态门禁的确定性生成和 Markdown 正文报告 | 没有正式输入或切换状态；诊断默认 `report-only` |

模式中的对象和测试夹具中的状态不是待维护的正式实例。不得因接口存在而创建正式数据、义务、委托、消费者或切换状态。

### 断言

人工赋值字段的值不是从来源直接复制，而是人作出的判断。designation 的准入依据只回答它能否被项目采用；本节的 `basis` 回答具体字段值或关系为什么成立。概念对应依据又回答 designation 所指为何。三项门禁相互独立：形式有依据不能证明断言成立，断言有依据也不能替代形式依据或概念判断。

人工赋值字段的清单以本表为准，各词表设计只引用。

| 词表 | 人工赋值字段 |
|---|---|
| 主题词表 | 本地概念的 `broader`、`related`、`scope`；复制概念之间的合并（同名归一） |
| 命名实体词表 | `subjects`、`form`（多个 Wikidata 类取一个时）、`scope`、`vendor` |
| 内容单元 | `subject`、`type` |

现行正式旧数据中，复制值不属于人工判断：`source` 非 `self` 的 `broader`、`match` 和 `label` 不记断言依据。人工赋值字段旁边记录现行紧凑 `basis`。

```yaml
- id: eslint
  subjects: [tools-and-environments]
  basis:
    subjects: cs2023:SE-Tools#3        # 来源 id + 条目 + 位置：SE-Tools 主题 3“静态和动态分析工具”
- id: uv
  subjects: [tools-and-environments]
  basis:
    subjects: self                      # 没核到依据
```

| `basis` 的值 | 含义 |
|---|---|
| `<来源 id>:<条目>[#<位置>]` | 在该来源的相应条目中核到了支持判断的文字 |
| `<来源 id>:scope` | 来源自身的范围声明支持判断 |
| `wikidata:<Q 号>/P31` | `form` 取自该条目的 instance of；多个值时全部记录，不挑选 |
| `self` | 本库判断，尚未核到外部依据 |

记录中只要有一项 `basis: self`，`status` 就不得为 `active`。把 `self` 改为有依据只能靠核到来源文字，不能靠“长期使用没有问题”。核到文字后批准属于 AI 可直接做的一级，判断本身属于二级，见[治理](governance.md)的决策权。

后置共享 `basis` 已实现结构化 `entity`、`locator` 和按内容可变性要求的 `checked`，且不接受 `self`；它尚未应用到正式数据。不得机械改写现行紧凑值，也不得用后置结构替代 designation 准入或概念对应依据。

## 指标

现行指标是脚本可以计算或外部可以通知的量。内容使用计数只有在具名消费者实际实现并启用后才成为指标输入；未来正式计数只读取通过校验的内容单元受控字段。

| 类 | 指标 | 对象 | 来自 |
|---|---|---|---|
| 计数 | 被内容单元引用的次数 | 概念记录、命名实体记录 | 内容单元的 `subject`、`entities`（Z39.19 §11.1.3.4 b） |
| 计数 | 未标引概念记录数及占比 | 概念记录 | `status: unassigned` |
| 计数 | `self` 断言数及占比 | 断言 | `basis` |
| 计数 | 处于 `candidate` 状态时经过的编辑审核次数 | 概念记录、命名实体记录 | `added` 与审核日期 |
| 计数 | “其他”类目的下位概念数 | 概念记录 | GB/T “其他学科”等剩余类目 |
| 计数 | 候选识别器报告的独立字符串数、总出现次数和出现文件数 | 带上下文的未解析字符串线索 | 公开的抽取、排除、标签比较和规范化规则（Z39.19 §11.1.3.4 a） |
| 计数 | 没有匹配任何概念的检索次数 | 带上下文的未解析字符串线索 | 应用提供的检索记录（Z39.19 §11.1.3.4 c） |
| 时间 | 距上次复核的月数 | 来源实体 | 现行 `checked` |
| 时间 | 距上次编辑审核的月数 | 词表 | `vocab/signals.yaml` |
| 外部事件 | 来源发布新版 | 来源实体 | 现行 `watch` 探测点 |
| 外部事件 | 链接失效 | 来源实体、引用 | 链接检查 |

脚本输出和人工提名后的 `candidate` 概念记录分别计量。未解析字符串保留来源上下文，只是复核线索；它不会因未匹配而直接成为项目采用的名称、概念、关系或结构结论。

未标引、`self`、长期 `candidate` 和“其他”四项对应 Star 与 Bowker 的剩余类目：分类没有安放好的内容，其规模和增长是分类失效的指标。维护不消灭这些内容，而是持续监控。每个现行指标的历次值记入 `vocab/signals.yaml`。

正文 Wikilink、Backlinks、用户索引、aliases、unlinked mentions 和 Graph edges 都不是正式计数输入。它们可以提供人工探索线索，不能替代受控字段的语义或校验结果。检索次数也只来自可审计的检索记录；现有检索界面或近期查询显示不构成查询日志。

[Obsidian 映射](targets/obsidian.md)已经完成完整内容应用设计，但尚未实现内容消费者。现有实现只生成词表参考表示，不读取内容单元或检索记录，因此不提供引用次数、未匹配检索次数或相应触发，见[决定记录](decisions/form-independence.md)。

已经实现的辅助材料不自动成为现行指标。

| 材料 | 能说明什么 | 不能说明什么 |
|---|---|---|
| 来源固定夹具观察 | 探测选择、信号分类和正式树不回写的行为 | 真实来源可用性、外部状态、内容变化或正式复核结果 |
| 来源反向索引 | 某一身份、角色、决定或义务可能影响的位置 | 影响位置的值应怎样修改 |
| 来源义务接口 | 在正式输入存在时计算复核事项的机械转换 | 不能证明当前已有正式义务或义务已经解决 |
| 术语正文诊断 | 动态 Markdown 中带上下文的同形或未匹配线索 | designation、概念、违规、阻断或术语候选结论 |
| 术语维护索引 | 在正式输入存在时反查决定、义务和对象 | 不能证明当前已有正式术语对象、委托、义务或周期 |

## 阈值

所有现行数字只在本节出现，其他文档和脚本引用本表。除标明外部依据的项目外，其余均为本库估值，须在首轮维护，即第一次编辑审核完成后校准。

| 指标 | 阈值 | 依据 |
|---|---|---|
| 引用次数，`unassigned` → `active` | 1 次，或有下位 | 本库 |
| 引用次数，`candidate` → `active` | ≥ 3 次，且有 `scope`，且通过审核四问，且 `basis` 无 `self` | 本库 |
| `candidate` 概念记录删除资格 | 引用为 0 连续两次编辑审核 | 本库 |
| 编辑审核触发 | `candidate` 记录攒到 20 个，或距上次审核满 12 个月 | 本库 |
| 某节点下 `self` 断言 | ≥ 5 | 本库 |
| 某节点下 `candidate` 记录 | ≥ 5 | 本库 |
| “其他”类目下位 | ≥ 3 | 本库 |
| 某顶层未标引占比 | 连续两次编辑审核（约 12 个月）无变化 | 本库 |
| 来源复核，de-jure | 24 个月，或发新版 | 本库 |
| 来源复核，de-facto | 12 个月 | 本库 |
| 来源复核，vendor | 6 个月 | 本库 |
| 来源复核，archival | 不复核内容 | 内容固定 |
| 链接检查 | 3 个月，所有档相同 | 本库 |
| 过度使用的概念 | 单个概念的引用占全部引用 ≥ 10% | Z39.19 §11.3.1.3：过度与过少使用都是修改或删除的复审线索；数字为本库估值 |

来源复核日期的后置计算已经实现 6／12／24 个月周期、月底规则和 30 天宽限。这一实现尚未进入正式 `review` 数据或定期运行，不改变上表，也不能把探测频率并入人工复核周期。来源地址观察与每 3 个月链接检查是不同事项。

术语接口没有获准的复核周期、阈值或自动动作。不得把 6、12、20、24 个月、30 天或任何现行 `candidate` 阈值继承给术语义务。

## 触发与动作

指标达到阈值后只触发有权限的复核或提案。动作只允许以下集合：**批准、废弃、删除、拆分、合并、找依据、复核来源、注明不覆盖、发版**。每个动作所属的决策权级别见[治理](governance.md)。

| 指标达到阈值 | 动作 |
|---|---|
| `candidate` 概念记录达到批准条件 | 批准：`candidate` → `active`（Z39.19 §11.1.6 approved） |
| `unassigned` 概念记录被引用 | 批准：`unassigned` → `active` |
| 本地 `candidate` 概念记录引用为 0 连续两次审核 | 只取得删除资格；AI 列清单，人批准后才能删除。其他状态和单个表示形式不继承该资格 |
| 某节点下 `self` ≥ 5 或 `candidate` 记录 ≥ 5 | 拆分：该节点需要下一级类目；先找文献依据，有依据才建 |
| “其他”类目下位 ≥ 3 | 拆分：寻找正式类目；找不到的保留在“其他”并写明 |
| 某顶层未标引占比长期不变 | 注明不覆盖：在顶层概念的 `scope` 写明原因；或承认尚未覆盖，不修改结构 |
| 过度使用的概念 | 拆分为更具体的概念，或增加下位概念（Z39.19 §11.3.1.3） |
| 两个概念被判断为同一个 | 合并：保留一个，另一个转为 `deprecated` 并记录 `replaced_by` |
| `self` 断言 | 找依据：核对来源文字；核到后修改 `basis`，记录才可转正 |
| 来源复核到期或发布新版 | 复核来源，见下文 |
| 链接失效 | 找官方新地址，其次 DOI／arXiv，最后 archive.org 快照 |
| 一批批准、废弃、来源改版后的增删改 | 发版，见[词表版本](versioning.md)；只补 `scope`、`alt`、`match` 不触发 |

观察、索引、义务和工具通过都不是新动作。它们不能自动批准、废弃、删除、拆分、合并、改来源、改术语或发版，也不能把第二级或第三级事项降为第一级。

### 候选的产生

输入线索与 `candidate` 概念记录按以下顺序处理。

1. 脚本在 Git 中动态取得 Markdown 清单，识别带来源上下文的字符串或名词短语。标题、加粗内容和中文引号纳入；代码围栏、行内代码、链接目标和路径排除；规范化只使用明确批准的规则。
2. 脚本把识别结果与现行 `concepts/glossary.md` 和三份现行词表中已登记的首选、替代和隐藏标签比较。
3. 已匹配结果按概念 ID 复核；未解析字符串留在 `report-only` 输出中，并分别记录独立字符串数、总出现次数、文件数、精确位置和上下文。
4. 人工可以从未解析结果或其他材料中提名。提名后先判断目标概念，再核验表示形式的采用依据。
5. 需要新增主题概念时，只有概念判断和依据核验完成后，才建立 `status: candidate` 的概念记录；经核验的表示形式作为现行记录标签保存。输入若表示命名实体，另按[命名实体词表](entities.md)处理。

未被提名的字符串留在报告中，等待后续复核。未命中的检索同样只提供带上下文的线索；是否进入概念记录仍由人工判断。通用 `origin` 不作为主题目标字段，也不由候选识别结果补写。

348 条术语迁移账本只保存冻结审查和消费者去向。`keep`、`defer`、`remove` 及其当前去向不创建主题候选或术语候选，不取得 designation 准入，也不授权删除。候选术语记录和独立状态的接口已经实现，但正式生命周期、编辑源、委托和消费者尚未激活；当前不得建立正式术语记录。

### 候选的审核

批准 `candidate` 概念记录前，按 Z39.19 §11.3.1.1 的四问审核。

1. 目标概念已由一个现有概念覆盖，或可由多个现有概念组合表达吗？如果可以，不新建概念记录，转入独立的表示形式审核。
2. 目标概念是否需要 `scope`？
3. 经准入核验的首选、替代和隐藏标签怎样记录，`label.zh`、`label.en` 和 id 是否符合现行规则？
4. 目标概念与现有概念之间的 `broader`、`related` 怎样建立？

概念覆盖判断和表示形式审核不能合并。同义表示不能制造概念缺口，同形异义也不能制造概念覆盖；本节接受程序中的 `candidate` 状态只作用于现行概念记录，不作用于单个表示形式或未激活术语接口。

### 来源的复核

现行正式旧数据继续按以下步骤人工复核。

1. 打开来源，确认引用事实仍在且未改。
2. 有新版时读取变更说明，判断是否影响本库引用部分；有影响就按决策权修改正文，无影响只更新实体的 `version` 和 `checked`。
3. 来源被撤销或替代时寻找替代来源并提案修改引用；找不到时把断言标为“来源已失效”，不删除。
4. 一并复核现行 `basis` 引用该来源的断言。
5. 完成有权限的正式修改后更新 `checked`。

链接存活与内容有效分开检查：前者由脚本提供线索，所有档相同；后者由人工按现行 `tier` 处理。archival 档写入时使用 DOI、arXiv 或带日期的永久链接。每个 de-jure 实体继续在现行 `watch` 中登记可脚本化的新版探测点。

现行 `watch` 登记与人工核对继续使用以下入口；本表不表示自动 live transport 已经可用。

| 发布方 | 探测点 | 检查内容 |
|---|---|---|
| ISO | `https://www.iso.org/standard/<id>.html` | 状态字段（Published／Under review／Withdrawn）和“将被替代”提示。iso.org 对脚本返回 403 时带浏览器 UA，或改用 iTeh 镜像页 |
| GB/T | `std.samr.gov.cn` 详情页 | 标准状态（现行／废止）和替代标准 |
| W3C | `https://www.w3.org/TR/<shortname>/` | “This version”日期和“Latest published version”链接 |
| IETF | `https://www.rfc-editor.org/info/rfc<n>` | Obsoleted by／Updated by |
| NISO | `https://www.niso.org/publications/<id>` | 状态与年份 |

已实现能力按以下层次使用，不得跨层自动推进。

| 层次 | 当前效力 | 后续边界 |
|---|---|---|
| 固定夹具观察 | 只验证 `HEAD`／`GET` 夹具、频率选择、六类信号和正式树不回写；输出留在 ignored 材料 | `--live` 禁用，实际 JSONL 与探测 schema 未闭合；不能确认真实来源状态或执行正式周期观察 |
| 来源变化 | 外部通知或人工打开来源后得到的线索，须由人确认内容、范围和现行引用影响 | 观察信号、地址变化或索引命中不能直接改 `version`、`checked`、状态、地址、角色、`tier` 或引用 |
| 术语变化 | 来源义务可以在未来通过稳定 id 提出术语复核范围 | 正式术语义务、委托和对象不存在；来源变化不能自动改 designation、概念对应、优先形式、状态或历史 |
| 正式修改 | 人工结论按三级决策权落实到当前正式数据、决定、history 或 CHANGELOG | 义务打开、解决、再次触发及工具通过不替代授权和依据 |
| 后置严格切换 | 严格接口只有在正式数据、角色决定、义务、索引和消费者另行激活后才接管对应流程 | 当前不创建这些对象，不运行正式严格链，也不把 schema 能力当成已切换 |

反向索引只定位可能受影响的正式值；它不能决定实际派生、概念映射或修改内容。复核义务接口只描述可审计的工作项转换；在正式义务文件不存在时，不得虚构义务、目标、解决结论或发布阻断。

## 审计追踪

审计追踪按下表分层，[治理](governance.md)只引用本节。正式审计只追加。

| 层 | 记在哪 | 记什么 |
|---|---|---|
| 对象 | 概念和实体的现行 `history` | 每次状态变化的日期、内容和原因（Z39.19 §11.3.2.2 历史注释） |
| 版本 | `vocab/CHANGELOG.md` | 每版新增、废弃、改名和来源更新；只追加 |
| 规则 | `design/decisions/` | 治理规则本身的变更；ADR 只追加 |
| 维护动作 | `vocab/CHANGELOG.md` 当前版节 | 每次定期复审执行的动作 |
| 指标快照 | `vocab/signals.yaml` | 历次定期复审指标、编辑审核日期和治理年审日期 |
| 来源迁移 | `vocab/migrations/source-v1/` | 六份旧身份、引用、分类和阻断账本；只作历史审计 |
| 术语迁移 | `vocab/migrations/term-v1/terms.tsv` | 348 条冻结审查和消费者去向；只作 audit-only 继承 |

注明不覆盖也是审计追踪。未安放的内容可以被承认，但必须记录。

来源和术语模式中的 `history` 与义务记录只有在正式对象另行激活后才进入相应审计层。当前正式义务和索引不存在；固定夹具探测、正文报告和其他 ignored 输出只提供执行证据，不取得正式状态、决定、指标快照或只追加对象历史的效力。

## 定期复审

| 时点 | 动作 |
|---|---|
| 内容或词表任何改动后 | 运行 `check-topics.py`（校验与指标表）、`check-links.py` |
| 每月 | de-jure 新版观察安排保留；当前只实现固定夹具，`--live` 禁用，故不执行真实来源周期观察 |
| 每 3 个月 | 外部链接存活检查安排保留；它与每月地址或新版观察分开，不能用固定夹具结果替代 |
| `candidate` 记录攒到 20 个，或距上次编辑审核满 12 个月 | 编辑审核；同时读取指标表，对照触发表执行动作；用 `--record` 写快照 |
| 按 `tier` | 人工复核来源 |
| 动作攒成一批 | 发版 |

人工操作只在定期复审时进行；脚本可以随时运行，指标表在定期复审时读取。来源 live transport 和探测输出契约闭合前，不执行真实来源周期探测，也不把夹具信号写入正式字段。

当前不运行术语定期复审。术语义务接口没有正式数据、周期或阈值；正文诊断可以随时生成报告，但命中不自动触发正式动作。

## 指标表

`check-topics.py` 在校验之外输出现行指标表，每个指标一行：当前值、上次值、阈值和是否触发。历次值保存在 `vocab/signals.yaml`，定期复审用 `--record` 追加快照。每个顶层的未标引数和每个字段的 `self` 数是其中两组。脚本目前只计算词表内部指标。

来源和术语反向索引、义务接口、迁移账本、固定夹具观察与正文诊断都不写 `vocab/signals.yaml`，也不冒充正式指标快照。工具可以报告机械状态，不能因此批准对象或执行动作。

## 应用映射

每个 target 的 `Application Profile` 说明怎样读取内容字段、取得检索记录和计算引用次数，见[内容模型](content-model.md)“应用映射”。本文只规定指标、阈值、触发和动作；profile 设计或导出 artifact contract 不是运行记录。

完整内容应用的 target 设计已经建立，但未实现的消费者、校验器、检索记录和回流接口都不提供当前指标输入。[Obsidian 映射](targets/obsidian.md)中的具体表示规则留在 target 内，不因设计、生成物或本地编辑而取得消费者运行证据。

未来报告只提供带位置和上下文的事实、指标和适用阈值触发，供人工复核；报告本身不批准、废弃、删除、拆分、合并、找依据、复核来源、注明不覆盖或发版，也不修改状态、关系、designation、来源或项目决定。未激活术语生成消费者、委托和可选快照不是现行 `Application Profile` 的正式输入；仓库 Markdown 正文诊断也不是外部知识库的导出、检索记录或回流。内容计数继续等待真实消费者，不因内容应用设计或词表参考导出完成而提前触发。

## 收录依据

本文件的来源复核回答“事实从哪里来、为什么可信”；[词表的建设与维护](../concepts/vocabulary-construction.md)中的 warrant 回答“某个 designation 为什么可以被采用”。处理来源材料时，还要区分来源中的字符串、字符串所表示的概念、现有概念是否覆盖目标概念，以及表示形式能否被项目采用。

来源中出现一个字符串只提供文献依据线索。人工仍须判断目标概念和现有覆盖，再独立审核表示形式。来源分级本身采用组织依据，即本库获取和信任知识的方式；它不能代替具体概念、形式或断言的核验。观察、索引和义务同样只能缩小复核范围，不能替代这些判断。

## 待定事项

- 阈值表中标“本库”的全部数字在首轮维护后校准。
- 名词短语采用哪种抽取方法；中英混排文本怎样分词。
- 候选术语接口何时取得正式编辑源、委托、消费者和生命周期效力；当前不创建相应数据。
- 内容单元的 `subject`、`type` 是否记录 `basis`，还是由引用计数代替。
- 现行紧凑 `basis` 的“#位置”在正式迁移时怎样对应后置 `locator`；不得提前机械改写。
- 注明不覆盖的节点在 `scope` 中怎样写。
- 来源 live transport、探测输出契约、真实周期运行、正式义务和正式索引何时闭合；固定夹具实现不回答这些问题。
- 内容引用和检索计数在真实内容消费者提供可审计输入前不触发；现行词表参考导出不满足该条件。
