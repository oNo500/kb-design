# 治理

治理是对管理的管理：谁有权决定什么、按什么政策、变更怎么准入、结果怎么被监督。它不直接操作词表和内容——那是[维护循环](maintenance.md)的事——它规定维护由谁做、按什么规则、怎么被审计。理论见[治理](../concepts/governance.md)。

本库的治理主体是一个人，管理层是一个 AI。ISO 37000 对治理主体与管理层的区分在这里落成一条授权边界：AI 可以直接做什么、必须先提案什么、什么只有人能定。

## 对象范围

治理覆盖以下对象；每类有自己的生命周期或验收标准，在对应文档里：

| 对象 | 在哪 | 生命周期 / 验收 |
|---|---|---|
| 词表数据 | `vocab/*.yaml` | 状态机见各词表设计；校验见[维护循环](maintenance.md) |
| 来源 | `entities.yaml` 中的标准与文献 | `tier` 与复核，见[维护循环](maintenance.md) |
| 设计文档 | `design/*.md` | 本文“质量与验收” |
| 决定记录 | `design/decisions/` | 只追加；推翻时新建并标被替代 |
| 草案 | `design/drafts/` | 各自写明触发条件；生效走变更控制 |
| 概念文 | `concepts/` | [CONVENTIONS](../concepts/CONVENTIONS.md) 硬规则 |
| 文献笔记 | `sources/` | 来源核过；阅读范围写明 |
| 脚本 | `scripts/` | 本文“质量与验收” |
| 执行体的内容 | 知识库，在别处 | [内容模型](content-model.md)；各形态映射 |
| 治理规则本身 | 本文 | 本文“治理自身的复核” |

## 政策

全库的硬规则，一处列出，各带依据。CLAUDE.md 是本节和写作规则的摘要。

| 政策 | 内容 | 依据 | 详见 |
|---|---|---|---|
| 来源优先 | 已有的规范和事实标准是设计的来源和依据；凭记忆写的事实联网核对后才提交 | 本库 README；Z39.19 §11.1.5 候选词入表前核验 | [写作规则](writing.md) |
| 先概念后设计 | 采用任何方法先有概念文和方法登记，再导出规则；推不出的规则不加 | [第一原理与设计理由](../concepts/first-principles.md) | [方法登记](principles.md) |
| 零自定 | 只用标准和权威文献里有的术语；自定要等治理方案落定；唯一例外是分析层的划分特征 | 受控词表：概念先于词 | [划分特征治理](drafts/division-characteristics.md) |
| 断言有依据 | 人判断的字段记 `basis`；`self` 不转正 | Z39.19 §11.1.4；W3C PROV-O | [维护循环](maintenance.md) |
| 完整性 | 改文章不打补丁；一节以上的改动整节或整篇重写，核对旧版逐项去向 | 本库实践 | CLAUDE.md |
| 范围决定顶层 | 顶层概念由范围声明决定；顶层之下按知识体系全借 | ISO 25964-1 §13.1；Z39.19 §11.1.3.1 | [层级结构](hierarchy.md) |
| 借入照抄 | 借入的结构原样保留，不拆不改；本地分析另建数组 | [决定记录](decisions/borrow-and-analyze.md) | [层级结构](hierarchy.md) |
| 不删 | 词表的废弃词、内容单元一律保留；唯一例外是误建且无引用 | Z39.19 §11.3.2；ISO 15489 处置决定 | [内容模型](content-model.md) |
| id 不变 | id 一经引用不改；改名只改 `label` | ISO 25964-1 §2.25 | [内容模型](content-model.md) |
| 形态无关 | 形态无关层不提任何工具的字段名和格式；`vocab/` 是源，各形态从它导出，不反向编辑 | 本库 README | [内容模型](content-model.md) |
| 决定留痕 | 规则的变更走决定记录，只追加不修改 | Nygard ADR | [决定记录](decisions/) |

政策的变更本身走变更控制。

## 决策权

三级：AI 可直接做、AI 提案后人定、只有人能定。边界按改动的**可逆性**和**是否改变规则**划。

| 级 | 改动 | 例 |
|---|---|---|
| **AI 直接做** | 不改规则、可逆、有脚本或规则可验的 | 数据采集与核对；按已定规则生成或校验数据；错字、坏链接、标点、标题违规的修正；索引与 CHANGELOG 同步；按既定小节清单写已批准的文档 |
| **AI 提案，人定** | 改规则、改结构，或没有规则可依的 | 新设计文档或概念文（先给小节清单）；修改任何一条规则或阈值；文件拆并、改名；词表结构变更（新顶层、新数组、新来源）；新方法登记；实体或概念的归属判断（`basis: self` 的那些） |
| **只有人定** | 改变范围或不可逆的 | 范围声明（顶层、排除）；零自定例外的开放；决定记录的采纳与推翻；删除任何非候选对象；发版；草案生效 |

提案的形式：说明改什么、为什么、依据是什么、影响哪些文件；人回复后再动文件。AI 不得以“顺手”为由把第二级的事当第一级做。

越权或欠权的事件发生后，本表修订一次并记决定。

## 变更控制

| 变更 | 流程 | 记录 |
|---|---|---|
| 规则变更（任何设计文档里的规则） | AI 提案 → 人定 → 改文档 → 受影响的文档同步 → 链接检查 | 决定记录（结构性的）或 git 提交说明（局部的）；哪类算结构性由人判断 |
| 方法准入 | 概念文 → 方法登记 → 导出规则 | [方法登记](principles.md) |
| 草案生效 | 触发条件出现 → 人确认 → 草案移出 `drafts/`，内容并入对应设计 → 决定记录 | [决定记录](decisions/) |
| 词表结构变更 | 提案 → 人定 → 改 `vocab/build/` 输入并重新生成，或直接改数据 → 校验通过 → CHANGELOG | CHANGELOG |
| 词表发版 | 维护循环触发 → 人定 → 版本块与 CHANGELOG | [词表版本](versioning.md) |
| 政策变更 | 同规则变更，且必须有决定记录 | 决定记录 |

## 质量与验收

每类对象“完成”的标准：

| 对象 | 完成的标准 |
|---|---|
| 概念文 | CONVENTIONS 五条硬规则；权威来源全部核过链接；术语在术语表或本文定义；索引已登记 |
| 设计文档 | 每节的规则有依据或标明“本库”；待定事项在文末；不出现“待写”；链接检查通过；用到的术语在术语表 |
| 词表条目 | 校验脚本零问题；借入的有 `match` 回源头；判断字段有 `basis`；`self` 不为 `active` |
| 脚本 | 幂等（重跑不改结果）；文本替换带断言；批量改动前先提交、改后 `git diff` 复核；输出可读 |
| 决定记录 | 背景、决定、后果、状态、日期；推翻时不改旧记录 |
| 文献笔记 | 标明读了哪部分、没读哪部分；条款号来自原文 |

## 审计

三层留痕各有义务：

| 层 | 记录 | 义务 |
|---|---|---|
| 对象 | `history` | 状态变化必记：日期、改了什么、为什么 |
| 版本 | `vocab/CHANGELOG.md` | 每版的增删改；每次周期点的治理动作和信号值 |
| 规则 | `design/decisions/`；git 提交说明 | 结构性变更必有决定记录；所有提交说明写清改了什么 |

防护措施，针对已经发生过的失败：

| 失败 | 防护 |
|---|---|
| 文本替换静默失败（目标不匹配时无事发生，六行登记丢失数周） | 替换必须带断言；改完 grep 确认 |
| 批量转换破坏规则文本（标点脚本把规则里的“”改成了“”） | 规则文本里的示例放行内代码；批量脚本跳过代码；转换后 `git diff` 逐段看 |
| 凭记忆写事实（条款号写错、声称国标认可“”） | 写入前核原文；核不到的标“未核对” |
| 设计跑在数据前（节点标签规则在枚举上塌掉） | 规则定稿前用真实数据试一遍 |
| 文档与数据不一致（设计里手写的 id 与生成的不同） | 数据为准；文档引用数据时从数据生成，不手写 |

审计动作：每次提交前跑 `check-links.py`、`check-topics.py`；每个周期点读信号报告；治理自身复核时抽查决定记录是否覆盖了实际发生的规则变更。

## 风险

| 风险 | 控制 |
|---|---|
| AI 编造或记错事实 | 来源优先政策；验收要求核过 |
| AI 越权改规则 | 决策权矩阵；事件后修订 |
| 判断债累积 | `self` 不转正；信号报告 |
| 来源漂移 | 按 tier 复核；de-jure 探测 |
| 规则无用例即定稿 | 先用数据试 |
| 单人单点 | git remote 备份；决定记录让下一个人能接 |
| 治理规则本身过时 | 下节 |

## 治理自身的复核

- 政策表、决策权矩阵、阈值表每 12 个月审一次；审的结果记决定
- 决策权矩阵在每次越权或欠权事件后修订
- 阈值在首轮维护循环后校准，之后随年审
- 本文的变更走政策变更流程

## 待定事项

- “结构性变更”与“局部变更”的界线，目前由人判断
- 决策权第二级里“实体或概念的归属判断”是否全部需要人定，还是 `basis` 核到文字后 AI 可直接转正
