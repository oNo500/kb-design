# 治理

治理是对管理的管理：谁有权决定什么、按什么政策、变更怎么准入、结果怎么被监督。它不直接操作词表和内容——那是[维护](maintenance.md)的事——它规定维护由谁做、按什么规则、怎么被审计。理论见[治理](../concepts/governance.md)。

本库的治理主体是一个人，管理层是一个 AI。ISO 37000 对治理主体与管理层的区分在这里落成一条授权边界：AI 可以直接做什么、必须先提案什么、什么只有人能定。首批边界的决定见[决策权的首批边界](decisions/decision-rights-defaults.md)。

## 政策

全库的硬规则，一处列出，各带依据。`AGENTS.md` 是本节和[写作规则](writing.md)的摘要。

| 政策 | 内容 | 依据 | 详见 |
|---|---|---|---|
| 来源优先 | 已有的规范和事实标准是设计的来源和依据；凭记忆写的事实联网核对后才提交 | Z39.19 §11.1.5 候选词入表前对照权威来源核验 | [写作规则](writing.md) |
| 先概念后设计 | 采用任何方法先有概念文和方法登记，再导出规则；推不出的规则不加 | Aristotle 第一原理；Nygard ADR，见[第一原理与设计理由](../concepts/first-principles.md) | [方法登记](principles.md) |
| 零自定 | 只用按术语准入阶梯查到的术语；五级都查不到的，由人走词典制定；AI 不得造词、不得以候选形式试用 | ISO 25964-1 §2.11 概念先于词；ISO 704；Z39.19 §11.1.5 | 本文“术语准入” |
| 实体类别取外部类 | 实体的 `kind` 取 Wikidata 的类，不自定 | 零自定的实例 | [命名实体词表](entities.md) |
| 断言有依据 | 人判断的字段记 `basis`；`basis` 含 `self` 的不得为 `active` | Z39.19 §11.1.4 词记录的来源字段；W3C PROV-O | [维护](maintenance.md) |
| 整篇重写 | 改文章不打补丁；一节以上的改动整节或整篇重写，核对旧版逐项去向 | 本库的过程规则，无外部依据，见[写作规范](../concepts/writing-conventions.md) | `AGENTS.md` |
| 先用数据试 | 规则定稿前用真实数据跑一遍 | 本库的过程规则，来自已发生的失败 | 本文“审计” |
| 范围决定顶层 | 顶层概念由范围声明决定；顶层之下按知识体系全借，借到有稳定编号的最深一层 | ISO 25964-1 §13.1；Z39.19 §11.1.3、§11.1.7、§11.1.8 | [层级结构](hierarchy.md) 规则 3–5 |
| 原样复制 | 复制的结构原样保留，不拆不改；本地分析另建数组；同一视角只取一个来源 | [决定记录](decisions/borrow-and-analyze.md) | [层级结构](hierarchy.md) 规则 6、13 |
| 结构来源的资格 | 可作结构来源的必须 `tier` 为 de-jure，或 de-facto 且有版本号；vendor 只作映射 | Z39.19 §5.3.5.2 组织依据；来源分级 | [来源名称规范表](sources-registry.md) |
| 映射来源须登记 | `source`、`match.source`、`basis` 引用的来源必须在 `sources.yaml` 里 | ISO 25964-2 §23 名称规范表 | [来源名称规范表](sources-registry.md) |
| 不删 | 词表的废弃词、内容单元一律保留；唯一例外是误建且无引用 | Z39.19 §11.3.2；ISO 15489-1 §3.8 处置决定 | [内容模型](content-model.md) |
| id 不变 | id 一经引用不改；改名只改 `label`，旧形式到新形式加 USE | Z39.19 §11.3.1.2 改词时从旧形式加 USE 引用 | [内容模型](content-model.md) |
| 与工具无关 | 与应用无关层不提任何工具的字段名和格式；`vocab/` 是源，各应用从它导出，不反向编辑；映射不得改动字段定义 | [决定记录](decisions/form-independence.md) | [内容模型](content-model.md) |
| 决定审计追踪 | 规则的结构性变更走决定记录，只追加不修改 | Nygard ADR | [决定记录](decisions/) |
| 写作规则 | 标题、标点、术语、文档类型按写作规则 | ISO 24495-1 四原则 | [写作规则](writing.md) |

政策的变更本身走变更控制。

## 决策权

三级：AI 可直接做、AI 提案后人定、只有人能定。边界按改动的可逆性和是否改变规则划。

| 级 | 改动 | 例 |
|---|---|---|
| **AI 直接做** | 不改规则、可逆、有脚本或规则可验的 | 数据采集与核对；按已定规则生成或校验数据；错字、标点、标题违规的修正；同一来源的新地址替换坏链接；索引同步；在 CHANGELOG 当前版节内追加；按既定小节清单写已批准的文档；新实体以 candidate 录入 `entities.yaml`；核到 `basis` 文字且校验通过后批准（candidate → active） |
| **AI 提案，人定** | 改规则、改结构，或没有规则可依的 | 新设计文档或概念文（先给小节清单）；修改任何一条规则或阈值，含脚本里的阈值常量；文件拆并、改名、删除；词表结构变更（新顶层、新数组、新结构来源、进 `sources.yaml`）；新方法登记；术语进术语表；`scope`、`broader`、`subjects` 的判断本身；候选删除（AI 列清单）；换来源或改用 archive 快照；概念文修订导致规则要跟着改 |
| **只有人定** | 改变范围或不可逆的 | 范围声明（顶层、排除）；零自定例外的开放；决定记录的采纳与推翻；删除任何非候选对象；发版（CHANGELOG 新开版节）；草案生效；来源改档 |

提案的形式：说明改什么、为什么、依据是什么、影响哪些文件；人回复后再动文件。AI 不得以“顺手”为由把第二级的事当第一级做。

检测：每条提交说明以 `[L1]`、`[L2]`、`[L3]` 标注本次改动的最高级别；人抽查 `[L1]` 提交是否真是第一级。越权或欠权的事件发生后，本表修订一次并记决定。

## 变更控制

| 变更 | 流程 | 记录 |
|---|---|---|
| 规则变更（设计文档表格里的规则行、阈值） | AI 提案 → 人定 → 改文档 → 受影响的文档与摘要同步 → 链接检查 | 默认视为结构性，决定记录；人可降为局部，只记提交说明 |
| 政策变更 | 同规则变更，必有决定记录 | 决定记录 |
| 方法准入 | 概念文 → 方法登记 → 导出规则 | [方法登记](principles.md) |
| 术语准入 | 本文“术语准入”的阶梯 | 术语表的出处列；查无记录 |
| 概念文修订 | 修订 → 检查方法登记里由它导出的规则是否受影响 → 受影响的走规则变更 | 提交说明 |
| 草案生效 | 触发条件出现 → 人确认 → 草案移出 `drafts/`，内容并入对应设计 → 决定记录 | 决定记录 |
| 词表结构变更 | 提案 → 人定 → 改 `vocab/build/` 输入并重新生成，或直接改数据 → 校验通过 → CHANGELOG | CHANGELOG |
| 来源改档 | 人定 → 改实体 `tier` → 受影响的断言复核 | 实体 `history` |
| 词表发版 | 维护触发 → 人定 → 版本块与 CHANGELOG 新版节 | [词表版本](versioning.md) |
| 新建应用的映射 | 按内容模型的五个问题写 → 人定 | `design/targets/` |
| 决定记录的推翻 | 新建决定 → 旧决定标被替代 | 决定记录 |
| 摘要同步 | 被摘要的文档改动后，`AGENTS.md`、README 随之改 | 同一提交 |

## 术语准入

本库用到的每个术语都要能在术语表里找到出处。准入按阶梯查，查到即止，登记时写明在哪一级查到：

| 级 | 来源 | 例 |
|---|---|---|
| 1 | de-jure：国际与国家标准、W3C Recommendation、RFC | ISO 25964、GB/T 13745、SKOS |
| 2 | de-facto：知识体系、行业组织的规范 | CS2023、SWEBOK、ASVS、Diátaxis |
| 3 | vendor：厂商文档 | Anthropic 文档、Obsidian 文档 |
| 4 | archival：论文、书、带日期的博文 | Hogan 2021、Bowker & Star 1999 |
| 5 | 其他：行业领袖的定义、业界共识（多个独立来源一致使用） | Nygard 的 ADR |

五级都查不到的，**由人制定词典**：人给定义、判据句和适用范围，登记为本库词典条目，`basis: self`。AI 在任何一级只有查的权限：查到就引用并登记；查不到只能报告五级均无，不得造词，不得以候选形式试用，不得在任何文档里出现未登记的术语。

查无记录是可审计的：提案必须逐级列出查了哪些来源、结果如何；空着不算查过。

检测：`scripts/check-terms.py` 扫全库正文里像术语的东西——加粗词、引号里的词、标题里的名词、术语表已有词的变体——不在术语表的报出。每次编辑审核时过一遍清单。发现已在用的未登记术语，先按阶梯查，查到则替换并在术语表登记，查不到则交人制定或删除；不得事后补登记为“本库”了事。

划分特征草案里的属性名同样走本节：将来要用，由人按词典制定流程定。

### 译名

中英对照只在术语表一处；词表的 `label` 与正文必须与术语表一致。译名的准入与术语同构，按阶梯查，查到即止：

| 级 | 来源 |
|---|---|
| 1 | 等同采用国际标准的 GB 给出的译名：GB/T 13190 对 ISO 25964，GB/T 26162 对 ISO 15489 |
| 2 | 学科权威教材、工具书，两个独立来源一致 |
| 3 | Wikidata 的中文标签 |
| 4 | 都没有：不译。正文用原名，首次出现给一句解释；术语表 `zh` 留空，解释填 `explanation` |

AI 在第 4 级只能给解释，不能给名；“有译名但不达意”的判断只有人能做，AI 不得以此为由改用自己的译法。反方向（中文概念的英文名）同样适用：GB/T 13745 的学科名没有官方英文，查不到就不给英文。

词表里每个标签带 `zh_basis`、`en_basis`：值是阶梯的级与来源（如 `gbt-13190`、`wikidata:Q978185`），或 `source`（标签直接来自借入的来源，不是译）、`none`（不译）。值为 `self` 的标签是已知的自造译名，待追溯；带 `self` 的记录状态不得为 `active`。

检测：`check-topics.py` 报 `self`；`check-terms.py` 报同一英文在全库对应不同中文，或反之。

追溯的做法：`scripts/lookup-labels.py` 按阶梯第 3 级查 Wikidata，只接受对方语言标签与本库名称完全一致、且描述像学科或概念的条目；中文优先简体标签，繁体经 OpenCC 转简并注明。结果是清单，交人审；词义是否对得上是判断，AI 不直接写入。人审后的决定记在 `vocab/build/label-decisions.json`（采纳的记 Q 号与标签，否决的记理由），`build-topics.py` 据此改标签与 `basis`；未查到和否决的一律不译，去掉自译标签，`basis` 记 `none`。2026-08-23 首次追溯：692 条自译，采纳 72，否决 13，不译 607。不译的概念在 `scope` 里给一句中文解释，解释按来源原文写（输入 `vocab/build/scope-zh.json`），不另起名；来源自带官方译文的（OWASP LLM Top 10 的 zh-CN）直接用，`basis` 记 `source`。

## 质量与验收

每类对象“完成”的标准：

| 对象 | 完成的标准 |
|---|---|
| 概念文 | CONVENTIONS 五条硬规则；权威来源全部核过链接；术语在术语表或本文定义；索引已登记 |
| 设计文档 | 每节的规则有依据或标明“本库”；待定事项在文末；不出现“待写”；链接检查通过；用到的术语在术语表 |
| 词表条目 | 校验脚本零问题；复制的有 `match` 回源头；人工赋值字段有 `basis`；`self` 不为 `active` |
| 脚本 | 幂等（重跑不改结果）；文本替换带断言；批量改动前先提交、改后 `git diff` 复核；阈值常量与阈值表一致；输出可读 |
| 决定记录 | 状态与日期、背景、决定、后果；推翻时不改旧记录 |
| 文献笔记 | 标明读了哪部分、没读哪部分；条款号来自原文 |
| 提交说明 | 写清改了什么；标注决策权级别 |

## 审计

审计追踪的层次和义务在[维护](maintenance.md)“审计追踪”。审计动作：每次提交前跑 `check-links.py`、`check-topics.py`；每个定期复审读指标表；治理年审时抽查决定记录是否覆盖了实际发生的规则变更、抽查 `[L1]` 提交。

防护措施，针对已经发生过的失败：

| 失败 | 防护 |
|---|---|
| 文本替换静默失败（目标不匹配时无事发生，六行登记丢失数周） | 替换必须带断言；改完 grep 确认 |
| 批量转换破坏规则文本（标点脚本把规则里的 `「」` 改成了 `“”`） | 规则文本里的示例放行内代码；批量脚本跳过代码；转换后 `git diff` 逐段看 |
| 凭记忆写事实（条款号写错、声称国标认可 `「」`） | 写入前核原文；核不到的标“未核对”；引用的标准在 `sources/` 有笔记 |
| 设计跑在数据前（节点标签规则在枚举上塌掉） | 规则定稿前用真实数据试一遍 |
| 文档与数据不一致（设计里手写的 id 与生成的不同） | 数据为准；文档引用数据时从数据生成，不手写 |
| AI 越权（把治理文档拆并改名而未提案） | 提交说明标级别；人抽查 |

## 风险

| 风险 | 控制 |
|---|---|
| AI 编造或记错事实 | 来源优先；验收要求核过；`sources/` 笔记 |
| AI 越权改规则 | 决策权矩阵；提交说明标级别；事件后修订 |
| 未核实的判断累积 | `self` 不转正；指标表 |
| 来源漂移 | 按 tier 复核；de-jure 探测 |
| 规则无用例即定稿 | 先用数据试 |
| 单人单点 | git remote 备份；决定记录让下一个人能接 |
| 治理规则本身过时 | 下节 |

## 治理评审

- 政策表、决策权矩阵、阈值表每 12 个月审一次；审的日期记在 `vocab/signals.yaml` 的 `governance_reviewed`，结果记决定
- 决策权矩阵在每次越权或欠权事件后修订
- 阈值在首轮维护（第一次编辑审核完成）后校准，之后随年审
- 本文的变更走政策变更流程

## 待定事项

- 词典制定流程的细则：人制定的条目怎么复审、怎么废弃
- “结构性变更”默认判定为设计文档表格里的规则行，例外由人降级——是否够用，首轮后看
