# 治理

治理是对管理的管理：谁有权决定什么、按什么政策、变更怎么准入、结果怎么被监督。它不直接操作词表和内容——那是[维护](maintenance.md)的职责——而是规定维护由谁做、按什么规则进行、怎样接受审计。理论见[治理](../concepts/governance.md)。

本库的治理主体是一个人，管理层是一个 AI。ISO 37000 对治理主体与管理层的区分在这里形成授权边界：AI 可以直接做什么、必须先提案什么、哪些事项只有人能决定。首批边界见[决策权的首批边界](decisions/decision-rights-defaults.md)。schema、索引、观察、义务接口、生成器、诊断或校验通过，只证明相应机械能力，不产生事实结论，也不扩大任何一方的决策权。

## 对象范围

治理对象按效力分开。正式数据、现行设计、`Application Profile`、导出 artifact contract、已经实现但未激活的基础、迁移审计和草案不能互相替代；target 文件或生成目录存在也不证明真实内容消费者已经启用。

### 能力边界

以下基础已经实现，但没有接管正式数据。

| 范围 | 已实现能力 | 未取得的效力 |
|---|---|---|
| 来源 | 六份 schema、共享来源模型、离线校验、反向索引、固定夹具探测、迁移预演和复核义务接口 | 没有正式来源 v2 数据、正式义务、正式索引、真实联网观察、具体角色批准或正式切换 |
| 术语 | 三层候选模式、状态转换校验、确定性生成器、正文诊断、维护索引和复核义务接口 | 没有正式术语数据、义务、委托、消费者、切换状态或编辑权转移 |
| Obsidian | 六份正式词表的单向参考导出、新 vault 初始化、UUIDv4 `draft` 建立、只读内容校验、派生报告、项目 manifest 和安全发布 | 没有实际用户内容、正式消费者、查询日志、回流、JCS、BagIt、reproducible build 或 durability 符合性与保证 |

来源探测的 `--live` 明确禁用，实际 JSONL 输出与探测 schema 尚未闭合。固定夹具只能证明只读行为和信号逻辑，不能确认真实来源状态。术语生成器和维护接口没有正式输入；测试夹具中的状态与消费者也不是仓库现状。

仓库当前不存在正式 `vocab/source-obligations.yaml`、`vocab/terms.yaml`、`vocab/term-obligations.yaml`、来源正式索引或术语正式切换状态。`concepts/glossary.md` 仍是现行可编辑登记；本次同步不创建上述正式对象。

### 迁移边界

`vocab/migrations/source-v1/` 的六份账本保存来源旧身份、旧用途、旧 `basis`、旧 `source`、旧 `match`、旧 `origin` 的库存、分类和阻断。账本的推荐值、`proposed` 或处置不批准真实来源事实，不修改正式数据；既有预演只能作为已保存的历史结果，不能宣称当前 HEAD 可按原冻结输入重放。

`vocab/migrations/term-v1/terms.tsv` 的 348 条记录保存冻结审查结论和消费者去向。`audit-only`、`retain-owner`、`retain-pending-l3`、旧 `keep`、`defer` 或 `remove` 都不构成 designation 准入、概念对应、术语候选、删除许可或正式状态。

迁移账本只作审计。它们不是正式词表、义务、委托、消费者、决定或切换状态。

### 草案边界

`design/drafts/` 中的文档各自写明触发条件。来源治理和术语治理的部分前置机器契约已经另经决定实现，不表示草案整体生效。草案中的角色、状态、周期、委托、正式数据和切换安排都不能在人工生效决定前写入正式对象。

草案生效仍走变更控制。阅读草案、实现 schema 或工具、生成 ignored 材料，均不取得正式规则效力。

## 决策权

决策权分三级：AI 可直接做、AI 提案后由人决定、只有人能决定。边界按改动的可逆性和是否改变规则划分。

| 级 | 改动 | 例 |
|---|---|---|
| **AI 直接做** | 不改规则、可逆、有脚本或规则可验 | 数据采集与核对；按已定规则生成或校验数据；修正错字、标点和标题违规；替换同一来源的坏链接；同步索引；在 CHANGELOG 当前版节内追加；按既定小节清单写已批准文档；新实体以 `candidate` 录入 `entities.yaml`；核到 `basis` 文字且校验通过后批准（`candidate` → `active`） |
| **AI 提案，人定** | 改规则、改结构，或没有规则可依 | 新设计文档或概念文；修改任何规则或阈值，包括脚本阈值常量；文件拆并、改名、删除；词表结构变更；新方法登记；designation 准入；`scope`、`broader`、`subjects` 的判断；删除 `candidate` 对象时列清单；换来源或改用 archive 快照；概念文修订导致规则变化 |
| **只有人定** | 改变范围或不可逆 | 范围声明；零自定例外；决定记录的采纳与推翻；删除任何非 `candidate` 对象；发版；草案生效；来源改档 |

提案须说明改什么、为什么、依据是什么、影响哪些文件。人回复后才能修改文件；AI 不得把第二级事项当作第一级事项。

模式或工具可以要求决定引用，却不能形成或采纳决定。观察到来源变化、建立反向索引、计算或重开义务、生成报告、通过 schema 或测试，都不改变上表。具体来源状态、地址、角色、替代、实际派生、概念映射、术语准入、概念对应、优先形式、委托和迁移去向仍按其内容落入第二级或第三级。

每条提交说明以 `[L1]`、`[L2]` 或 `[L3]` 标注本次改动的最高级别。人抽查 `[L1]` 提交是否确属第一级；发生越权或欠权后，本表修订一次并记决定。

| 新建 target | 核对概念文 → 核对[方法登记](principles.md) → 引用适用的已采纳决定 → 写 `Application Profile` 上层职责与五个操作问题 → 分开导出 artifact contract → 人定 | `design/targets/` 与决定记录 |

来源正式迁移、术语正式激活、编辑权转移、委托、消费者启用和切换状态，都必须等待其阶段由人开放并取得所需决定。本次已有基础没有建立这些对象，也不提供完整 candidate、handoff、payload、原子应用或补偿回滚。

## 准入对象

项目拟采用的每个 designation 都必须能在 `concepts/glossary.md` 中找到出处。准入按下列阶梯检索，查到即止；登记时写明在哪一级取得依据。

| 级 | 来源 | 例 |
|---|---|---|
| 1 | de-jure：国际与国家标准、W3C Recommendation、RFC | ISO 25964、GB/T 13745、SKOS |
| 2 | de-facto：知识体系、行业组织规范 | CS2023、SWEBOK、ASVS、Diátaxis |
| 3 | vendor：厂商文档 | Anthropic 文档、Obsidian 文档 |
| 4 | archival：论文、书、带日期的博文 | Hogan 2021、Bowker & Star 1999 |
| 5 | 其他：行业领袖的定义，或多个独立来源一致使用的业界共识 | Nygard 的 ADR |

五级都查不到时，由人制定词典条目：人给出定义、判据句和适用范围，登记为本库词典，`basis: self`。AI 在任何一级只有检索权限：查到后引用并登记；查不到只能报告五级均无，不能主动形成或选定无依据的 designation，也不能借 `candidate`、`defer`、草案、占位、示例、schema 状态或迁移去向试用。普通叙述、来源转录、文件路径、代码和值不因字符串首次出现自动成为项目采用的名称。

查无记录必须可审计。提案逐级列明检索过的来源和结果；空白不算检索过。一个 designation 的形式依据、它所表示的概念以及记录中具体字段值或关系的依据须分别核对，任何一个状态门禁都不能替代另一个。

`scripts/check-terms.py` 是已经实现的候选识别器。它从 Git 中取得动态 Markdown 清单，检查标题、加粗内容和中文引号，排除代码围栏、行内代码、链接目标和路径；再与现行 `concepts/glossary.md` 及三份现行词表中的已登记写法比较。默认输出是带精确位置的 `report-only` 人工复核材料，命中不构成项目名称、概念、关系或违规，也不阻断提交。可选状态或人工裁定输入目前不改变这个效力。

348 条术语迁移账本只继承既有审查位置、动作和去向。它不建立候选术语记录，不重准入现行 designation，也不改变 `concepts/glossary.md` 的编辑权。候选术语三层模式只有接口效力；未来正式数据只有在另行生效后才可能接管登记。

划分特征草案中的属性名同样适用本节。将来需要采用时，由人按词典制定流程决定；零自定例外尚未开放。

### 译名

中英对照只在 `concepts/glossary.md` 一处登记；词表的 `label` 与正文必须使用已登记形式。译名按下列阶梯核对，查到即止。

| 级 | 来源 |
|---|---|
| 1 | 等同采用国际标准的 GB 给出的译名：GB/T 13190 对 ISO 25964，GB/T 26162 对 ISO 15489 |
| 2 | 学科权威教材、工具书，两个独立来源一致 |
| 3 | Wikidata 中文标签 |
| 4 | 都没有时不译。正文使用原名，首次出现给一句解释；登记中的 `zh` 留空，解释写入 `explanation` |

AI 在第 4 级只能给解释，不能给名称。“有译名但不达意”的判断只有人能做，AI 不得以此为由改用自己的译法。反方向同样适用：GB/T 13745 的学科名没有官方英文时，查不到就不给英文。

词表中的每个标签带 `zh_basis`、`en_basis`：值是阶梯级别与来源，如 `gbt-13190`、`wikidata:Q978185`；也可以是 `source`，表示标签直接来自借入来源，或 `none`，表示不译。值为 `self` 的标签是已知自造译名，待追溯；含 `self` 的记录不得为 `active`。

`check-topics.py` 报告现行 `self`。`check-terms.py` 只报告按上述扫描规则得到的候选字符串和上下文，不裁定中英对应关系。

追溯时，`scripts/lookup-labels.py` 按阶梯第 3 级查询 Wikidata，只接受对方语言标签与本库名称完全一致、描述与相应概念相符的条目；中文优先简体标签，繁体经 OpenCC 转简并注明。结果是清单，交人审；词义是否对得上是判断，AI 不直接写入。人工决定记在 `vocab/build/label-decisions.json`：采纳项记录 Q 号与标签，否决项记录理由。`build-topics.py` 据此修改标签与依据；未查到或被否决的一律不译，去掉自译标签，依据记 `none`。2026-08-23 首次追溯共 692 条自译，采纳 72 条、否决 13 条、不译 607 条。不译的概念在 `scope` 中按来源原文给出中文解释，输入为 `vocab/build/scope-zh.json`；来源自带官方译文时直接使用，依据记 `source`。

## 质量与验收

各类现行对象的完成标准如下。

| 对象 | 完成标准 |
|---|---|
| 概念文 | CONVENTIONS 的五条硬规则；权威来源链接均已核对；项目采用的 designation 有依据；索引已登记 |
| 设计文档 | 每节规则有依据或标明“本库”；已实现能力不写成待建；真实未决事项集中在文末；链接检查通过；项目采用的 designation 有依据 |
| `Application Profile` | 引用概念文、方法登记和适用决定；功能范围、模型引用、field constraints、`Usage Guidelines`、`Encoding Syntax Guidelines` 与五个操作问题完整；target binding 不改写应用无关语义 |
| 导出 artifact contract | 与语义选择交接清楚；输入快照、byte serialization、order、quoting、newlines、file set、manifest、post-generation validation 和 publication 与实现一致；确定性、完整性、原子可见性、durability 和外部符合性分别陈述 |
| 词表条目 | 现行校验脚本零问题；复制项有现行 `match` 回到源头；人工赋值字段有现行 `basis`；`self` 不为 `active` |
| 脚本 | 幂等；文本替换带断言；批量改动前后复核 Git 差异；现行阈值常量与阈值表一致；输出可读 |
| 决定记录 | 有状态与日期、背景、决定和后果；推翻时不改旧记录 |
| 文献笔记 | 标明读过和未读的部分；条款号来自原文 |
| 提交说明 | 写清改动并标注决策权级别 |

基础接口完成与正式激活完成采用不同证据。schema 生成一致、转换校验、确定性输出、索引覆盖、夹具只读、报告位置和迁移身份对账，可以验收基础能力；它们不能验收正式数据、具体来源或术语事实、委托、消费者、周期运行或切换。正式激活还需要相应人工决定、完整候选、消费者契约、应用后验证，以及风险所需的回滚证据；当前阶段没有这些证据不构成基础接口失败。

target 文件验收与消费者验收也分开。前者证明语义选择、表示和物化合同自洽；后者必须由具名消费者实际读取内容字段或检索记录并提供运行证据。生成文件可以编辑、Base 可以编辑 properties，但这些产品能力和本地修改都不构成回流、消费者启用或项目效力。

来源探测目前只能验收固定夹具行为。`--live` 禁用且输出契约未闭合，不能写成真实探测、模式通过或正式运行完成。

## 验证投入

每项审查和测试必须回答三个问题：它要发现什么失败，失败会造成什么后果，它是否提供其他门禁没有的证据。任一问题没有明确答案，或者同一风险已经由更强的 schema、哈希、写集、端到端验证或人工决定覆盖时，不设计也不执行该检查。

必须保留的检查集中在真实高风险边界。

| 风险 | 必要证据 |
|---|---|
| 语义或效力变化 | 逐项依据、决定引用和反例 |
| 决策权越界 | 授权边界与写集对账 |
| 稳定身份丢失或错误合并 | 迁移前后身份集合双向对账 |
| 数据迁移损坏 | 旧值保留、异常清单和候选差异 |
| 生成不确定 | 相同输入双跑逐字节一致 |
| 共享接口断裂 | 消费者契约和最小端到端路径 |
| 删除、正式切换或回滚失败 | 完整候选、绑定清单、应用后验证和补偿演练 |

以下检查默认没有独立价值：文件存在、固定常量回显、重复计数、包装函数透传、实现细节、相同输入的重复正例，以及已经由模式、哈希、写集或端到端检查覆盖的事实。真实风险表明其中某项具有独有价值时，计划须写明目标失败和后果后才能保留。

TDD 只用于保留下来的行为测试。文档、静态配置、确定性生成物和纯机械迁移使用直接解析、模式、哈希、差异或一次端到端验证；不为形成 RED／GREEN 步骤而另造测试。完整回归只在接口闭合、迁移闭合、完整候选、正式切换和回滚等风险边界运行。普通任务只执行定向检查。

独立审查只用于需要第二判断者的语义、权限、完整候选或正式切换风险。测试通过、格式、计数、哈希和写集等机械事实由命令证明。已发生的真实缺陷若现有门禁不能稳定复现，新增最小回归测试。

## 审计

审计追踪的层次和义务见[维护](maintenance.md)“审计追踪”。每次提交前按“验证投入”运行与写集风险直接相关的检查：Markdown 链接发生变化时运行链接检查，词表或其生成链发生变化时运行主题检查，阶段边界再运行相应完整回归；不在无关提交中重复执行。每次定期复审读取指标表；治理年审抽查决定记录是否覆盖实际发生的规则变更，并抽查 `[L1]` 提交。

来源与术语迁移账本保留历史身份、旧位置、分类、去向和阻断，是只追加审计材料。正文诊断、反向索引和固定夹具输出只保存机械证据；ignored 探测输出不进入正式审计层，也不证明真实事实。正式对象的状态与历史仍以正式数据、决定和 CHANGELOG 为准。

针对已经发生过的失败，采用以下防护。

| 失败 | 防护 |
|---|---|
| 文本替换静默失败 | 替换必须带断言；修改后用检索确认 |
| 批量转换破坏规则文本 | 规则文本中的示例使用行内代码；批量脚本跳过代码；转换后逐段复核 Git 差异 |
| 凭记忆写事实 | 写入前核对原文；核不到时标明“未核对”；引用标准在 `sources/` 中留笔记 |
| 设计跑在数据前 | 规则定稿前用真实数据试一遍 |
| 文档与数据不一致 | 现行正式数据决定当前事实；已批准未激活接口另按决定和实现核对，不用任一侧抹掉另一侧 |
| AI 越权 | 提交说明标级别；人抽查 |
| 候选识别命中被当作结论 | 保留抽取、排除、标签比较和人工判断边界；脚本输出只作复核线索 |
| 基础实现被当作正式激活 | 分开基础验收与正式激活证据；检查正式写集、决定、编辑权和消费者是否真实存在 |

## 风险

| 风险 | 控制 |
|---|---|
| AI 编造或记错事实 | 来源优先；验收要求核对；`sources/` 留笔记 |
| AI 越权改规则 | 决策权矩阵；提交说明标级别；事件后修订 |
| 未核实判断累积 | `self` 不转正；指标表 |
| 来源漂移 | 按现行 `tier` 人工复核；夹具观察不冒充真实探测 |
| 规则无用例即定稿 | 先用数据试 |
| 单人单点 | Git remote 备份；决定记录便于后续接手 |
| 治理规则本身过时 | 治理评审 |
| 部分实现提前取得效力 | 对象按正式数据、未激活基础、迁移审计和草案分层；正式激活保留人工门禁 |
| 观察或索引被当作结论 | 观察只提复核范围，索引只给影响范围；义务和工具通过不自动改正式值 |
| 探测契约被误报闭合 | 明记 `--live` 禁用和输出契约未闭合，只验收固定夹具行为 |

## 治理评审

- 政策表、决策权矩阵和阈值表每 12 个月评审一次；日期记入 `vocab/signals.yaml` 的 `governance_reviewed`，结果记决定。
- 决策权矩阵在每次越权或欠权事件后修订。
- 阈值在首轮维护，即第一次编辑审核完成后校准，之后随年审复核。
- 本文变更走政策变更流程。

## 待定事项

- 人制定的词典条目怎样复审和废弃。
- “结构性变更”默认指设计文档表格中的规则行，例外由人降级；首轮后评估这个判据是否充分。
- 来源和术语正式激活阶段何时开放，以及届时需要哪些完整候选、消费者和回滚证据；基础已实现不提前回答这些问题。
