# 治理

治理是对管理的管理：谁有权决定什么、按什么政策、变更怎么准入、结果怎么被监督。它不直接操作词表和内容——那是[维护](maintenance.md)的职责——而是规定维护由谁做、按什么规则进行、怎样接受审计。理论见[治理](../concepts/governance.md)。

本库的治理主体是一个人，管理层是一个 AI。ISO 37000 对治理主体与管理层的区分在这里形成授权边界：AI 可以直接做什么、必须先提案什么、哪些事项只有人能决定。首批边界见[决策权的首批边界](decisions/decision-rights-defaults.md)。

## 政策

全库硬规则统一列在下表。每条政策都标明依据；`AGENTS.md` 是本节和[写作规则](writing.md)的摘要。

| 政策 | 内容 | 依据 | 详见 |
|---|---|---|---|
| 来源优先 | 已有规范和事实标准是设计的来源和依据；凭记忆写的事实联网核对后才提交 | Z39.19 §11.1.5 要求采用表示形式前对照权威来源核验 | [写作规则](writing.md) |
| 先概念后设计 | 采用任何方法前先有概念文和方法登记，再导出规则；推不出的规则不加 | Aristotle 第一原理；Nygard ADR，见[第一原理与设计理由](../concepts/first-principles.md) | [方法登记](principles.md) |
| 零自定 | 项目采用的 designation 必须按准入阶梯取得依据；AI 不得主动形成、选定或借状态试用无依据的 designation。普通叙述、来源转录、路径、代码和值不因首次出现纳入禁令 | ISO 25964-1 §2.11 概念先于表示形式；ISO 704；Z39.19 §11.1.5 | 本文“Designation 准入” |
| 实体类别取外部类 | 实体的 `kind` 取 Wikidata 的类，不自定 | 零自定的实例 | [命名实体词表](entities.md) |
| 断言有依据 | 人判断的字段记 `basis`；`basis` 含 `self` 的记录不得为 `active`。designation 的准入依据和具体断言依据是两道门禁，任何一项都不能替代另一项 | Z39.19 §11.1.4 的来源记录；W3C PROV-O | [维护](maintenance.md) |
| 整篇重写 | 改文章不打补丁；改动涉及一节以上时整节或整篇重写，并逐项核对旧版去向 | 本库的过程规则，见[写作规范](../concepts/writing-conventions.md) | `AGENTS.md` |
| 先用数据试 | 规则定稿前用真实数据跑一遍 | 本库的过程规则，来自已发生的失败 | 本文“审计” |
| 范围决定顶层 | 顶层概念由范围声明决定；顶层之下按知识体系全借，借到有稳定编号的最深一层 | ISO 25964-1 §13.1；Z39.19 §11.1.3、§11.1.7、§11.1.8 | [层级结构](hierarchy.md)规则 3–5 |
| 原样复制 | 复制的结构原样保留，不拆不改；本地分析另建数组；同一视角只取一个来源 | [决定记录](decisions/borrow-and-analyze.md) | [层级结构](hierarchy.md)规则 6、13 |
| 结构来源资格 | 可作结构来源的实体必须为 de-jure，或为有版本号的 de-facto；vendor 只作映射 | Z39.19 §5.3.5.2 组织依据；来源分级 | [来源名称规范表](sources-registry.md) |
| 映射来源登记 | `source`、`match.source`、`basis` 引用的来源必须登记在 `sources.yaml` | ISO 25964-2 §23 名称规范表 | [来源名称规范表](sources-registry.md) |
| 不删 | `deprecated` 概念记录和内容单元保留；旧表示形式按既有检索、替代关系或历史追踪需要随概念记录保留。只有本地 `candidate` 概念记录可以按维护条件取得删除资格，实际删除仍服从决策权 | Z39.19 §11.3.2；ISO 15489-1 §3.8 处置决定 | [内容模型](content-model.md)、[维护](maintenance.md) |
| id 不变 | id 一经引用不改；改名只改 `label`，旧形式按检索和历史需要保留并建立替代引导 | Z39.19 §11.3.1.2 的替代与引用处理 | [内容模型](content-model.md) |
| 与工具无关 | 与应用无关层不提工具字段和格式；`vocab/` 是源，各应用从它导出，不反向编辑；映射不得改动字段定义 | [决定记录](decisions/form-independence.md) | [内容模型](content-model.md) |
| 决定审计追踪 | 规则的结构性变更走决定记录，只追加不修改 | Nygard ADR | [决定记录](decisions/) |
| 写作规则 | 标题、标点、项目命名和文档类型按写作规则 | ISO 24495-1 四原则 | [写作规则](writing.md) |

政策本身的变更走变更控制。

## 决策权

决策权分三级：AI 可直接做、AI 提案后由人决定、只有人能决定。边界按改动的可逆性和是否改变规则划分。

| 级 | 改动 | 例 |
|---|---|---|
| **AI 直接做** | 不改规则、可逆、有脚本或规则可验 | 数据采集与核对；按已定规则生成或校验数据；修正错字、标点和标题违规；替换同一来源的坏链接；同步索引；在 CHANGELOG 当前版节内追加；按既定小节清单写已批准文档；新实体以 `candidate` 录入 `entities.yaml`；核到 `basis` 文字且校验通过后批准（`candidate` → `active`） |
| **AI 提案，人定** | 改规则、改结构，或没有规则可依 | 新设计文档或概念文；修改任何规则或阈值，包括脚本阈值常量；文件拆并、改名、删除；词表结构变更；新方法登记；designation 准入；`scope`、`broader`、`subjects` 的判断；删除 `candidate` 对象时列清单；换来源或改用 archive 快照；概念文修订导致规则变化 |
| **只有人定** | 改变范围或不可逆 | 范围声明；零自定例外；决定记录的采纳与推翻；删除任何非 `candidate` 对象；发版；草案生效；来源改档 |

提案须说明改什么、为什么、依据是什么、影响哪些文件。人回复后才能修改文件；AI 不得把第二级事项当作第一级事项。

每条提交说明以 `[L1]`、`[L2]` 或 `[L3]` 标注本次改动的最高级别。人抽查 `[L1]` 提交是否确属第一级；发生越权或欠权后，本表修订一次并记决定。

## 变更控制

| 变更 | 流程 | 记录 |
|---|---|---|
| 规则变更 | AI 提案 → 人定 → 改文档 → 同步受影响文档与摘要 → 链接检查 | 默认视为结构性，记决定；人可降为局部，只记提交说明 |
| 政策变更 | 同规则变更，必须有决定记录 | 决定记录 |
| 方法准入 | 概念文 → 方法登记 → 导出规则 | [方法登记](principles.md) |
| designation 准入 | 本文“Designation 准入”的阶梯 | `concepts/glossary.md` 的出处记录与查无记录 |
| 概念文修订 | 修订 → 检查方法登记中由它导出的规则 → 受影响规则走规则变更 | 提交说明 |
| 草案生效 | 触发条件出现 → 人确认 → 草案移出 `drafts/` → 内容并入相应设计 | 决定记录 |
| 词表结构变更 | 提案 → 人定 → 修改 `vocab/build/` 输入并重新生成，或直接改数据 → 校验通过 | CHANGELOG |
| 来源改档 | 人定 → 修改实体 `tier` → 复核受影响断言 | 实体 `history` |
| 词表发版 | 维护触发 → 人定 → 新建版本块与 CHANGELOG 版节 | [词表版本](versioning.md) |
| 新建应用映射 | 按内容模型的五个问题写 → 人定 | `design/targets/` |
| 推翻决定记录 | 新建决定 → 旧决定标为被替代 | 决定记录 |
| 摘要同步 | 被摘要文档改动后同步 `AGENTS.md`、README | 同一提交 |

## Designation 准入

项目拟采用的每个 designation 都必须能在 `concepts/glossary.md` 中找到出处。准入按下列阶梯检索，查到即止；登记时写明在哪一级取得依据。

| 级 | 来源 | 例 |
|---|---|---|
| 1 | de-jure：国际与国家标准、W3C Recommendation、RFC | ISO 25964、GB/T 13745、SKOS |
| 2 | de-facto：知识体系、行业组织规范 | CS2023、SWEBOK、ASVS、Diátaxis |
| 3 | vendor：厂商文档 | Anthropic 文档、Obsidian 文档 |
| 4 | archival：论文、书、带日期的博文 | Hogan 2021、Bowker & Star 1999 |
| 5 | 其他：行业领袖的定义，或多个独立来源一致使用的业界共识 | Nygard 的 ADR |

五级都查不到时，由人制定词典条目：人给出定义、判据句和适用范围，登记为本库词典，`basis: self`。AI 在任何一级只有检索权限：查到后引用并登记；查不到只能报告五级均无，不能主动形成或选定无依据的 designation，也不能借 `candidate`、`defer`、草案、占位或示例状态试用。普通叙述、来源转录、文件路径、代码和值不因字符串首次出现自动成为项目采用的名称。

查无记录必须可审计。提案逐级列明检索过的来源和结果；空白不算检索过。一个 designation 的形式依据、它所表示的概念以及记录中具体字段值或关系的依据须分别核对，任何一个状态门禁都不能替代另一个。

`scripts/check-terms.py` 是候选识别器。它检查指定位置中可能承担命名功能的字符串：纳入标题、加粗内容和中文引号，排除代码与链接目标；与已登记的首选、替代和隐藏标签比较，规范化只使用明确批准的规则。命中只进入人工判断，不能直接裁定为项目采用的名称或违规。每次编辑审核检查报告；若人工判断某个命中拟作项目名称，再按本节阶梯处理。

划分特征草案中的属性名同样适用本节。将来需要采用时，由人按词典制定流程决定。

### 译名

中英对照只在 `concepts/glossary.md` 一处登记；词表的 `label` 与正文必须使用已登记形式。译名按下列阶梯核对，查到即止。

| 级 | 来源 |
|---|---|
| 1 | 等同采用国际标准的 GB 给出的译名：GB/T 13190 对 ISO 25964，GB/T 26162 对 ISO 15489 |
| 2 | 学科权威教材、工具书，两个独立来源一致 |
| 3 | Wikidata 中文标签 |
| 4 | 都没有时不译。正文使用原名，首次出现给一句解释；登记中的 `zh` 留空，解释写入 `explanation` |

AI 在第 4 级只能给解释，不能给名称。“有译名但不达意”的判断只有人能做，AI 不得以此为由改用自己的译法。反方向同样适用：GB/T 13745 的学科名没有官方英文时，查不到就不给英文。

词表中的每个标签带 `zh_basis`、`en_basis`：值是阶梯级别与来源，如 `gbt-13190`、`wikidata:Q978185`；也可以是 `source`，表示标签直接来自借入来源，或 `none`，表示不译。值为 `self` 的标签是已知自造译名，待追溯；含 `self` 的记录不得为 `active`。

`check-topics.py` 报告 `self`；`check-terms.py` 报告同一英文在全库对应不同中文或反向对应不一致的情况。

追溯时，`scripts/lookup-labels.py` 按阶梯第 3 级查询 Wikidata，只接受对方语言标签与本库名称完全一致、描述与相应概念相符的条目；中文优先简体标签，繁体经 OpenCC 转简并注明。结果是清单，交人审；词义是否对得上是判断，AI 不直接写入。人工决定记在 `vocab/build/label-decisions.json`：采纳项记录 Q 号与标签，否决项记录理由。`build-topics.py` 据此修改标签与依据；未查到或被否决的一律不译，去掉自译标签，依据记 `none`。2026-08-23 首次追溯共 692 条自译，采纳 72 条、否决 13 条、不译 607 条。不译的概念在 `scope` 中按来源原文给出中文解释，输入为 `vocab/build/scope-zh.json`；来源自带官方译文时直接使用，依据记 `source`。

## 质量与验收

各类对象的完成标准如下。

| 对象 | 完成标准 |
|---|---|
| 概念文 | CONVENTIONS 的五条硬规则；权威来源链接均已核对；项目采用的 designation 有依据；索引已登记 |
| 设计文档 | 每节规则有依据或标明“本库”；待定事项集中在文末；不出现“待写”；链接检查通过；项目采用的 designation 有依据 |
| 词表条目 | 校验脚本零问题；复制项有 `match` 回到源头；人工赋值字段有 `basis`；`self` 不为 `active` |
| 脚本 | 幂等；文本替换带断言；批量改动前后复核 Git 差异；阈值常量与阈值表一致；输出可读 |
| 决定记录 | 有状态与日期、背景、决定和后果；推翻时不改旧记录 |
| 文献笔记 | 标明读过和未读的部分；条款号来自原文 |
| 提交说明 | 写清改动并标注决策权级别 |

## 审计

审计追踪的层次和义务见[维护](maintenance.md)“审计追踪”。每次提交前运行 `check-links.py`、`check-topics.py`；每次定期复审读取指标表；治理年审抽查决定记录是否覆盖实际发生的规则变更，并抽查 `[L1]` 提交。

针对已经发生过的失败，采用以下防护。

| 失败 | 防护 |
|---|---|
| 文本替换静默失败 | 替换必须带断言；修改后用检索确认 |
| 批量转换破坏规则文本 | 规则文本中的示例使用行内代码；批量脚本跳过代码；转换后逐段复核 Git 差异 |
| 凭记忆写事实 | 写入前核对原文；核不到时标明“未核对”；引用标准在 `sources/` 中留笔记 |
| 设计跑在数据前 | 规则定稿前用真实数据试一遍 |
| 文档与数据不一致 | 数据为准；文档引用数据时从数据生成，不手写 |
| AI 越权 | 提交说明标级别；人抽查 |
| 候选识别命中被当作结论 | 保留抽取、排除、标签比较和人工判断边界；脚本输出只作复核线索 |

## 风险

| 风险 | 控制 |
|---|---|
| AI 编造或记错事实 | 来源优先；验收要求核对；`sources/` 留笔记 |
| AI 越权改规则 | 决策权矩阵；提交说明标级别；事件后修订 |
| 未核实判断累积 | `self` 不转正；指标表 |
| 来源漂移 | 按 `tier` 复核；de-jure 探测 |
| 规则无用例即定稿 | 先用数据试 |
| 单人单点 | Git remote 备份；决定记录便于后续接手 |
| 治理规则本身过时 | 治理评审 |

## 治理评审

- 政策表、决策权矩阵和阈值表每 12 个月评审一次；日期记入 `vocab/signals.yaml` 的 `governance_reviewed`，结果记决定
- 决策权矩阵在每次越权或欠权事件后修订
- 阈值在首轮维护，即第一次编辑审核完成后校准，之后随年审复核
- 本文变更走政策变更流程

## 待定事项

- 人制定的词典条目怎样复审和废弃
- “结构性变更”默认指设计文档表格中的规则行，例外由人降级；首轮后评估这个判据是否充分
