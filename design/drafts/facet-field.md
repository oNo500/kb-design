# 分面字段草案

状态：草案，未生效。`topics.yaml` 目前不设分面字段；本文只记录研究方向，不构成 schema、数据或脚本规则。

## 定位

主题树用顶层概念和层级关系表达学科归属与层级范围。分面表达纳入分析的概念集合中各概念的内在类别，不进入主题树，也不改变概念的 `broader`。

查询组合先选择一个主题分支，再按分面过滤。主题分支由一个现有概念及其传递下位概念划定；分面结果与该分支相交，而不是成为树中的一层。理论见[分面](../../concepts/facet.md)，树的既有选择见[树按学科而非分面的决定](../decisions/tree-by-discipline.md)。

## 触发条件

分面研究由树无法直接完成的内在类别查询触发。例如，在 `security` 分支中只查看威胁建模和渗透测试，不查看防火墙和 WAF；或者跨不同主题分支查找 SQL 注入、prompt injection 和缓冲区溢出。前者先限定一个主题分支，后者不以树中的共同上位概念为前提。

这些需求只说明需要研究横向过滤，不直接批准字段。`related` 表达概念间经核实的语义联系，概念组按用途圈定概念；二者都不替代按内在类别进行的分面分析。概念组的草案见[概念组草案](concept-groups.md)。

## 适用性研究

具体分面的适用性仍未决定。研究须先选取已批准范围内的实际概念集合，再用有外部依据的既有分面试标，记录来源、适用情况、无法归类情况和判断依据。

试标只产生供决定使用的证据。结果不得直接写入正式字段，不得改变主题树或 `broader`，也不得自动批准或否决任何具体分面。现有证据不足以把某类技术内容视为统一的适用范围。

## 模型职责

各结构在研究中承担不同职责。

| 结构 | 职责 | 边界 |
|---|---|---|
| 主题树 | 表达学科归属与概念层级 | 分面不进入树，不改变 `broader` |
| 主题分支 | 划定一次查询的层级范围 | 由一个概念及其传递下位概念组成 |
| 概念集合 | 提供分面分析的对象 | 只取已批准范围内纳入分析的概念 |
| 分面 | 按内在类别组织概念 | 具体分面及其适用性仍待决定 |
| 概念组 | 按用途提供概念视图 | 不表示内在类别，不改变树 |

查询可以把主题分支与分面结果相交，但这种组合只是拟议的检索职责，不表示字段已经存在或草案已经生效。

## 待定事项

- 哪些外部已有分面适用于实际概念集合；
- 是否建立正式字段，以及字段结构、取值和缺省处理；
- 分布检查的汇总边界、阈值和严重性；
- 是否建立诊断，以及相应的脚本行为和人工处置。

在这些事项获得决定前，不设分布规则。零计数不自动构成缺陷，当前也不产生诊断。

## 生效条件

1. 对已批准范围内的实际概念集合完成试标，形成可复核的适用情况与无法归类证据。
2. 人决定具体分面、正式字段以及全部待定的校验语义。
3. 按[治理](../governance.md)的草案生效流程确认生效，并把获准内容并入对应设计。

条件满足前，本文继续保持“草案，未生效”，`topics.yaml` 不增加分面字段。
