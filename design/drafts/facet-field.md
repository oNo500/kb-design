# 分面字段草案

状态：草案，未生效。正式主题词表当前没有分面字段。仓库内可核的真实查询消费者为 0；Obsidian `Application Profile` 已存在，但只提供词表参考浏览，不查询分面；已执行试标为 0／111。本文只保留研究职责和决定门禁，不批准具体概念集合、外部分面、试标记录、查询增量、字段、校验或诊断。

## 当前边界

主题树按学科表达归属和层级范围；分面拟按概念本身的内在类别横向分析。查询可以先选择一个主题分支，再与分面结果相交，这一“主题分支 × 分面”的职责仍是研究方向，不表示字段、取值或查询实现已经存在。

现行 [Obsidian 映射](../targets/obsidian.md)从六份正式词表生成单向参考区，保留全部主题关系并提供 Base 浏览入口。其 `Application Profile` 不定义分面字段、不生成内容单元、不保存真实查询记录，也不提供与主题分支相互独立的人工相关集合。因此，profile 与导出能力已经存在，但分面查询消费者仍不存在，也没有形成试标触发。

现有 111 个可重现身份只是一组候选输入。它们全部为 `unassigned`，当前没有决定允许其作为试标集合，也没有逐项判断产物。草案例子、分支规模、来源数组、映射成员和零计数都不能替代真实查询或完成证据。

## 对象职责

| 对象 | 职责 | 边界 |
|---|---|---|
| 主题分支 | 由一个现有概念及其传递下位概念划定层级范围 | 不把来源、用途或内在类别变成树层 |
| 概念集合 | 冻结一次试标实际读取的概念身份与上下文 | 不因可重现、规模或状态自动取得试标资格 |
| 分面 | 按概念本身的内在类别分析合格集合 | 不表示内容单元属性、来源、用途或映射存在 |
| 手工概念组 | 按真实项目、角色或专题用途圈定视图 | 不回答概念是什么类，且草案尚未生效 |
| 映射视图 | 从现行来源角色和正式映射确定计算本地概念集合 | 不登记成员，不暴露未建或未映射的盲区，也不是查询消费者 |
| `Application Profile` | 规定某一 target 的功能范围、模型引用、字段约束、使用和具体表示 | 文件存在不证明 target 实现了分面查询或产生运行记录 |
| 内容元数据 | 描述内容单元自身属性 | 不替概念建立内在类别，也不改变主题树 |

查询增量必须相对于这些现行职责分别计算。已有路径能够回答的查询不能被重复记作分面价值；映射视图为空也不能自动记作分面缺陷。

## 真实触发

分面研究须由具名应用或工作流中的实际接收方触发，并保存真实查询记录。触发材料至少说明查询对象是概念还是内容单元，给出与拟议分面结果相互独立的人工相关集合，并记录主题分支、来源数组、手工概念组、映射视图、应用映射和内容元数据的基线结果。

只有现行路径无法回答、且分面可能提供不可替代增量时，才进入试标。示例查询、目录不存在、零成员集合、`Application Profile` 文件存在或对未来浏览的设想均不构成真实触发。当前 Obsidian 参考区没有分面查询、内容消费者或运行记录，所以研究尚未进入这一阶段。

## 样本资格

试标集合必须由人按实际查询范围决定，并冻结概念身份、上下文、来源和版本。当前三支合计 111 个身份可以在数据中重现，但其试标资格未获批准；0／111 的状态不能写成部分完成。

若将来选择这组身份，须重新按当时正式数据冻结输入，并明确 `unassigned` 记录是否可参与。若选择其他集合，也须说明范围、完整性和与真实查询的对应。集合不得由拟议分面结果反向挑选。

## 外部依据

候选外部分面须来自标准发布机构或其他可核官方材料，并记录发布者、版次、原文类别、适用范围和稳定定位。公开类名、目录、schema、旧报告摘要和未读收费正文不能补出具体类别或适用判断。

选择某一外部分面、确认其适用于当前技术概念、以及把每个本地概念对应到某一类别，是不同判断。三者分别取得依据和 L2 决定；本文不预先选择任何具体分面。

## 试标过程

完整试标须逐项保存当前概念身份与上下文、外部定位、判断依据、查询后果、无法归类情况和未决事项。试标输入不得直接写入正式字段，工作表栏名也不得自动成为 schema。

人工相关集合须独立于试标结果建立。每个真实查询分别报告现行组织与分面结果的命中、误收、漏收，以及具体身份层面的差额；汇总数字不能替代成员清单。只有人的相关判断和机械计数都可回查时，才能评价查询增量。

试标的停止条件、完成标准和失败后果须在执行前形成 L2 提案。试标结果无论正负都只提供决定材料，不自动批准或否决字段，也不改变 `broader`。

## 待定设计

真实触发和试标通过后，才提案字段语义、作用域、类别身份、版本、基数、多解、无法归类、缺省、依据、迁移和回退。字段名称、值和值域均未批准。

校验须只检查获准字段的机械约束，不替代概念对应判断。合法值、引用、基数、漂移和迁移规则目前未批准；现行 schema、生成器和主题校验均不消费分面。

诊断须先说明要发现的失败、失败后果和独有证据，再决定汇总边界、阈值、严重性、输出和人工处置。当前没有获准诊断，零计数不自动构成错误。

现行 Obsidian `Application Profile` 没有分面字段和查询契约。真实需求出现后，须修改该 profile 或建立另一份具名 target 文件，回答功能范围、模型引用、字段读取、词表导出、引用、回流和应用限制；已有词表参考导出不能冒充消费者验收。

## 生效门禁

L2 可以选择真实查询和具名应用消费者，决定试标集合资格和候选外部分面，审查逐项判断，并形成字段、校验、诊断、生成、迁移、应用和回退提案。L2 不能建立正式字段或使草案生效。

只有真实消费者、具备分面查询契约的 `Application Profile`、合格冻结样本、外部分面依据、完整逐项试标、独立相关集合、不可替代查询增量和完整 L2 设计全部闭合后，才有资格另行提出精确 L3 生效请求。现行 Obsidian profile 只满足“已有 target 文件”，不满足消费者、查询契约或运行证据门禁。随后仍须按批准内容建立正式字段并验证应用结果。

范围变化、草案生效、正式字段或文件建立、零自定例外、来源改档、正式切换和发版分别保留人定权限。当前条件不成立，本文没有 L3 请求。

## 不采用后果

当前不采用不会改变主题树、来源数组、映射或任何现有消费者。按学科浏览、按来源查看、按现行映射计算集合以及 Obsidian 词表参考浏览继续使用各自职责。

跨主题分支、按概念内在类别统一查询仍没有正式入口，必要时只能人工并集和逐项判断。由于真实查询消费者为 0，这一后果目前是待验证的能力缺口，不是已证明的应用故障。真实需求出现后，应以查询记录和独立相关集合重开 L2 研究，而不是直接采用当前未执行的 111 项候选试标。
