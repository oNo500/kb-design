# 分面字段草案

状态:草案,未生效。`topics.yaml` 目前不设分面字段。

## 定位

主题词表的树按学科分,树里的位置回答「它属于哪个领域」,不回答「它是什么类的东西」(理由见[树按学科而非分面的决定](tree-by-discipline.md))。分面作为概念上的一个横向字段补这一项,不动树。理论见 [分面](../../concepts/facet.md)。

## 触发条件

出现树回答不了的查询时才生效:

- 列全库所有的标准、所有的缺陷
- 某个领域下只看实践,不看制品
- 开始用 `related` 或手工概念组硬凑上述查询——这是最明确的信号

## 取值从哪来

零自定之下,取值只能来自标准或由映射派生。三条路:

| 路 | 取值 | 覆盖 | 缺口 |
|---|---|---|---|
| A. ISO 25964-1 §2.20 示例 | 对象、动作、施动者(材料、地点、时间对技术领域不贴,不取) | 制品、实践、人与组织 | 理论、缺陷、标准 |
| B. 由映射派生,不设字段 | 「缺陷」= 映射到 CWE 的概念;「标准」= 映射到 ISO、RFC、W3C 等的概念 | 缺陷、标准 | 理论、实践、制品——没有外部体系专门收它们 |
| C. A + B | 字段取 A 的三个值;缺陷、标准走派生概念组 | 除理论外全部 | 理论 |

**采用 C。** 理论一项暂缺;自定开放后只需加一个值,机制不变。

## 字段规则

```yaml
- id: threat-modeling
  facet: action          # object / action / agent 之一;对应 ISO 示例 objects / actions / agents
```

1. 一个概念至多属于一个分面(严格用法,见 [分面](../../concepts/facet.md))
2. 允许不填;未标引的借入概念一般不填
3. 缺陷、标准不用此字段,靠派生组:`sources.yaml` 中 CWE、ISO 等体系的 `role` 含 `group`
4. 校验脚本统计分布;某分面在某子领域下为零,可能是盲区也可能是分面不贴,人工判断

## 与概念组的分工

分面回答「是什么类」,稳定;概念组回答「谁要用」,易变。同一需求按维护成本从低到高依次考虑:派生组 → 分面字段 → 手工组。见[概念组草案](concept-groups.md)。
