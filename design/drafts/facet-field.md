# 分面字段草案

状态:草案,未生效。`topics.yaml` 目前不设分面字段。

## 定位

主题词表的树按学科分,树里的位置回答「它属于哪个领域」,不回答「它是什么类的东西」(理由见[树按学科而非分面的决定](../decisions/tree-by-discipline.md))。分面作为概念上的一个横向字段补这一项,不动树。理论见 [分面](../../concepts/facet.md)。

## 触发条件

树按学科分,能回答「security 下面有什么」。有些问题跨学科,树答不了:

- 某个领域下只看实践(威胁建模、渗透测试),不看制品(防火墙、WAF)——它们在树里混在同一分支下
- 全库所有的缺陷——SQL 注入在 security,prompt injection 在 artificial-intelligence,缓冲区溢出在 systems,散在三处

这两类问题问的是「它是什么类的东西」,树只知道「它属于哪个领域」。

「全库所有标准」「全库所有文献」**不在此列**:标准和文献是个体,收在[命名实体词表](../entities.md),按 `kind` 查询即可。

没有分面字段时,人会硬凑:给所有缺陷之间互相加 `related`,或手工建一个「缺陷」概念组。发现自己在这么做,就是该加分面字段的信号——用 `related` 和手工组做横切查询是拿错工具。

## 取值从哪来

零自定之下,取值只能来自标准或由映射派生。三条路:

| 路 | 取值 | 覆盖 | 缺口 |
|---|---|---|---|
| A. ISO 25964-1 §2.20 示例 | 对象、动作、施动者(材料、地点、时间对技术领域不贴,不取) | 制品、实践、人与组织 | 理论、缺陷 |
| B. 由映射派生,不设字段 | 「缺陷」= 映射到 CWE 的概念 | 缺陷 | 理论、实践、制品——没有外部体系专门收它们 |
| C. A + B | 字段取 A 的三个值;缺陷走派生概念组 | 除理论外全部 | 理论 |

**采用 C。** 理论一项暂缺;自定开放后只需加一个值,机制不变。

## 字段规则

```yaml
- id: threat-modeling
  facet: action          # object / action / agent 之一;对应 ISO 示例 objects / actions / agents
```

1. 一个概念至多属于一个分面(严格用法,见 [分面](../../concepts/facet.md))
2. 允许不填;未标引的借入概念一般不填
3. 缺陷不用此字段,靠派生组:`sources.yaml` 中 CWE 的 `role` 含 `group`;标准是实体,不在主题词表
4. 校验脚本统计分布;某分面在某子领域下为零,可能是盲区也可能是分面不贴,人工判断

## 与概念组的分工

分面回答「是什么类」,稳定;概念组回答「谁要用」,易变。按需求的性质选:要「是什么类」用分面字段,要「谁在用」用概念组。派生组只是已映射内容的视图,不能替代任何一方。见[概念组草案](concept-groups.md)。
