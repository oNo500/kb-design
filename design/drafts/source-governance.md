# 来源治理
状态：草案，未生效。

## 草案边界

本文提出来源身份、来源用途、外部证据、实际派生、概念映射、项目决定和复核义务的统一边界。草案只规定拟采用的项目模型，不修改[现行治理](../governance.md)、[现行维护](../maintenance.md)、[命名实体词表设计](../entities.md)、[来源名称规范表](../sources-registry.md)、正式数据或脚本；草案获准生效前，现行规则继续适用。

本文所引用的 DCMI、PROV-O 和 SKOS 材料只支持来源、派生和概念映射的外部概念边界，见[元数据标准笔记](../../sources/metadata-standards.md)。字段名、枚举、基数、状态转换、复核流程、权限和生效条件均为项目提案，不宣称由外部标准直接规定。[治理概念](../../concepts/governance.md)只支持治理与维护分层，[术语数据库概念](../../concepts/terminology-database.md)只说明逐项依据、状态和历史需要分开保存。

本草案不批准任何具体来源的新用途，不改变任何来源的 `tier`，不迁移正式记录，也不使探测结果成为正式事实。TBX、应用映射、导入和往返编辑不属于本文范围。

## 对象边界

本项目提案区分以下对象。每个对象只回答一种问题。

| 对象 | 回答的问题 | 正式引用目标 | 不能替代 |
|---|---|---|---|
| 来源实体 | 材料是什么、哪个版本、当前地址和外部状态是什么 | 来源实体 `id` | 用途批准、具体断言、派生或概念映射 |
| 用途登记 | 来源获准承担哪些角色 | 用途登记 `id` 和获准角色 | 来源实体状态、具体映射或项目决定 |
| `basis` | 一个具体值为什么成立 | 来源实体和可重复定位的位置 | 实际派生、概念映射或项目批准 |
| `source` | 当前记录或结构实际从哪个外部条目派生 | 获准用途登记及其外部条目 | 普通参考材料、人工判断依据或概念等同 |
| `match` | 本地概念与哪个外部概念具有哪种关系 | 获准用途登记及其外部概念 | 标签、层级、范围或译名依据 |
| 项目决定 | 项目是否允许采用规则、用途或结论 | 决定记录 `id` | 外部证据、来源身份或内容事实 |
| 复核义务 | 哪个变化要求复核哪些正式引用 | 来源实体和反向引用目标 | 复核结论或正式数据修改 |

来源实体与用途登记分离。同一实体可以有多个用途角色，每个角色各有状态；实体处于现行外部状态，不表示任何用途已经获准。用途获准也不表示某个 `source` 或 `match` 已经成立。

外部证据、实际派生、概念映射和项目决定互不替代。一个外部事实有依据，只说明事实获得支持；项目是否采用该事实仍由项目决定。项目决定允许采用一个值，也不能补足缺失的外部证据。

## 引用结构

以下结构是本项目共享接口提案，并只在本文定义。其他草案只能链接本文，不得复制、缩减或改变字段语义。

```yaml
basis:
  - entity: z39-19
    locator: "§ 11.1.4"
    checked: 2026-08-28

source:
  registry: cs2023
  item: SE
  locator: "Knowledge Area description"
  basis:
    - entity: cs2023
      locator: "SE overview"
      checked: 2026-08-28

match:
  - registry: cwe
    item: CWE-89
    rel: exactMatch
    basis:
      - entity: cwe
        locator: CWE-89
        checked: 2026-08-28
```

这些字段和约束均为项目提案。

| 对象 | 字段 | 约束 |
|---|---|---|
| `basis` 项 | `entity`、`locator`、`checked` | `entity` 指向来源实体；`locator` 必填并能重复定位被支持的内容；内容可能变化时 `checked` 必填，内容固定时可以省略 |
| `source` | `registry`、`item`、`locator`、`basis` | `registry` 指向拥有所需获准角色的用途登记；`item` 标识被派生的外部条目；`locator` 定位实际取值位置；`basis` 证明派生关系与条目身份 |
| `match` 项 | `registry`、`item`、`rel`、`basis` | `registry` 必须有获准的 `mapping` 角色；`item` 标识外部概念；`rel` 取 `exactMatch`、`closeMatch`、`broadMatch`、`narrowMatch`、`relatedMatch`；`basis` 支持双方概念范围与关系判断 |

`basis` 必须与被支持的具体值相邻，或由模式唯一定位到该值。它不接受 `self`，不接受自由文本来源名、裸 URL、只有标准号而没有位置的引用，也不接受没有 `locator` 的现行断言。URL 只能作为来源实体的地址或定位信息的一部分，不能代替来源实体引用。

`source` 只用于实际派生。综合多份材料形成的本地判断不选择其中一个材料伪装成派生源，而由各具体值的 `basis` 分别说明。`source.basis` 不能证明派生值已获项目批准；相应项目决定另行引用决定记录。

`match` 只用于不同概念体系之间的概念映射。标签相同、译名相同、来源已登记或用途已批准，都不能自动产生 `match`。`rel` 的五个值复用 SKOS mapping property 的边界；选择哪个值仍是需要依据与项目决定的判断。

项目决定使用决定记录 `id` 引用，不进入 `basis`、`source` 或 `match`。决定记录说明项目采用了什么，不作为外部来源实体，也不进入来源用途登记。

## 实体记录

来源实体记录描述标准或出版物本身。以下字段、字段含义和必填条件均为项目提案。

| 字段 | 必填 | 含义 |
|---|---|---|
| `id` | 是 | 稳定的本地引用标识；一经引用不改 |
| `label` | 是 | 来源实体的有依据名称；引用不得用它代替 `id` |
| `kind` | 是 | 只取现有 `standard` 或 `publication` |
| `version` | 条件必填 | 有版本标识时记录所引用版本；没有公开版本时明确为空，不用抓取日期伪装成版本 |
| `url` | 是 | 当前规范地址；地址不是来源身份，也不是断言依据 |
| `status` | 是 | 取 `current`、`superseded`、`withdrawn` |
| `basis` | 是 | 按字段保存支持身份、名称、版本和外部状态的 `basis` 项 |
| `review` | 是 | 保存最近人工复核、下次复核和未结义务引用 |
| `watch` | 条件必填 | 对可变化来源保存只读探测点及允许观察的信号 |
| `replaced_by` | 条件必填 | 已知正式替代来源时指向另一来源实体 |
| `history` | 是 | 只追加保存字段变化、日期、依据和相关决定 |

`review` 的目标结构为 `checked`、`next_due` 和 `obligations`。`checked` 只表示人工复核过具体引用内容，不由链接探测自动填写；`next_due` 按获准规则计算；`obligations` 保存尚未解决的复核义务 `id`。

`watch` 的目标结构为 `locator` 和 `signals`。`locator` 是探测入口；`signals` 只取 `availability`、`redirect`、`version`、`revision`、`replacement`、`withdrawal`。它们表示允许采集的变化信号，不是正式状态枚举，也不构成复核结论。

`status` 描述来源实体在发布方体系中的外部状态，不描述本项目是否批准使用。暂时不可访问不是实体状态，不得把 `current` 自动改为 `withdrawn`。`replaced_by` 只在发布方或可核材料明确给出替代关系时填写；新版仍属于同一来源实体还是需要新实体，按生效前获准的身份判据处理。

现有 `tier` 在迁移期只作兼容字段，继续承载现行数据含义和复核周期，不再推出用途资格或实体状态。目标模型的用途资格由角色决定，复核时间由 `review` 决定。草案不删除 `tier`，也不改变任何具体来源的档级。

## 用途登记

用途登记描述一个来源实体可以怎样被本项目使用。以下结构、角色和角色状态均为项目提案。

```yaml
- id: cs2023
  entity: cs2023
  roles:
    - role: mapping
      status: approved
      decision: decision-record-id
    - role: structure
      status: proposed
      decision: null
  history: []
```

用途记录只含 `id`、`entity`、`roles` 和 `history`。`entity` 指向 `kind` 为 `standard` 或 `publication` 的来源实体。每个 `roles` 项含 `role`、`status` 和 `decision`；`decision` 在 `approved` 或 `retired` 时必填，指向项目决定记录。

| 角色 | 允许用途 | 不能推出 |
|---|---|---|
| `mapping` | 作为 `match.registry` 的目标 | 结构复制、派生概念组或映射关系成立 |
| `structure` | 作为结构或记录的实际派生来源 | 映射关系、人工归属或定义依据 |
| `group` | 从已有映射确定性计算概念组 | 新概念、新映射或结构复制 |
| `discovery` | 发现待审字符串、表达或材料线索 | 形式依据、概念身份、候选记录或项目准入 |

角色状态只取 `proposed`、`approved`、`retired`。`proposed` 表示已登记但尚未授权使用；`approved` 表示相应角色经项目决定获准；`retired` 表示该角色不再用于新增引用，历史引用和反向引用继续保留并进入复核。一个角色获准不改变同一用途记录中的其他角色。

现有 `candidate` 来源角色只迁移为 `discovery`；迁移不得顺带批准其他角色，也不得把发现结果变成概念记录。迁移映射本身须经离线校验，并在历史中保留原值和迁移决定。

## 状态转换

来源实体的首次登记和后续状态转换均为项目提案。每次进入状态都必须由可定位的来源身份、版本和发布方状态信息支持，并只追加写入 `history`。

| 当前状态 | 目标状态 | 条件 | 后续义务 |
|---|---|---|---|
| 未登记 | `current` | 来源身份已经核实；版本已记录或有依据表明没有公开版本；发布方材料在核对日表明来源现行或有效，且没有已知替代或撤回信息 | 建立实体记录；保存状态 `basis`、核对日期和首次登记历史 |
| 未登记 | `superseded` | 来源身份和所指版本已经核实；发布方材料在核对日明确表明已有后继版本或正式替代 | 建立实体记录；填写已知 `replaced_by`；保存状态 `basis` 和首次登记历史；建立新版或替代复核义务 |
| 未登记 | `withdrawn` | 来源身份和所指版本已经核实；发布方材料在核对日明确表明来源已撤回、废止或失效 | 建立实体记录；填写已知 `replaced_by`；保存状态 `basis` 和首次登记历史；建立撤回复核义务 |
| `current` | `superseded` | 可核材料确认已有后继版本或正式替代 | 填写已知 `replaced_by`，建立新版或替代复核义务 |
| `current` | `withdrawn` | 可核材料确认来源已撤回，且证据不是暂时不可访问 | 建立撤回复核义务，检查全部反向引用 |
| `superseded` | `withdrawn` | 可核材料进一步确认旧来源已撤回 | 保留替代和历史，继续复核未处置引用 |

首次登记的 `history` 项必须记录登记日期、首次状态、支持该状态的 `basis` 和登记理由。暂时不可访问不能作为首次进入 `superseded` 或 `withdrawn` 的依据，也不能阻止有充分发布方状态依据的历史来源首次登记。

状态不直接反向转换。若先前记录错误，新增历史项说明更正依据和决定，不删除或覆盖原历史。`withdrawn` 不自动恢复为 `current` 或 `superseded`；撤回后出现的新材料先按待定的来源身份判据判断是否属于新实体。来源首次登记或转为 `superseded`、`withdrawn` 都不自动废弃概念、断言、派生记录或映射。

角色状态按 `proposed` → `approved` → `retired` 转换。`approved` 需要项目决定；`retired` 需要项目决定、反向引用清单和处置方案。`retired` 不直接回到 `approved`；重新考虑时新增提案与历史，再作新的批准决定。

实体状态、角色状态和现有 `tier` 相互独立。实体为 `current` 不批准角色，角色为 `approved` 不保证引用内容仍有效，`tier` 也不替代任何状态。

## 复核义务

复核义务是来源或决定变化与正式修改之间的可查询对象。其目标字段为 `id`、`entity`、`trigger`、`targets`、`decisions`、`previous`、`state`、`opened`、`resolved` 和 `history`；字段和枚举均为项目提案。`trigger` 取 `periodic`、`address_change`、`content_change`、`new_version`、`replacement`、`withdrawal`、`temporarily_unavailable`、`decision_adopted`、`decision_superseded`、`decision_overturned`，`state` 只取 `open` 或 `resolved`。

义务创建时必须分配新的稳定 `id`，`state` 取 `open`，`opened` 记录创建日期，`resolved` 为空；第一条 `history` 记录触发事实、触发日期和初始目标。每个 `targets` 项必须指出引用种类、文件、记录和字段路径；目标为既有复核义务时还须记录其义务 `id`。`decisions` 保存与触发或处置有关的决定记录 `id`。`previous` 在没有同类已解决义务时为空。

只有所有目标完成复核、结论已记录且所需项目决定齐备后，`state` 才能从 `open` 转为 `resolved`；关闭日期写入 `resolved`，关闭事实只追加到 `history`。`resolved` 不得回到 `open`。同一来源实体的同一 `trigger` 在义务解决后再次发生时，必须建立新的 `open` 义务，并用 `previous` 指向最近一项同类 `resolved` 义务；旧义务的状态、日期、目标、结论和历史均不得覆盖。上一项仍为 `open` 时，同一事件的新增观察只追加到该义务的 `history`，不得重写原触发记录或创建伪造的关闭与重开过程。

复核义务不保存正式字段的新值，也不能充当批准记录。决定被采纳、替代或推翻时，先从决定反向引用和该决定列明的影响对象生成清单，清单至少列出受影响的用途记录、具体角色路径和复核义务 `id`；随后按受影响来源实体建立相应的 `decision_adopted`、`decision_superseded` 或 `decision_overturned` 复核义务。决定变化只建立义务，不自动批准或退役角色，不自动解决或重开旧义务，也不自动修改来源实体、`basis`、`source` 或 `match`。决定记录的正式位置和模式继续留待决定。

离线反向引用索引必须覆盖 `basis.entity`、`source.registry`、`match.registry`、用途登记的 `entity`、来源实体的 `replaced_by`、用途角色的 `decision`、复核义务的 `decisions` 与 `previous`、历史中的决定引用，以及复核义务的 `targets`。来源或决定变化按引用种类触发不同复核。

| 引用种类 | 复核对象 | 必须回答的问题 |
|---|---|---|
| `basis` | 被支持的具体值 | 原定位是否仍支持该值，版本与核对日期是否仍适用 |
| `source` | 派生记录、字段和结构 | 外部条目标识、定位与实际派生内容是否变化 |
| `match` | 两个概念及关系 | 双方定义和范围是否仍支持原 `rel` |
| 用途角色 | 依赖该角色的新增与既有引用 | 角色是否仍满足获准用途，决定变化后怎样处置既有引用 |
| 项目决定 | 引用该决定的用途角色和复核义务 | 决定的采纳、替代或推翻影响哪些角色与义务，需要哪些新的复核义务 |

反向引用清单只确定影响范围，不自动给出结论。用途批准不能推出概念映射，映射不能推出译名，外部证据不能推出项目批准，项目批准也不能替代外部证据。

## 失效处理

来源异常按下表分类；分类、动作和阻断条件均为项目提案。

| 情形 | 判据 | 立即动作 | 禁止动作 |
|---|---|---|---|
| 地址改变 | 身份和内容未变，只发生规范地址或重定向变化 | 建立义务；核实后更新 `url` 和历史 | 不改版本、状态、用途或引用语义 |
| 内容改变 | 同一地址或身份下，被引用内容发生实质变化 | 建立义务；复核全部受影响引用 | 不以链接可访问证明内容仍有效 |
| 发布新版 | 发布方给出新的版本标识或版本页面 | 建立新版义务；比较版本与引用范围 | 不自动改 `version`、`locator` 或派生内容 |
| 正式替代 | 发布方或可核材料明确给出后继来源 | 建立替代义务；核对实体身份并填写提案 | 不把替代关系自动写成概念映射 |
| 来源撤回 | 发布方确认撤回、废止或不再有效 | 建立撤回义务；列出全部反向引用 | 不自动删除来源或废弃下游对象 |
| 暂不可用 | 超时、拒绝访问、证书或短期网络故障，尚无撤回证据 | 记录只读探测结果并建立义务 | 不改变实体状态、角色状态或正式引用 |

地址改变在确认来源身份和被引内容未变后，可以按现行 L1 规则更新地址。其余情形先建立复核义务；任何正式值的修改都按该对象原有决策权处理。来源失效不删除历史引用，旧定位、核对日期、替代关系和处置结论保留在 `history`。

对仍作为现行结论发布的断言，缺少 `locator`、引用已确认不再支持该值，或开放义务已经证明证据失效时，离线校验必须阻断发布。单次暂不可访问不触发阻断；持续不可访问的期限和阻断阈值留待生效前决定。

## 探测边界

来源维护分为离线校验和只读联网探测。二者的输入、输出和权限均为项目提案。

离线校验读取正式数据和本地文件，检查字段结构、枚举、引用目标、角色批准、状态转换、历史、反向引用和发布阻断条件。它不得联网，也不得修复正式数据。

联网探测只读取 `watch` 与 `url`，可以观察可访问性、重定向、响应元数据、版本标识、修订状态、替代提示、撤回提示和内容变化信号。探测输出写入独立的复核材料，至少包含探测时间、入口、响应、观察值、前次观察值和错误；输出不得回写 `url`、`version`、`status`、`review.checked`、角色状态、`basis`、`source` 或 `match`。

探测信号只说明“需要复核”。页面可访问不能证明被引内容仍支持断言，重定向不能证明来源身份未变，文本相同不能证明概念范围未变，页面不可访问也不能证明来源撤回。只有人工复核和相应权限下的正式修改才能更新数据。

探测器必须使用只读请求，不登录、不绕过访问控制、不提交表单、不接受会改变远端状态的操作。无法只读确认时记录未知结果，不扩大探测权限。

## 决策权限

以下分工是本草案对[现行决策权](../governance.md#决策权)的项目提案；草案未生效前不改变现行分工。

| 级别 | 可以进行的事项 | 不包含的事项 |
|---|---|---|
| L1 | 运行离线校验和只读探测；生成反向引用与复核材料；按既定规则记录可重复核对的事实；在身份和内容均确认未变时修正同一来源地址 | 批准新角色、选择替代来源、改变规则、改变来源档级或使草案生效 |
| L2 | 提出或修订字段、枚举、状态转换和阻断规则；提议来源角色的批准或退役；提议来源身份、版本和失效处置方案；提议替代来源 | 改变范围、改变具体来源档级、开放零自定例外、使草案生效或发版 |
| L3 | 决定范围、具体来源改档、零自定例外、来源改档关联的下游处置、草案生效和发版 | 不以决定代替缺失的外部证据或定位 |

探测、清单和校验结果不因由自动化产生而提升权限。正式数据修改仍按被修改对象的级别处理。具体来源的 `tier` 变化和本草案生效明确保留给人作 L3 决定。

## 校验规则

草案生效后，离线校验至少执行以下规则；规则本身均为项目提案。

- 来源实体包含规定字段，`kind`、实体 `status`、角色、角色 `status`、`match.rel`、复核触发和复核状态只取规定枚举。
- 所有实体、用途、决定、替代和复核义务引用都指向存在且类型正确的记录；`id` 不重复、不因名称或地址变化而改变。
- 来源实体首次登记时，`status` 只取 `current`、`superseded` 或 `withdrawn`，并有支持身份、版本和首次状态的 `basis`、核对日期与首次登记历史；暂不可访问信号不得单独产生首次状态。
- 实体后续状态只按规定路径转换；`withdrawn` 不自动恢复；状态更正和每次转换只追加历史，不删除或覆盖首次登记和旧状态事实。
- `basis.entity` 指向来源实体，`locator` 非空；会变化内容的现行断言有 `checked`；任何现行断言不接受 `self`、裸 URL、自由文本来源名或无定位标准号。
- `source.registry` 指向具有所需 `approved` 角色的用途登记，`item`、`locator` 和 `basis` 完整；没有实际派生关系的记录不得填写 `source`。
- `match.registry` 指向具有 `approved` `mapping` 角色的用途登记；`item`、`rel` 和关系 `basis` 完整；关系选择不能由标签相同自动生成。
- `group` 只消费已有映射，`discovery` 只输出发现线索；二者都不得生成新概念、新映射或批准结论。
- 每个 `approved` 或 `retired` 角色有决定记录；角色转换、实体状态转换、地址、版本、替代、撤回和决定变化均有只追加历史。
- `superseded` 在已知正式替代来源时有 `replaced_by`；`withdrawn` 和暂不可访问严格区分。
- 新建复核义务有新 `id`，以 `open`、非空 `opened`、空 `resolved` 和首条历史进入；义务只允许从 `open` 转为 `resolved`，关闭时有结论、日期和只追加历史。
- `resolved` 义务不得重开。同一来源实体的同一触发再次发生时，新义务的 `previous` 指向最近同类已解决义务，旧义务全部字段保持不变；同一未结事件的新增观察只追加历史。
- 复核义务的 `targets`、`decisions` 和 `previous` 均能解析到类型正确的记录；义务不得保存或自动写入正式字段的新值。
- 决定反向引用完整覆盖用途角色的 `decision`、复核义务的 `decisions` 和历史中的决定引用。决定被采纳、替代或推翻时，影响清单同时覆盖用途记录、具体角色和复核义务，并建立相应的新 `open` 义务。
- 决定变化不得自动批准或退役角色，不得自动解决或重开旧义务，也不得自动修改来源实体、`basis`、`source` 或 `match`。
- 反向引用索引完整覆盖 `basis`、`source`、`match`、用途实体引用、替代引用、决定引用、义务前项引用和义务目标；每个开放义务的目标都能解析到正式记录。
- 来源实体、用途角色和复核义务的 `history` 均只追加；校验器比较前后快照，拒绝删除、改写、重排或用新摘要覆盖既有历史项。
- 探测输出与正式数据物理分离；任何探测命令不得修改正式数据，任何探测结果不得被校验器当作批准结论。
- 迁移后不再存在旧 `candidate` 来源角色；它只能对应 `discovery`。兼容期 `tier` 的原值、含义和历史保持不变。
- 已确认不再支持现行值且尚未处置的引用阻断发布；单次暂不可访问只产生义务，不直接阻断。

校验器只判断结构和已明确的机械条件。来源身份、内容是否实质变化、两个概念是否匹配、派生是否真实、证据是否充分和项目是否批准，仍由复核与决定回答。来源身份判据、持续不可访问阈值以及决定记录的正式位置和模式仍按“待定事项”处理，校验器不得自行补定。

## 生效条件

本草案默认不生效。以下条件全部满足后，才可以提交草案生效的 L3 决定：

1. 人逐节批准本文的对象边界、共享接口、字段、枚举、状态转换、权限和阻断条件。
2. 现行[命名实体词表设计](../entities.md)、[来源名称规范表](../sources-registry.md)、[维护](../maintenance.md)和[治理](../governance.md)的逐项去向已经形成并获准，没有让新旧规则同时定义同一对象。
3. 正式模式、离线校验器、反向引用索引和只读探测器有独立提案、正反例与确定性输出，并证明探测不会修改正式数据。
4. 迁移清单覆盖现有来源实体、用途角色、`basis`、`source`、`match`、`tier` 和旧 `candidate` 角色；每项都有可逆去向，具体来源不在迁移中自动改档。
5. 地址、内容、新版、替代、撤回和暂不可访问六类场景都有测试材料，离线阻断与人工判断边界一致。
6. 项目正式数据在迁移预演中通过引用、历史、反向引用和禁用模式校验，且没有产生新的术语准入、范围、来源改档或发版决定。
7. 人作出草案生效的 L3 决定，并另行批准实际迁移批次。

草案获准生效也只批准已列规则，不自动批准任何具体来源用途、具体映射、替代来源、来源改档、术语准入或发版。

## 待定事项

- 来源新版仍属同一实体还是建立新实体的判据，以及不同发布体系怎样应用该判据。
- `review.next_due` 的周期怎样从现有 `tier` 迁移，何时可以删除兼容字段。
- 持续不可访问达到何种期限后阻断发布，以及镜像、存档快照和出版者页面怎样排序。
- `url` 是否需要扩展为多个有角色的地址；扩展前仍只保留一个规范地址，不用自由文本地址承担来源身份。
- 内容变化信号采用整页摘要、目标片段摘要还是发布方版本元数据，以及怎样控制动态页面误报。
- 决定记录引用、复核义务和探测材料的正式文件位置与模式；确定前不得写入正式数据。
- 来源角色批准与具体 `source`、`match` 判断之间需要哪些最小复核材料。
