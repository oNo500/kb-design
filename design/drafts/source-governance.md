# 来源治理

状态：草案，未生效。

## 草案边界

本文提出来源身份、用途、外部证据、实际派生、概念映射、项目决定和复核义务的统一治理规则。草案未改变[现行治理](../governance.md)、[现行维护](../maintenance.md)、[命名实体词表设计](../entities.md)、[来源名称规范表](../sources-registry.md)或正式数据；在人工作出生效决定前，现行文件继续决定编辑权、数据形状和维护动作。

本草案的部分前置机器契约已经另经决定建立。六份来源 schema、共享来源模型、离线校验、反向索引、固定夹具探测、迁移预演能力、六份历史迁移账本和复核义务接口属于已完成基础。它们只有结构、行为或审计效力，不使本文整体生效，也不批准任何具体实体状态、地址、角色、`basis`、`source`、`match`、义务、迁移结果或发布结论。

正式 `vocab/entities.yaml`、`vocab/sources.yaml` 和 `vocab/topics.yaml` 仍采用现行旧形状。正式来源义务和正式来源索引不存在；具体角色、外部状态、真实地址和逐值依据尚未形成获准的正式数据。本文不改变任何来源的 `tier`，不创建完整 candidate、handoff、payload、原子应用或补偿回滚，也不执行严格切换或发版。

DCMI、PROV-O 和 SKOS 只支持来源、派生和概念映射的外部概念边界，见[元数据标准笔记](../../sources/metadata-standards.md)。项目字段、枚举、状态转换、复核流程、权限和生效条件仍由项目决定；机器接口存在不能代替这些决定。

## 对象边界

本草案区分以下对象。对象分工是拟议规则；已实现 schema 只固定其机器表达，不为任何记录填写事实。

| 对象 | 回答的问题 | 引用目标 | 不能替代 |
|---|---|---|---|
| 来源实体 | 材料是什么、哪个版本、地址和外部状态是什么 | 来源实体 `id` | 用途批准、具体断言、派生或概念映射 |
| 用途登记 | 来源获准承担哪些角色 | 用途登记 `id` 和角色 | 来源实体状态、具体映射或项目决定 |
| `basis` | 一个具体值为什么成立 | 来源实体和可重复定位的位置 | 实际派生、概念映射或项目批准 |
| `source` | 记录或结构实际从哪个外部条目派生 | 用途登记和外部条目 | 普通参考材料、人工判断依据或概念等同 |
| `match` | 本地概念与哪个外部概念具有哪种关系 | 用途登记和外部概念 | 标签、层级、范围或译名依据 |
| 项目决定 | 项目是否允许采用规则、用途或结论 | 决定记录 `id` | 外部证据、来源身份或内容事实 |
| 复核义务 | 哪个变化要求复核哪些正式引用 | 来源实体和反向引用目标 | 复核结论或正式数据修改 |

来源实体与用途登记分离。同一实体可以登记多个角色，每个角色有独立状态；外部状态不能推出用途批准，用途批准也不能推出具体 `source` 或 `match` 成立。

外部证据、实际派生、概念映射和项目决定互不替代。观察、索引、义务、迁移分类和校验通过只能缩小复核范围或证明机械条件，不能给出这些对象的语义结论。

## 引用结构

共享 `basis`、`source` 和 `match` 的 schema 与引用校验已经实现。它们是未激活的严格接口，不是当前正式旧数据已经使用的形状。

| 对象 | 已实现字段 | 已实现机械约束 | 仍需语义判断 |
|---|---|---|---|
| `basis` 项 | `entity`、`locator`、`checked` | `entity` 指向来源实体；`locator` 非空；可变内容要求 `checked` | 定位内容是否支持相邻的具体值 |
| `source` | `registry`、`item`、`locator`、`basis` | `registry` 指向拥有 `approved` `structure` 角色且决定已采纳的用途登记 | 记录或结构是否真实派生自该条目 |
| `match` 项 | `registry`、`item`、`rel`、`basis` | `registry` 指向拥有 `approved` `mapping` 角色且决定已采纳的用途登记；`rel` 只取五种映射关系 | 双方概念范围是否支持所选关系 |

严格 `basis` 不接受 `self`、自由文本来源名、裸 URL 或没有定位的标准号。URL 只作为来源实体地址或定位材料，不能代替实体引用。形式依据、概念对应依据和具体值依据继续分门，任何一项都不能替代另一项。

`source` 只表达实际派生。综合材料形成的本地判断不选择其中一项伪装成派生源，应由具体值旁的 `basis` 分别支持。`match` 只表达概念映射；标签相同、译名相同、来源已登记或角色已批准都不能自动生成关系。

当前正式数据仍消费紧凑 `basis`、标量 `source` 和 `match.source`。严格接口只有在正式迁移、具体角色批准、逐项语义复核和消费者切换后才能接管；本草案不机械改写旧值。

## 实体记录

来源实体 v2 schema 已实现 `id`、`label`、`kind`、`version`、带角色的 `urls`、外部 `status`、字段级 `basis`、`review`、`watch`、`replaced_by` 和只追加 `history`。schema 固定可表达的结构；下列使用规则仍属于未生效草案。

- `id` 表示稳定身份，一经引用不因名称或地址变化而改变。
- `kind` 只在来源实体适用的既有类别中取值；schema 不能据此证明整个一般实体文件已经形成严格切换契约。
- `urls` 区分规范页、入口页、DOI、全文、状态页、镜像和存档等地址角色；地址不是来源身份，也不是断言依据。
- `status` 只描述发布方体系中的外部状态，不描述项目用途批准；暂时不可访问不等于撤回。
- `basis` 按字段支持身份、名称、版本、地址和外部状态；具体值仍须逐项复核。
- `review` 保存人工复核日期、计算所得期限和义务引用；探测不能自动填写人工复核结论。
- `watch` 保存只读观察入口与允许信号；它不表示 live transport 已启用。
- `replaced_by` 只在可核材料明确给出替代关系时使用。
- `history` 只追加保存变化、依据和决定；schema 存在不表示正式历史已经生成。

现有 `tier` 仍在正式旧数据中承载现行分档和人工复核周期。本草案拟将外部状态、用途资格和复核记录分开，但不删除 `tier`，不改变任何具体档级，也不由 `tier` 自动生成角色、地址或状态。

当前没有获准的 v2 正式实体候选。真实版本、地址、外部状态、字段依据、复核日期、观察入口和替代关系均须在正式激活阶段逐项形成，不能从 schema、迁移推荐值或固定夹具输出推导。

## 用途登记

用途 v2 schema 已实现用途记录的 `id`、`entity`、`roles` 和 `history`。每个角色项包含 `role`、`status` 和 `decision`；角色只取 `mapping`、`structure`、`group`、`discovery`，状态只取 `proposed`、`approved`、`retired`。`approved` 和 `retired` 要求指向已采纳决定，`proposed` 不携带批准决定。

| 角色 | 拟议用途 | 不能推出 |
|---|---|---|
| `mapping` | 作为 `match.registry` 的目标 | 映射关系成立、结构复制或派生概念组 |
| `structure` | 作为结构或记录的实际派生来源 | 映射、人工归属或定义依据 |
| `group` | 从已批准映射确定计算概念组 | 新概念、新映射或结构复制 |
| `discovery` | 提供待审字符串、表达或材料线索 | designation 准入、概念身份、候选记录或项目批准 |

角色状态的完整治理仍属本草案。`proposed` 只表示进入待审清单；`approved` 需要具体角色决定；`retired` 需要决定、反向引用清单和处置方案。一个角色获准不改变同一登记中的其他角色。

迁移账本中的 47 个角色全部保持 `proposed`，旧 `candidate` 只获得 `discovery` 的机械去向。账本不修改正式 `vocab/sources.yaml`，不批准任何角色，也不把发现线索变成概念、术语或关系。

## 状态转换

来源实体和用途角色的状态枚举已经进入 schema，仓库校验也已覆盖部分稳定身份、决定引用和历史前缀条件。以下完整转换语义仍是草案，不得写成当前正式状态机已经运行。

| 对象 | 拟议路径 | 必要语义门禁 |
|---|---|---|
| 来源实体首次登记 | 未登记 → `current`／`superseded`／`withdrawn` | 核实身份与版本；以发布方材料支持首次外部状态；保存逐值依据和首次历史；暂时不可访问不能决定状态 |
| 来源实体变化 | `current` → `superseded`／`withdrawn`；`superseded` → `withdrawn` | 可核材料确认变化；列出反向引用；已知替代时记录 `replaced_by`；不自动废弃下游对象 |
| 状态更正 | 不作直接反向转换 | 新增依据、决定和历史，不覆盖旧状态事实 |
| 用途角色 | `proposed` → `approved` → `retired` | 每次正式变化有相应决定；退役前有引用清单和处置方案；重新考虑另建提案和历史 |

实体状态、角色状态与现行 `tier` 相互独立。实体为 `current` 不批准角色，角色为 `approved` 不证明引用内容仍有效，档级也不能替代任何状态或决定。

## 复核义务

来源复核义务 schema 与开启、解决、再次触发的操作接口已经实现。义务可表达 `id`、`entity`、`trigger`、`targets`、`decisions`、`previous`、`state`、`opened`、`resolved` 和 `history`；`state` 只取 `open` 或 `resolved`。

接口已经能够拒绝已解决义务直接重开，并支持同类事件再次发生时建立新义务、以前项义务串联历史。它不证明仓库已有正式义务，也不提供任何目标的复核结论。

本草案拟要求每个目标指出引用种类、文件、记录和字段路径；义务只保存工作范围、结论和决定引用，不保存正式字段的新值。只有全部目标有结论、所需决定齐备且正式处置可核对后，义务才可解决。新事件不得覆盖旧义务；同一未结事件的新增观察只追加历史。

决定变化只应建立复核范围，不自动批准或退役角色，不自动解决义务，也不修改来源实体、`basis`、`source` 或 `match`。义务目标解析、完整触发枚举、全部历史只追加规则和正式发布阻断尚未形成闭合实现。

正式 `vocab/source-obligations.yaml` 不存在。没有具体义务 `id`、目标、决定、打开或解决状态获得本草案授权。

## 失效处理

固定夹具探测已经能够产生地址、内容、新版、替代、撤回和暂不可用等复核信号。下列分类和正式处置仍是草案；信号本身不执行动作。

| 情形 | 拟议处置 | 禁止动作 |
|---|---|---|
| 地址改变 | 建立复核范围；确认身份和内容未变后按现行权限更新地址 | 不改版本、状态、用途或引用语义 |
| 内容改变 | 复核全部受影响引用 | 不以链接可访问证明内容仍有效 |
| 发布新版 | 比较版本与引用范围 | 不自动改版本、定位或派生内容 |
| 正式替代 | 核实身份与替代关系并提案 | 不把替代关系写成概念映射 |
| 来源撤回 | 列出全部反向引用并逐项处置 | 不自动删除来源或废弃下游对象 |
| 暂不可用 | 保存只读材料并等待人工判断 | 不改变实体状态、角色状态或正式引用 |

持续不可访问的期限和发布阻断阈值尚未决定。来源身份、内容变化、派生真实性、映射关系和证据充分性均须人工判断；离线校验不得补定这些结论。

## 探测边界

固定 `HEAD`／`GET` transport 夹具探测已经实现。它按既定频率选择入口、生成六类复核信号、比较正式树哈希，并拒绝把观察回写到正式字段。该能力只证明只读隔离和信号逻辑。

live transport 尚未完成：`--live` 明确退出，仓库没有取得真实联网观察，也没有确认任何真实来源的可用性、地址、版本、内容或外部状态。

探测输出契约也尚未闭合。探测 schema 要求包含 `observations` 的 JSON 文档及逐条 `request`、`signals`、`errors` 和日期时间；当前探测器实际追加 JSONL，并使用不同字段和日期形状。在二者一致前，不得宣称探测输出已通过模式、可以作为正式周期运行产物或可被消费者稳定读取。

后续 live 探测仍须只读、不登录、不绕过访问控制、不提交表单，也不接受改变远端状态的操作。观察只提出复核范围；页面可访问、重定向、文本相同或暂时不可访问都不能单独成为正式结论。

## 决策权限

本草案不另建现行权限表，继续服从[治理的决策权](../governance.md#决策权)。运行离线校验、生成索引和固定夹具材料只能证明机械事实；具体来源状态、地址、角色、替代、实际派生、概念映射和迁移去向仍按内容先提案或由人决定。

草案生效、正式迁移、来源改档和发版只有人能决定。已采纳的来源结构、校验、探测和迁移控制决定只批准控制边界，不批准具体来源事实。工具要求一个决定引用，也不表示工具能够形成或采纳该决定。

## 校验规则

来源基础已经实现以下机械检查。

- 六份来源 schema 可由共享模型确定生成。
- 严格引用校验可检查 `basis.entity`、`source.registry`、`match.registry` 和 `external_group.registry`，并检查所需角色及其决定。
- 仓库校验已覆盖三份正式文件的 schema 入口、旧 `origin`／`url` 拒绝、角色决定检查、稳定 id、实体历史前缀和已解决义务不得重开。
- 反向索引可确定遍历共享引用、用途实体、角色决定、替代、决定、义务前项和义务目标，并可选择纳入旧引用。
- 固定夹具探测可验证正式树不回写。

这些检查没有覆盖草案列出的全部状态转换、触发枚举、义务目标解析、用途历史和所有只追加规则。当前正式旧数据也尚未进入严格来源校验，不能把严格检查写成现行正式数据已经通过的门禁。

迁移预演能力已实现冻结哈希、库存计数、补丁覆盖、字段所有权和身份覆盖检查；六份账本保存过一次历史预演结果。当前 HEAD 已改变冻结输入，重跑会在冻结哈希处失败，不能宣称这些账本可由当前仓库快照重新物化。

校验器只能判断结构和明确的机械条件。来源身份、内容是否实质变化、派生是否真实、两个概念是否匹配、证据是否充分和项目是否批准，仍由逐项复核和决定回答。

## 迁移边界

六份来源迁移账本保存 138 个来源身份、47 个角色、1,501 个旧 `basis`、726 个旧 `source`、756 个旧 `match` 和 19 个旧 `origin` 身份。账本保留库存、分类、推荐去向和切换阻断；合计仍有 2,487 个 `blocks_cutover`。

这些数字证明历史库存和阻断范围，不证明其中任何真实关系获准。账本不修改正式文件，不改变 `tier`，不批准角色，也不把旧值机械提升为严格 `basis`、实际派生或概念映射。旧 `origin` 的逐项去向只保存迁移审计，不能替代新的语义判断。

当前阶段没有完整正式候选、handoff、payload、原子应用或补偿回滚。正式迁移须在阶段另行开放后重新绑定当前输入，逐项取得具体事实与关系决定，并验证消费者和回滚边界。

## 生效条件

本草案默认不生效。已完成的前置条件包括 schema、部分离线校验、反向索引、固定夹具探测、历史迁移账本、迁移预演能力和复核义务接口；它们不需要继续写成未来待建，也不能替代下列尚未完成条件。

1. 人逐节批准本文拟议的对象语义、状态转换、复核、失效处理、权限和阻断规则。
2. 形成覆盖当前 HEAD 的完整正式候选，为具体来源逐项给出身份、版本、地址、外部状态、角色、决定、`basis`、`source` 和 `match`，且不在迁移中自动改档。
3. 解决来源实体 schema 与一般实体字段共同承载正式文件的契约边界。
4. 闭合探测 schema 与实际输出，并在另行授权后实现和验证 live transport；固定夹具不能替代真实运行。
5. 重新绑定当前 HEAD 完成迁移预演，逐项消除切换阻断；历史账本不能替代当前预演重放。
6. 建立正式义务和正式索引候选，闭合义务目标、决定反查、历史与发布阻断接口。
7. 明确消费者契约、严格校验入口、正式写集、应用后验证和风险所需的回滚证据。
8. 人作出草案生效和实际迁移的决定；严格切换与发版分别取得授权。

条件未全部满足时，正式旧数据与现行规则继续生效。本草案不得创建正式数据、义务、索引、消费者、切换状态或发布物。

## 待定事项

- 来源新版仍属同一实体还是建立新实体的判据，以及不同发布体系怎样应用。
- 多角色地址怎样从正式旧地址形成逐项候选，镜像、存档快照和出版者页面怎样排序。
