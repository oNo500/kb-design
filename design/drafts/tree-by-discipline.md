# 树按学科而非分面的决定

状态:草案。记录主题词表顶层为什么按学科切、不按分面切,以及分面和概念组分别什么时候需要。按 [第一原理与设计理由](../../concepts/first-principles.md) 里 ADR 的做法写:背景、决定、后果。

## 背景

一棵层级树的顶层只能按一个划分特征切。主题词表有两个候选:

| | 按学科 | 按分面 |
|---|---|---|
| 顶层 | mathematics / computing / library-and-information-science …… → security / networking-and-communication …… | 对象 / 动作 / 施动者 …… → 各自成树 |
| 上层结构的来源 | 知识体系(CS2023、SWEBOK、GB/T 13745)都按学科分,可直接借入 | 没有知识体系按分面分,全靠自建 |
| 树里位置回答的问题 | 它属于哪个领域 | 它是什么类的东西 |
| 做不了的查询 | 横切:全库所有实践、所有标准 | 纵向:某领域的全部 |

## 决定

**顶层按学科。** 理由是本库 README 的前提:上层结构要完整到能暴露盲区,而完整只能借自公认的知识体系;知识体系全部按学科分。选了分面就借不到任何现成结构。

由此,分面不能是树的一层,只能是概念上横着标的字段;概念组按定义不在树里,与树并存。

## 后果

- 树回答不了横切查询。需要时加分面字段,不动树,见[分面字段草案](facet-field.md)。触发信号:开始用 `related` 或手工组硬凑「所有标准」「所有缺陷」这类查询
- 概念组分两种:由映射派生的组有映射就自动存在,已生效;手工圈定的组等多项目、多角色时再建,见[概念组草案](concept-groups.md)
- 同一划分特征只取一个知识体系,不同划分特征可并列数组——这条约束是「按学科」的直接推论,详见 [topics.md](../topics.md)

## 何时重新考虑

- 某个子领域下概念类型混杂到按学科浏览已无法使用
- 出现按分面分的权威知识体系(目前没有)

两者都未发生前,不重开此决定。
