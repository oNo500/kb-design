# 概念组草案

状态：草案，未生效。派生组不在此列——它由映射自动产生，已在 [topics.md](../topics.md)“外部知识体系的用法”生效；本草案只管手工圈定的组。理论见 [概念组](../../concepts/concept-group.md)。

## 两种来源

| 来源 | 成员 | 登记 | 状态 |
|---|---|---|---|
| 派生组 | 映射到某外部体系的全部概念 | 不登记；`sources.yaml` 中该体系 `role` 含 `group` | 已生效 |
| 手工组 | 人工圈定 | `vocab/groups.yaml` | 本草案 |

## 触发条件

单人单项目不建手工组。以下情况之一出现时生效：

- 多个项目共用这份词表，各自要看自己的子集
- 多个角色（如写作、审校）要看不同子集
- 一次专题需要临时圈一批概念，且派生组和分面字段都凑不出

## 登记文件

```yaml
# vocab/groups.yaml
- id: project-foo
  label: 项目 foo 常用
  purpose: 项目 foo 的内容单元打标签时的候选范围
  members: [sql-injection, input-validation, postgresql]
  added: 2026-08-23
```

## 规则

1. 组不改树：成员在 `topics.yaml` 里的位置、关系一律不动
2. 一个概念可属任意多个组
3. 组可嵌套（ISO 25964-1 数据模型 hasSubgroup / hasSupergroup），本库暂不用
4. 组名是普通标签，不是概念：不进术语表，不能做 `broader` 或 `match` 的目标
5. 校验脚本：`members` 指向存在的概念；长期无人打开的组提示删除——组是视图，可以删

## 与分面字段的分工

按需求的性质选：要“是什么类”用[分面字段](facet-field.md)，要“谁在用”用概念组。派生组是已映射内容的视图，暴露不了盲区，不能替代复制或分面。
