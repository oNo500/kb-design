# 划分特征的自定治理

状态：草案。本库“当前阶段零自定”的唯一例外：分析层数组的划分特征允许本库自定，条件是按本文登记和复核。其他一切术语仍不开放。背景见[借入照抄与本地分析分层的决定](../decisions/borrow-and-analyze.md)。

## 登记

`vocab/characteristics.yaml`，每个自定的划分特征一条：

```yaml
- id: paradigm
  label: 按范式
  definition: 程序组织与执行的基本模型
  test: OOP 和函数式的区别是范式          # 判据句,必填
  applies_to: [foundations-of-programming-languages]     # 允许用在哪些概念之下
  basis: self                             # 有外部依据写来源 id;没有写 self
  added: 2026-08-23
  status: candidate
  history: []
```

## 准入

1. 判据句必须成立，且该数组内任意两个成员都能用它区分（能填进“A 和 B 的区别是 ___”）
2. **完备划分**:`applies_to` 概念的每个下位落进且只落进一组；落不进的显式列为“未归”，不得漏
3. 不得改动借入概念的任何字段：不加、不删、不动 `broader` 和 `match`
4. 有外部依据的优先：先找教材、标准、综述里现成的分法，`basis` 填来源 id；确实没有才 `self`
5. 不得是来源名、来源的层级名或知识体系名——那些是底层的 `source`，不是划分特征
6. 新登记的为 `candidate`；用过一段时间复核一次，仍成立才转 `active`

## 范围

7. 只能用于两处：重组借入的下位集合；本地概念（第 4 层起）的分组。不能用来新造概念、起字段名，不进术语表

## 废弃

8. 不删，转 `deprecated`，保留 `history`；该划分特征下的数组随之失效；底层的下位集合不受影响

## 复核

9. 来源改版时，`applies_to` 涉及该来源的划分特征强制复核：新增条目是否归组、删除条目是否清出
10. 校验脚本：每个分析层数组的成员都在上位的下位集合内；每个下位在同一划分特征下至多属一组；未归项列出

## 待定

- `candidate` 转 `active` 的“用过一段时间”怎么量化
- 同一划分特征在多个概念下使用时，判据句是否需要逐个概念写
