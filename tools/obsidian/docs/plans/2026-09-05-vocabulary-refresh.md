# 词表刷新实施

目标：用户继续使用现有 `kb-vault`，通过显式 `refresh` 命令更新最新词表，保留用户内容、应用视图和配置。

## 版本依据

新设计快照为 `37a78c775d867eb9d1f7610ced23aee43ce345ec`，保存于独立的干净设计工作区；原 `kb-design` 目录及其中无关未提交修改不移动、不混入提交。应用继续接受旧 `59e033d64b230fe658aa09955e1a66ec38aa5c6f`，允许旧 vault 刷新至已验证的新快照。

## 写入范围

只替换 `kb/` 和 `app/manifest.json`。其余文件逐字保留；生成过程、检查和备份位于 vault 外。语义未变的 Base 格式差异，只有其旧清单与原生成模板一致时才可接受，保留实际文件并记录新哈希。语义差异仍是冲突，不静默认可。

## 实施步骤

- [x] 建立应用专用分支和干净的设计版本，校验新设计能被参考导出适配器读取。
- [x] 实现 `refresh_vocabulary` 与 CLI `refresh`／`--dry-run`。
- [x] 验证旧清单、旧 Git 输入、受管理文件及新引用；检查内容的受控引用和显式指向 `kb/` 的 Wikilink。
- [x] 在外部目录准备新参考区与清单，发布前再次检查目标文件，异常时回滚，保留恢复备份。
- [x] 验证用户及配置保留、冲突拒绝、格式差异、无写入预览、发布失败回滚等行为。
- [x] 对实际 `kb-vault` 预检后执行，运行内容校验，并记录版本、覆盖率、备份和保留文件证据。

## 验收边界

文件与哈希差异由命令证明，审查重点是写集、引用、权限和回滚，不重复进行机械计数。失败结果不能通过重写清单消除；不把成功目录替换宣称为多文件崩溃一致性或断电持久性。应用表示更新不等于正式消费者激活。
