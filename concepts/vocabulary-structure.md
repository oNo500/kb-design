# 词表的结构 (Vocabulary Structure)

受控词表内部怎么组织:领域、分面、树、节点、数组、分组这些词各指什么,互相什么关系。本文把它们放进一张图里,再逐个解释。

## 定义

词表的结构是**概念在词表里的排列方式**。ISO 25964-1 的数据模型里,结构由四种容器承载:树(层级关系)、数组(ThesaurusArray)、节点标签(NodeLabel)、概念组(ConceptGroup)。分面不是数据模型里的类,是决定「有几棵树、树里怎么分」的分析方法。

## 一张图

以技术知识库为例:

```
领域                              词表覆盖的范围:「我的技术知识库」
│
├─ 分面                           领域切成几个互不重叠的类别
│   软件 | 动作 | 环境 | 人物 | 时间
│
│   每个分面内部是一棵树:
│
│   软件                          顶层概念
│   └─ 数据库                     概念,树上的一个节点
│       (按数据模型)              节点标签:说明下面按什么分
│       ├─ 关系型数据库   ┐
│       ├─ 文档数据库     ├─ 数组:同一标签下的一组兄弟
│       └─ 图数据库       ┘
│       (按部署方式)              同一概念可以有第二个节点标签
│       ├─ 嵌入式数据库   ┐
│       └─ 服务端数据库   ┘       另一个数组
│
│       关系型数据库
│       └─ PostgreSQL             概念;挂着词:首选 PostgreSQL,非首选 pg、postgres
│
└─ 分组                           横跨分面,按用途圈一批概念
    「后端组常用」= {PostgreSQL, 部署, 生产, 张三}
```

## 逐个解释

| 术语 | 一句话 | 出处 |
|---|---|---|
| **领域** domain | 词表管到哪为止。最外层边界 | — |
| **分面** facet | 同一内在类别的概念分组:对象、材料、动作、施动者、地点、时间 | ISO 25964-1 §2.20 |
| **分面分析** facet analysis | 把领域分解成概念,按分面分组,再按划分特征细分 | ISO 25964-1 §2.21;Z39.19 §5.3.4 |
| **划分特征** characteristic of division | 把一个概念细分成一组下位概念所依据的属性 | ISO 25964-1 §2.4 |
| **树 / 层级** hierarchy | 按 BT/NT 排出的上下位结构 | ISO 25964-1 §10.2 |
| **单层级 / 多层级** mono- / polyhierarchy | 每个概念只能有一个 / 可以有多个直接上位 | ISO 25964-1 §2.34, §2.42 |
| **节点** node | 树上的一个位置。通常是一个概念;节点标签也占位置但不是概念 | — |
| **顶层概念** top concept | 树的根,没有上位 | ISO 25964-1 数据模型 `topConcept` |
| **节点标签** node label | 树里插入的一行「(按 ×× 分)」,说明下面兄弟为什么分开。既非首选词也非非首选词,不能标引 | ISO 25964-1 §2.38 |
| **数组** array | 一组同级概念(兄弟),通常由一个划分特征产生、一个节点标签引导 | ISO 25964-1 §2.1 |
| **分组 / 概念组** concept group | 按用途圈出的一批概念,可横跨分面和树;一个概念可属多组;组可嵌套 | ISO 25964-1 数据模型 `ConceptGroup` |
| **微词表** micro-thesaurus | 概念组的一种用法:从大词表里圈出某子领域用的部分 | ISO 25964-1 数据模型 `conceptGroupType` |

## 分面的两种用法

「分面」有严格和宽松两种用法,**两种都有标准背书**,容易混:

| | 严格用法 | 宽松用法 |
|---|---|---|
| 作用对象 | 概念 | 内容对象(文档) |
| 回答 | 这个概念本质上是哪类东西 | 这条记录的某个属性是什么 |
| 例子 | PostgreSQL ∈ 软件;部署 ∈ 动作 | 主题、作者、地点、格式、语言 |
| 出处 | ISO 25964-1 §2.20;Ranganathan 的基本范畴 | Z39.19 §5.3.4 图 4;电商的「分面导航」 |

严格用法里一个概念只属于一个分面;宽松用法里 facet 就是可筛选的字段。在知识库设计里两者分别对应**词表有几棵树**和**元数据有哪些字段**,见下文。

## 分面与分组的区别

| | 分面 | 分组 |
|---|---|---|
| 归堆理由 | 概念本身是什么类 | 谁用、用在哪 |
| 一个概念属于几个 | 一个 | 任意多 |
| 稳定性 | 领域不变就不变 | 随组织、项目变 |
| 数据模型 | `ThesaurusArray` + `NodeLabel` | `ConceptGroup` |
| SKOS | `iso-thes:ThesaurusArray`(`skos:Collection` 子类) | `iso-thes:ConceptGroup`(`skos:Collection` 子类) |

一句话:分面回答「它是哪一类」,分组回答「它归谁管、给谁看」。

## 先组与后组

多个分面的概念怎么组合来描述一个东西:

| | 先组 pre-coordination | 后组 post-coordination |
|---|---|---|
| 组合时机 | 建表或标引时就拼好 | 检索时再组合 |
| 产物 | 一个复合标目或组配号:`数据库教材` | 几个独立的词:`数据库` + `教材` |
| 优点 | 精确,可排架 | 灵活,词表小 |
| 缺点 | 组合爆炸 | 检索要会组合,可能误配 |
| 出处 | ISO 25964-1 §2.44 | ISO 25964-1 §2.43 |

分类法的**辅助表**(auxiliary table,《中图法》叫复分表,DDC 叫 Tables,UDC 叫 common auxiliaries)是先组式的分面:把地区、时间、形式等通用维度单独列表,编号时拼到主表号码后面。它是为在一个线性排架号里塞进多个维度而发明的,电子系统不需要;但它提示了**地区、时间、形式是几乎任何领域都需要的通用维度**。

## 在知识库中的用法

| 词表结构 | 知识库里 |
|---|---|
| 领域 | 仓库范围 |
| 分面(严格) | 主题词表有几棵树:软件 / 动作 / 概念 / 人物 |
| 分面(宽松)/ 属性 | frontmatter 有哪些字段:`topic:` `type:` `env:` `created:`。其中 `topic:` 取值来自主题词表,`type:` 取值是代码表,`created:` 是字面值 |
| 划分特征 + 节点标签 | 树里一层分成几堆时,写明划分依据;否则半年后不知道为什么这么分 |
| 多层级 | 允许一个概念有两个上位,但标明主上位供显示和排序 |
| 分组 | 视图:某项目或某角色看到哪些标签。有多项目或多人时再做 |
| 先组 / 后组 | 天然后组(多字段),工具选型时确认支持多字段组合查询 |
| 辅助表 | 不用;但时间、形式这两个通用维度从词表结构降级为元数据字段 `created:` `type:`,是一个设计决定 |
