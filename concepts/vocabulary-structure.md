# 词表的结构 (Vocabulary Structure)

## 定义

词表的结构是**概念在词表里的排列方式**。ISO 25964-1 用四样东西描述它:层级(上下位)、数组、节点标签、概念组;分面不是数据模型里的类,是决定「整个词表先切成几大块」的分析方法。本文按遇到问题的顺序逐个引入,例子用「人」,最后对到技术知识库。

## 一个概念下面怎么分

你有一个概念「人」,要列它的下位。立刻遇到一个问题:按什么分?

- 按年龄分:儿童、青年、成人、老人
- 按职业分:医生、教师、工程师
- 按国籍分:中国人、日本人、法国人

三种分法都对,但不能混在一起列——「儿童、医生、中国人」放一排,读者会问:一个中国儿童医生算哪个?

**划分特征**(characteristic of division)就是「按什么分」这个问题的答案。年龄、职业、国籍各是一个划分特征。ISO 25964-1 §2.4 的原例就是「人 → 按年龄段 → 儿童 / 青年 / 成人」。

## 每个划分特征产生一组兄弟

按年龄分出来的「儿童、青年、成人、老人」是一组,按职业分出来的「医生、教师、工程师」是另一组。每一组叫一个**数组**(array,ISO 25964-1 §2.1:一组同级概念)。「人」下面现在有三个数组。

## 组前面写上按什么分

列出来的时候,为了让读者知道每组是怎么来的,在每组前面插一行说明:

```
人
  (按年龄)          ← 节点标签
    儿童
    青年
    成人
  (按职业)          ← 节点标签
    医生
    教师
  (按国籍)
    中国人
    日本人
```

括号里那行叫**节点标签**(node label,ISO 25964-1 §2.38)。它不是概念——不能给一篇笔记打「按年龄」这个标签;它只是组的名牌,说明下面的兄弟为什么是兄弟。

到这里三个词讲完了:**划分特征是问题,数组是这个问题分出来的一组,节点标签是写在组前面的问题本身。** 三者是一回事的三个侧面。

## 一个概念可以同时在几个组里

「张三」是成人、是医生、是中国人,所以他在三个数组里都出现。这就是**多层级**(polyhierarchy,ISO 25964-1 §2.42):一个概念有多个上位。概念还是一个张三,只是从三个问题都能找到他。反之,规定每个概念只能有一个上位,叫单层级(§2.34)。ISO 25964 两者都允许,多数现代词表用多层级。

## 分面:词表顶层的横切

上面说的都发生在「人」这一个概念**下面**。分面发生在整个词表的**最顶上**。

分面问的不是「人怎么分」,而是「这个词表里的所有概念,本质上是哪几类东西」。比如一个医院词表:

```
人物分面:  医生、患者、护士
动作分面:  手术、诊断、护理
地点分面:  病房、手术室
时间分面:  术前、术后
```

「手术」和「医生」不是谁是谁的下位,它们是不同种类的东西——一个是动作,一个是人。**分面**(facet,ISO 25964-1 §2.20:同一内在类别的概念分组)就是把整个词表先按「东西的种类」切成几大块,每块里面再各自建树、各自用划分特征分。ISO 给的高层类别示例是对象、材料、施动者、动作、地点、时间,来源是 Ranganathan 的分面分类法;这是示例,不是封闭集合。

一句话区分:**分面是词表顶层的横切,划分特征是某个概念下面的纵切。**

分面还有一种宽松用法:Z39.19 §5.3.4 图 4 把文档的属性——主题、作者、地点、格式、语言——也叫 facet,电商的「分面导航」沿用这个意思。宽松用法里 facet 就是可筛选的字段,作用对象是文档不是概念。两种用法都有标准出处,读到时要分清。

## 分组:为了用,不为了分类

还有一个词容易混进来:**概念组**(concept group,ISO 25964-1 数据模型)。它不问「是什么」,只问「谁要用」。「急诊科常用词」= {医生, 手术, 病房, 术前},四个概念来自四个分面,凑在一起只因为急诊科要用。它是视图,不改变任何概念在树里的位置;一个概念可以属于任意多个组,组可以嵌套。从大词表里圈出一个子领域给某个系统用,叫微词表(micro-thesaurus),是概念组的典型用法。

| | 分面 | 划分特征 / 数组 | 概念组 |
|---|---|---|---|
| 发生在哪 | 词表顶层 | 某个概念下面 | 任何地方 |
| 问的问题 | 它是哪类东西 | 这一层按什么分 | 谁要用 |
| 一个概念属于几个 | 一个 | 每个问题一个数组 | 任意多 |
| 稳定性 | 领域不变就不变 | 随分析深入增加 | 随组织、项目变 |

## 先组与后组

多个分面的概念怎么组合来描述一个东西:

| | 先组 pre-coordination(ISO 2.44) | 后组 post-coordination(ISO 2.43) |
|---|---|---|
| 组合时机 | 建表或标引时就拼好 | 检索时再组合 |
| 产物 | 一个复合标目:「术后护理」 | 几个独立的词:「术后」+「护理」 |
| 优点 | 精确,可排架 | 灵活,词表小 |
| 缺点 | 组合爆炸 | 检索要会组合 |

分类法里的辅助表(《中图法》复分表、DDC 的 Tables、UDC 的 common auxiliaries)是先组式的分面:把地区、时间、形式单独列表,编号时拼到主表号后面。它为纸质排架而生,电子系统不需要;但它提示了地区、时间、形式几乎是任何领域都需要的通用分面。

## 在知识库中的用法

把「人」的例子对到技术知识库:

| 例子里 | 知识库里 |
|---|---|
| 人 | `security` |
| 按年龄 / 按职业 / 按国籍 | 按验证要求 (ASVS) / 按缺陷类型 (CWE) / 按攻击战术 (ATT&CK) |
| 儿童、青年…… | 认证、输入验证…… |
| 张三同时是成人、医生 | `sql-injection` 同时属于「输入验证」和「注入类缺陷」 |
| 节点标签「(按年龄)」 | 节点标签「(按验证要求)」 |
| 人物 / 动作 / 地点分面 | 暂不设,见设计草案 |
| 急诊科常用词 | 某项目或某角色看到的标签子集;有多项目时再做 |

两条实际规则:

1. 一个概念下按不同划分特征分出的组,各自用节点标签标明;同一划分特征只保留一种分法
2. 文档的属性(类型、日期、环境)是宽松意义的 facet,落到 frontmatter 字段,不进词表的树
