# 分面 (Facet)

## 定义

分面是**同一内在类别的概念分组**(ISO 25964-1 §2.20)。它回答的不是「某个概念下面怎么分」,而是「这个词表里的所有概念,本质上是几种东西」。

## 建树之前先归类

分面不是树上的某个位置,是对整个词表的全部概念做的第一次归类——在建任何树之前先问「这些概念本质上是几种东西」,归出来的每一种各自成一棵树。

用医院的例子:

```
全部概念:{医生, 患者, 手术, 诊断, 病房, 手术室, 术前, 术后}

第一次归类(分面):
  人物:{医生, 患者}
  动作:{手术, 诊断}
  地点:{病房, 手术室}
  时间:{术前, 术后}

然后每一块各自建树:
  人物                动作               地点
  ├─ 医务人员         ├─ 治疗            ├─ 病房
  │   └─ 医生         │   └─ 手术        └─ 手术室
  └─ 患者             └─ 诊断
```

「手术」和「医生」不是谁是谁的下位,它们是不同种类的东西。分面决定有几棵树、每棵树的根是什么;树里面的分叉才是划分特征的事。

ISO 给的高层类别示例是对象、材料、施动者、动作、地点、时间。这是示例,不是封闭集合;来源是 Ranganathan 的分面分类法(1933),经分类研究小组扩展。

## 分面怎么组合

一篇笔记讲「术后护理」,涉及时间分面的「术后」和动作分面的「护理」。两种处理:

| | 先组(pre-coordination,ISO §2.44) | 后组(post-coordination,ISO §2.43) |
|---|---|---|
| 做法 | 建表时就把「术后护理」做成一个词 | 词表里只有「术后」和「护理」,标引时各打一个,检索时组合 |
| 优点 | 精确 | 词表小,任意组合 |
| 缺点 | 组合数爆炸 | 检索要会组合 |

分类法的辅助表(《中图法》复分表、DDC 的 Tables、UDC 的 common auxiliaries)是先组的一种:把地区、时间、形式这几个分面单独列表,编号时拼到主表号后面。它为纸质排架而生;它提示的是地区、时间、形式几乎任何领域都需要。

## 宽松用法

Z39.19 §5.3.4 图 4 把文档的属性——主题、作者、地点、格式、语言——也叫 facet,电商的「分面导航」沿用这个意思。宽松用法里 facet 是可筛选的字段,作用对象是文档不是概念。两种用法都有标准出处,读到时要分清:严格用法归概念,宽松用法归文档。

## 在知识库中

本库的 `topics.yaml` 顶层不是按分面切的,是按学科切的(computing / information-science)。学科不是「东西的种类」——`security` 下面既有动作(威胁建模)也有对象(防火墙)也有缺陷(SQL 注入)。所以本库的树没有分面层;分面如果要有,只能作为每个概念上的一个字段横着标,这就是分面字段草案的由来。两种做法标准都允许:Z39.19 §5.3.4 说分面分析是「层级之外的另一种组织方式」。

文档的属性(类型、日期、环境)按宽松用法处理,落到 frontmatter 字段,不进词表。
