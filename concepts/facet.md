# 分面 (Facet)

## 定义

分面是**同一内在类别的概念分组**(ISO 25964-1 §2.20)。它回答的不是「某个概念下面怎么分」,而是「这个词表里的所有概念,本质上是几种东西」。把一个领域分解成概念、按分面归类、再按划分特征细分的整套方法,叫**分面分析**(facet analysis,§2.21)。

## 建树之前先归类

分面不是树上的某个位置,是对整个词表的全部概念做的第一次归类——在建任何树之前先问「这些概念本质上是几种东西」,归出来的每一种各自成一棵树。

用医院的例子:

```
全部概念:{医生, 患者, 手术, 诊断, 病房, 手术室, 术前, 术后}

第一次归类(分面):
  人物:{医生, 患者}
  动作:{手术, 诊断}
  地点:{病房, 手术室}
  时间:{术前, 术后}

然后每一块各自建树:
  人物                动作               地点
  ├─ 医务人员         ├─ 治疗            ├─ 病房
  │   └─ 医生         │   └─ 手术        └─ 手术室
  └─ 患者             └─ 诊断
```

「手术」和「医生」不是谁是谁的下位,它们是不同种类的东西。

ISO 给的高层类别示例是对象、材料、施动者、动作、地点、时间。这是示例,不是封闭集合;思想来源是 Ranganathan 的分面分类法(1933)。

## 分面与层级的分工

分面决定有几棵树、每棵树的根是什么;树里面的分叉是划分特征的事。两者在树上的位置不同,所问的问题也不同:

| | 分面 | 划分特征 |
|---|---|---|
| 发生在哪 | 建树之前,对全部概念 | 树里某个概念下面 |
| 问的问题 | 它是哪类东西 | 这一层按什么分 |
| 一个概念属于几个 | 一个 | 每个划分特征一个数组,可同属多个 |
| 产物 | 几棵树 | 树里的一组兄弟 |

Z39.19 §5.3.4 说分面分析是「层级之外的另一种组织方式」,两者可以并存:先分面,每个分面里再建层级。

## 严格与宽松两种用法

「分面」还有一种宽松用法,两种都有标准出处,读到时要分清:

| | 严格用法 | 宽松用法 |
|---|---|---|
| 作用对象 | 概念 | [内容对象](glossary.md)(文档) |
| 回答 | 这个概念本质上是哪类东西 | 这条记录的某个属性是什么 |
| 例子 | 手术 ∈ 动作;医生 ∈ 人物 | 主题、作者、地点、格式、语言 |
| 出处 | ISO 25964-1 §2.20;Ranganathan | Z39.19 §5.3.4 图 4;电商的「分面导航」 |

宽松用法里 facet 就是可筛选的字段。在知识库里两者分别对应「词表有几棵树」和「元数据有哪些字段」。

## 分面怎么组合

一篇笔记讲「术后护理」,涉及时间分面的「术后」和动作分面的「护理」。两种处理:

| | 先组 pre-coordination | 后组 post-coordination |
|---|---|---|
| 组合时机 | 建表或标引时就拼好 | 检索时再组合 |
| 产物 | 一个复合标目或组配号:「术后护理」 | 几个独立的词:「术后」+「护理」 |
| 优点 | 精确,可排架 | 灵活,词表小 |
| 缺点 | 组合数爆炸 | 检索要会组合,可能误配 |
| 出处 | ISO 25964-1 §2.44 | ISO 25964-1 §2.43 |

分类法(如 DDC、UDC、《中图法》)用辅助表实现先组式的分面:把地区、时间、形式单独列表,编号时拼到主表号后面。它为纸质排架而生,电子系统不需要;见术语表「辅助表」。

## 在知识库中

本库的 `topics.yaml` 顶层不是按分面切的,是按学科切的(computing / information-science)。学科不是「东西的种类」——`security` 下面既有动作(威胁建模)也有对象(防火墙)也有缺陷(SQL 注入)。所以本库的树没有分面层;分面如果要有,只能作为每个概念上的一个字段横着标,这就是分面字段草案的由来。两种做法标准都允许。

文档的属性按宽松用法处理,落到笔记的[元数据](glossary.md)字段,不进词表。字段的取值来源有三种:`topic:` 取自主题词表,`type:` 取自一份代码表,`created:` 是字面值——前两者分别是[叙词表和术语表](controlled-vocabulary.md),第三种无需控制。

本库天然是后组的:一篇笔记打多个字段,检索时组合。工具选型时要确认支持多字段组合查询。辅助表不用;但时间、形式这两个通用分面从词表结构降级为元数据字段 `created:` `type:`,这是一个设计决定,而不是它们不重要。
