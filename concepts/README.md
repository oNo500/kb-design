# 概念文索引

`concepts/` 中的文章解释本库使用的理论：它是什么、解决什么问题、为什么成立。先用[术语数据库](terminology-database.md)理解概念、多语形式、状态和维护怎样分层，再用[术语表](glossary.md)查找本库已经登记的名称。项目规则见 `design/`，实际阅读的文献范围见 `sources/`。

## 文章关系

```
知识组织
├─ 术语数据库                概念、多语形式、状态和历史怎样分别记录
│  └─ 术语表                已登记名称和定义怎样面向读者汇集
├─ 受控词表                  概念怎样由已核实的名称、标目或代码表示并组织
│  ├─ 词表的层级            概念之间的上下位关系怎样组织
│  ├─ 分面                  概念怎样先按内在类别归类
│  ├─ 概念组                怎样按用途圈出概念视图
│  ├─ 词表的建设与维护      怎样从输入判断概念并维护概念记录
│  └─ 新主题的分类          标准里没有的主题怎样分类
├─ 词表映射                  多份词表中的概念怎样对应
├─ 知识体系                  各类体系怎样提供结构、核对或映射材料
├─ 元数据                    字段从哪里来，受控词表怎样为字段提供值
│  └─ Application Profile   应用需求怎样约束 metadata 并与具体表示分层
├─ 笔记的类型                体裁、作者立场、成熟度、载体和认知层级怎样分开描述
└─ 知识图谱                  词表怎样扩展为带类型的实体关系

方法论
├─ 第一原理与设计理由        怎样检验方法的起点并保存决定理由
├─ 写作规范                  写作规则怎样从面向读者的原则推出
├─ 治理                      怎样管理决策权、政策、变更和审计
└─ Reproducible Builds      怎样区分确定性、独立重建、完整性和 provenance 证据
```

术语数据库先区分记录对象，术语表再提供名称入口，受控词表使用已经核实的表示来组织概念。词表映射连接不同词表中的概念，不因两个标签相同就合并记录。这条依赖关系不改变各篇文章的职责。

## 词表结构总览

第一组示例说明术语数据库、术语表和受控词表怎样分工。术语数据库保存概念、语言和术语的分层记录；术语表是面向读者的汇集；受控词表再按检索用途组织其中的概念。

```
术语数据库
└─ PostgreSQL 所指的概念
   ├─ 某种语言
   │  ├─ 优先使用的形式
   │  └─ 其他已核实形式
   └─ 另一种语言
      └─ 已核实形式
          │
          ├─ 进入术语表的读者视图
          └─ 供受控词表选择表示形式
```

第二组示例说明一份受控词表内部的结构。方括号标出解释相应结构的文章。

```
词表中的全部概念
│
├─ 按内在类别归类：分面 [分面]
│
│   每个分面各自形成层级 [词表的层级]：
│
│   技术                              ← 顶层概念
│   └─ 数据库                         ← 概念，树上的节点
│       （按数据模型）                ← 节点标签，说明划分特征
│       ├─ 关系数据库  ┐
│       ├─ 图数据库    ├─ 数组
│       └─ 键值数据库  ┘
│
│       PostgreSQL：关系数据库、开源软件
│                                      ← 多层级，一个概念有多个上位概念
│
└─ 按用途圈出概念组 [概念组]
    例如，按一次数据库学习任务圈出 {数据库，关系数据库，PostgreSQL}
```

第三组示例说明本地词表与外部体系的关系。ASVS、CWE 和 OWASP Top 10 分别演示结构复用、概念映射和派生视图，一个本地概念把三种用法联系起来。

```
本地概念 sql-injection
  ├─ 位于数组“（按验证要求）”中的 input-validation 之下  ← 数组结构来自 ASVS
  ├─ match → CWE-89                                      ← 映射到 CWE 的一条
  └─ match → A03:2021                                    ← 映射到 OWASP Top 10 的一条
                                                            由此进入派生概念组“Top 10”
```

三种用法在本地承担不同职责。

| 用法 | 外部体系 | 做法 | 本地产物 |
|---|---|---|---|
| 结构复用 | ASVS | 把它的章节结构转成本地结构 | `security` 下的一个数组，成员是本地概念 |
| 概念映射 | CWE | 让本地概念指向它的稳定条目 | 概念记录中的一条 `match` |
| 派生视图 | OWASP Top 10 | 圈出所有映射到它的本地概念 | 一个概念组 |

概念位于哪一套本地结构中，与它映射到哪个外部条目，是两件事。前者由本地层级决定，后者由概念之间的对应关系决定。
