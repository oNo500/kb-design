# 词表规则审查

审查日期：2026-09-19。覆盖六篇目标设计，按重复规则归并为 72 项，另列 92 行 RDF 属性合同。本轮只形成审查建议，未修改设计、决定、实现或数据。

## 审查结论

上轮文件分离没有消除全部设计问题。本轮确认存在旧合同的表示限制、旧流程的算法要求及标准语义遗漏；同时，单一综合词表、稳定身份、来源可追溯和版本化引用等选择有独立理由，应保留。

建议分布：保留 54 项，修订 12 项，删除通用限制 2 项，待核 4 项。本轮另列 12 组具体处理建议；标准正文及交换方案尚未核定的部分继续标为待核。“删除”针对限制，不删除能力、数据或历史。

结论区分四种情况：标准不允许或语义遗漏；标准允许但项目没有充分收紧理由；由现行接口或算法直接继承；标准允许且项目需求足以支持。不能仅凭“不是标准强制”判定污染，也不能仅凭“已采纳”停止审查。

### 字段基数

F07 · 对象范围不清 · P2

位置：[设计-词表数据规范](../../docs/model/vocabulary/设计-词表数据规范.md)，第 83 行；[设计-词表数据规范](../../docs/model/vocabulary/设计-词表数据规范.md)，第 127 行；[设计-词表数据规范](../../docs/model/vocabulary/设计-词表数据规范.md)，第 257 行；[设计-词表数据规范](../../docs/model/vocabulary/设计-词表数据规范.md)，第 141 行。

判断：公开 schema 支持概念有 PreferredTerm、ConceptGroup 有标签，但 Array 的 NodeLabel 可选。不能把所有 Collection 都当作必需命名的 ConceptGroup。 ISO 交换模型的概念和术语日期为可选单值，能支持本地记录设计；DCMI 不规定所有来源同一基数，来源记录与本地记录的时间对象仍需分开。 本轮还核到 ISO 交换 schema 的 date 类型为 xsd:date 与 xsd:dateTime 的联合，因此本地日期格式本身有公开模型参照，不能误判为纯实现习惯。

依据：[ISO-XSD](https://www.niso.org/schemas/iso25964/iso25964-1_v1.4.xsd)（ThesaurusConceptStruct、ThesaurusTerm、ConceptGroupStruct、ThesaurusArrayStruct）；[SKOS](https://www.w3.org/TR/skos-reference/)（§3–10、附录 B；S9、S13–14、S27、S35–37、S46、S48、S52、S55–57、S62）；[DCMI](https://www.dublincore.org/specifications/dublin-core/dcmi-terms/)（title、type、format、identifier、source、description、dates、relations）。

原论证或继承位置：[设计-现行数据规范](../../docs/practices/vocabulary/设计-现行数据规范.md)，第 147 行。

建议：保留本地概念必名；分开概念组、数组和一般集合的标签要求，来源缺项另行处理。 本地记录可保留单一创建和最近修改时间；不要把此基数无条件施加给所有来源日期。

### 名称约束

F09 · 额外限制待论证 · P2

位置：[设计-词表数据规范](../../docs/model/vocabulary/设计-词表数据规范.md)，第 49 行；[设计-多语言词表](../../docs/model/vocabulary/设计-多语言词表.md)，第 70 行。

判断：SKOS 的文字值唯一不等于 Label 身份唯一；两个不同 Label 可有同一 literalForm。尚缺支持额外资源唯一性的编辑需求及来源处理方案。 标准允许更广的 Label 使用，SKOS-Thes 也给出集合标签用 XL 的方式。独立维护概念名称能支撑本次用途，但保持旧普通合同本身不是排除其他对象的理由。

依据：[SKOS](https://www.w3.org/TR/skos-reference/)（§3–10、附录 B；S9、S13–14、S27、S35–37、S46、S48、S52、S55–57、S62）；[THES](https://www.dublincore.org/specifications/skos-thes/ns/)（ConceptGroup、ThesaurusArray、superGroup、subGroup）。

建议：先补两个同文来源名称的场景，决定是否只约束首选文字，或保留资源唯一并明示选择与身份保留方法。 明确独立名称管理的对象范围与来源 XL 标签保留策略；普通标签可作默认方式，不写成标准的类型限制。

## 保留依据

| 选择 | 保留理由 | 审查项 |
|---|---|---|
| 单一综合词表 | 对应用户整合使用目标；不抹掉来源归属，SKOS 允许该选择 | R03 |
| 稳定身份及修订历史 | 支持持久引用、版本读取和来源追溯；不等同强制某一种 URI 技术 | R07–R10、R60–R62 |
| 本地概念有名称 | 公开 ISO 交换模型有 PreferredTerm 下限，适合可标引记录；不能泛化为所有数组必名 | R13 |
| 按需整合与直接映射 | 符合已有词表整合用途；不靠同名、对称性或传递性自动授予用途许可 | R05、R34、R37 |
| 允许缺译及非对称覆盖 | IFLA 官方指南提供方法依据，避免为齐全而造词、改含义或删概念 | R40–R42 |
| 译文记录与适用性分开 | 原翻译事实不随来源变化消失，新版适用性另有判断，符合维护已有译文的需求 | R43–R45 |
| 版本、停用及旧引用分开 | 持久身份不保证内容不变，避免自动重标引及历史失真 | R57–R62 |

## 未核事项

- R12：首选文字唯一不自动推出首选 Label 资源唯一，需具体编辑与来源身份场景论证。
- R30：层级细分类尤其整体部分的完整成立条件，不能只靠 SKOS 属性和 ISO schema 的 role 值确认。
- R35：组合映射的逻辑要求可保留，具体成熟交换表示与消费语义尚未完成核定。
- R70：未取得的 ISO 权威正文及缺页保持未核。Z39.19 的旧本地阅读记录没有作为本轮已核正文的替代。

## 审查边界

审查基于已记录 SHA-256 的未提交工作区，位置变化后按原文和摘要重新定位。项目选择的现行效力与其理由是否充分分别判断；本报告不自动撤销决定、放宽准入、改变语言范围或切换数据合同。

验证只检查审查定位、清单覆盖、引用和六篇原文未变。标准符合性、实现是否满足要求以及未知来源的所有转换情况，不由这些机械检查推定。
