## 结构方案

建议继续使用既有概念、语言、术语三层结构，不另建术语平台。具体变化如下。

| 对象 | 拟议字段处置 | 生效边界 |
|---|---|---|
| 术语概念 | `id` 保持 `tc-` 加 UUIDv4；定义、语言、状态和历史沿用现有结构 | 只为已明确的概念分配一次身份；不能把每个表格行都当成概念 |
| 术语形式 | `id` 保持 `tm-` 加 UUIDv4；`text` 与 `language` 逐项保存 | 首选与允许形式由具体采纳决定指定，不按斜杠、逗号或位置自动判定 |
| 语言 | 使用 `zh-Hans`、`zh-Hant`、`en`；缺失语言不补记录 | 第一列的纯英文仍是英文，不生成同文中文副本；`—` 不生成术语 |
| 领域 | `subject_fields` 允许尚未作出领域归属时为空 | 仅有章节名称不要求伪造主题 ID 或依据；正式归属值另行具体采纳 |
| 章节布局 | `glossary-layout.yaml` 按术语概念 ID 列出章节成员 | 章节 ID 不进入 `subject_fields`；分组只决定展示位置 |
| 外部依据 | 保留来源 v2 的严格 `entity`、`locator`、适用的 `checked` | 本轮未取得原文不得写成本轮已核；不把原登记或模型判断伪装成外部 basis |
| 历史登记 | 原行、原出处、原位置及输入哈希保留于迁移审查记录 | 建议维持现行登记效力；是否进入正式三层数据须逐项满足准入，不自动升级 `active` |
| 形式与符号 | `BT`、`NT`、`USE`、`UF` 等保留为关系指示符说明 | 它们不是缺失英文名称的替代值，不因为旧表格第二列存在就建立语言记录 |
| 数据枚举 | `de-jure`、`de-facto`、`vendor`、`archival` 保留现行来源字段说明 | 本轮不把来源分级说明展开成四个新术语概念 |

`subject_fields` 的可空调整、布局成员表达、术语生效与编辑权转移属于需要采纳的结构和规则变化。修复现有校验器不意味着这些变化已获准。

| glossary L111 | 演绎法／归纳法；deductive／inductive | 两种方法不同；现有词表建设文已分别解释其专门语境，不能按一般逻辑学印象擅自调换 |

| glossary L133 | 精确／不精确／部分等价；exact／inexact／partial equivalence | 三个程度不能共用一个无差别术语状态；原行没有独立定义 |
| glossary L172 | 相关／可找到／可理解／可使用 | 四项原则分别核对，不能一行升级为一个概念 |

`exactMatch / closeMatch`、`broadMatch / narrowMatch / relatedMatch`、`RDFS / OWL`、`Cypher / GQL` 也要逐个说明，但首先判断其作用是技术对象名称、属性代码还是拟独立治理的术语，不强行将全部代码变成术语概念。

其他疑点见逐项审查的 `lead_review`；该字段不是已批准状态。特别是“属性／维度”不能凭斜杠确认同义或非同义；`crosswalk` 的定义涉及多个词表并不表示该行包含多个概念；`reasoning / inference` 的范围不能凭逗号确认完全等价。

## 字段结果

[具体字段提案](2026-09-06-term-field-proposals.json)已为上述 8 组混合行列出 20 个组件的准确拟议形式。14 个组件找到现行项目文字中的独立描述并逐字保留位置；6 个组件没有找到独立定义，保持 `null` 而不是由模型补写。

这 6 个组件是 `recall`、`precision`、`relevant`、`findable`、`understandable`、`usable`。其中 Z39.19 的旧阅读范围未覆盖 §5.3.6；写作阅读记录保存了四原则名称与适用边界，没有保存各项独立定义。建议限定读取 NISO 的 §5.3.6 及术语定义、IPLF 原则说明，补齐所需含义，不扩展为全文解析或新增资料库。

其余 14 个描述也不因存在本地文字就取得外部核实身份。尤其等价程度的本地概念文引用 ISO-2 §11，但现有 ISO 阅读记录未读该章；三类笔记的来源记录明确含论坛转引和转述。建议连同这些直接影响拆分的数据核对原始依据；打不开则保留具体阻断，不用第二份模型回答代替出处。

已按文件名检索当前仓库、现有 worktrees、Documents、Downloads 和临时目录中的相关 PDF、HTML、TXT、TTL、XSD，未找到这些标准和笔记方法的原始副本。该结果只覆盖上述路径与名称检索，不能宣称整台机器没有材料；已存在的历史阅读记录继续保留。

## 模型登记

建议保留 `label-adoptions.json`、主题与载体词表的既有所有权。模型译名区从现行标签和精确采纳记录派生，唯一对象键继续为 `topics/<id>` 或 `forms/<id>`，不建立新的 `tc-*`、`tm-*` 或词表委托。

仅使用同一中英形式合并显示行，保留全部目标身份；同英文而中文或含义不同的对象分别显示。生成前复用语言依据校验与已采纳范围更正，`original.scope` 不回写，历史路径不改写。

模型行固定标注“模型知识 · 第 5 级，外部用法未核实”，保留出处链接与逐项采纳说明。它们可以生成展示，但生成不改变既有名称、定义、范围、状态或关系。

## 应用合同

建议每个获准术语概念生成 `kb/terms/<tc-id>.md`。这里的 `tc-id` 是术语概念身份，不是 `tm-id` 形式身份，也不是主题身份。页内显示各语言形式、定义、适用范围、出处与依据性质；术语名称不自动成为内容分类或主题标签。

正式所有者为 `data/vocab/terms.yaml`，参考页为只读派生物。模型译名没有独立术语概念时不生成对应术语概念页，也不借此创建 `kb/topics/` 对象。

实现需要同时覆盖 `exporter.load_repository` 的输入捕获、术语专用渲染、manifest 路径与身份校验、`reference_export` 的目录种类、设计快照哈希与刷新链接验证。新增术语输入、决定与渲染必须来自同一干净 Git 快照，不能只在文件写出后手动修改清单。

刷新写集仍为 `kb/` 和 `app/manifest.json`。用户内容、配置和现有稳定路径不变；正式库只作 CLI 只读预检，实际同步在基础设施验收后进行。
