# 离线证据验收

日期：2026-09-05。范围依据为用户批准的两个对象离线工程化试用，以及[首批来源准备](2026-09-05-source-v2-preparation.md)。本次增加核心命令，不创建正式来源数据或切换状态。

## 命令结果

`uv run kb-core prepare-source-evidence` 读取既有输入，固定处理 `computing ↔ gbt-13745:520` 与 `explanation ↔ diataxis:explanation`。默认在 `build/source-evidence/` 生成完整 Markdown、JSON、变化清单和派生缓存。

报告给出当前字段、旧账本结论、来源登记版本、材料文件哈希、章节、行号与原样片段。GB/T 材料明确标为转载清单，Diátaxis 材料明确标为阅读记录，不称为本轮核实的原页面。尚缺原始材料及语义判断时继续待审。

## 变化处理

缓存指纹包含选定记录、来源实体与用途、相关账本行、材料文件、适用政策和程序实现。相同输入复用片段，但不复用或生成任何人工批准；材料删除不沿用旧片段。填写了相邻 basis 只将提示从缺失改为待核，不能证明关系成立。

输出只允许在所选仓库真实 `build/` 的子目录内，拒绝源数据区、vault 区、符号链接和含无关文件的目标。输出以完整临时目录替换；普通替换失败尝试恢复旧目录，恢复失败保留备份。不宣称并发写入安全、无间隙可见性或断电持久性；同一目标串行运行。

## 验证结果

| 目标失败与后果 | 独有证据 |
|---|---|
| 命令不可运行或材料失去位置，无法实际回查 | CLI 端到端先复现命令缺失；实现后输出原样行、行号和材料性质，正式输入字节不变 |
| 缓存使新字段或证据变化被忽略 | 定向测试覆盖当前记录、材料、旧账本和政策变化；只重算受影响对象，政策变化影响两项 |
| 离线材料删除后继续展示旧片段 | 删除材料后重新运行，报告缺失、片段为空，不自动采纳 |
| 新填写的依据被误作已核或仍被错报为缺失 | 先复现新增 basis 后仍报告缺失；修复后显示已填写待核，结果仍为 review_required |
| 重复运行继续展开旧结果，浪费人工审阅 | 未变化运行不再调用片段提取，变化清单为空，完整结果继续保留 |
| 输出选择使正式数据被覆盖 | 正式目录与符号链接 build 目标均被拒绝，原数据和外部目录保持不变 |
| 新命令接入破坏既有生成入口的参数保护 | 既有 CLI 安全检查通过，帮助与错误参数不会生成主题数据 |

新增定向用例六项、既有 CLI 安全用例两项均通过。未改核心生成、来源校验或应用实现，不重复运行它们的全量回归。链接检查和 Git 差异格式检查通过。

独立代码与语义审查只检查陈旧证据、误采纳和输出越界风险，未发现 Important 或 Critical 问题；没有重复执行机械检查。

## 实际运行

本机连续两次运行均约 1.8 秒。第一次处理两项，复用零项；第二次处理的变化项为零，复用两项。两次都保留两项待审，不输出获准结论。

缓存没有明显缩短这两个小对象的命令耗时，因为仍需读取和解析输入以判断变化。实际收益是免去重复寻找位置、对照旧账本和人工重读未变化项；不能把该结果外推为任意材料规模的加速比。

## 适用边界

当前只有两个检索对象和 Markdown 材料，不支持任意文件导入、PDF 解析、联网下载、正式候选、角色采纳或切换。原始材料缺失不靠模型补造；新增材料或对象时先明确材料性质、路径、定位及审查范围。输出和缓存可重新生成，不是正式数据、schema 或决定编辑源。
