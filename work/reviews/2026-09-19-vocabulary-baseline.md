## 词表范围

自有知识体系采用一份词表，八个领域同时具有顶层概念和分组入口。自有词表使用一个 `skos:ConceptScheme`；顶层领域使用 `skos:Concept`，原领域分组继续使用独立的 `skos:Collection`。两种资源不共用 URI，不把分组成员关系直接改成上下位关系。

| 对象 | 表达 | 职责 |
|---|---|---|
| 自有词表 | 一个 `skos:ConceptScheme` | 统一的概念成员范围、名称规则和版本管理 |
| 顶层领域 | 八个 `skos:Concept` | 作为自有词表明确声明的顶层，通过上下位关系连接经配置确定的来源分支 |
| 领域分组 | 八个 `skos:Collection` | 计算机科学、数学、图书馆与信息科学、写作研究、技术传播、学习科学、认知科学、哲学的分组；允许交叉 |
| 概念 | `skos:Concept` | 保存主题意义、名称与概念关系；跨来源尚未消重的对象保持独立身份 |
| 来源词表 | 五份独立来源及其原有 ConceptScheme | 保存原始范围、归属、关系和版本，作为自有词表的来源依据 |

自有 `vocabulary.ttl` 以一个自有 ConceptScheme 组织概念。五份来源仍在来源快照和来源图中独立保存，不作为另外五套自有体系；主文件里的来源定位通过配套来源清单和对账记录追溯。统一自有词表不表示合并五份来源的身份或元数据。

来源原件和独立来源 Turtle 完整保留；概念按来源清单中的可选收录规则筛选后进入未编辑基线 `upstream.ttl`，过滤去向保存在 `source-selection.json`。本地编辑可以显式排除节点或增加本地节点，差异保存在 `local-effects.json` 和编辑历史中。最终主图中的概念统一属于一个自有词表。领域分组通过 `skos:member` 引用概念，同一概念可以成为多个分组的成员；没有领域分组或内容不会自动排除概念。同步与冲突规则见[词表维护设计](../../docs/model/vocabulary/设计-词表维护.md)。

领域分图是同一自有词表的派生子集，不是独立词表。应用可以按分组读取或导出，但分组归属本身是模型数据，不是仅存于界面的目录设置。

## 顶层记录

`knowledge-system.json` 的每个领域可配置 `hierarchy`：`uri` 是独立于分组的稳定概念身份，`roots` 是明确采用的分支概念 URI 列表。领域名称沿用已有中英文名称，`vocabulary.top_concepts` 显式列出顶层领域。生成器写入 `hasTopConcept`／`topConceptOf`、分支到领域的 `broader` 及其逆关系，并以组织配置的哈希定位关系依据。

领域节点不能与来源节点或 Collection 共用身份，不能有上位概念；挂接入口必须存在于当前选择结果且属于对应领域组。同一来源概念可以挂接到多个领域，原有身份与内部关系保留。配置不存在的入口导致构建失败，不自动跳过、不按名称猜测替代节点。

当前只连接已明确的分支入口。八个领域分组的原成员规则保持不变，不由新层级派生。数学连接显式配置的 MSC 大类；图书馆与信息科学为空顶层。未连接概念不自动成为顶层，仍可通过字母索引、搜索或分组访问。领域入口是项目组织选择，不冒称来源指定的上位关系，也不表示领域内部已全部完成组织。


来源收录规则可用 `selection.ancestors` 显式列出需要恢复的来源父节点。每项必须是原来源中现有入选概念的祖先；只加入列出的节点，不展开其其他后代，也不自动把全部祖先收录。关系沿用来源原文，顶层连接仍由领域 `hierarchy.roots` 独立声明。

2026-09-15 的来源路径修复恢复了 27 个 MSC 父节点，并将其中 17 个大类明确连接到数学。处理限于已选择的数学分支，量子物理、生物、教育等跨领域路径及来源缺失关系继续保留待确定状态。

## 结构迁移

目标主文件组织一份自有词表，领域分图仍是它的派生子集；五份来源快照继续独立保存。结构转换由生成器执行，输入配置与输出均应记录版本，不直接修改 `current` 指向的既有文件。

| 对象 | 迁移要求 |
|---|---|
| 自有词表 | 从配置读取稳定身份和中英文名称，统一记录成员与版本；重建不临时分配新身份 |
| 八个旧领域 Scheme | 为对应领域 Collection 明确独立稳定身份，登记旧 Scheme 与新分组的迁移对应；不能将原 IRI 原地改成集合类型或用 exactMatch 表达不同种类对象的替代 |
| 概念与关系 | 保持概念 IRI 和上下位、相关关系；统一自有 inScheme，领域成员改用 Collection 的 member，不要求先消重 |
| 未归属记录 | 全量概念均纳入自有词表；原“未归属”明确改为“未归入领域分组”，记录继续保留 |
| 原顶层声明 | 在来源图和历史版本中保留；自有统一词表的顶层单独确定，不从各领域顶层机械拼接 |
| 元数据与字段依据 | 来源元数据保留原对象和来源版本；自有词表与领域集合的名称、成员和类型转换逐项对账 |

### 多语差异

以下按 2026-09-19 的代码核对当前行为；[多语言设计](../../docs/model/vocabulary/设计-多语言词表.md)中的统一规则仍需实施和验收。

| 环节 | 当前行为 | 尚未满足的目标 |
|---|---|---|
| 语言范围 | [归一器](../../packages/kb-vocab/src/kb_vocab/normalization.py)按标签首段保留 `en`／`zh`，其他语言留在来源副本 | 不能代替完整标签语法及按固定 IANA 注册表的登记校验 |
| 标签角色 | 图校验按忽略大小写后的完整标签检查普通首选名，检查三种角色值冲突 | XL 投影与统一名称登记尚未接入 |
| 翻译任务 | [提取器](../../packages/kb-vocab/scripts/extract-translation-tasks.py)遇到任一中文标签即跳过；英文优先 `en`，其余按既有排序选取 | 未按完整目标标签分别补缺，也不是通用 RFC 4647 Lookup |
| 翻译合并 | [合并器](../../packages/kb-vocab/scripts/merge-translation-batch.py)核对源文字及实际源语言，输出 `@zh` | 不支持由多语任务通用指定目标标签；既有输出不能自动视为 `zh-Hans` |
| 显示与复核 | 中文流程具有英文回退；复用代码仍专门比较 `@en` | 各入口尚未形成统一的语言优先列表、Lookup、变体复核和缺项显示合同 |

以上差异不由扩大语言范围或修改旧标签绕过；具体采用、转换和回退分别留痕。应用切换前应核对实际匹配结果及返回的语言标签，不能把双语文件存在当成多语言消费已完整支持。
