## 历史保护

目标失败是已有历史被改写后，后续纯文档提交使读取器误将改写后的记录视为可信前态，导致历史丢失无法被发现。Git 前态读取按最近一次术语文件变更的父提交取值；生成、维护 CLI 和应用直接磁盘入口均使用已读取的当前术语字节，显式 previous 不能覆盖 Git 比较。

最终定向执行 `apps.obsidian.tests.test_term_export.TermExportTests.test_docs_only_commit_cannot_hide_a_term_history_rewrite`，结果为 1 项通过。该真实 Git 用例同时证明直接 `load_repository(root)` 和干净快照 `load_design(root)` 拒绝被后续文档提交掩盖的历史改写，错误为 `TERM_HISTORY_NOT_APPEND_ONLY`。

源码核对确认：显式 `input_bytes` 入口使用已捕获的 previous 字节，不调用磁盘输入捕获；维护 CLI 对当前术语读取一次，显式 previous 仅增加一次独立校验。本结论不把 Git 前态比较表述为独立于 Git 历史的全历史审计。
