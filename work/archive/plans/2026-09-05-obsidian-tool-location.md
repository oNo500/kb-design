# Obsidian 工具迁移

目标：按已采纳的[工具归属](../../../design/decisions/obsidian-tool-location.md)，将应用历史与实现迁入 `tools/obsidian/`，取消跨仓库版本白名单，保持旧 vault 可刷新。

实施使用 writing-plans、executing-plans 与 dispatching-parallel-agents；源码读取、文档同步与刷新兼容分工，文件所有权分开。用户已批准迁入、验证与合并；不再次请求同一授权。

## 迁入范围

- [x] 通过不压缩历史的 Git subtree 导入原应用 `master`，逐字核对导入树及祖先关系；原仓库与未提交 `uv.lock` 保留。
- [x] `tools/obsidian/src/kb_obsidian/design_source.py` 移除白名单，提供 `default_design_root()`，保留 `load_design(root)` 的干净快照与输入校验；`reference_export.py` 保留快照漂移检查。
- [x] `cli.py` 的 `--design-root` 改为可省略，显式参数继续有效；迁入测试从本仓库推导根目录，去掉个人机器绝对路径。
- [x] `refresh.py` 从旧清单记录的真实祖先提交验证输入，不依赖白名单；对能由原哈希及模板证明的等价参考 Base 排版保留实际字节。
- [x] 根入口、应用说明、治理摘要与现行 target 同步到同仓工具，历史决定只追加后续状态或引用新决定。

## 验证范围

- 新快照被误拒绝会导致每次提交后工具失效；临时 Git 仓库验证新提交可读、脏输入仍拒绝、默认定位正确。
- 旧来源冒用或哈希漂移会使刷新失去依据；保留旧版本、伪造输入、非祖先及快照变化的行为检查。
- Base 排版或迁移破坏刷新会影响既有 vault；在副本验证旧清单升级，保留用户文件与等价 Base 字节，实质改动拒绝，复用既有回滚检查。
- 路径迁移遗漏会破坏工具运行；在干净提交上运行设计与工具全量回归，比较同一词表生成的参考页与当前基线。机械文件集和历史由 Git 与哈希证明，不另委托重复审查。
- [x] 有行为变化的检查先取得 RED，再实现并取得 GREEN；文档和纯迁入不制造测试。
- [x] 对版本、来源、写集及兼容变化作一次独立审查，修复重要问题后合并 `master`。
- [x] 原应用目录保留备份，实际 `kb-vault` 保持原字节，不推送或发版。

## 验收结果

工具通过 87 项全量测试，设计通过 156 项全量测试；Python 3.9 验证默认根定位和正式输入读取。独立审查未发现 Critical 或 Important 问题。

实际 vault 的临时副本从旧设计快照完成预览、刷新和校验，只改变应用清单；全部参考页及主题、实体 Base 的实际排版保持原字节，实际 vault 未改变。原应用提交历史作为迁入提交的祖先保留，原目录及未提交文件继续留作备份。
