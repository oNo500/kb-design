# 消费者分类设计

状态：已批准（2026-08-30）。

本文是 Superpowers 设计规格，承接[概念依据计划](../plans/2026-08-28-terminology-concept-foundations.md)的“基本单位”复核和[证据复核设计](2026-08-29-e2-evidence-review-validator-design.md)的交接结果。它只规定原始命中位置的语义分类、独立复审和人工关口，不批准术语、译名、概念对应、消费者迁移或新增形式。

## 文档边界

本阶段处理七个待删除形式的原始命中位置，不重新研究 E2，不修改临时校验器，也不重跑已经关闭的三百四十八条结构回归。若当前输入相对交接快照发生变化，只刷新消费者位置和交接身份；没有新的失败证据时，不重新打开已关闭阶段。

“消费者”“候选分类”“字符串误命中”“来源陈述”“实际消费者”和“待人判断”都是本次执行表的临时值，不进入项目术语表、概念文或设计正文。本规格保存在 Superpowers 目录，分类产物保存在忽略的执行目录或临时目录。

本阶段止于人工决策包。项目正文、脚本、术语表和其他正式文件的迁移必须在人批准精确范围后另行规划，不能在分类过程中顺手修改。

## 问题边界

E2 交接留下七个待删除形式：`domain`、`term`、内容对象、复合概念、复合词、词和领域。原始检测器对每行执行不区分词界的子串包含检查，因此能够高召回地发现位置，也会把较长写法、代码标识和来源讨论一并列入候选。

交接快照有六百二十三条唯一“形式、位置”记录，分布如下：

| 形式 | 数量 |
|---|---:|
| `domain` | 7 |
| `term` | 72 |
| 内容对象 | 3 |
| 复合概念 | 1 |
| 复合词 | 3 |
| 词 | 431 |
| 领域 | 106 |

交接之后，根目录入口从 `CLAUDE.md` 改为 `AGENTS.md`，设计索引也增加了一条决定记录。2026-08-30 在提交 `ab8a118` 上只读刷新，候选总数和各形式数量均不变，但十一条位置身份因文件改名或行号移动而改变。旧交接表因此是已复审的历史快照，不能直接作为新分类的当前身份集。

原始检测回答“哪里包含这个字符串”，不能回答“这里是否以该形式表达待删除概念”。如果不补语义分类，删除保护会把所有命中都当成迁移义务；如果让字符串规则直接分类，又会漏掉较长表达中真实使用目标概念的情况。

## 设计目标

本阶段完成后，应当能够证明：

- 当前输入从冻结的仓库状态重新生成，与七个阻断精确对应；
- 六百二十三条候选逐条读取实际上下文，没有抽样、自动预填或遗漏；
- 每条候选都有首轮分类和具体处理说明；
- 未参与首轮对应记录的代理全量复审，每条候选都有第二个判断；
- 字符串规则只安排顺序和发现候选，不产生语义结论；
- 两轮一致的误命中和来源陈述可以在执行产物中关闭；
- 两轮一致的实际消费者只进入迁移提案，不修改项目文件；
- 分歧、待人判断、英文 `term`、必要新增形式和最终“基本单位”清单全部进入人工关口；
- 完整分类和复审产物保持可追踪，人工只需处理收敛后的决定包。

## 方案选择

可采用三种复审结构：

| 方案 | 收益 | 风险 | 结论 |
|---|---|---|---|
| 首轮分类加全量独立复审 | 每条记录有两个判断，工作量可按批次控制，分歧能够显式交人 | 复审者会看到首轮结论，必须重新打开上下文，避免只沿用首轮判断 | 采用 |
| 双盲全量分类 | 两轮互不读取对方结论 | 两次都要从零形成完整说明，工作量接近翻倍 | 不采用 |
| 字符串分层加风险抽查 | 速度最快 | 字符串规则事实上参与语义决定，可能漏掉真实消费者 | 不采用 |

采用方案允许首轮和复审分别分批执行，但每一条候选都必须经过两轮。复审不能抽样，也不能由首轮处理该记录的代理完成。

## 输入快照

实施开始前冻结以下输入及其 SHA-256：

- 当前 Git 提交和清洁状态；
- 三百四十八条临时审查表；
- 消费者提取器；
- E2 交接表；
- 按当前提交刷新的“基本单位”交接表。

刷新顺序固定为：从当前审查表重新扫描消费者，生成当前消费者列，再展开七个阻断的位置。刷新后的七个形式、每形式数量和总数预期仍为七、上述分布和六百二十三；若不同，先解释新增、消失或移动位置，不把旧数量写成强制真值。

当前交接表与历史交接表比较时，允许由已知项目提交造成的位置移动，但形式、语言、小节和原行必须仍对应同一七个阻断。当前身份集确认后立即锁定；分类期间项目文件变化会使快照失效。

## 分类单元

一条分类单元由“形式、语言、小节、原行、位置”五列共同标识。“位置”是冻结提交中的文件路径和行号。同一行命中多个目标形式时分别分类；同一形式在多个位置出现时也分别分类。

分类者必须读取命中行、所在段落或表格，以及判断概念用途所需的相邻小节。固定行窗只能帮助定位，不能替代上下文。目录名称、文件类型、代码字体和链接形式都不能单独决定分类。

“处理说明”必须指出该位置中的实际写法及其语义角色。只写“明显”“不是消费者”“见上下文”或复述分类值不算完成。

## 分类依据

每条记录按以下顺序判断：

1. 找出原始检测器实际命中的字符串和它所在的完整写法；
2. 对照该形式在临时审查表中的定义、依据结论和待删除理由；
3. 判断当前句段是在使用该形式表达概念，还是只记录字符串或来源用语；
4. 上下文不足时扩大阅读范围，不从目录或词界启发式直接下结论；
5. 仍存在两个合理解释，或判断会决定概念归属和术语准入时，记为“待人判断”。

分类只判断当前位置与待删除形式的关系，不反向证明术语表定义正确，也不决定应采用哪个替代形式。

## 分类值域

分类值只有以下四种：

| 分类 | 判据 | 处理 |
|---|---|---|
| 字符串误命中 | 检测到的字符不在该位置充当目标形式，例如只属于其他完整写法、代码标识或文件名 | 两轮一致后关闭该位置 |
| 来源陈述 | 句段在准确转述、引用或登记外部来源用语，没有把该形式作为本库自己的概念表达 | 两轮一致后关闭该位置 |
| 实际消费者 | 本库正文或脚本以该形式命名、定义、约束或推理目标概念；删除该形式会使该位置失去已用表达 | 两轮一致后进入迁移提案 |
| 待人判断 | 上下文不足、来源话语与本库话语混合、存在多个合理概念解释，或判断超出代理权限 | 进入人工决策包 |

较长写法不是“字符串误命中”的充分条件。如果较长写法中的目标形式仍承担相同概念作用，应记为“实际消费者”。`sources/` 中的记录也不自动属于“来源陈述”；作者自己的概括、规则或判断仍可能是实际消费者。

## 审查批次

当前身份集可以按文件重新排序，使同一文件的上下文尽量由一个首轮批次连续读取；输出时仍恢复稳定的五列身份顺序。批次数量按实际上下文规模确定，不按七个形式平均切分，也不把“词”的四百三十一条交给单个无检查点的长任务。

字符串长度、是否位于代码中、目录和较长写法只可用于安排先后顺序。批次输入中的“候选分类”和“处理说明”必须为空，禁止由脚本或控制器预填建议。

每个批次原子交付：要么全部身份都有合法分类和说明，要么保持为未合并检查点。不得把半批结果写入汇总表。

## 首轮分类

首轮代理对分配的每条身份重新打开冻结提交中的文件，按分类依据填写“候选分类”和“处理说明”。代理不得修改仓库文件、临时审查表和其他批次，也不得研究或批准替代术语。

控制器合并批次时只按五列身份连接，不允许按行号顺序覆盖。合并后必须证明：身份集与当前交接表完全相同、无重复、无新增、无空分类、无空说明，分类值只来自固定值域。

## 独立复审

复审阶段使用首轮汇总表和同一冻结仓库快照。复审者可以看到首轮分类和说明，但必须重新打开每个位置的实际上下文，并为每条记录填写“复审分类”和“复审说明”。复审不能只检查格式、只查看首轮标为“待人判断”的记录或抽样高频形式。

复审可以分批，但每条记录的复审代理不得是该记录的首轮代理。全部复审批次合并后，再按形式、完整写法和相邻位置检查横向一致性；相同文本可以因语义角色不同而分类不同，但说明必须解释差异。

复审结果保留首轮字段，不回写或覆盖首轮判断。两轮记录共同构成审计追踪。

## 分歧处理

分类结果按以下集合机械分流：

| 集合 | 条件 | 后续 |
|---|---|---|
| 已关闭 | 两轮分类相同，且为“字符串误命中”或“来源陈述” | 不逐条请求人工批准，完整记录仍保留 |
| 迁移提案 | 两轮分类均为“实际消费者” | 汇总文件、位置和说明，等待人工批准 |
| 人工判断 | 两轮分类不同，或任一轮为“待人判断” | 保留两轮意见，不由第三个代理投票决定 |

三个集合必须互斥且并集等于当前全部身份。复审分歧不是失败，也不能通过强制统一来追求通过率；它是需要人工判断的正常输出。

## 形式问题

英文 `term` 是否作为单语形式保留或重新建立，是术语记录层的决定，不能从七十二个位置的数量或分类直接推出。本阶段汇总 `term` 的四类分布、真实消费者上下文和现有直接依据，形成单独的人审问题。

必要新增形式不能由“需要替换”自动产生。候选形式只有按现行译名与术语准入阶梯取得直接形式依据、定义依据和必要的概念对应依据后，才能进入人工决定包；未取得依据时只记录缺口，不给出自造名称。

位置分类、`term` 处理和新增形式是三个不同判断。任何一个结论都不能替代另外两个。

## 人工关口

提交给人的决定包至少包括：

- 两轮一致的实际消费者迁移清单；
- 全部分类分歧和“待人判断”记录；
- 英文 `term` 的位置分布、现有依据和保留或重建问题；
- 每个必要新增形式的直接依据，或明确的查无记录；
- 拟议的最终“基本单位”保留、删除和新增清单；
- 已关闭记录的数量、分类分布和完整审计表链接。

人批准前，迁移清单只是提案，最终“基本单位”清单不生效。人的批准也只覆盖明确列出的项目，不顺带批准其他术语迁移、译名、概念归属或来源改档。

## 数据接口

本阶段保留五类逻辑产物：

| 产物 | 必需内容 | 修改权限 |
|---|---|---|
| 当前交接表 | 五列身份，分类与说明为空；附输入哈希 | 只由当前扫描生成 |
| 首轮分类表 | 五列身份、候选分类、处理说明 | 首轮代理分批填写，控制器按键合并 |
| 独立复审表 | 首轮全部字段、复审分类、复审说明 | 独立复审阶段追加，不覆盖首轮 |
| 批次清单 | 每批身份范围、首轮代理、复审代理、输入与输出哈希 | 控制器追加，用于证明同一记录由不同代理处理 |
| 人工决策包 | 三个分流集合、`term` 问题、新增形式依据和最终清单提案 | 只从已复审全集生成 |

实施计划决定具体文件名，但所有产物都放在新的 Superpowers 执行目录；正式项目目录只保存获批的规格和计划。分类表不得写入 `design/`、`concepts/`、`sources/`、`vocab/` 或 `scripts/`。

## 迁移门禁

本阶段不执行迁移。只有以下条件全部成立，后续迁移计划才可以提交人批准：

- 当前交接身份已冻结，首轮和复审均全量完成；
- 三个分流集合无遗漏、无重叠；
- 迁移提案只含两轮一致的实际消费者；
- 分歧和待人判断均保留，未伪装为已关闭；
- `term` 和新增形式问题具有独立依据包；
- 人明确批准迁移范围和最终“基本单位”清单。

后续迁移完成后必须重新扫描当前文件；旧位置分类不能跨项目文件变更直接复用。新扫描出现的未分类位置必须先经过同样的双轮分类，删除保护才能依据当前且已复审的分类判断。该后续行为不在本阶段实施。

## 失败处理

若冻结后项目文件变化，停止合并新分类，刷新当前身份并判断哪些批次失效。不得只改行号后沿用旧语义判断。

若位置不存在、文件不可读或命中字符串已变化，记录输入失效并回到刷新阶段。若分类说明缺少实际上下文依据，整行退回复核，不用默认分类补齐。

若批次超出可靠上下文范围，缩小后从该批次重新开始；已经原子合并且输入未变化的其他批次保持不动。运行时长不是分类完成条件，完整身份、合法值和可核说明才是。

若复审发现分类值域本身不足以表达真实情况，停止该类记录并回到设计，不临时增加第五种分类。若只是两个现有分类都合理，使用“待人判断”。

## 验证方法

输入至少验证：

- 七个阻断的四列身份与当前三百四十八条审查表精确相同；
- 当前交接的“形式、位置”无重复；
- 当前扫描与历史交接的差异逐项有当前 Git 变更解释；
- 分类开始后，冻结提交和输入哈希保持不变。

首轮至少验证：

- 身份集合与当前交接逐键相同；
- 每行分类和说明完整；
- 分类值只来自四个允许值；
- 没有脚本预填、半批合并或项目文件修改。

复审至少验证：

- 复审身份与首轮身份逐键相同；
- 六百二十三条全部有复审分类和说明；
- 每条记录的复审者没有参与其首轮分类；
- 三个分流集合互斥、完备并可由两轮分类机械重建；
- 人工决策包中的每条记录都能回到两轮原始判断和冻结上下文。

## 权限边界

两轮一致的“字符串误命中”和“来源陈述”可以在 Superpowers 执行产物中直接关闭，不需要逐条人工批准。两轮一致的“实际消费者”只能进入迁移提案。

分类分歧、“待人判断”、英文 `term`、新增形式、最终“基本单位”清单和任何项目文件迁移都由人批准。代理不得以多数票、字符串规则、出现次数、目录位置或来源数量替代人工决定。

本规格不开放零自定例外，不改变正式校验规则，不批准来源改档、草案生效或项目范围变化。

## 验收条件

本阶段完成时，以下条件同时成立：

- 当前六百二十三条输入已经按当前提交刷新并冻结；
- 每条候选都有上下文支持的首轮分类和说明；
- 每条候选都经过独立全量复审；
- 字符串检测没有自动决定任何分类；
- 已关闭、迁移提案和人工判断三个集合精确覆盖全集；
- `term` 和新增形式没有被位置分类替代决定；
- 人收到完整但收敛的决策包；
- 项目正文、术语表、脚本和正式数据没有在人工批准前被修改。
