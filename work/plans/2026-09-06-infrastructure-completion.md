## 完成边界

- 正式术语范围内的每个现行条目都有可追溯去向，不能遗漏、擅自合并、删除或提升效力。
- 形式、定义、概念对应、领域、状态及依据分别表达；模型判断不能冒充外部核实。
- 正式术语数据与生成术语表具备唯一编辑源；原有模型译名登记仍能完整追溯，不凭同名建立术语委托。
- 生成必须经过模式、引用、决定、身份和状态检查；未批准内容不能进入获准视图。
- 出处、适用范围、允许形式和历史形式能被人读懂；代码测试通过不代替展示验收。
- 来源、术语与应用共享接口一致，变更可以定位受影响记录；不为填充状态而创建虚构义务或消费者。
- 临时 vault 完成初始化、刷新、引用及非受管理文件保护验证，形成正式库接入的具体写集和前置条件。

## 并发审查

采用 4 个并发 `gpt-5.6-luna` 任务进行首轮离线审查；用户已明确选择并发小模型，执行时显式指定模型，若不可用则报告并采用可用的小模型或减少并发，不暗中替换成等量昂贵模型。

任务按来源分批，每批约 15–25 行；共同的来源材料只准备一次。每个子任务获得精确条目、上下文、离线原文位置和现行准入规则。子任务不得修改正式数据、采纳决定、规则或主实现，也不得自行联网或下载资料。

每个结果包含原条目标识、原值、原文路径与定位、对应摘录、形式依据、定义依据、中英对应判断、建议拆分或保留、未解决问题。没有原文时填写“未取得原文”，不得补造出处、核对日期或批准状态。

## 验收证据

预计投入 2–3 小时。每项执行前说明失败、后果与独有证据。新增行为测试放入现有相应测试文件；静态记录、文档与确定性生成物直接校验。

| 失败 | 后果 | 必要证据 |
|---|---|---|
| 输入条目漏迁、误合并或身份重分配 | 原有知识和引用丢失 | 冻结输入与采纳清单、正式数据逐项差异，稳定身份比较 |
| 未批准值进入正式视图 | 机器替人做出准入决定 | 未采纳或不覆盖该值的决定、非法首次准入、身份搬动及删除的负例均被入口拒绝 |
| 生成绕开校验 | 错误正式数据产生貌似正常输出 | 从真实 CLI 注入坏引用或状态，确认失败且输出未被改写 |
| 名称、出处、模型依据在展示中丢失 | 读者误解内容或把未核事实当已核 | 代表性真实条目的生成对照，覆盖多概念拆分、同义、多语言及模型依据 |
| 索引漏掉术语引用或引用旧审计值 | 后续修改无法定位实际影响 | 真实术语的来源与决定反查结果、审计排除结果 |
| 生成随运行变化 | 版本差异无法解释 | 同环境同输入两次重建逐字节一致，并核对漂移检查 |
| 刷新越界或破坏已有引用 | 用户内容、配置受到损害 | 临时 vault 中含用户内容与配置的前后哈希、旧新链接检查、并发修改拒绝行为 |
| 应用读取的提交与验收不同 | 已测结果不能覆盖正式接入 | 干净 worktree 的提交 ID、临时运行记录与接入 dry-run 使用同一提交 |
