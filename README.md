# 新的 KB 设计

在这里设计自己的知识体系，包含方向和维护治理。

## 它为什么会出现在这里

比较干净，不会被现有的知识带向已知的盲区，也不会被现有的知识误导；这是经历几次失败的教训。

## 打算如何设计

不限制 AI 的发挥，尽情地设计，以达到最好的效果，当然也不能制造误导和错误。

已有的规范和事实标准是最好的设计来源和依据。

## 边界

本库只有研究、概念、设计和词表数据。知识库本身——笔记、内容——不在这里，在别处；它的形态首先是 Obsidian，以后可能是 DITA，也可能是其他。

正式知识库位于仓库外的 ~/Documents/kb-vault/，本仓库维护模型、规则、词表和应用工具。AI 检查和验证知识库时优先使用 Obsidian CLI，仅在检查界面显示或交互时使用 Computer Use。

因此设计分两层：

| 层 | 内容 | 在哪 |
|---|---|---|
| 形态无关 | 概念、词表、内容模型、导出与回流的规则 | `concepts/`、`design/`、`vocab/` |
| 形态相关 | 每种执行形态一篇映射：内容模型的字段落到什么、词表怎么导出、链接怎么表达 | `design/targets/` |

形态无关层不提任何工具的字段名和文件格式；形态相关层不改动形态无关层的定义。词表数据 `vocab/` 是源，各形态从它导出，不反向编辑。
