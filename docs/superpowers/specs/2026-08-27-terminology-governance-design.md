# 术语治理设计

状态：待批准。

本文是 Superpowers 设计规格，记录术语治理重写的目标、边界和架构。它不是本项目的设计正文，不使 `design/` 中的规则、`design/drafts/` 中的草案或任何词表数据生效。本文获准后，实施步骤另写入 `docs/superpowers/plans/`；项目自己的概念文、来源笔记和设计文仍按各自目录的职责整篇重写。

## 文档边界

本文只回答要解决什么、采用什么架构、各对象如何分工、哪些条件必须成立。逐文件处置、迁移批次、脚本接口、测试命令和提交顺序不属于本文，留给获准后的实施计划。

Superpowers 的审查过程不写入项目设计正文。项目确需长期保存的术语检索、来源复核和批准记录，由项目治理另行批准审计记录的格式和位置；在此之前，审查意见保留在评审对话和本规格的修订历史中。

## 设计目标

术语治理完成后，项目能够从正式记录回答以下问题：

- 一个术语表示哪个概念；
- 两种语言的术语是否有依据表明它们表示同一概念；
- 术语、定义、译名和人工断言分别依据什么来源及位置；
- 一个术语当前是优先使用、允许使用、已经废弃还是已经被替代；
- 一条记录处于登记、复核、批准、废弃或维护的哪个阶段；
- 一个来源变化后，哪些当前断言、派生关系和映射关系必须复核；
- 术语表、其他词表标签和正文是否仍与获准记录一致。

文件格式本身不构成治理。唯一编辑位置、概念身份、逐项依据、状态转换、决策权限、历史、来源维护、确定性生成和校验共同构成治理。

## 工作范围

本轮设计覆盖用户确认的全部工作，不把低优先级项目从范围中删除：

- 翻译与术语依据审查；
- 术语登记、依据、复核、批准、废弃和维护；
- `basis`、`source`、`match` 和旧 `origin` 的边界；
- 来源复核、链接检查、新版探测和替代来源；
- 首轮候选、`unassigned` 和 `self` 断言维护；
- 划分特征、分面字段和手工概念组三份草案；
- 生活领域、实体类别、大语言模型归属和技术传播等待定设计。

Obsidian 应用映射、应用导出和 TBX 导出不在本轮实现范围。它们都以内部模型和项目设计稳定为前提。

## 优先关系

优先级表示依赖关系，不表示是否执行：

| 阶段 | 工作 | 完成条件 |
|---|---|---|
| 基础治理 | 翻译与术语依据、术语准入、断言边界、来源维护、首轮维护 | 概念依据、记录职责、状态、权限、失效处理和校验边界已经获准 |
| 草案复核 | 划分特征、分面字段、手工概念组 | 每份草案逐项核对外部概念、项目用途和生效条件 |
| 范围补充 | 生活领域、实体类别、大语言模型归属、技术传播等 | 每项形成独立提案，并按现行决策权处理 |
| 应用实现 | Obsidian 映射、项目导出、TBX 交换 | 与应用无关的模型已经稳定，相关草案已经单独获准 |

基础治理内部先确定术语与断言的身份和依据，再确定来源变化如何传播，最后用首轮真实维护校准本地阈值。三份草案不得反过来为尚未确定的术语、来源或断言规则提供事实标准。

## 概念依据

本规格只采用官方公开页面能够确认的范围。收费标准中尚未核对的条款，不写成条款级断言；实施前须在 `sources/` 中记录实际阅读范围、版本和未读部分。

| 来源 | 已核范围 | 本设计用途 |

| [GB/T 20001.1-2024](https://std.samr.gov.cn/gb/search/gbDetailed?id=14156507D1FC0337E06397BE0A0AE656)、[ISO 10241-1:2011](https://www.iso.org/standard/40362.html) | 国家标准页面确认非等效采用；ISO 页面说明其适用于单语和多语术语条目的起草与结构 | 术语条目内容与多语条目边界；不从采标关系推断逐条等同 |

| [PROV-O](https://www.w3.org/TR/prov-o/) | W3C Recommendation 区分派生、修订、第一手来源和失效 | `source` 的派生语义及来源变化边界 |

外部来源只支持概念边界。YAML、文件路径、必填数量、状态转换、批准权限、复核期限和发布阻断条件都是本地设计，必须明确标为项目决定，不得写成标准的直接要求。

## 方案取舍

内部编辑源有三种可行方向。选择依据是本库已经采用的 Git 审查、离线校验和生成流程，不是外部标准对文件格式的要求：

| 方案 | 收益 | 约束 | 结论 |
|---|---|---|---|
| 直接编辑 Markdown 术语表 | 阅读直接，现有文件可以沿用 | 概念、语言、术语、状态和逐项依据难以稳定校验；正文视图与治理数据混在一起 | 不采用 |
| 直接编辑 TBX XML | 交换结构明确，可以使用方言验证材料 | 目标方言、扩展和信息损失尚未设计；把交换约束提前带入内部编辑 | 后置为交换物 |
| 编辑 YAML 并生成视图 | 差异可审查，模式和引用可离线校验，可以生成 Markdown 并为将来 TBX 保留语义 | 需要独立模式、生成器和迁移 | 采用 |

采用 YAML 不表示 XML 不可治理，也不表示内部记录已经符合 TBX。治理能力来自模式、依据、状态、权限、历史、复核和发布约束。

## 表示架构

术语治理采用一个编辑源和多个只读用途：

```text
外部来源与项目决定
          │
          ▼
  YAML 正式编辑源 ──▶ Markdown 术语表
          │
          ├────────▶ 校验与审计报告
          ├────────▶ 将来的 TBX 交换物
          └────────▶ 将来的应用映射与导出
```

术语数据库的预定正式编辑源是 `vocab/terms.yaml`。它保存概念身份、各语言术语、逐项依据、状态、复核义务和历史，并接受模式与引用校验。`concepts/glossary.md` 改为从获准记录确定性生成的读者视图，不再直接编辑。

内部结构按概念、语言和术语分层，以保留将来转换为 TBX 所需的语义。内部 YAML 不复制 TBX 的 XML 标签，也不宣称符合某一 TBX 方言。TBX 文件只能在独立交换设计获准后，从发布快照单向生成；本阶段不设计导入和往返编辑。

其他词表继续以各自的 YAML 为正式编辑源。现有生成脚本是否退出正式写入流程，必须在实施计划中通过基线复现、差异检查和独立提案决定，不能由本规格直接停用。

## 数据边界

术语数据库只收入需要独立治理概念身份、多语形式或术语状态的记录，不默认复制主题词表、命名实体词表和枚举词表的全部标签。

同一概念在同一语言中的全部术语只能有一个正式编辑位置；写法相同但表示不同概念的同形异义词分别治理。某个既有词表把一个概念在一种语言中的术语交给术语数据库管理前，必须先证明两条记录表示同一概念，并列出全部引用和生成影响。未建立这种委托时，标签留在原词表，但仍使用统一的译名、逐项依据和状态规则。

术语记录至少表达以下语义，具体字段和基数在项目设计中确定：

- 稳定的概念身份、适用领域和定义；
- 以 BCP 47 标签区分的语言组；
- 每个语言组中的术语及其管理状态；
- 概念对应、定义和每个术语各自的来源与定位；
- 项目工作流状态、批准、复核、替代和只追加历史。

概念记录的工作流状态与术语的管理状态是两类状态。概念获准使用，不表示它的每个旧术语都优先使用；一个概念可以在现行状态下同时保存优先术语、允许术语和历史术语。

`unassigned` 只用于已经收入主题结构、但尚未用于标引的概念，不用于术语、来源或批准记录。`candidate` 不是自造术语的试用区；当前零自定政策下，没有外部依据的词不进入正式候选数据。

## 治理流程

术语记录采用完整生命周期：

1. 登记需要治理的概念或形式，并保存发现范围。
2. 检索外部来源，逐项记录查到、未查到和冲突结果。
3. 建立有概念、定义、各语言术语和精确定位的候选提案。
4. 校验身份引用、语言标签、状态条件、重复形式和来源可用性。
5. 复核概念一致性、定义范围、形式选择和多语对应。
6. 按项目决策权批准或否决；批准记录进入正式编辑源。
7. 从正式记录生成术语表并检查正文。
8. 来源、概念或用法变化时复核；不再使用的记录保留历史并建立替代关系。

检索、抓取、整理和校验可以自动化。概念对应、译名采用、术语优先级、术语准入、废弃和替代仍按项目现行决策权处理。自动化结果只能形成提案或报告，不能自行写成批准结论。

复核过程需要只追加的批次记录，以保存未采用来源、冲突和人工决定。其正式路径、标识和提交关联在项目设计中决定；在该设计获准前，不把临时审查文档放进 `design/`。

## 译名治理

译名治理以同一概念的多语术语为对象，不以字符串替换为对象。每个术语需要自己的来源和定位；把两种语言的术语放进同一概念，还需要能够支持概念一致性的依据。

实施开始时先审查现行译名阶梯，逐级确认来源资格、停止条件、冲突处理和“不译”结果。审查至少遵守以下边界：

- 标准的采标关系不能代替具体术语条目的逐项核对；
- 修改采用或非等效采用不能推出中外文术语逐项等同；
- 出版者、机构和厂商的双语形式只支持其明确指向的同一对象或概念；
- Wikidata 和机器检索可以发现候选，不能自动批准概念对应；
- 机器翻译、拼写相似和搜索结果数量不能作为译名依据；
- 简体与繁体形式分别记录，来源只支持一种文字体系时不自动生成另一种；
- 没有足够依据时不译，正文保留有依据的原语言术语，并给出有来源的中文定义或解释。

现有 `basis` 中的 `source`、`none`、`self` 和紧缩来源字符串必须逐项审查，不能机械改写成看似精确的新结构。历史上已经删除的自译形式也要保留原复核材料，不反向改写旧决定文件。

正文和标题最终只使用获准术语。缺少某种语言术语时的标题和首次出现规则，需要与 `design/writing.md`、`concepts/CONVENTIONS.md` 一并提案；本规格不提前修改现行写作规则。

## 断言边界

四个既有字段必须回答不同问题：

| 字段 | 回答的问题 | 引用目标 | 不能代替 |
|---|---|---|---|
| `basis` | 当前这个具体值为什么成立 | 来源实体和可重复定位的位置 | 派生关系、概念映射、本地批准 |
| `source` | 当前记录或结构从哪个外部对象派生 | 获准来源登记中的具体条目 | 普通参考材料、概念等同、人工判断依据 |
| `match` | 本地概念与哪个外部概念具有哪种映射关系 | 外部概念和 SKOS 映射关系 | 标签、范围、层级或归属的依据 |
| `origin` | 现有设计中含义不一致 | 暂不新增使用 | 不继续作为一个含义模糊的通用来源字段 |

`basis` 必须与被支持的值相邻或能由模式唯一定位，并至少保存来源实体和定位。裸网址、来源名称自由文本、`self` 和没有位置的标准号不能成为获准断言的完整依据。外部依据证明一个值，项目批准记录证明项目允许采用它；两者不得互相冒充。

`source` 只表示实际派生。综合多份材料形成的本地记录不选择一个材料伪装成唯一派生源，而由各个值的 `basis` 分别说明。PROV-O 的修订、第一手来源和失效具有比日常用语更严格的含义，只有满足相应条件时才建立对应映射。

`match` 必须根据两个概念的定义和范围判断。标签相同、译名相同或外部条目存在，都不能自动证明 `exactMatch`。

旧 `origin` 在实施前先做全库清单，再按实际语义分别迁移到候选发现记录、逐值 `basis` 或派生 `source`。字段变更属于项目结构提案；清单和逐项去向进入实施计划，不在本规格中直接改数据。

## 来源维护

来源实体与来源用途分开治理。来源实体回答材料是什么、哪个版本、当前地址、何时核过、是否被替代或失效；来源名称规范表回答某个外部知识体系获准用于映射、结构复制、派生视图或候选发现中的哪些用途。

来源用途和生命周期状态必须分开表示，不能让同一个值既表示“候选发现用途”，又表示“尚未批准的记录”。一个用途获准，不自动批准同一来源的其他用途。

现有 `tier` 同时承担来源权威性、用途资格和复核周期，实施时必须拆开审查。是否保留、拆分或替换这个模式字段属于 L2 规则与结构提案；获准方案导致某个既有来源改变档位时，该来源的改档仍由人作 L3 决定。本规格只登记问题，不预先决定字段和各来源的去向。

来源维护分成两类检查：

- 离线校验检查记录结构、状态、日期、替代目标、反向引用和发布阻断条件；
- 联网探测检查链接、重定向、版本标识、修订状态和内容变化信号。

联网探测只生成复核材料，不更新正式数据，不把网页可访问等同于内容仍支持当前断言。链接存活与内容有效必须分别记录。

来源变化通过反向引用触发复核：

- `basis` 引用变化时，复核被支持的具体断言；
- `source` 引用变化时，复核派生值、外部条目标识和结构；
- `match` 引用变化时，重新比较两个概念的定义、范围和关系；
- 只有地址改变、来源身份与内容未变时，才按现行 L1 规则更新地址。

来源失效不自动改写断言，也不自动废弃概念。系统先建立可查询的复核义务；复核确认仍受支持时更新依据和日期，确认不再受支持时按批准流程修改或废弃当前断言，并保留历史引用。

## 首轮维护

首轮维护使用执行时重新生成的指标，不沿用规格中的静态数量。基线至少包括候选、`unassigned`、`self` 断言、来源复核状态、未登记术语候选和现有译名决定。

处理顺序如下：

1. 先处理违反现行硬规则的状态与依据组合，阻止新的无依据记录进入现行状态。
2. 再复核候选的概念身份、用途、引用和依据，不按存续时间自动批准。
3. 再检查 `unassigned` 是否仍准确表示范围内的未标引概念，不以减少数量为目标。
4. 再处理 `self` 断言，能找到外部依据的逐项替换，找不到的保持非现行状态或交人决定。
5. 最后根据真实工作量、误报、漏报和处置结果，提出现有阈值的校准方案。

候选删除、范围缩减、`self` 例外和阈值变更继续按现行决策权处理。首轮维护不能借“清理”删除盲区记录或历史记录。

## 草案复核

三份草案在基础治理完成后分别复核，不合并成一个生效决定：

| 草案 | 概念核对 | 生效前提 |
|---|---|---|
| 划分特征 | ISO 25964 的数组、节点标签和划分特征；外部分类方法与本地分析的边界 | 明确术语来源、登记对象、成员约束、复核和零自定例外；人作 L3 决定 |
| 分面字段 | 分面分析、元数据字段和叙词表组织的差异 | 真实内容样本证明查询需求，值域有外部依据，字段不与现有实体和概念组重复；人作 L3 决定 |
| 手工概念组 | 概念组、SKOS 集合、叙词表数组和映射派生视图的差异 | 用途、成员来源、生命周期和生成规则明确，不能由现有映射自动得到；人作 L3 决定 |

复核结论可以是继续保持草案、整篇重写或提出废弃。规格获准不等于三份草案获准生效。

## 文档分工

实施阶段按以下职责写文档：

| 位置 | 单一职责 |
|---|---|
| `docs/superpowers/specs/` | 已讨论的设计规格和边界，不作为项目现行规则 |
| `docs/superpowers/plans/` | 规格获准后的逐步实施计划、验证和提交边界 |
| `concepts/` | 外部概念是什么、为什么适用，不写项目字段和参数 |
| `sources/` | 实际读到的来源、版本、条款、页面和未读范围 |
| `design/` | 已获准的项目规则，按参考文档写法陈述 |
| `design/drafts/` | 尚无依据或尚未生效的项目设计，明确触发条件 |
| `vocab/` | 正式数据、历史、指标和获准后的审计记录 |
| `scripts/` 与测试 | 生成、校验、探测和正反例，不以实现补写规则 |

项目文档的重写必须先列旧节去向，再按文档目的整篇重写并逐项核对。旧节去向、文件清单和迁移顺序属于实施计划，不写进新的项目设计正文。

## 决策边界

本规格是 L2 设计提案，不是 L3 生效决定。它获准后只允许编写实施计划，不自动授权修改项目规则、文件结构、词表模式、来源档位或草案状态。

实施计划必须把下列关口分开：

- 新概念文、设计文、模式和术语准入先给 L2 改动说明；
- 范围、来源改档、零自定例外、草案生效和发版单独交人作 L3 决定；
- 每个决定只授权列明的文件和对象，不用一次总批准覆盖后续未知判断；
- 项目设计未获准前，样例数据、脚本和生成物不得进入正式编辑源；
- Obsidian 映射和 TBX 导出在各自前置条件满足后另写规格。

## 验收条件

术语治理设计完成时，以下条件同时成立：

- 术语、定义、译名、概念对应和人工断言都有可重复定位的依据，或明确保持未获准状态；
- 同一概念在同一语言中的全部术语只有一个正式编辑位置，生成视图不产生记录中不存在的术语或状态；
- 术语记录、其他词表标签和正文使用同一套获准术语规则；
- `basis`、`source` 和 `match` 的模式、引用目标、证据要求和失效处理互不混用；
- 来源实体、来源用途、生命周期和复核义务可以分别查询；
- 来源变化能够列出受影响记录，探测工具不能自动批准或改写正式数据；
- 候选、`unassigned` 和 `self` 的首轮维护有基线、逐项结论和阈值校准记录；
- 三份草案和其他待定项都有独立结论或明确保留理由；
- 项目文档按目录职责整篇重写，旧内容逐项有去向；
- 离线校验、确定性生成、反向引用检查和正反例测试覆盖已经生效的规则；
- Obsidian 映射和 TBX 导出仍保持后置，没有绕过内部设计直接实现。

## 待定事项

本文获准后才编写实施计划。计划需要列出逐文件重写顺序、旧节去向、数据迁移批次、测试先后、复核检查点和提交边界，但不得把尚需 L2 或 L3 判断的内容预写成既定结论。

内部模型、来源维护和首轮维护完成后，再分别提出 TBX 交换设计与 Obsidian 应用映射。两者不合并：TBX 解决术语资源交换，Obsidian 映射解决内容模型和词表在应用中的落点。

其他待定项分别提案，不在术语治理重写中顺手决定：

| 事项 | 先核对象 | 决策边界 |
|---|---|---|
| 生活领域 | 知识库范围、顶层学科和排除项 | 改变范围由人作 L3 决定 |
| 实体类别 | 外部类别、实例判据和现有记录影响 | 新类别与归属判断按 L2；具体来源改档另按 L3 |

| 技术传播 | 学科范围、专业实践、内容类型和现有传播学节点 | 先补概念依据，再按是否改变范围确定 L2 或 L3 |

每项提案都要说明外部概念、项目问题、受影响文件和不采用时的后果。没有足够依据时保持待定，不造一个临时类别或术语占位。
