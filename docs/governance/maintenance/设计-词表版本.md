# 词表版本

稳定标识确定对象身份，版本确定采用该对象当时的哪些描述。本专题规定版本固定、引用、历史读取、发布和回退；变更过程见[词表维护](../../model/vocabulary/设计-词表维护.md)，记录字段见[数据规范](../../model/vocabulary/设计-词表数据规范.md#维护记录)。

## 版本对象

来源、自有词表和语言展示分别标识版本，通过明确关联确定一次交付所用的数据。

| 对象 | 固定内容 | 关联要求 |
|---|---|---|
| 来源快照 | 来源身份、上游版本、取得记录及内容摘要 | 缺少上游版本时如实记录；不同取得内容可区分 |
| 自有词表 | 来源选择、编辑、名称登记、组织规则、依据和结果 | 能定位实际采用的来源版本及规则版本 |
| 语言展示 | 词表基准、译文、名称登记、语言选择及适用性记录 | 明确对应的词表版本，消费者记录实际加载版本 |

数据规范版本、工具版本和构建标识分别保留，不替代内容版本。版本标识与历史记录参考 [W3C 数据发布最佳实践](https://www.w3.org/TR/dwbp/#dataVersioning)；上述三类版本职责是[项目选择](../../model/vocabulary/决定-词表维护约束.md)。

## 版本标识

每个发布版本必须可唯一定位，并能核对其内容完整性、来源、规则及发布记录。当前入口可以指向不同版本，但不能充当不可变的历史版本标识；版本说明文字也不能独自证明文件或数据未被改写。

已发布版本不得原地修改。即使只修订名称、范围说明或映射，形成新交付时仍须保留新版本及差异；新构建与治理发版分别满足其条件。版本号格式、存储方式、完整性证据及文件清单等由适用交付合同规定；版本模型本身不要求所有数据都以一套文件交付。

## 引用方式

引用按用途明确身份和版本，具体字段及载体由相应 Application Profile 表达。

| 用途 | 必须确定的信息 | 读取规则 |
|---|---|---|
| 普通主题标引 | 概念稳定标识 | 默认读取当前描述；退出时提示，不自动替换标记 |
| 历史含义或关系论述 | 概念标识、所引词表或来源版本 | 读取指定版本，不用当前内容冒充历史描述 |
| 名称或译名论述 | 名称标识及文字版本；涉及角色时还有概念和角色 | 读取相应文字、依据和用法，不能只保存显示字符串 |

标引对象当时的含义若影响论述，应使用带版本引用。身份稳定不保证各版本的范围和关系相同，也不保证旧引用无需处理。

## 历史读取

未指定版本时先查当前词表。保留停用记录时返回该记录及提示；当前不再收录时，通过发布记录定位最近一个包含该身份的历史版本，显示版本、已知退出原因及有依据的后继对象。无法唯一定位时列出可用版本，缺少原因时明确未记录，不按目录或名称猜测。

指定版本时只读取该版本；记录或版本不可获得时明确报告，不能静默改读当前版本。历史对象不自动恢复为可标引对象，多个后继也不默认展开成全部新标记。不同退出事件按[概念退出](../../model/vocabulary/设计-词表维护.md#概念退出)处理。

历史定位应有稳定的版本关联与读取约定；保存了文件不等于可正确读取旧引用。清理历史前核对依赖和影响，并按相应权限取得决定。

## 发布与回退

发布使用已完成具体采用与[统一校验](../../model/vocabulary/设计-词表数据规范.md#校验范围)的结果，固定来源、项目输入、名称登记、译文及适用规则的版本。读取多份数据时选择完整相容的一组，避免把不同版本的概念、名称、译文和依据混成同一结果。

| 环节 | 版本要求 | 记录职责 |
|---|---|---|
| 发布 | 固定被检查和采用的内容，保存不可原地改写的版本 | 发布记录关联变更及相应决定，摘要引用既有维护事件 |
| 切换入口 | 明确切换到哪个完整版本；失败保留可用版本 | 切换结果可核对，工程成功不自动取得治理发版权限 |
| 应用加载 | 消费方记录实际读取的词表和相容展示版本 | 分别报告成功、失败及版本落后，不以一个副本成功推定全部一致 |
| 回退 | 选择完整既有版本及其相容展示，不拼接旧词表与新译文 | 保留后续身份分配和决定历史，版本快照说明实际包含的记录 |

编辑、发布、入口切换和应用加载分别留痕；字段合同见[维护记录](../../model/vocabulary/设计-词表数据规范.md#维护记录)。回退不重用名称身份，不撤销后续采纳或改写历史决定。变更原因来自实际维护记录，名称、日期或哈希差异本身不能解释含义变化。
