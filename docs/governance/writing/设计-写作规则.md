# 写作规则

本库所有 Markdown 文件的写作规则，按 ISO 24495-1 的 4 条原则组织：相关、可找到、可理解、可使用。每条规则标出处；没有出处的规则不收。理论见[写作规范](概念-写作规范.md)，依据的整理见[写作规范阅读笔记](阅读-写作规范.md)。

`AGENTS.md` 是本文的摘要。designation 的准入与译名规则以[治理](../decision-making/设计-治理.md)为准；术语概念、定义和形式由 `data/vocab/terms.yaml` 管理，`docs/参考-术语表.md` 是只读生成页。主题、载体及模型标签输入保留各自的编辑权，详见[术语设计](../../model/terminology/设计-术语.md)。

## 文档类型

文档按其回答的问题和承担的职责分类。同一主题内的概念、设计、依据、决定与提案分别成文，由索引关联；类型不替代批准状态。

| 类型 | 职责 | 文件前缀 |
|---|---|---|
| 概念解释 | 解释含义、机制和适用边界，项目选择链接现行设计 | 概念- |
| 设计正文 | 规定项目当前的对象、关系与规则 | 设计- |
| 决定记录 | 保存背景、方案选择、状态和后果 | 决定- |
| 阅读笔记 | 保存来源事实、实际阅读位置和核对范围；个人判断独立标明 | 阅读- |
| 项目提案 | 说明待议问题、方案及生效条件 | 提案- |
| 导航索引 | 按问题指向相关正文，说明收录范围，不复制动态进度 | 索引- |
| 项目概述 | 说明由来、目标、范围和阅读主线 | 概述- |
| 操作指南 | 帮助完成具体任务，说明条件、步骤和可核对结果 | 指南- |
| 术语参考 | 汇集已登记名称、定义和依据，供查阅 | 参考- |

目录按项目主题组织，文章职责与效力分别识别。“未生效”是状态，“生成”是产生方式，两者均不作为文件类型。前缀不使不合格依据、未采纳提案或 schema 记录取得授权。

## 文件命名

全部 docs Markdown 文件使用“类型-名称.md”，名称取现有文章标题的中文部分，去掉括号中的英文对照。前缀已经表达的“设计”“决定”“草案”“阅读笔记”等字样不重复，例如《术语设计》使用“设计-术语.md”，《原样复制与本地分析分层的决定》使用“决定-原样复制与本地分析分层.md”。标题正文不因文件前缀而改变。

项目明确保留英文的名称继续沿用，包括 Application Profile 和 Reproducible Builds；不得为文件命名另造译名。文件名中的斜杠等路径分隔符用连字符替代；混排保留字间空格，Markdown 链接中的空格写为 %20，中文可直接书写。

主题首页使用“索引-主题名.md”，根入口为“索引-项目文档.md”。索引不依赖 README 自动展示，访问入口由明确链接提供。项目概述使用“概述-项目.md”，开发指南使用“指南-开发.md”，生成术语表使用“参考-术语表.md”。此命名规则不改变内容单元 type 词表。

现行链接和工具入口随文件名更新；既有决定、正式数据与执行历史中的路径按原基线及明确迁移关系解释。决定的中文显示名与原机器读取分组分别保存，重命名不扩大来源或术语采纳。术语参考页仍由生成器维护，人工只修改其既有编辑源。

具体采纳见[文档类型命名](../decision-making/决定-文档类型命名.md)。

## 表达规则

| 规则 | 出处 |
|---|---|
| 一般 designation 按治理的来源阶梯检索并在其现行编辑源登记；无依据时不由 AI 自定。既有概念的译名可按已开放的第 5 级使用模型既有知识，明确记录模型判断及外部用法未核实；不据此创造概念、类别或划分特征 | 本库；[治理](../decision-making/设计-治理.md#译名)、[模型知识译名](../../model/terminology/决定-模型知识译名.md) |
| 同一概念全库一种写法；英文术语首次出现时中文后括号给英文，此后只用中文；单篇长度不设上限，由“一篇一个问题”约束 | 受控词表；Google word list 的做法 |
| 中文句子用全角标点；整句英文用半角 | GB/T 15834 §4 |
| 引号用“ ”，内层‘ ’；不用 `「」` | GB/T 15834 §4.8 |
| 补充说明用全角圆括号（ ）；方括号、六角括号、方头括号按 §4.9 的用途 | GB/T 15834 §4.9 |
| 破折号——、省略号……各占两字位 | GB/T 15834 §4.10、§4.11 |
| 连接号：号码和复合词用短横线-；起止用一字线―或“至”；数值范围用浪纹线～ | GB/T 15834 §4.13 |
| 汉字与西文字母、数字之间加一个半角空格；西文或数字与全角标点之间不加 | clreq §6.3.3（间距不超过四分之一汉字宽，空格为 Markdown 中的实现） |
| 第二人称“你”，不用“我们” | Google highlights |
| 主动语态，说清谁在做 | Google highlights |
| 句首大写（sentence case），不用 Title Case | Google、Microsoft |
| 英文并列用序列逗号 | Google、Microsoft |
| 去掉弱写法；不用口语强调语（“一句话”“说白了”“其实就是”），直接陈述 | Microsoft top 10；Google 的 conversational but not frivolous |
| 外部事实核对原文后才提交；本阶段只用已有离线资料，不联网或新增下载，未核实事实如实标明。经授权的译名第 5 级按模型知识登记，明确外部用法未核实 | 本库；[模型知识译名](../../model/terminology/决定-模型知识译名.md)、[语言依据结构](../../model/terminology/决定-语言依据结构.md) |

结构化语言依据中的第 5 级必须在可读表示中保留模型知识及外部用法未核实的声明，不能只显示译名或把判断当外部引文。术语中英形式在 `data/vocab/terms.yaml` 登记；主题与载体的采纳输入保留原编辑权。

形式依据、概念对应依据和具体断言依据分别核对，任何一项都不能替代另一项。普通叙述、来源转录、文件路径、代码和值中的字符串不因首次出现自动成为项目采用的名称；`candidate`、`defer`、草案、占位、示例、schema 状态和迁移去向也不能取得试用资格。

`uv run kb-core check-terms` 从 Git 中取得动态 Markdown 清单，检查标题、加粗内容和中文引号，排除代码围栏、行内代码、链接目标和路径；默认与 `docs/参考-术语表.md` 及现行主题、实体、类型词表中的已登记写法比较。输出保留精确位置和上下文，只是 `report-only` 人工复核材料。命中不形成 designation、概念、关系、违规、阻断或候选记录；人工拟采用某个命中时，仍须走现行准入阶梯。

`data/audit/migrations/term-v1/terms.tsv` 只继承冻结审查与消费者去向，不是术语词表。正式术语记录与参考发布按已采纳决定启用；义务、委托和草案中的未来周期不因数据或生成能力存在而生效。

划分特征草案提出的零自定例外尚未开放；已开放的模型知识译名只作用于既有概念的语言表示。草案中的属性名在实际采用前仍须按治理规则由人决定。

## 使用条件

| 规则 | 出处 |
|---|---|
| 参考类只陈述；解释类才讨论 | Diátaxis reference、explanation |
| 条件放在指令前面 | Google highlights |
| 表格前用完整句子说明用途；表头简短、不以标点结尾；不合并单元格；只有一行或一列不用表格 | Google tables |
| 示例用代码块，不用文字描述“形如……” | 本库，由“可使用”推出 |
| 日期用 ISO 8601 | Google highlights（日期无歧义） |

## 写作过程

以下规则管写作过程；依据是本库实践及用户明确采纳的内容要求，同步摘要到 `AGENTS.md`。

- **内容先于篇数。** 写作前明确读者要解决的问题、相较原始资料新增的价值，以及适用的文档类型；说不清楚就不建文章。正文必须履行该类型的要求，不得用泛泛建议冒充操作指南。
- **组织依据明确。** 优先使用现有主题、实体、文档类型和载体组织内容。索引必须有明确的收录范围和查找依据。现有模型不能表达需求时，先提出设计缺口，不临时创造分类。
- **入库前审阅。** 分别检查内容价值、类型符合性、组织合理性和元数据有效性。字段校验通过不能代替前三项。批量写作先完成一篇样稿及索引示例，经用户确认后再扩展。

- 改文章不打补丁。改动涉及一节以上时，整节或整篇按目的重写
- 重写或拆分前，先列旧版逐节去向；写完逐项核对，确认没丢
- 重写是发现空缺的手段：补丁掩盖的缺口在重写时暴露，暴露了就补
