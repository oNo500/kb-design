# 术语治理

状态：草案，未整体生效；已单独采纳的实施结构见[术语实施范围](../decisions/term-infrastructure-scope.md)。

## 草案边界

本草案以[术语数据库](../concepts/terminology-database.md)为概念前置，说明术语概念、多语形式、依据、状态、委托和生成视图的职责。2026-09-06 的[术语实施范围](../decisions/term-infrastructure-scope.md)已单独采纳三层结构、领域与章节分离、旧登记保留、模型译名生成边界和 Obsidian 术语概念页合同；未采纳部分仍须按本文生效条件决定。

三层 schema、状态转换、348 条历史审查继承账本、正文诊断及维护索引已建立；本次继续补齐完整采纳校验、生成与应用读取。历史账本是审计材料，本次实际登记范围以[冻结清单](../../work/reviews/2026-09-06-term-inventory.json)为准，不按旧 348 条数量生成正式对象。

仓库仍不存在正式 `data/vocab/terms.yaml`、正式术语义务或切换状态，`docs/glossary.md` 继续保持现行编辑权。具体名称、定义、概念对应、状态、身份分配、委托、消费者、切换与发版不会因工具或测试存在而获准。

共享外部 `basis`、`source` 和 `match` 复用已完成的[来源 v2 收尾](../decisions/source-completion.md)。旧的“来源正式数据尚未完成”描述已不适用；来源完成仍不替代具体术语准入。旧登记及未核材料保留原效力与明确限制，不转换为已核外部事实。

## 对象边界

本草案拟管理的对象按下表区分。对象职责仍是草案规则；schema 只证明机器记录可以表达这些层次。

| 对象 | 拟议职责 | 不承担的职责 |
|---|---|---|
| 术语概念 | 保存稳定概念身份、定义、适用学科、多语内容、工作流和历史 | 不以某个字符串充当概念身份 |
| 语言记录 | 按语言组织同一概念的定义和术语 | 不证明不同语言的形式必然对应 |
| 术语记录 | 保存一种语言中的一个具体形式、管理状态、依据和替代目标 | 不单独决定概念状态 |
| 生成视图 | 从获准记录呈现术语表和受委托标签 | 不成为编辑源或批准记录 |
| 委托标签 | 让其他词表引用术语概念中的获准形式 | 不复制术语编辑权，也不自动建立概念对应 |
| 复核义务 | 记录触发、目标、结论、决定和状态 | 不自动修改目标对象 |

未来术语数据只收入需要独立治理概念身份、多语形式或术语状态的记录，不默认复制主题词表、命名实体词表和枚举词表的全部标签。定义、适用学科、形式依据、跨语言概念对应和具体断言分别核对；其中一项有依据不能替代另一项。

普通叙述、来源转录、文件路径、代码和值中的字符串不因出现而自动成为项目术语。候选、草案、`defer`、迁移分类、报告命中、示例和模式状态都不能替代[治理](../design/governance/governance.md#准入对象)规定的准入依据。

## 记录层次

`schemas/terms-v1.schema.json` 已固定 `schema`、`version` 和 `concepts` 三个顶层键，并固定概念、语言和术语三层候选记录。概念层保存共享身份、定义、适用学科、工作流和历史；语言层组织允许语言；术语层保存具体形式及管理状态。

候选概念和术语身份已经分别使用 `tc-*` 和 `tm-*` UUIDv4 格式。这个格式只有接口效力；仓库没有正式实例，不能把现行词表 slug 或迁移账本位置改写为这些身份，也不能由标签批量分配正式身份。

当前 schema 的语言值域只含 `en`、`zh-Hans` 和 `zh-Hant`，不表示已经支持任意 BCP 47。不同语言或文字体系不自动转换、不自动补出变体，也不因并列记录证明概念相同。

未来唯一术语编辑源仍拟为 `data/vocab/terms.yaml`。该文件不存在，路径被 schema 或生成器引用也不使它成为正式数据。正式激活前，`docs/glossary.md` 的登记和编辑方式保持不变。

## 概念记录

概念记录 schema 已实现以下字段和机械基数。

| 字段 | 接口职责 | 仍未满足的语义门禁 |
|---|---|---|
| `id` | 稳定标识候选术语概念 | 正式身份尚未分配，不能从现行标签推导 |
| `subject_fields` | 保存适用学科及逐值依据；未判断时允许空列表 | 每个值的归属仍须逐项判断和批准，章节名称不充当主题 ID |
| `definitions` | 保存带语言的定义及逐值依据 | 定义范围、语言和来源对应仍须复核 |
| `languages` | 保存语言记录 | 多语并列不证明共同概念身份 |
| `basis` | 保存概念身份和多语对应所需依据 | 依据是否充分仍由人工判断 |
| `source`／`match` | 按共享引用接口保存可选关系 | 真实派生与概念映射尚未形成正式结论 |
| `workflow` | 保存候选工作流状态 | 状态校验不能授予准入或转换权限 |
| `history` | 保存只追加变化 | 正式历史不存在，决定与语义结论尚未产生 |

每个适用学科值和定义须分别取得可重复定位的依据。多个值引用同一材料时仍逐值关联，不以概念记录的一项总依据替代。多语记录还须另有足以支持共同概念身份的依据；某个形式在一种语言中存在，不证明它与另一语言形式表示同一概念。

## 语言记录

语言记录 schema 已实现 `language` 和 `terms`，并要求同一概念内的语言分组满足固定值域。语言记录不设置独立工作流；它受概念工作流约束，其中每个术语保留自己的管理状态。

缺少某种语言的合格形式时，不建立空术语，不填推测形式，也不从其他语言自动生成。简体、繁体和英文分别取得形式依据；把这些形式放入同一概念还须满足概念对应门禁。

语言值域的扩展、规范化和地区变体处理仍须另行提案。当前 schema 的三个值不能被解释为一般语言政策已经定稿。

## 术语记录

术语记录 schema 已实现 `id`、`text`、`administrative_status`、`basis`、条件使用的 `replaced_by` 和只追加 `history`。管理状态只取以下四个既有接口值。

| 取值 | 草案拟议用途 |
|---|---|
| `preferredTerm-admn-sts` | 当前语言中供项目优先使用的术语 |
| `admittedTerm-admn-sts` | 已获准但不作为优先形式的术语 |
| `deprecatedTerm-admn-sts` | 不再用于新的正文，因检索或历史需要保留的术语 |
| `supersededTerm-admn-sts` | 已由同一概念、同一语言中的另一术语替代的术语 |

schema 与转换校验已要求同一概念、同一语言恰有一个优先术语，且被替代术语的 `replaced_by` 指向同一概念、同一语言中的可用术语，替代链不得成环。其他状态不携带 `replaced_by`。

这些机械条件不构成任何形式的准入、优先、允许、废弃或替代决定。写法相同但表示不同概念的记录不得自动合并；只有概念身份依据和项目决定能够确定记录归属。

术语 `history`、概念 `history` 和复核义务 `history` 分别保存各自变化，不互相覆盖。接口能够表达决定引用不表示决定已经形成。

## 译名准入

本节是未生效提案，不替代[现行治理的译名规则](../design/governance/governance.md#译名)。未来译名准入拟同时核对每种语言的形式依据和把这些形式归入同一概念的对应依据。

拟议检索阶梯如下；上一层取得足够依据后停止，每层仍须核对具体条目和所指概念。

1. 同一权威双语条目明确给出两种形式及其共同概念。
2. 等同采用的两份标准正文经逐项核对，具体术语条目和定义能够对应；采标元数据本身不够。
3. 同一权威主体明确把两种形式用于同一对象或概念。
4. 两种单语形式分别有合格依据，并另有独立材料支持概念一致。
5. 以上各层都不能支持时不译，只保留有依据的原语言形式；需要说明时使用有来源的普通解释，不形成目标语言术语。

修改采用、非等效采用、Wikidata 标签、搜索结果数量、机器翻译、拼写相似、标准编号相近、标签并列或长期正文使用都只能提供检索线索，不能单独批准译名。

没有依据时不译。不得以候选、草案、占位、迁移去向或管理状态试用无依据形式；本草案不对任何具体译名作出结论。

## 状态转换

候选术语概念的 `candidate`、`active`、`deprecated` 工作流，以及术语管理状态的转换校验已经实现。校验器覆盖允许路径、决定引用、历史前缀、唯一优先形式、原子变更、恢复时新决定、替代目标和替代环。它只能拒绝机械非法变化，不能授予决定权或证明依据充分。

概念工作流的拟议语义如下。

| 路径 | 必要门禁 |
|---|---|
| 未登记 → `candidate` | 识别目标概念；拟记录形式均有依据；多语记录另有概念对应依据 |
| `candidate` → `active` | 模式与引用校验通过；概念、定义、译名、优先形式、委托和消费者影响逐项复核并获准 |
| `active` → `deprecated` | 停止使用的理由、引用影响和替代去向获准 |
| `deprecated` → `active` | 全部依据、来源、术语状态、委托和引用影响重新复核并取得新决定 |

概念工作流不使用现行主题概念的 `unassigned`。主题 `candidate`、迁移账本中的 `defer` 或正文报告命中也不机械映射为术语概念状态。

术语管理状态独立于概念工作流。概念处于 `candidate` 时，术语状态只是提案内容；只有概念为 `active` 且相应术语状态已经取得项目决定后，形式才可供正文或委托消费。schema 可解析或转换校验通过都不能替代这两个条件。

新术语首次进入 `preferredTerm-admn-sts` 或 `admittedTerm-admn-sts` 前，必须逐项复核形式依据、概念身份、语言、多语对应、同形异义和现有消费者。项目决定须明确准入的形式、语言、概念和目标状态；缺少其中任一项时不得首次进入可用状态。

术语管理状态的拟议语义保留下列完整门禁。

- 新术语只可正式进入优先或允许状态；废弃或被替代的初始状态只用于有依据的历史迁移或补录，不能绕过准入。
- 进入优先状态时，同一概念、同一语言必须在一次原子变更前后恰有一个优先术语；进入允许状态不能改变现有唯一优先术语。
- 优先术语降为允许、废弃或被替代时，同一原子变更必须同时确定另一项优先术语。
- 允许术语可以提升为优先、停止使用或被替代；提升为优先时同一原子变更处置原优先术语。
- 废弃或被替代术语恢复使用时，只能进入优先或允许状态，并重新完成准入、现行依据和影响复核，取得新决定；旧依据、旧决定和旧优先地位不自动恢复。
- 废弃与被替代之间的变化须由新证据和决定说明是否存在直接替代关系，并同步增删 `replaced_by`。
- 每个受影响术语分别只追加原状态、目标状态、日期、理由、决定和替代变化；同状态写入不伪装成状态转换。

正式术语数据和状态实例不存在。测试夹具中的 `active`、`rolled_back` 或其他状态只证明接口行为，不是仓库现状。

## 委托关系

`term_concept` 委托仍是本草案拟议的正式关系。委托以术语概念身份和语言集合为单位，使其他词表读取获准形式；原词表保留自己的概念身份、结构和关系，但不再手工维护已委托语言中的重复形式。

委托建立前须分别核对两端概念身份、各语言形式、全部引用和生成影响，并按现行决策权批准。标签相同、译名相同、`match` 存在或 schema 可解析都不能自动建立委托。同形异义可以属于不同概念，不能因字符串相同合并。

维护索引接口和生成器可以接受未来委托输入，但仓库没有正式委托数据，没有任何词表标签的编辑权已经转移，也没有消费者启用。

## 生成边界

生成入口从同一捕获上下文读取六份词表、有效来源与术语决定、语言采纳输入以及术语数据和显式发布状态。来源 v2、术语模式、引用、精确采纳、身份、状态及布局校验都通过后才写输出；`--previous` 只用于检查变更，不能把旧快照当作批准来源。

章节由 `glossary-layout.yaml` 的概念成员列表决定，与 `subject_fields` 分开。领域未获判断时允许空列表，不补造主题 ID；重复、缺失或未知展示成员会被拒绝。术语表和 Obsidian 术语概念页共享多语言、逐项依据与历史形式的渲染实现。

生成只展示获准的 `active` 术语概念；首选与允许形式须有具体采纳，历史形式只进入历史或检索表示。模型译名区依据现行主题／载体对象和既有语言采纳输入生成，同一中英形式可以合并显示，但每个目标身份及其模型依据仍分别保留。原范围快照不改写，已批准范围修正由现有精确决定承接。

`uv run kb-core term-data check` 校验术语数据，`term-data index` 生成只读维护索引；`build-terms build` 与 `build-terms check` 保留显式输入、输出和漂移检查。正文 `check-terms` 仍只报告复核线索：没有正式术语状态时读现行登记；有术语输入时须先核对发布状态与具体采纳，不能凭文件存在切换或把生成视图中的定义、ID 当登记形式。

当前没有正式术语输入和发布状态，因此这些路径只在隔离夹具中运行；不覆盖现行 `docs/glossary.md` 或正式 vault。TBX 继续后置，不实现往返编辑或为无接收方场景新增交换发布。

## 复核义务

术语复核义务 schema、状态转换校验、开启接口、决定反查和双向引用索引已经实现。接口可表达稳定 `id`、`targets`、`trigger`、`state`、`opened`、`closed`、`decision` 和只追加 `history`，并要求已解决义务不直接重开。

来源义务只通过稳定 `id` 触发未来术语义务；术语接口不复制来源义务的字段、状态或结论。决定、义务、概念、术语、委托和生成对象之间可以反向定位，但索引只说明复核范围。

本草案拟要求每个目标分别记录结论和所需决定。只有全部目标有明确结论、必要决定齐备且要求的正式处置可核对时，义务才能解决；相同对象再次触发时创建新 `id` 并引用前项义务，不覆盖旧记录。义务本身不得自动改写概念、术语、委托、消费者或生成物。

以下变化必须创建术语复核义务，不自动改写正式数据。

| 触发 | 必须列入的目标 |
|---|---|
| 来源义务影响 `basis`、`source` 或 `match` | 受影响的概念值、术语值、概念状态、术语状态和委托；引用来源义务 `id`，不复制其定义或结论 |
| 概念定义或适用学科变化 | 概念状态、多语一致性、全部术语状态和委托 |
| 术语形式或管理状态变化 | 同语言唯一优先术语、替代链、正文、委托标签和生成视图 |
| 语言标签变化 | 语言记录身份、重复分组、全部术语和受委托标签 |
| 委托建立、修改或撤销 | 两端概念身份、唯一编辑权、原词表引用和生成影响 |
| 同形集合变化 | 涉及的概念和术语；不得自动合并概念 |
| 模式或生成器变化 | 状态约束、确定性、输出差异、正文一致性和历史保留 |
| 项目决定被采纳、替代或推翻 | 反向引用该决定的概念状态、术语状态、委托和未结或已结义务 |

决定被采纳、替代或推翻时，必须先用决定反向索引列出全部受影响对象，再创建以决定变化为触发的新术语义务。决定变化只触发复核，不自动恢复、废弃、替代、撤销委托、关闭义务或改写历史。

反向引用索引以目标记录 `id` 为入口列出所有仍为 `open` 的术语义务。义务转为 `resolved` 后必须退出未结义务索引，但其 `targets`、结论、决定和历史继续保留；索引只确定复核范围，不给出处置结论。

仓库没有正式术语义务或人工裁定数据，也没有正式义务索引。定期术语复核字段被当前实现明确拒绝；现行其他对象的周期和阈值不能继承给术语义务。

## 决策权限

本草案沿用[治理的决策权](../design/governance/governance.md#决策权)，不扩大任何一级权限。采集材料、运行校验、生成报告或索引只能形成机械证据；术语准入、译名采用、概念对应、优先形式、管理状态、委托、废弃、替代和迁移去向仍按内容提案后由人决定。

范围、零自定例外、草案生效、非候选对象删除和发版只有人能决定。校验通过、存在决定字符串、迁移账本去向、生成器可运行或索引可定位均不提升权限；项目决定也不能补出缺失的外部依据。

## 校验规则

术语基础已经实现以下机械门禁。

- 三层 schema 固定顶层键、身份格式、语言值域、概念工作流、术语管理状态、逐项依据、可选共享引用和历史字段。
- 状态转换校验覆盖允许路径、唯一优先术语、原子变更、恢复时新决定、替代目标、替代环和历史前缀。
- 生成器可在显式门禁输入下生成固定排序输出并检查漂移。
- 正文诊断按动态 Markdown 清单输出精确位置与上下文，默认不阻断。
- 维护接口可校验义务转换并建立决定、义务和对象的反向索引。
- 迁移工具可校验 348 条冻结身份、旧位置、消费者、原动作和审计去向。

这些能力仍没有闭合实际正式迁移。统一入口和应用读取可以拒绝机械非法输入，但当前没有已采纳的完整术语数据与发布状态；正文人工裁定、正式义务、委托和消费者也未自动激活。实际字段依据与具体采纳、迁移逐项对账和应用后验收仍须完成。Git 承担版本恢复，不新增专用补偿回滚。

机械校验不能决定概念是否相同、定义范围是否合适、译名依据是否充分、优先形式是否应采用、同形记录是否应合并、委托是否成立或义务目标是否充分复核。这些结论须逐项取得依据和决定。

正式激活阶段，任一机械错误、未结义务或未完成的语义门禁都必须阻止相关概念转为 `active`、术语状态转换、委托切换、义务结清、生成发布视图或进入迁移切换。基础能力完成、索引可生成或局部校验通过都不能降低这项阻断。

## 迁移边界

`data/audit/migrations/term-v1/terms.tsv` 已确定继承 348 条冻结审查身份、位置、消费者、原动作和去向，其中 286 条为 `audit-only`、56 条为 `retain-owner`、6 条为 `retain-pending-l3`。全部记录的 `blocks_cutover` 为 `false`。

该账本只说明当前阶段的审计继承已经完成。它不含正式 `tc-*`、`tm-*`、`workflow` 或 `administrative_status`，不生成术语概念、术语记录、委托或正式身份，也不重准入现行 designation。旧 `keep`、`defer`、`remove` 不能分别解释为准入、候选或删除许可；六条待 L3 记录也不因账本存在获得处置决定。

未来正式迁移仍须冻结当前编辑源、词表标签、译名决定、消费者和生成结果，逐项判断概念身份、语言、形式、依据、状态和委托。现行主题 `unassigned`／`candidate`、紧凑依据、`none`、`self`、同形标签和长期正文使用都不能机械映射为正式术语数据。

正式迁移结果必须与冻结输入逐项对账，分别说明保留、转移、废弃、不译、待人判断和不在范围内的去向。任何无法解释的新增、丢失、概念合并、语言变化或状态提升都必须阻断切换。迁移不得修改既有决定材料，也不得把后来的判断反写成旧决定。

当前阶段没有完整 candidate、handoff、payload、原子应用或补偿回滚，也没有正式切换工具。审计继承完成不能替代正式迁移候选和消费者验证。

## 生效条件

本草案默认不生效。三层 schema、状态校验、348 条审计继承、确定性生成器、`report-only` 正文诊断和维护索引已经完成；这些前置能力不需要重复建设，也不能替代下列尚未满足条件。

1. 人逐节批准对象语义、译名准入、概念工作流、术语管理状态、委托、复核义务、生成边界和阻断条件。
2. 来源 v2 严格数据与接口已完成；具体术语引用仍须命中有效实体、适用用途与准确依据，不能借来源整体完成免除逐项核对。
3. 形成经过准入、概念对应和逐项依据复核的完整术语候选，并正式分配身份；迁移账本不能作为该候选。
4. 明确正式编辑源、术语义务、委托、切换状态和消费者的数据位置、所有权与契约。
5. 将 schema、来源引用、状态转换、生成和消费者组成最小端到端路径，验证启用、禁用、输出差异和应用后结果。
6. 明确正文人工裁定怎样取得正式效力；`report-only` 命中不能直接升级为阻断。
7. 为正式切换记录准确 Git 基线、写集、输入和发布边界，验证必要的用户内容保护；版本恢复使用 Git，不新增交付包或补偿演练体系。
8. 人作出草案生效和正式迁移决定；生效决定记录至少明确生效日期、模式版本、迁移批次、回退边界和受影响文件，消费者启用、严格切换与发版分别取得授权。

条件未全部满足时，`docs/glossary.md` 继续保持现行编辑权，不创建或消费正式 `data/vocab/terms.yaml`、正式义务、委托、切换状态或发布视图。

## 待定事项

- 术语准入、概念对应、优先形式和委托的最小复核材料。
- `term_concept` 在各词表中的正式结构、语言集合表达和撤销程序。
- 术语表的分组、历史区和缺少中文形式时的固定版式。
- 正文人工裁定怎样进入正式门禁，何时仍保持报告型输出。
- 术语复核周期、阈值和正式义务文件何时由人批准；不得从现行阈值推导。
- 正式编辑源、切换状态、消费者、应用后验证和回滚证据何时进入获准阶段。
- TBX 目标方言、字段映射、信息损失报告和发布快照边界。
