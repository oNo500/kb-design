# 模型对象分层

状态：草案，未生效。

## 状态边界

本文处理任务所指 `large language model` 待审类概念及其相关实体怎样分层，不批准该概念、任何中文形式、首选英文形式、缩写、ID、实体类别、关系、来源用途或正式记录。

文中的“类概念”“模型家族”“具体模型”“应用实体”是对象职责说明。来源材料直接出现的 `large language model`、`LLM`、family、collection 等形式只证明来源怎样表述，不自动取得项目 designation 资格。没有中英概念对应决定时，不自译、不创建占位概念、模型实体、映射或 `source: self`。

| 深度学习 | 没有相应概念记录 | 不为补齐外部路径创建占位 |

| 预留类别 | `docs/design/model/entities.md` 预留 `large-language-model`，正式实例为 0 | 设计示例不等于实体记录或类别依据已复核 |

## 依据边界

### 形式依据

- [CS2023 Final Report](https://csed.acm.org/wp-content/uploads/2025/11/CS2023-Report.htm)、[GPT-4 Technical Report and System Card](https://cdn.openai.com/papers/gpt-4.pdf)和[Claude 4 System Card](https://www-cdn.anthropic.com/6be99a52cb68eb70eb9572b4cafad13df32ed995.pdf)直接使用 `large language model`；CS2023 与 [Llama 3 Model Card](https://github.com/meta-llama/llama-models/blob/main/models/llama3/MODEL_CARD.md)直接并列英文全称和缩写。
- [SJ/T 12120-2026 官方登记](https://std.samr.gov.cn/hb/search/stdHBDetailed?id=594CFDC622F98BADE06397BE0A0A2CD3)的现行标题使用一个中文形式，相近标准计划使用另一个中文形式；二者的优先级和与待审概念的对应均未批准。
- [GB/T 45288.1-2025 官方登记](https://openstd.samr.gov.cn/bzgk/std/newGbInfo?hcno=C401156D6EF7F77E416BB4C988172610)提供更宽对象的标题形式，不能据此判定同义或上下位。

英文形式已有直接来源线索，中文对应仍是阻断项。本文不替人选择任何中文 designation，也不把文件名当作准入依据。

### 概念依据

- CS2023 `AI-ML` 把 large language models 作为生成式神经网络的例，支持机器学习路径。
- CS2023 `AI-NLP` 在 Deep learning for NLP 下列 transformers 和 generative language models，并交叉引用 `AI-ML`，支持自然语言处理路径，但没有证明两个英文类概念完全等同。
- Transformer、BERT 和 GPT-3 论文分别支持架构、具体模型和语言模型实例事实，不是待审类概念的唯一源头。
- [Foundation Models Report](https://crfm.stanford.edu/report.html)证明 foundation model 是范围跨语言与视觉的不同划分维度，不能与待审概念自动作 `exactMatch`。

没有一篇已核材料可诚实承担待审类概念的唯一 `origin`。相关论文与课程材料未读的实验、附录和无关课程细节不用于扩大结论。

### 身份依据

- [NIST SP 800-218A](https://doi.org/10.6028/NIST.SP.800-218A)区分 AI model 与使用模型的系统、软件、应用和工具，支持模型与产品分离。
- GPT-4、Claude 3 和 Llama 3 的一手材料明确出现 family 或 collection 及成员，支持家族与具体模型分离。
- 模型卡区分具体发布、参数规模、训练阶段、对齐状态和评估版本，但名称后缀不自动决定项目实体边界。
- 同一模型可通过多个产品或服务提供，同一软件也可运行多个模型；产品、软件和模型不得共用身份。

## 对象分层

| 记录层 | 管理对象 | 记录位置 | 建档依据 | 禁止替代 |
|---|---|---|---|---|
| 类概念 | 可用于标引并形成概念上下位的待审模型类 | 主题词表 | 课程最终报告、标准和概念范围复核 | 用具体模型名、目录或出现次数建概念 |
| 模型家族 | 发布方明确命名的一组模型或 collection | 命名实体词表 | 发布方模型卡直接声明家族和成员 | 用共享前缀或代际数字推断家族 |
| 具体模型 | 有可固定发布身份的模型或版本化模型 | 命名实体词表 | 模型卡、系统卡或原始模型论文 | 把 API alias、检查点、参数后缀或微调名自动当新实体 |
| 应用实体 | 使用模型的产品、服务、系统、API 或软件工具 | 命名实体词表 | 对象自身身份与合格外部类别依据 | 把产品与模型合并，或因使用模型继承模型类别 |

组织、标准和论文是旁接实体，不算第五个模型层。产品是交付或市场角色，不自动等于 `software`；只有对象身份和外部类别分别成立时，才可使用现行类别。

## 方案比较

| 方案 | 记录与归属 | 收益 | 代价 |
|---|---|---|---|
| 现状方案 | 不建待审类概念、家族或具体模型；内容继续使用现有主题和已有应用实体 | 没有名称、schema、来源或身份被提前固化 | 无统一类概念检索，家族和版本缺少稳定反查 |
| 简化方案 | 建类概念，把家族和具体模型合并一层，应用实体另列；上位可选 ML、NLP 或双上位 | 近期关系较少 | 家族、成员、版本、替代和生命周期混杂 |
| 分层方案 | 建四层记录；类概念提议 ML 与 NLP 双上位；家族、模型和产品用显式关系连接 | 身份、版本、产品替换和检索职责分开 | 需要类别、关系、去重、生成和迁移门禁，不能批量生成 |

## 结构选择

| 选项 | 直接上位 | 支持 | 代价 |
|---|---|---|---|
| ML 单上位 | `machine-learning` | CS2023 `AI-ML` 的直接例证 | NLP 直接检索路径缺失 |
| NLP 单上位 | `natural-language-processing` | CS2023 `AI-NLP` 的直接课程结构 | 机器学习机制路径缺失 |
| 双上位 | 两者同时 | 两个知识单元分别提供直接依据；现行结构允许多 `broader` | 导航须按概念 ID 去重，并分别保存关系依据 |

`artificial-intelligence` 不建议作为第三个直接上位，因为两条推荐路径已经传递到该概念。应用、社会影响、安全和 agents 视角不是待审类概念的类属上位；具体内容可以按事实同时标引相关主题。

## 推荐方案

推荐分层方案，并把 ML 与 NLP 双上位作为一项独立 L2 提案。实施顺序必须是先决定待审类概念的范围、形式和两条上位关系，再决定家族与具体模型身份判据，再设计关系，最后逐条审记录、来源、生成输入和消费者。

该推荐不指定新 ID、中文首选形式、家族类别或关系字段名。家族须有发布方明确声明，具体模型须有可固定发布身份；API alias、路由名、评估内部名、参数后缀和微调名默认不产生新实体，除非另有身份决定。

## 替代方案

在名称、概念或关系门禁未通过时，保持现状是安全替代。简化方案只在真实消费者证明家族与具体模型无需分别查询和维护时重开；当前一手模型卡已经显示两层身份，故不推荐。

## 检索路径

| 查询对象 | 入口与处理 |
|---|---|
| 待审类内容 | 由类概念 ID 直接检索；从 ML 或 NLP 分支传递检索时按概念和内容 ID 去重 |
| 模型家族 | 由家族实体及获准形式检索，再通过成员关系展开具体模型 |
| 具体模型 | 由模型卡固定的发布身份检索，不把移动 API alias 当稳定 ID |
| 产品或软件 | 由独立应用实体检索，再通过获准关系联到当前或历史模型 |
| 发布方对象 | 从组织责任关系反查，分别返回家族、模型和应用实体，不合并对象层 |
| 主题与对象交集 | 内容的主题字段选类概念或应用主题，实体字段选模型或产品，再计算交集 |

同名家族、模型和产品必须显示对象层或范围说明，不能靠共享标签合并身份。

## 不采后果

- 不建立类概念，会继续依赖 ML、NLP 和具体实体的组合查询，但避免概念未决时误建档。
- 不建立家族层，会把家族材料、成员集合和代际替换重复到具体模型。
- 不建立具体模型层，会混淆家族、发布、规模、对齐状态和同名产品。
- 不分产品与模型，会让产品换模改写模型身份，并把产品功能与模型性质互相传播。
- 不采用双上位，会失去 ML 或 NLP 中一条直接证据路径；采用后不去重则会形成重复导航。
- 不把 foundation model 等同待审类概念，可避免错收非语言对象；该不采用没有负面数据影响。

## 影响范围

若推荐以后获准，可能影响 `docs/glossary.md`、`docs/design/model/topics.md`、`docs/design/model/hierarchy.md`、`docs/design/model/entities.md`、主题生成输入与生成器、`data/vocab/topics.yaml`、`data/vocab/entities.yaml`、来源登记、schema、校验器以及内容和应用消费者。

每一层都须单独建档和取证。类概念归属不向模型实体自动传播，模型归属不向产品或软件自动传播，组织归属也不向其全部对象传播。

## 权限门禁

### 提案门禁

- 待审类概念与 language model、generative language model、foundation model、multimodal model 和具体模型的概念边界；
- 英文全称、缩写、中文形式和多语对应；
- ML 与 NLP 两条 `broader` 的分别依据和双上位决定；
- 现行预留类别对具体模型的适用性，以及家族的合格外部类；
- 家族、具体模型、版本、检查点、变体和 API alias 的身份判据；
- 家族成员、版本、替代、提供方和产品使用模型等关系的方向、基数、时间和依据；
- 每条记录的 `subjects`、ID、生成输入、`basis`、`source` 和 `match`；
- schema、校验、消费者去重、迁移批次和回退。

### 保留门禁

- 一手材料的来源登记、用途角色和档位；
- 草案生效、正式概念与实体写入、消费者启用、正式切换、发版和任何范围变化。

## 生效条件

本草案只有在人批准待审概念、designation、双上位及四层身份规则，相关外部类和关系契约闭合，生成器能正确表达无实际派生的本地概念，逐条记录与来源用途另获批准，消费者完成双路径去重和应用后验证，迁移与回退证据齐备，并另行决定草案生效后，才可并入正式设计。

四层中的任一层可以继续为空。概念批准不自动创建家族、模型或产品记录；实体批准也不自动创建主题概念。

## 错误代价

| 错误 | 后果 | 代价 |
|---|---|---|
| 错认概念对应 | 标签、范围和映射共同污染 | 高 |
| 错选单一上位 | 一条真实检索路径消失 | 中 |
| 冗余直挂 AI | 直接与传递关系重复 | 中 |
| 合并家族与模型 | 成员、版本和生命周期混乱 | 最高 |
| 合并模型与产品 | 产品换模和多产品承载不可追溯 | 最高 |
| 按名称后缀自动拆分 | 实体爆炸并形成重复标引 | 高 |
| 自动继承主题归属 | 检索精度下降，错误关系看似有统一依据 | 高 |
| 错填 `source` 或 `match` | 派生与概念对应被伪造 | 高 |
| 过早选择中文形式 | 未准入名称进入标签、索引和用户习惯 | 高 |
