# 产物维护

Obsidian 产物维护负责目录、生成页面、内部链接、配置、模板、视图及交付清单，使指定版本的数据可以在知识库中使用。输入是已明确选择的词表版本及应用配置，输出是可核对的应用状态；不编辑词表含义、身份、关系或文章正文。

本篇适用于 `kb-obsidian-rdf` 的编号 PARA 实例，维护分工见[职责分离](../../development/决定-维护职责分离.md)。新正式库按[正式库创建](决定-正式库创建.md)独立建立，旧库不自动迁移；开发与正式实例不得通过普通刷新互换。词表侧见[维护工程](../../practices/vocabulary/设计-词表维护工程.md)。

## 操作分工

| 操作 | 写入范围 | 保留内容 |
|---|---|---|
| 初始化 | 空目标库的知识文件、必要配置及库外状态 | 不接管已有非空库 |
| 词条刷新 | `05-vocabulary/` 与库外当前交付 | 用户文章、配置、视图、模板与首页 |
| 配置与视图维护 | 明确预览的配置键、缺失配套文件和可确认旧基准的首页 | 用户不同配置与自改文件 |
| 布局迁移 | 独立计划指定的路径、链接与对应清单 | 稳定身份、正文及完整旧版材料 |

词条刷新不隐式升级应用配置，配置维护也不换词表版本。两者可以由用户一起发起，但分别比较、授权和记录结果。文章所选引用不属于任何普通刷新写集。

## 初始配置

| 用途 | 初始设置 |
|---|---|
| 附件 | 默认保存到 `08-attachments` |
| 模板 | 原生 Templates 使用 `07-templates` |
| 文件链接 | 启用原生文件移动或改名时更新内部链接的偏好 |
| 属性类型 | 按内容字段声明文本、列表及日期类型 |

Obsidian UI 的列表类型在 `types.json` 中使用原生 `multitext` 表示，aliases 使用其专用 `aliases` 类型；这只是应用存储表示，不改变内容模型的值域和基数。初始配置不添加自由字段代替受控引用。

对既有库先显示差异。缺失键可以补齐；用户已有的不同值保留并说明，不把新默认值当成用户选择。后续更新仍以明确旧基准或用户决定处理，不能借“修复配置”反复重置偏好。配置文件解析失败或类型冲突时保留原件并停止相关写入。

## 文章视图

`06-views/` 提供全部笔记、收件箱、项目、领域、资源、归档、草稿和最近修改入口，首页集中链接。收件箱展示捕获材料；PARA 各区视图按所在目录筛选，资源按子目录分组；全部笔记覆盖 PARA 四区中的 Markdown 文件。词条、模板和首页不混入内容列表。

草稿和最近修改限定 PARA 四区中已声明有效格式文章身份的记录；草稿还要求 draft 状态。目录归属与文章状态分开，整理进资源或归档目录不等于定稿。UUID 格式符合不能代替内容校验。

默认列为可点击标题、主题、实体、文档类型和修改时间；无标题时显示文件名。按文件修改时间降序排序，筛选和分组只服务查找，不改变文章状态或标引。表示依据见 [Bases 语法](https://obsidian.md/help/bases/syntax)。

新视图在缺失时生成，已有私人排序、筛选、显示列和模板保留。首页只有仍等于已知生成基准时才可更新，否则提供候选。用户明确批准已有视图升级后，按逐文件差异和备份应用，不把一次批准扩大为后续自动覆盖权限。

## 维护流程

```text
明确目标库与操作
       |
核对当前版本、配置及用户修改
       |
生成候选与差异
       |
按已确认写集应用
       |
读取实际结果、保存凭据
```

初始化和词条交付沿用[导出合同](提案-Obsidian%20导出与导入.md)。配置维护使用独立库外基准、备份及执行记录，不扩张词表 manifest 的受管理页面集合。

每次写入前复核当前值和基准。重复执行只复用仍完整的结果，缺失或未知修改明确报告；中断不能通过重新生成整个库覆盖文章或偏好。应用时关闭目标库并暂停其他写入与同步，实际保证以工具核对范围为限。

原生链接更新偏好只处理 Obsidian 所知的引用，不更新本工具的库外身份对应。因此受管理词条改名和顶层布局迁移继续走显式迁移；不能只调用原生改名后就宣布工程状态一致。

## 数据交接

词表版本选择明确记录来源、内容摘要、准用范围和实际加载结果。源端新增实体不自动使所有应用加载它，应用安装成功也不把 candidate 提升为 active。

文章正文、登记、状态及所选引用由内容维护负责。缺词需求可以关联一篇文章，但词表交付和应用安装完成后，只能报告词条已可用；文章是否补引用需要另一个明确操作及结果。

## 工具与验收

本方案由 `apps/obsidian-rdf/` 实施，操作见[包说明](../../../apps/obsidian-rdf/README.md)。验收优先使用 Obsidian CLI：模板能列出，视图范围及排序符合预期，现有文章可以查到，词表刷新不覆盖配置，配置维护不改词条和文章。

旧 `apps/obsidian/` 的初始配置和视图作为工程参考，其 `kb_*` 属性、UUID 文件名和 `app/` 目录不回迁。新库仍采用编号 PARA、可读文件名及库外工程状态。旧工具仍使用的[映射合同](设计-Obsidian%20映射.md)只在其原范围生效，不能作为新工具的默认合同。
