# Obsidian 导出与导入

本合同规定词表应用的固定输入、条目生成、查询数据、文件管理及恢复。目标是支持文章选择、引用和检索；开发库只表示验证环境，不把“完整浏览所有 RDF 字段”作为日常使用前提。

本合同采用 PARA 开发库的编号布局，工程交付与知识文件分开。第 2 版开发实例通过显式布局迁移处理；其他旧实例迁移、正式采用及正式目录写入另行决定。数据语义遵循[共同模型](../../model/vocabulary/设计-词表整体设计.md)和[应用分层](../shared/设计-适配要求.md)，文件及命令属于工程选择。

## 输入清单

导出读取固定 JSON 清单，`format_version` 为 `1`，本阶段 `mode` 为 `preview`。最终使用的清单原字节和全部输入原件在库外随工程交付保存；导出期间不联网更新来源。

| 字段 | 要求 |
| --- | --- |
| `sources` | 非空列表；每项有稳定 key、路径、格式、SHA-256、数据身份和版本说明，未知版本明确记录未知 |
| `sources[].scope` | subject_iris、concept_scheme_iris、entity_class_iris 三选一，列明 IRI；不按标签或 URI 前缀推断类型 |
| `sources[].trial_subjects` | 本次允许开发试选的主体列表，必须属于 scope；空列表只供查看 |
| `sources[].base_iri` | 输入含相对 IRI 时提供来源基准，不使用下载路径充当身份 |
| `sources[].authority` | 预览授权、范围和可空的正式采用依据分别定位；不能用文件存在或校验通过补造批准 |
| `compatible_sources` | 明确允许共同解释的来源键分组；跨来源的名称与说明也须核对，不只检查主对象 |
| `auxiliary` | 现行类型、体裁、载体及书目；每项有 key、kind、路径、格式、schema_version、摘要、版本与采用依据 |
| `display` | 具体语言请求列表；默认 zh、en，按既有语言设计匹配，缺名回退为身份 |
| `rules` | 明确 SHACL 规则选择；交付保存实际规则、投影、模板和实现版本及摘要 |
| `producer` | 导出器版本；与数据版本分开 |
| `previous_delivery` | 初建为 null；刷新明确提供旧库绝对路径、库外 state_root 和旧 manifest 摘要，固定历史依赖 |

RDF 首版接受 Turtle 及其 N-Triples 子集；辅助数据沿用已有 YAML／JSON 结构，不要求手工重录为另一套词表。路径相对输入清单解析，读取先核对摘要和格式。

概念体系范围按直接 `skos:inScheme` 选择 Concept；实体范围按明确源类的直接 `rdf:type` 选择。任意带类型的非 SKOS 资源不能自动成为普通实体。实际选择的主体须有源 IRI；名称、说明和集合不作为普通文章主题选项。

同一身份或附属名称、说明由多个来源共同提供时，必须明确相容范围，记录实际贡献来源，不能按读取顺序取值。原件分别保留，不因组合而抹去出处。

## 使用条件

开发试选和正式准用分别记录。只允许明确范围内、身份和对象种类可辨认的记录参与试写；明确禁止新标引、停用、身份冲突或无法解释的状态不能被预览模式绕过。

文档类型、体裁、载体和文献使用各自已采用值域。采用依据与原状态分别保留；源记录尚未使用不等于可自行改变状态，未采纳候选也不因在目录中而获准使用。

来源状态不能从说明文字中出现“正式”“候选”等字样推断。工具返回的可选条件只服务当前应用，不向 RDF 添加新的对象状态。

## 条目生成

| 资源 | 应用用途 |
| --- | --- |
| Concept | 概念条目；适用主题可用于 subject，类型等概念按各自字段值域使用 |
| 普通实体 | 实体记录；用于 entities，保留明确的类别和有依据的事实 |
| ConceptScheme | 体系范围保留在库外 resources.json 及原始图，不生成普通用户目录或主题选项 |
| Collection | 分组信息保留在库外，不把成员关系改成上下位，不直接展开为用户目录 |
| OrderedCollection | 保留 RDF 列表的顺序、重复位置和空列表；异常结构报告 |
| XL Label | 保留在所附对象的名称数据中，不为每个名称复制一个概念页 |
| 说明及其他资源 | 依原附着对象保留说明与原始数据；不因展示而变换其语义 |

条目页面主要显示名称、使用条件、定义、范围、关系和简短来源。完整 RDF 属性表、XL 资源明细与校验报告放在库外工程数据中；页面不各自展开长篇 Bases 查询代码。

原始信息必须完整可回查。数据未在页面显示，不等于字段缺失或不合法；投影记录须明确说明保留位置。工具不能以页面简化为由删减词表模型要求。

## 字段表示

| 来源信息 | 页面或查询表示 |
| --- | --- |
| 原 IRI、带语境的局部 ID | identifier 和身份对应，原值保留 |
| 显示名称 | 可读标题及初次文件命名；按语言请求选择 |
| 首选名与替代名 | aliases、查询名称及完整名称身份记录；相同显示文字可去重，名称资源不合并 |
| 隐藏名 | 保留原件和投影记录，不进入默认推荐别名 |
| 定义、范围说明、一般描述 | 分别保存；摘要按这个顺序择取并标注来源属性与语言，缺失不补造 |
| XL 名称上的定义或其他说明 | 保持名称身份和原附着位置，不提升成概念定义 |
| broader、narrower、related | 保留关系种类及目标身份；查询可使用其明确互逆或对称语义，不推断额外实体事实 |
| 集合成员与有序列表 | 分别保留成员、位置和重复，不混成层级 |
| 译名依据和使用提醒 | 保留原名称及证据；未核实提示不能在精简页面中变成已确认 |
| 来源、权利、日期、版本及映射 | 完整原件和结构化详情；保留原主体、类型及不同版本职责 |
| 未专门投影的属性、嵌套结构 | 记录主体、谓词及原件位置，不静默截断或丢弃 |

同一完整语言标签下的不同首选文字、互斥名称角色或非法 literalForm 不能通过排序取第一项解决。名称显示按[多语言设计](../../model/vocabulary/设计-多语言词表.md#匹配与显示)执行，不自动把 zh 改成 zh-Hans 或 zh-Hant。

进入页面的来源内容按安全文本处理，不能执行源 HTML 或 Markdown 指令。不能安全成为链接文字的名称保留原文及排除原因。空白节点仅在原输入中解释，不使用解析器临时编号作为文件名、跨版本身份或排序依据。

## 路径规则

新条目以显示名称生成 `05-vocabulary/<对象目录>/<名称>.md`。文件名处理与名称记录分开：原始名称及 IRI 不改变。

- 用户条目目录为 concepts、entities、document-types、genres、forms、references；内部 kind=types 对应 document-types，不改变类型概念的原身份。
- 新生成文件名中的英文使用小写，空格和下划线改为中划线，连续分隔符合并。中文保留；title、别名和源 IRI 不随文件命名改写。另处理文件系统或链接不支持的字符、控制字符、保留设备名、尾部点空格和 UTF-8 字节长度。
- 同目录内按 NFC 和大小写折叠检测冲突；整组新同名对象在可读名称后以中划线连接原身份摘要前 8 位，实际冲突时依次增加至 16、32、64 位。仍冲突则报错，不覆盖或合并。
- 摘要计算沿用原规则：IRI 使用完整绝对 IRI 的 UTF-8 SHA-256；局部身份使用目录键、NUL 分隔符和局部 ID。仅文件名比较规范化，不规范化源身份。
- 刷新按原身份保留已安装路径；名称或译文更新不自动改路径。旧格式实例另列迁移，不能借普通刷新把库内状态悄悄移出或重命名用户文件。
- 旧身份退出当前输入后，原路径保留为旧引用入口，禁止新试选，并链接固定历史版本；不把来源缺席自行认定为停用或后继。

历史路径为 `05-vocabulary/history/<旧 manifest 摘要>/<对象目录>/<原文件名>.md`，保留所引身份与版本，完整名称、说明和原始历史图保存在库外；库内只保留明确历史引用需要的知识页。历史页不进入当前候选；指定版本缺失必须报告。

显式重命名需要同时更新文章内链、条目间引用、查询路径、身份对应和清单。此操作另行处理，不使用通用文件改名绕过受管理文件检查。

## 查询数据

`records.json` 是身份对应和条目查询的共同数据。每条记录保留 identity、kind、sources、versions、path、use、source_state、trial_selectable、formal_basis、restrictions、history；identity 为完整 iri 或 catalog 与 id。use 区分 current、retained、historical，这些是应用用途，不是源对象状态。

用于日常查询的 `entry` 与页面从同一输入生成：

| 字段 | 内容 |
| --- | --- |
| `aliases` | 默认可查找的名称列表，排除隐藏名和不安全别名 |
| `fields` | 可作为哪些文章字段的值，属于应用角色 |
| `summary` | 简短正文、语言和原属性，或 null；不生成新的定义 |
| `definitions`、`scope_notes`、`descriptions` | 原对象对应的文字、语言及属性，分别保存 |
| `relations` | 按关系种类保存目标身份、显示名称和路径 |
| `notes` | 保留说明主体、属性、文字和语言，不混淆概念与名称 |
| `facts` | 实体的有依据源属性，不能从共享主题或名称相似生成 |
| `raw_sources` | 来源键、版本及原始数据路径 |

条目查询默认返回适用字段中的名称、类型、身份、链接、简短说明和可用条件。完整名称数据、关系及来源需要详情时再返回；默认结果设置数量上限，不一次输出整份词表。

精确名称匹配必须在字段范围内唯一，多个同名候选须明确选择。匹配的大小写处理只用于搜索，不改写身份或宣称同义。历史或不可用条目仅在明确请求时供查看，不能作为新选择的默认结果。

## 分离交付

生成器产生两套文件：知识文件用于 Obsidian，工程文件用于外部状态。两套文件都核对来源和完整性，不能通过把工程 JSON 改名或改后缀混入库。

| 知识文件 | 维护归属 |
| --- | --- |
| `05-vocabulary` 中列明的条目 Markdown | 工具管理；人工改动先报冲突 |
| home.md、`06-views` 中的 Base、`07-templates` 中的正文模板 | 初建提供，之后保留用户修改 |
| `00-inbox`、PARA 四区、`08-attachments` | 用户内容；初始化只建目录，文章由明确建立动作产生 |
| .obsidian | Obsidian 自身配置，生成工具不接管 |

库内不放原始 TTL、身份映射 JSON、manifest、校验报告、运行日志或工程备份。普通知识资料和附件仍由用户保存，不因文件扩展名自动变成工程数据。

| 库外工程文件 | 职责 |
| --- | --- |
| records.json | 原身份、路径、使用条件和条目查询数据 |
| resources.json | 无用户页面的体系、集合、名称等资源信息 |
| projection.json | 原属性的显示或保留位置，明确未投影信息 |
| validation.json | 实际规则及检查结果，未执行范围单列 |
| manifest.json | 输入、规则、工具、环境及两套文件的清单与摘要 |
| inputs/ | 输入清单、原始数据、授权材料及历史交付，保留原字节 |

manifest 使用格式版本 3，files 只列工具管理的知识条目，state_files 列工程文件且排除 manifest 自身。records 的内部格式版本仍为 1；输入清单格式仍为 1。第 2 版实例须先显式迁移，普通刷新不能静默改成编号布局。

派生文本使用 UTF-8、LF 与末尾换行，JSON 稳定排序，YAML 由成熟库序列化。固定输入、历史依赖、配置和环境下，两套生成文件都应可重复；运行时间与随机操作编号属于安装记录，不混入确定性产物。

## 实例绑定

默认工程状态位于项目 `output/obsidian-rdf/state/<库标识>/`，可通过 state_root 显式指定其他库外位置。库标识由规范化绝对路径派生，binding.json 另保存实例 UUID 与绑定路径；原始知识对象 ID 不参与这一目录命名。

实例目录的 current/ 保存完整工程交付，current.json 保存已安装版本凭据，reports/、receipts/、backups/ 保存报告、操作记录及备份。恢复记录也在库外。目标库内不写工具 marker。

操作前须核对目标与状态绑定，不借相似名称接管非空库，不静默重新绑定被移动的库。状态目录不得位于库内，也不得与库的写集重叠。缺失或不一致的绑定须报告；不能从“文件看起来完整”补造成功记录。

第 2 版开发实例的布局迁移先准备候选和明确写集，切换时保留完整原库、旧工程交付及原绑定和安装凭据；既有报告、操作记录及历史备份继续保留。迁移同步顶层目录、内部链接、身份对应、查询路径、文件清单与摘要，保留原始对象身份、文章 UUID、正文及内部文件名，`home.md` 保持原路径。迁移写集与普通刷新分开列明；其他实例迁移和重新绑定另行处理。知识文件脱离工程状态仍可由 Obsidian 阅读；工具不能在缺少绑定时声称可以安全刷新。

## 操作合同

| 操作 | 主要输入和结果 |
| --- | --- |
| 输入准备 | 固定已有交付、摘要、范围及依据，不批准新数据 |
| 初建 | 输入清单与显式空目标；完整生成、核验并记录实际安装结果 |
| 条目查找 | 字段、名称或别名；返回有界的可选候选，精确匹配优先 |
| 条目读取 | 字段与明确引用或唯一名称；默认概要，详情按需 |
| 文章检索 | 字段与对象；按已保存引用查文章，下位展开仅适用于主题 |
| 文章建立 | 标题与必要字段；按原身份核对并新增 draft，不覆盖已有文章 |
| 内容检查 | 明确文章范围；输出字段及引用问题，不改正文 |
| 参考刷新 | 当前库与新固定输入；默认比较，明确确认后才切换 |
| 中断恢复 | 已记录现场与完整旧版或候选；核对后恢复，不回退文章 |

日常编辑后显式检查，不监听每次保存。查询读取库外绑定、安装凭据、manifest 与身份记录摘要；读取某页再核对该页，报告这是局部核验，不冒充全库检查。新建和刷新仍执行完整的对应门禁，不因查询为了快速返回而放宽写入要求。

文章扫描覆盖 PARA 四区，以显式 identifier 声明识别待校验记录。没有声明的文件单列未登记及未检查，不猜测内容类型，不计为通过；已声明但无效的身份和字段仍报错。文章检索读取实际元数据，不能把普通正文提及计入。查询和文章检查不重复运行 SHACL；词表结构结果绑定所使用的固定交付，不能从零条错误推定实体事实或语义已审核。

## 刷新与恢复

同一目标的工具写操作互斥。刷新和恢复前停止 Obsidian、同步及其他外部写入；工具锁不能约束任意其他程序。实现必须检查支持的文件系统条件，不满足时在写入前拒绝；当前工程限制在使用说明中明确。

1. 生成完整候选，核对当前绑定、旧基准、用户修改、未知文件及引用依赖；候选必须对应当前安装基准，过期候选不能覆盖较新版本。
2. 初建或切换前，在库外保存恢复记录、候选及必要旧版，记录知识文件和工程状态各自的摘要与位置。
3. 按明确写集安装知识条目和工程状态；用户 PARA 内容、附件、首页、模板、视图及配置不在普通刷新写集中。
4. 核对实际安装结果后才更新凭据并关闭恢复记录。中断时保留现场，不把某一侧完成等同整体成功。

恢复按日志、实际目录和摘要判断，保留中断后新增引用所需数据。文章相对链接按文章目录解释；无法安全回退时拒绝完成并保留证据。资料中的普通链接也应保护，不因它未登记为文章就忽略其引用依赖。

初建失败不能覆盖用户已写入的内容，也不能留下无法解释的成功标记。工程备份不自动清理。支持恢复不等于保证跨目录事务、跨设备同步或断电持久性。

## 验收范围

高价值检查覆盖身份与名称消歧、正确字段选择、来源与复杂值保留、可读路径冲突、当前及历史引用、用户内容保护和中断恢复。字段格式、文件集合及摘要由机械检查证明，不重复设计同义测试。

规范依据、应用约束和具体工程选择分别说明。本合同不宣称 DCAP、DCTAP、JCS、BagIt 或外部 reproducible-build conformance。命令、依赖、运行记录和实现限制在[应用包](../../../apps/obsidian-rdf/README.md)维护；本轮可验证开发行为，不使正式库自动切换。
