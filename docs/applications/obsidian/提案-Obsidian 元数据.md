# Obsidian 元数据

本方案规定文章字段、对象引用和条目查询在 Obsidian 中的表示，配合[使用与维护](提案-词表使用与维护.md)。以下表示用于独立编号 PARA 实例，正式新建范围见[正式库创建](决定-正式库创建.md)；旧库的字段、路径及值域迁移另行决定。

字段含义和生命周期由[内容模型](../../model/content/设计-内容模型.md)规定；应用通过已登记的 [Application Profile](../shared/概念-Application%20Profile.md) 选择具体表示，不反向改变概念、实体或字段的含义。

## 内容位置

文章存放在 `10-projects`、`20-areas`、`30-resources`、`40-archives`；领域与资源默认平铺，具体项目可保留目录。人工索引统一在 `00-indexes`，采用依据见[索引与存放](决定-索引与存放.md)。名称和位置用于组织使用，不赋予对象身份、主题或状态；归档仍保留原 UUID 与元数据。`01-inbox` 是自由捕获区，词条、模板、视图和附件不作为文章扫描。

人工索引与 PARA 中显式声明 identifier 的记录按内容模型校验。无声明文件单列未登记及未检查，不归类为已通过，也不由程序判断它是资料还是待补元数据的文章。损坏的身份声明仍报错。普通正文可以链接资料，受控 source、relation 等字段继续要求符合相应对象与身份约束。

## 字段用途

| 字段 | 所引用的数据 | 判断依据 |
| --- | --- | --- |
| `subject` | 计算机或写作概念 | 文章实际讨论的内容 |
| `entities` | 人物、组织、软件等实体 | 文章涉及的具体对象 |
| `type` | 已采用文档类型概念 | 读者使用文章的用途 |
| `genre` | 已采用体裁概念 | 当前内容模型规定的作者立场 |
| `form` | 已采用载体概念 | 文章采用的载体 |
| `references` | 已登记文献 | 实际引用的材料 |

这些是字段值域，不是六种互斥的资源本体类型。名称相同不能把主题概念、文档类型或实体自动合并；写作词表里的“教程”不自动成为 `type` 的选项。

## 属性约定

property 使用共同字段名。单值引用用 Text，多值引用用 List；链接在 YAML 中保存为带引号的字符串。名称用于查找和显示，引用以原身份和已安装的路径对应为准。

原生 List 允许输入其他内容，不能单独保证受控选择。工具必须检查对象种类、字段值域、基数和可用条件。同名 property 的原生类型作用于整个 vault，迁移前须核对已有设置。[Properties](https://obsidian.md/help/properties)

### 常用字段

| 字段 | 含义 | 原生类型 | 数量与约束 |
| --- | --- | --- | --- |
| `identifier` | 文章稳定身份 | Text | 1；工具分配小写 UUIDv4，永久保留且全库唯一 |
| `title` | 文章标题 | Text | 1；非空，与正文主标题的文字一致 |
| `subject` | 文章讨论的概念 | List，内部链接 | 1..n；适用的概念，作者依据定义与内容选择 |
| `entities` | 文章涉及的实体 | List，内部链接 | 0..n；涉及对象时填写，不从正文提及自动产生 |
| `type` | 文档类型 | Text，内部链接 | 1；已采用文档类型 |
| `genre` | 作者立场 | Text，内部链接 | 1；已采用体裁，不从 `type` 推导 |
| `created` | 内容建立日期 | Date | 1；ISO 8601 日期，不随普通编辑改变 |
| `status` | 文章处理状态 | Text | 1；`draft`、`active`、`deprecated`；工具只建立 draft |

### 补充字段

| 字段 | 含义 | 原生类型 | 数量与填写条件 |
| --- | --- | --- | --- |
| `form` | 载体 | Text，内部链接 | 0..1；采用相应载体时填写，长文不填 |
| `level` | 作者自评的认知活动 | Text | 0..1；`remember`、`understand`、`apply`、`analyze`、`evaluate`、`create`，不代表难度或学习已达成 |
| `source` | 本文实际派生自的对象 | Text，内部链接 | 0..1；文章、普通实体或文献，保留所指对象种类 |
| `references` | 实际引用的文献 | List，内部链接 | 0..n；已登记且适用的文献 |
| `modified` | 受记录修改日期 | Date | 0..1；按内容修改记录，不直接取文件 mtime |
| `isReplacedBy` | 直接替代本文的文章 | Text，内部链接 | 因直接替代而 deprecated 且存在后继时为 1，否则省略 |
| `relation` | 符合内容模型的文章关联 | List，内部链接 | 0..n；必须互反，主题不同且常被一起阅读，并不属于其他关系时使用 |
| `language` | 正文的主要语言 | Text | 0..1；默认 `zh`，与默认不同时填写，不由条目显示语言推断 |

可选多值字段可省略或保存空列表；可选单值字段省略。字符串“[]”“null”和没有解析的名称不是有效引用。原生 `tags`、`aliases`、`cssclasses` 服务个人组织、名称查找和显示，不替代上述字段，也不另建自由 keywords 入口。

### 工具列表

正式库《常用工具》按[工具列表属性](决定-工具列表属性.md)使用以下补充属性，仅适用于该列表，不属于共同内容字段，也不替代主题、实体引用或正式分类。

| 属性 | 原生类型 | 内容与约束 |
| --- | --- | --- |
| `tool_purpose` | Text | 可选单值，记录实际用途 |
| `tool_platforms` | List | 可选多值，记录已核对的操作系统 |
| `tool_install_url` | Text | 可选单值，记录官方安装说明的 HTTPS 地址 |
| `tool_category` | Text | 可选单值，记录个人列表的用途分组 |

原生 `常用工具` 标签表示人工收录；Base 只读取 `30-resources/` 内符合条件的 Markdown 文件，缺少补充属性仍保留该行。列表显示名称、用途、平台和安装入口，按 `note.tool_category` 分组，组内按名称升序。名称链接到工具笔记，安装入口链接到官方安装说明；用途、平台和安装入口缺失时显示“未填写”。

用途分组沿用系统与网络、语言环境、检索与改写、版本与协作、文档与媒体、编程代理、自动化工具，分组及归属的后续变更由人工决定。现有内容校验对四个补充属性保留未识别字段的信息提示，不能据内容校验通过宣称补充属性或分类已经验证。

## 引用表示

文章的内部链接定位条目文件，交付记录把该路径对应到原 IRI 或带目录语境的局部 ID。路径和链接显示文字都不成为新的概念身份。页面 `identifier` 是身份的可核对表示，手工改动它不能登记或批准一个新对象。

新开发库的文章和条目使用小写中划线文件名；中文保留，title 与源名称不变。文章独立 UUID 保存在 `identifier`。新条目按显示名称生成路径；同名消歧、非法字符处理和后续路径稳定性统一见[路径规则](提案-Obsidian%20导出与导入.md#路径规则)。这一表示沿用新 RDF/PARA 实例的稳定身份约定，不改写旧工具及旧库的文件名合同。

普通标引读取当前描述；引用历史含义或关系时保留对象身份与指定版本。论述名称或译文时保留名称身份和文字版本，涉及角色时还保留概念与角色。历史链接不自动成为 `references`，所需版本缺失时不能静默改读当前数据。

## 文章示例

以下展示新库的字段表示。实际条目路径以该次交付为准；显示同名不构成具体文章的采纳判断。

```yaml
identifier: "b5cb08aa-dc2f-4bbc-9d04-9634e8052c70"
title: "JavaScript 数组排序教程"
type: "[[90-vocabulary/document-types/教程|教程]]"
genre: "[[90-vocabulary/genres/背景|背景]]"
subject:
  - "[[90-vocabulary/concepts/排序与查找|排序与查找]]"
entities:
  - "[[90-vocabulary/entities/javascript|JavaScript]]"
created: 2026-09-23
status: draft
```

这一组 YAML 位于 Markdown 文件开头的 `---` 分隔线内，后接标题与正文。类型和体裁来自各自值域；文章使用了代码块或步骤，并不因此把这些写作手法也填为主题。

## 条目查询

先指定字段，再按名称或别名检索。例如 `subject` 中的“教程”表示文章讨论的主题，`type` 中的“教程”表示文章用途。检索不能把这两种字段语义混成同一候选列表。

每条候选返回名称、类型、身份、可粘贴链接、简短定义或范围和可用条件；缺失说明保持为空并明确提示。匹配只用于查找，不改写原名称，也不推断同义或概念合并。

准确名称在该字段范围内只有一个适用结果时，工具可解析它；多个结果则返回候选并要求明确身份。确定写入时仍用原身份核对最新版本，不能仅用查询时的文件路径继续写入另一个对象。

结构化详情按需返回定义、范围、名称与关系，以及原始数据位置。程序不必先读取整页 Markdown、完整 RDF 或展开的 Bases 代码，才能识别一个条目。

## 文章检索

默认在人工索引与 PARA 内容中，按选定字段的明确引用查文章。正文提及、全文搜索和 Backlinks 各有用途，不代替字段标引。通过多个概念或路径命中同一文章时，以文章身份去重。

主题查询可明确包含下位概念，只根据已采用的 `broader`／`narrower` 关系计算范围。实体、文档类型和文献不继承这一展开行为，也不能由查询反向修改文章元数据。

文章列表使用独立 Base，覆盖 PARA 四区，按标题、主题、实体、类型及状态显示和筛选。动态查询放在查询入口或共享视图中，条目页不必各复制一份长路径表达式。[Bases 语法](https://obsidian.md/help/bases/syntax)

## 更新规则

名称、定义或译文更新时保持原身份。工程身份对应和版本清单位于库外，库内条目仍保存可核对的原标识。常规刷新保留已安装的路径；更新页面的 title 与 aliases，不自动改写文章里的既有显示文字。

明确的文件重命名属于另一次操作，需要一起维护 Obsidian 内链、身份对应、查询引用、文件清单和摘要。原生 CLI 支持内链更新，但不能独自更新本应用的工程记录。[CLI 重命名](https://obsidian.md/help/cli)

停用对象退出新选择，旧引用仍应可解释。合并、拆分和替代不自动重标引文章。旧 `kb_*` 字段、值身份和文章路径的迁移继续分别列明，不借更新条目偷偷改写内容。

## 校验边界

| 检查对象 | 必须区分的结果 |
| --- | --- |
| 条目查询 | 字段范围、身份和可用条件；索引完整性不冒充全库检查 |
| 文章字段 | 缺失、基数、类型、UUID、日期和无效值 |
| 对象引用 | 缺页、身份冲突、错类型、退出、历史版本缺失 |
| 词表结构 | 适用 SHACL 规则及实际目标；未运行条件单列 |
| 内容语义 | 定义是否正确、标引是否恰当、状态是否获批，不能由机械检查代替 |

开发试选与正式准用分别记录。辅助文档类型、体裁、载体与文献仍需要各自采用依据，不能借概念试选权限扩大值域。新建文章只创建 draft，不批准状态变化。

查询、写入及刷新报告分别绑定所使用的数据版本。执行方式及当前结果见[独立应用包](../../../apps/obsidian-rdf/README.md)，原始输入、完整保留和恢复规则见[导出合同](提案-Obsidian%20导出与导入.md)。
