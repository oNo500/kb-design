# 视图排序

状态：已采纳，2026-09-08。用户批准将 Base 排序作为本地偏好保留，筛选、列和其他受管理内容继续严格校验，并修复正式库的内容入库。

## 适用范围

本决定引用 [Application Profile](../concepts/application-profile.md)、[应用约束](application-profile-boundary.md)和[词表参考刷新](obsidian-reference-refresh.md)，扩展后者仅接纳 Base 排版差异的范围。仅作用于完整 vault 中已登记的 `app/views/*.base` 与 `kb/views/*.base`，不改变独立参考导出的字节校验、词表语义、内容状态或回流边界。

表格视图的 `sort` 可以新增、更换、清空或删除。排序只能引用该视图 `order` 中已有的属性，每项只包含 `property` 与 `direction`，方向限 `ASC` 或 `DESC`，属性不得重复；笔记属性的 `note.` 前缀与其简写按同一属性核对。筛选、列及列次序、视图类型、名称、公式、分组和其他字段仍属于受管理结构，不因本决定取得个性化权限。

## 清单校验

应用清单的 Base 文件条目增加可选 `base_snapshot`，保存发布时的原始 YAML 文本；`sha256` 继续校验该快照的完整字节。运行时将实际文件与已核验快照解析为 YAML，仅去掉合格的 `sort` 后比较规范化内容。排序和 YAML 排版差异不阻断内容建立、校验或报告，不要求每次点击排序后刷新清单。其他文件仍按当前字节校验。

此扩展保留现有清单版本与无快照条目的读取。旧版工具严格拒绝新增条目字段，因此迁移后应使用支持本决定的工具；不得宣称新清单可由旧工具读取。

## 旧库迁移

无 `base_snapshot` 的旧库通过显式 `refresh` 迁移。只有旧哈希能与生成模板对应，且去除合格排序后的内容一致，才接纳当前 Base；不直接修改清单哈希绕过来源检查。祖先校验仅在临时副本中将已证明的差异转成旧版字节合同。

刷新保留 Base 实际字节，并在新清单保存快照。参考 Base 的新模板若与已保留排序存在结构冲突，拒绝刷新并交由人处理，不静默丢弃排序。普通写集仍为 `kb/` 与 `app/manifest.json`；保留发布前并发检查、失败回滚与成功备份。

## 依据范围

[Obsidian Base 语法](https://obsidian.md/help/bases/syntax)说明 Base 使用 YAML，视图可以保存排序等显示状态；属性可以区分笔记、文件与公式。本机差异实际记录为 `sort: [{property: file.mtime, direction: ASC}]`。本决定只采纳上述限定形状，不声称覆盖所有插件视图偏好。
