# 词表工程能力

词表工程负责把可核对的来源转换为自有词表，并提供校验、版本保留和应用读取能力。本文记录现有能力、维护责任和缺口；业务流程见[词表生成流程](../model/vocabulary/设计-词表生成流程.md)，实际操作见[词表工具链](指南-词表工具链.md)。

## 能力分工

| 环节 | 实现位置 | 输入与产物 | 能力边界 |
| --- | --- | --- | --- |
| 领域与来源确定 | 领域说明、组织配置、来源目录 | 领域范围、来源选择、分组规则 | 工程执行已确定的选择，不自动判断领域边界与来源权威性 |
| 来源下载 | `kb-sources fetch`、`fetch-cognitive-atlas` | 下载清单 → 原件快照、获取记录 | 支持超时、重试和下载限制；专用 API 获取支持已校验批次续传 |
| 原件校验 | `kb-sources verify` | 标准下载快照 → 校验结果 | 检查文件集、格式与哈希，不证明内容正确或来源权威 |
| 结构提取 | `extract`、`extract-all`、专用提取器 | 原件 → 结构记录、原文定位 | 原生结构化数据直接交给导入器；文献章节不自动成为概念层级 |
| 来源词表转换 | `kb-vocab import-*` | 来源记录 → 独立 Turtle、转换记录 | 各来源分别处理身份与关系；尚无统一的跨版本身份迁移能力 |
| 自有词表生成 | `kb-vocab build-system` | 来源 Turtle、配置、约束 → 一份自有词表 | 全量保留来源概念身份，统一词表归属、语言和表示；不自动合并同名概念 |
| 数据校验 | 基础校验、构建内 SHACL | 词表 → 错误、警告、转换统计 | 检查结构和规定约束，不替代语义判断；独立 `validate` 不包含完整构建门禁 |
| 版本管理 | `build-system`、`activate-system` | 新构建或已有版本 → `current` | 支持校验后切换、写锁和保留版本回退；不保证应用同步完成 |
| 查询与盘点 | `show`、`find`、`query`、字段盘点脚本 | Turtle → 节点、查询或字段报告 | 只读诊断，不修改词表、不产生采纳决定 |
| 交叉关系处理 | `kb-vocab review` | 来源词表 → 候选、证据、决定及映射产物 | 独立可选流程，不是全量生成的前置条件；未接入 AI 语义分析器 |
| 应用预览 | `apps/skosmos/` | 自有词表 → Fuseki 图与导航文件 | 已有导入实现；应用更新与词表版本切换尚未形成共同事务 |

`kb-sources` 负责取得和转录来源，`kb-vocab` 负责 RDF/SKOS 表示与自有词表构建，应用负责消费结果。`kb-core`、`kb-topics` 继续服务原有 YAML 路径；新 Turtle 产物不表示旧数据和 Obsidian 消费已迁移。

## 输入与产物

| 对象 | 权威位置或职责 | 维护方式 |
| --- | --- | --- |
| 来源事实 | 原件快照及获取记录 | 保留原件与哈希；新来源版本建立新快照 |
| 项目组织选择 | `data/inputs/vocabulary/knowledge-system.json` | 维护领域分组、来源采用方式和构建配置 |
| 来源词表目录 | `data/inputs/vocabulary/sources.json` | 指向明确的来源 Turtle；路径本身不等于内容版本锁定 |
| 数据约束 | `data/inputs/vocabulary/shapes.ttl` 与数据规范 | 规则变更与实现同步，不用放宽校验掩盖来源问题 |
| 来源转换结果 | `packages/kb-vocab/output/` 中的各来源目录 | 由导入器生成，保留身份输入及转换记录，不直接改 Turtle |
| 自有词表版本 | `output/vocabulary/versions/<build-id>/` | 保留词表、输入副本、来源副本和构建记录 |
| 当前读取入口 | `output/vocabulary/current/vocabulary.ttl` | 通过版本切换更新，应用读取这一入口 |
| 诊断与候选 | 校验、字段盘点、交叉候选和转换账本 | 用于解释结果，不作为正式概念或有效映射 |
| 应用数据 | Skosmos 的图、导航及导入记录 | 由同一词表快照生成；需要能证明实际加载的版本 |

自有词表使用一个 `skos:ConceptScheme`。领域通过 `skos:Collection` 分组，来源层级通过概念关系保留。未进入领域分组的概念仍属于自有词表，不能把分组覆盖率当作概念收录完整率。

## 变更边界

工程维护需要同时登记“谁处理文件”和“谁能改变含义”。包归属只说明实现责任，不授予来源选择或语义采纳权限。

| 变更 | 处理原则 |
| --- | --- |
| 同一输入重新生成 | 使用已有配置与工具，保留身份输入和生成记录 |
| 新来源版本 | 建立新快照，核对身份和关系变化，再更新来源目录 |
| 领域归属、概念合并、映射采纳 | 按治理权限确定，并保存可重放的配置或决定记录 |
| 字段与校验规则 | 同步数据规范、转换实现和约束；保留迁移说明 |
| 当前版本切换 | 校验目标版本，保留上一个可用版本；应用同步另行确认 |
| 输出删除或清理 | 区分持久数据与临时产物，不把 `output/` 当作构建缓存清空 |

权限依[治理](../governance/decision-making/设计-治理.md)执行。`review` 中的操作者和授权文本是审计信息，不是身份认证或自动授权机制。

## 依赖维护

现有工具优先使用第三方库：BeautifulSoup 处理 HTML，pdfplumber 及 pdfminer.six 处理文本 PDF，RDFLib 处理 RDF 和 SPARQL，defusedxml 处理 XML，pySHACL 执行约束，JSON Schema 和 PyYAML 处理配置。

依赖版本由 workspace 的 `uv.lock` 管理。引入或升级依赖前，检查现有等效能力、维护活跃度、体积影响和安全记录；锁定版本只证明依赖选择固定，不代表已完成安全审计。

## 维护缺口

以下是现有实现的限制，不是已完成的修复。治理重点是让来源更新、重建和消费状态可核对，避免增加重复人工确认。

| 优先级 | 缺口与证据 | 后果与补齐方向 |
| --- | --- | --- |
| 高 | ERIC 身份生成包含整份 XML 的哈希；修改一个条目的说明会改变其他未修改条目的 URI。IEEE 与 Cognitive Atlas 的身份复用限定同一来源输入 | 来源升级可能影响分组锚点和内容引用。需要稳定来源键及跨版本身份对应，不能把同源复用当作版本迁移 |
| 高 | 构建归档的配置引用 `sources.json`，归档目录实际保存 `catalog.json`；目录内部还保留原工作区相对路径 | 副本可以审计，但不能直接用归档配置独立重建。需要归档内部自洽的路径和重建入口 |
| 高 | 构建工具记录名称、版本和代码哈希，未完整保存锁文件、运行环境及可恢复的代码版本 | 有指纹不等于能恢复运行环境。需要关联可取得的代码、依赖锁和 Python 环境 |
| 中 | 转换账本记录来源到产物的处理；没有上一版本到新版本的完整差异报告 | 难以快速发现概念身份、关系和分组变化。需要自动生成版本差异，不必把全量人工审查加回构建流程 |
| 中 | Skosmos 的图替换、关系补充和导航生成分别执行，未自动形成统一完成记录 | 中途失败可能留下不同步的应用文件。需要记录实际加载哈希、各步状态和恢复方式 |

实现依据见 [ERIC 导入器](../../packages/kb-vocab/src/kb_vocab/eric.py)、[自有词表构建器](../../packages/kb-vocab/src/kb_vocab/system_build.py)和 [Skosmos 导入脚本](../../apps/skosmos/import-current.sh)。

## 验收证据

2026-09-13 的本地核对中，当前构建已生成并通过构建校验；概念缺少首选名、空标签和语言过滤后说明值缺失仍以警告记录。通过校验不表示名称、语义或来源更新问题已经全部解决。

Skosmos 的当前导入记录和导航文件记录了与当前词表一致的哈希，但另有历史导航验证报告保留旧哈希。这说明证据文件尚未统一管理，不能据此断言当前应用数据错误；本次没有查询运行中的服务。

维护验收应分别提供来源完整性、转换与身份处理、结构校验、版本切换、应用加载版本的证据。不能用单个“校验通过”覆盖整个流程，也不宣称已满足完整的可复现构建或持久性保证。
