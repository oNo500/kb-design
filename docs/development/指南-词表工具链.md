# 词表工具链

本指南说明来源获取、结构提取、来源词表转换、自有词表生成和应用同步的执行顺序。能力边界与待补项见[词表工程能力](设计-词表工程能力.md)。命令从仓库根目录执行；大写路径参数是占位符，使用前替换为实际路径。操作仍按已授权范围执行。

## 执行起点

| 当前情况 | 执行路径 |
| --- | --- |
| 已有来源 Turtle，只需生成自有词表 | 核对输入配置 → 全量构建 → 读取结果 → 按需同步应用 |
| 来源内容更新 | 新快照 → 原件校验 → 对应解析 → 来源转换 → 身份变化核对 → 更新配置 → 全量构建 |
| 只调整组织配置或字段规范 | 更新已采纳的配置、约束及实现 → 全量构建 |
| 词表已更新，应用尚未更新 | 应用同步，不重复下载和转换 |
| 需要恢复已有版本 | 校验并切换保留版本 → 同步应用 |

当前来源目录已有六份 Turtle，因此通常从输入配置和全量构建开始。知识覆盖文献的通用提取独立保留，不是主题词表生成的前置条件。

## 环境准备

使用仓库的 Python 环境和统一锁文件：

```sh
uv sync --all-packages --locked
```

下载、解析和导入分别保存产物。需要新输出目录的命令不要指向已有版本，也不要直接修改生成的 Turtle。

## 来源获取

普通文件按来源清单下载；命令返回的具体快照目录用于后续校验：

```sh
uv run kb-sources fetch --manifest MANIFEST_FILE --output SNAPSHOT_ROOT
uv run kb-sources verify SNAPSHOT_DIR
```

`SNAPSHOT_ROOT` 是容纳快照的根目录，`SNAPSHOT_DIR` 是本次取得的具体快照。`verify` 检查标准下载快照，不适用于手动获取记录或自有词表构建目录。手动材料按已有获取记录保留原件、地址和哈希，不伪装为自动下载结果。

Cognitive Atlas 使用专用 API 获取与导出：

```sh
uv run kb-sources fetch-cognitive-atlas --manifest MANIFEST_FILE --output BUNDLE_DIR
uv run kb-sources export-cognitive-atlas BUNDLE_DIR --output TRANSCRIPTION_DIR
```

同次获取可以复用已校验批次；来源升级使用新目录。分批获取不保证远端 API 在整个期间保持同一事务快照。

## 解析分支

| 来源形式 | 工具与处理结果 |
| --- | --- |
| 原生 Turtle、XML、TSV、JSON 或相应压缩包 | 直接交给对应来源导入器；批量提取中记录为原生结构化输入 |
| IEEE PDF | `extract-ieee` 提取词条及明确关系，保留定位与异常记录 |
| Cognitive Atlas API 数据 | `export-cognitive-atlas` 校验完整获取结果并导出转录数据 |
| 普通 HTML、文本 PDF | `extract` 或 `extract-all` 提取章节、段落等文献结构，不自动生成概念层级 |

IEEE 专用提取命令：

```sh
uv run kb-sources extract-ieee --acquisition ACQUISITION_FILE --output EXTRACTION_DIR
```

当前提取器适用于 2025 年 7 月 Version 1.04。需要既有第三方对照材料时，`--reference-csv` 与 `--reference-taxonomy` 成对提供。未分配文本以诊断保留；退出码为 `2` 时不能当作完整成功继续发布。

普通文献提取命令：

```sh
uv run kb-sources extract SNAPSHOT_DIR --file-id FILE_ID --output EXTRACTION_DIR
uv run kb-sources extract-all --snapshot SNAPSHOT_DIR --output EXTRACTION_DIR
```

批量选择多个快照可重复传入 `--snapshot`。使用 `--sources` 扫描根目录时，如果同一来源存在多个可选快照，应改用明确的快照列表。图片和 OCR 不在这条处理路径中。

## 来源转换

解析完成后，按来源执行一个导入器，不把全部文件套进同一种 PDF 或 HTML 转换流程。

| 来源 | 导入命令 | 输入 |
| --- | --- | --- |
| IEEE | `import-ieee` | 专用提取的词条 JSON |
| MSC2020 | `import-msc` | 来源分类表文件 |
| ERIC | `import-eric` | 来源 XML |
| PhilPapers | `import-philpapers` | 来源分类结构文件 |
| UNESCO | `import-unesco` | 原生 RDF 数据 |
| Cognitive Atlas | `import-cognitive-atlas` | 已校验的专用转录数据 |

例如：

```sh
uv run kb-vocab import-msc SOURCE_FILE --output NEW_SOURCE_DIR
uv run kb-vocab import-ieee SOURCE_FILE --identities PRIOR_VOCABULARY_FILE --output NEW_SOURCE_DIR
```

输出目录必须是新目录。IEEE 和 Cognitive Atlas 重做同一来源输入时，使用已有 Turtle 作为 `--identities` 输入复用身份；省略时会新建身份。这一能力不解决跨来源版本迁移。ERIC 也存在来源内容变化导致 URI 变化的限制，因此来源升级不能直接视为无影响的文件替换。

当前目录中的来源 Turtle 已包含既有冲突处理结果。重新导入的结果不能未经相应处理就覆盖这些路径；来源导入成功与得到当前已处理版本是两件事。

## 输入配置

构建前核对以下文件：

| 文件 | 职责 |
| --- | --- |
| `data/inputs/vocabulary/sources.json` | 列出实际采用的来源 Turtle |
| `data/inputs/vocabulary/knowledge-system.json` | 定义自有词表、领域分组和采用方式 |
| `data/inputs/vocabulary/shapes.ttl` | 定义构建使用的字段与结构约束 |

来源目录路径相对于目录文件解析。更新来源版本时同步路径和依赖该来源的组织规则，保留旧版本。配置不直接决定来源事实是否正确；同名也不自动产生概念合并或映射。

## 全量构建

使用当前输入生成新版本，并在验证通过后切换当前入口：

```sh
uv run kb-vocab build-system --config data/inputs/vocabulary/knowledge-system.json --output-root output/vocabulary
```

构建顺序是读取来源和配置、生成自有表示、执行结构约束和完整性检查、写入版本记录，最后切换 `current`。有阻断错误时不切换当前入口；警告保留在结果中。

| 产物 | 位置 |
| --- | --- |
| 应用读取入口 | `output/vocabulary/current/vocabulary.ttl` |
| 保留版本 | `output/vocabulary/versions/<build-id>/` |
| 输入与来源副本 | 版本目录中的 `inputs/`、`sources/` |
| 构建及校验记录 | 版本目录中的 manifest、来源记录和校验报告 |

需要只生成而不切换时，将 `--output-root output/vocabulary` 换为 `--output NEW_BUILD_DIR`。这两项互斥。可用 `--build-id` 指定版本名，但它只能与 `--output-root` 配合。

当前归档配置尚不能直接独立重建：归档来源目录文件名及内部路径未完全自洽。不要把版本中的 `inputs/config.json` 当作已经可用的离线重放入口。

## 查询与诊断

查找标签和查看节点：

```sh
uv run kb-vocab find output/vocabulary/current/vocabulary.ttl LLM
uv run kb-vocab show output/vocabulary/current/vocabulary.ttl CONCEPT_URI
```

`show` 接受 URI 或完整标签；查找不确定的名称先用 `find`。SPARQL 入口只允许本地只读 SELECT：

```sh
uv run kb-vocab query output/vocabulary/current/vocabulary.ttl --query-file QUERY_FILE
```

需要单独检查基础图约束或盘点字段时：

```sh
uv run kb-vocab validate output/vocabulary/current/vocabulary.ttl
uv run python packages/kb-vocab/scripts/profile_vocabulary.py output/vocabulary/current/vocabulary.ttl --output NEW_PROFILE_DIR
```

`validate` 不能替代构建中的完整 SHACL 校验；字段盘点是诊断，不是新增字段的自动授权。构建已完成相应校验时，不为重复取得相同证据再跑一遍。

## 应用同步

Skosmos 环境准备见[应用说明](../../apps/skosmos/README.md)。服务可用后，从仓库根目录进入应用目录导入当前词表：

```sh
cd apps/skosmos
./import-current.sh
```

脚本先捕获一份当前 Turtle，再用于图导入和导航生成，避免执行期间 `current` 切换导致两次读取不同来源。图替换、补充关系与导航生成仍是分步执行，尚无共同回滚机制。

应用成功需要证明图与导航加载了同一来源哈希。现存验证 JSON 可能来自历史运行，不能仅凭文件存在判断本次同步成功。该流程也不更新原有 YAML 消费者或外部 Obsidian 知识库。

## 版本回退

切换到 `versions/` 中已有且通过校验的版本：

```sh
uv run kb-vocab activate-system --output-root output/vocabulary --version BUILD_ID
```

`BUILD_ID` 是该根目录下的版本目录名，不是任意历史产物路径。词表入口回退后，已运行的应用需要重新导入；词表回退成功不表示应用已经回退。

## 失败处理

| 失败位置 | 处理方式 |
| --- | --- |
| 下载或原件校验 | 检查获取记录、文件格式和哈希；保留旧快照，不将失败原件继续导入 |
| 批量结构提取 | 根据失败项定位；成功产物可以保留，但不能把部分成功声明为全部完成 |
| IEEE 文本未分配 | 检查提取诊断及版本适配；退出码 `2` 不按完整提取处理 |
| 来源转换或身份变化 | 保留新旧结果，解决转换问题或跨版本对应后再替换输入 |
| 自有词表构建 | 读取错误和转换记录，修正输入或实现；保留当前可用版本 |
| 应用同步 | 定位图、关系补充或导航步骤；恢复后从选定版本重新导入并核对哈希 |

交叉候选的 `review` 工具是独立可选流程，详细命令见[词表工具说明](../../packages/kb-vocab/README.md)。它不是上述全量构建的必经步骤，也不承担自动 AI 语义判断。
