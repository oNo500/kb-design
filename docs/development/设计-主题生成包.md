# 主题生成包

## 职责

`packages/kb-topics/` 负责从现行输入与采纳记录生成 `data/vocab/topics.yaml`。包名为 `kb-topics`，Python 模块为 `kb_topics`，命令为 `uv run kb-topics`。

生成包依赖 `kb-core` 的仓库定位、语言采纳、来源与书目校验能力。核心包不反向声明生成包依赖；应用继续依赖核心包读取主题数据，不需要调用生成器。

## 文件结构

- `src/kb_topics/build.py`：主题组装、来源迁移、输出路径检查和命令入口。
- `src/kb_topics/gbt_en.py`：现行学科英文名称表。
- `tests/`：保留生成身份、依据授权与输出写集的行为检查。

`kb_core.build_topics` 保留兼容入口和原函数导入路径，实际转交生成包。单独安装核心包不包含生成器；使用旧生成命令时也需要安装 `kb-topics`。仓库 workspace 统一安装两者。

## 输入与输出

输入仍由 `data/inputs/topics/`、名称表、生成规则和核心依据校验所需文件组成，完整清单见[主题词表](../model/vocabulary/设计-主题词表.md#生成路径)。本次拆包不改变节点、关系、状态和依据，也不实施[关系统一表示](../model/vocabulary/决定-关系统一表示.md)。

默认命令写入正式生成文件；审查使用 `--output build/<新文件名>.yaml`。显式候选路径必须不存在，并限于仓库 build 子目录或允许的外部临时位置。`--references` 与 `KB_DESIGN_ROOT` 的原语义保持。

生成器中已有的顶层选择、合并、多上位、状态规则和历史迁移继续保留，拆包不表示这些规则已经完成独立输入设计或语义复核。

## 兼容约束

旧命令 `uv run kb-core build-topics` 继续可用。为保持原有生成字节，输出头部暂保留该兼容命令。后续修改头部应作为显式输出变更处理。

## 实施步骤

- 将生成器和专用名称表移入新包，接入 uv workspace 与统一锁文件。
- 保留核心兼容入口，迁移生成器行为测试，更新当前输入路径说明。
- 在临时路径比较拆包前后生成字节，验证新旧命令等价。
- 运行授权缺失、路径保护与命令参数检查，验证数据写集未扩大。

## 验收依据

字节对比用于发现包迁移导致的节点、关系、状态、来源或序列化变化；行为检查用于发现新入口绕过授权或覆盖非目标文件的问题。安装与入口检查用于发现 workspace 依赖和命令分发失败。文档使用链接校验，不另建内容存在性测试。
