# 项目文档

kb-design 规定知识内容怎样描述、分类、引用和维护，并提供维护词表与应用这些规则的工具。知识内容本身保存在仓库外，项目文档说明它的组织依据、现行设计和应用边界。

初次阅读从[项目概述](概述-项目.md)开始，了解项目由来与范围；整体职责与工程关系见[项目架构](设计-项目架构.md)。具体设计按下表查找。

## 知识模型

| 主题 | 主要问题 | 阅读入口 |
|---|---|---|
| 内容 | 一条内容有哪些字段，怎样标识、引用和维护？ | [内容模型](model/content/索引-内容模型.md) |
| 主题词表 | 内容讲什么，主题之间怎样组织和关联？ | [主题词表](model/vocabulary/索引-主题词表.md) |
| 实体 | 内容涉及的软件、组织和编程语言怎样登记？ | [命名实体词表](model/entities/索引-实体.md) |
| 术语 | 概念、定义、多语名称和各自依据怎样分开？ | [术语设计](model/terminology/索引-术语.md)、[术语表](参考-术语表.md) |
| 来源 | 文献身份、获准用途和具体字段依据怎样对应？ | [文献与来源](model/sources/索引-文献与来源.md) |

## 应用与工具

具体应用引用共享模型，再规定其表示方式与操作行为。

- [共同适配要求](applications/shared/索引-共同适配要求.md)：共享模型与具体表示之间的约束。
- [Obsidian 映射](applications/obsidian/索引-Obsidian%20适配.md)：内容、词表和术语如何在 Obsidian 中表示和使用。
- [词表预览](applications/vocab-preview/索引-词表预览.md)：维护者如何浏览仓库工作区的词表及其依据。
- [开发指南](development/索引-工程开发.md)：开发环境、命令与工程操作。

## 文档效力

现行设计规定当前规则；已采纳决定记录具体选择及其授权；概念解释和来源笔记支持理解与核对；草案中的推荐需经采纳才生效。文档按主题关联，效力由各自内容与适用决定确定。
