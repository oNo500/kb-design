# 维护

维护让词表和内容随时间保持可信。它在[治理](governance.md)授权之下运行：治理规定政策、决策权和阈值复核，维护按规则执行。维护由一个循环中的六个要素组成。

```
对象 ──有状态──▶ 指标 ──达到阈值──▶ 触发 ──▶ 动作 ──▶ 审计追踪
```

本文按这六个要素组织。“指标”“阈值”“监控”的用法依据 ISO 15489-1 §6.4 的监控与评价。来源复核、`candidate` 概念记录转正、断言复核、剩余监控和发版都是这个循环的实例，不另立规则。指标和观察只触发复核；正式修改始终服从[治理](governance.md)的决策权。

## 对象与状态

现行维护作用于以下六类对象，每类对象有自己的状态。来源字段按已采纳的[来源字段合同](../../decisions/source-v2-field-contract.md)实施；具体字段与引用按[来源收尾](../../decisions/source-completion.md)采纳范围实施，严格工具不保留旧格式兼容。

| 对象 | 在哪 | 状态 | 说明 |
|---|---|---|---|
| 来源实体 | `data/vocab/entities.yaml`，kind 为 standard／publication | status 为项目状态；source_status 为 current／superseded／withdrawn，或省略表示外部状态未核实 | tier 另行决定复核周期，不是状态，不自动增加用途 |
| 概念记录 | `data/vocab/topics.yaml` | `unassigned`／`candidate`／`active`／`deprecated` | 见[主题词表设计](../model/topics.md) |
| 命名实体记录 | `data/vocab/entities.yaml` | `candidate`／`active`／`deprecated` | 见[命名实体词表](../model/entities.md) |
| 断言 | 各词表的人工赋值字段 | 外部 basis 与项目 assertions 分开 | 见下节；语言依据使用独立合同 |
| 内容单元 | 知识库 | `draft`／`active`／`deprecated` | 见[内容模型](../model/content-model.md)；不删，处置决定在该文档中 |
| 词表版本 | 各词表的 `version` 块 | 当前版 | 见[词表版本](../model/versioning.md) |

来源实体、概念记录和命名实体记录的状态互不继承。`unassigned` 只属于现行主题概念；`candidate` 概念记录只表示概念进入现行审核，不表示其中任一 designation 获得试用资格。

来源用途继续受现行 `tier` 和[来源用途登记](../model/sources-registry.md)共同限制：de-facto 和 vendor 默认只作入口和例证，不作定义来源，vendor 的接口文档不进概念文和设计文档；有版本号的 de-facto 只有在正式用途已经登记时才可承担现行结构用途。[限定定义许可](../../decisions/term-limited-definition-source-use.md)只允许知识体系、普遍接受的知识使用列明的 swebok 材料，知识领域、知识单元、主题使用列明的 cs2023 材料，体裁使用列明的 iptc-genre 材料。每项许可绑定同一术语概念的完整 `definition_source_permission`：来源、登记档级与版本、实际材料、核对日期、概念依据和精确定义值，并同时要求完整 record grant。来源登记版本不冒充网页 revision；许可不改变来源 tier、版本或用途，不开放其他概念和定义。其他 de-facto／vendor 定义根默认拒绝，不以同一来源的泛许可、其他概念的决定或旧版定义放行。

### 能力边界

来源实体外部状态、来源用途角色状态、来源复核义务状态、候选术语记录、术语状态转换和术语复核义务已经有模式或操作接口。字段和角色按各自已采纳决定实施；接口存在不自动接管现行六类对象的决策权。

| 接口 | 已实现能力 | 当前边界 |
|---|---|---|
| 来源实体与用途 | 结构化地址、外部状态、字段级依据、复核字段、观察入口、逐角色状态、决定引用和只追加历史 | 本批字段与具体角色按来源收尾决定采纳；完整记录的机械合格不代替证据、决定或正式切换 |
| 来源义务与索引 | 开启、解决、再次触发和反向定位接口 | 正式来源义务和正式索引不存在；接口结果不是复核结论 |
| 术语记录与转换 | 三层记录、独立状态、身份与精确采纳校验 | 本批具体值按采纳决定实施；不替代主题或实体状态；publication 已通过规定验收并启用 |
| 术语义务与索引 | 义务转换、决定反查和双向定位接口 | 正式术语义务和正式索引不存在；没有获准周期或阈值 |
| 术语生成与诊断 | 受精确发布门禁的确定性生成和 Markdown 正文报告 | terms 为术语唯一编辑源，glossary 只读生成；诊断仍为 `report-only`，历史纠正标签不作准用名 |

模式中的对象和测试夹具中的状态不是待维护的正式实例。术语数据按[术语具体采纳](../../decisions/term-data-values.md)实施，发布已按[术语发布](../../decisions/term-complete-publication.md)完成；不得因接口存在而创建义务、委托、消费者或切换状态。[术语实施结构](../../decisions/term-complete-structure.md)仅为内容单元、断言、阈值的既有概念和定义开放 project basis，并仅为 assertion、threshold 两个既有英文形式开放相同依据。project 保存 approval、origin 的 commit／file／locator 与 rationale；有效 L3 决定须精确覆盖完整记录及该项目范围。它保存迁移前已存在的本库含义，不是外部依据、英文模型兜底或第二个日常编辑源；中文形式继续使用独立语言依据。

### 断言

人工赋值表达项目判断，designation 的形式依据回答名称能否采用，概念对应依据回答所指为何，字段 basis 回答具体值或关系为何成立。三者互不替代。

| 词表 | 人工赋值字段 |
|---|---|
| 主题词表 | 本地概念的 broader、related、scope；复制概念之间的合并 |
| 命名实体词表 | subjects、form 的类别选择、scope、vendor |
| 内容单元 | subject、type；具体依据表示仍待决定 |

外部依据使用 entity、locator、按内容可变性要求的 checked。subjects 的依据使用 values 与 references 分组，明确每条材料支持哪些主题；values 不得超出该记录 subjects，外部依据与项目判断合计覆盖全部 subjects。复制派生与映射也分别要求相邻依据，不能因“直接复制”免除 source 或 match 的证据门禁。

原 self 归属判断以 assertions.subjects 保存 values、disposition: project_assertion、original: self、migration。原 source: self 以 assertions.source 保存项目建立事实；外部 source 与该判断互斥。载体数组的本地分析按 Q16 保存 local_analysis，不充当外部 source 或 external_group。

紧凑引用、旧 scope 标记和未核材料保留在迁移审计；只有确认材料、定位和逐值范围后才转为严格 basis。不能把未核对外部引用放进 assertions 解除阻断，也不能依长期使用自动取得依据。[来源收尾](../../decisions/source-completion.md)明确隔离的 17 条 match 保存于决定隔离清单与 Git 历史，不进入正式引用；对象、标签、状态及其他关系保留。该处置只适用于列明旧值，不能以隔离名义自动跳过其他引用。subjects 仍有项目判断的实体不得 active；语言 legacy: self 的原有限制继续适用。本地 source 判断仅表示建立方式，不能与归属或标签尚无依据混为一谈。

核到文字后的结构性更新与归属、关系采纳分别服从[治理](governance.md)。证据存在不自动批准新的判断。语言第 5 级模型判断继续按模型授权合同复核原英文、范围与采纳记录，不改变项目状态；历史 none 不表示第 6 级未采用结论。

## 指标

现行指标是脚本可以计算或外部可以通知的量。内容使用计数只有在具名消费者实际实现并启用后才成为指标输入；未来正式计数只读取通过校验的内容单元受控字段。

| 类 | 指标 | 对象 | 来自 |
|---|---|---|---|
| 计数 | 被内容单元引用的次数 | 概念记录、命名实体记录 | 内容单元的 `subject`、`entities`（Z39.19 §11.1.3.4 b） |
| 计数 | 未标引概念记录数及占比 | 概念记录 | `status: unassigned` |
| 计数 | `self` 断言数及占比 | 断言 | 外部 basis、assertions.subjects 与语言 legacy 标记 |
| 计数 | 处于 `candidate` 状态时经过的编辑审核次数 | 概念记录、命名实体记录 | `added` 与审核日期 |
| 计数 | “其他”类目的下位概念数 | 概念记录 | GB/T “其他学科”等剩余类目 |
| 计数 | 候选识别器报告的独立字符串数、总出现次数和出现文件数 | 带上下文的未解析字符串线索 | 公开的抽取、排除、标签比较和规范化规则（Z39.19 §11.1.3.4 a） |
| 计数 | 没有匹配任何概念的检索次数 | 带上下文的未解析字符串线索 | 应用提供的检索记录（Z39.19 §11.1.3.4 c） |
| 时间 | 距上次复核的月数 | 来源实体 | review.checked；旧日期仅作迁移历史 |
| 时间 | 距上次编辑审核的月数 | 词表 | `data/audit/maintenance/signals.yaml` |
| 外部事件 | 来源发布新版 | 来源实体 | 结构化 watch 的 locator 与 signals |
| 外部事件 | 链接失效 | 来源实体、引用 | 链接检查 |

脚本输出和人工提名后的 `candidate` 概念记录分别计量。未解析字符串保留来源上下文，只是复核线索；它不会因未匹配而直接成为项目采用的名称、概念、关系或结构结论。

未标引、`self`、长期 `candidate` 和“其他”四项对应 Star 与 Bowker 的剩余类目：分类没有安放好的内容，其规模和增长是分类失效的指标。维护不消灭这些内容，而是持续监控。每个现行指标的历次值记入 `data/audit/maintenance/signals.yaml`。

正文 Wikilink、Backlinks、用户索引、aliases、unlinked mentions 和 Graph edges 都不是正式计数输入。它们可以提供人工探索线索，不能替代受控字段的语义或校验结果。检索次数也只来自可审计的检索记录；现有检索界面或近期查询显示不构成查询日志。

[Obsidian 映射](../targets/obsidian.md)和 `apps/obsidian/` 中的 `kb-obsidian` 工具已经实现内容建立、只读校验与派生报告，已观察到正式 vault 有 draft 内容，但内容消费者没有正式激活。旧空库报告不提供当前引用次数；应用没有可审计检索记录，因此仍不提供未匹配检索次数或相应触发，见[决定记录](../../decisions/form-independence.md)。

已经实现的辅助材料不自动成为现行指标。

| 材料 | 能说明什么 | 不能说明什么 |
|---|---|---|
| 来源固定夹具观察 | 探测选择、信号分类和正式树不回写的行为 | 真实来源可用性、外部状态、内容变化或正式复核结果 |
| 来源反向索引 | 某一身份、角色、决定或义务可能影响的位置 | 影响位置的值应怎样修改 |
| 来源义务接口 | 在正式输入存在时计算复核事项的机械转换 | 不能证明当前已有正式义务或义务已经解决 |
| 术语正文诊断 | 动态 Markdown 中带上下文的同形或未匹配线索 | designation、概念、违规、阻断或术语候选结论 |
| 术语维护索引 | 在正式输入存在时反查决定、义务和对象 | 不能替代具体数据采纳，不能证明委托、义务或周期已经启用 |

## 阈值

所有现行数字只在本节出现，其他文档和脚本引用本表。除标明外部依据的项目外，其余均为本库估值，须在首轮维护，即第一次编辑审核完成后校准。

| 指标 | 阈值 | 依据 |
|---|---|---|
| 引用次数，`unassigned` → `active` | 1 次，或有下位 | 本库 |
| 引用次数，`candidate` → `active` | ≥ 3 次，且有 `scope`，且通过审核四问，且归属 assertions 与语言 legacy 无 self | 本库 |
| `candidate` 概念记录删除资格 | 引用为 0 连续两次编辑审核 | 本库 |
| 编辑审核触发 | `candidate` 记录攒到 20 个，或距上次审核满 12 个月 | 本库 |
| 某节点下 `self` 断言 | ≥ 5 | 本库 |
| 某节点下 `candidate` 记录 | ≥ 5 | 本库 |
| “其他”类目下位 | ≥ 3 | 本库 |
| 某顶层未标引占比 | 连续两次编辑审核（约 12 个月）无变化 | 本库 |
| 来源复核，de-jure | 24 个月，或发新版 | 本库 |
| 来源复核，de-facto | 12 个月 | 本库 |
| 来源复核，vendor | 6 个月 | 本库 |
| 来源复核，archival | 不复核内容 | 内容固定 |
| 链接检查 | 3 个月，所有档相同 | 本库 |
| 过度使用的概念 | 单个概念的引用占全部引用 ≥ 10% | Z39.19 §11.3.1.3：过度与过少使用都是修改或删除的复审线索；数字为本库估值 |

review 使用 checked、next_due、interval_months、grace_days、obligations；日期计算按既有周期、月底规则和 30 天宽限。本批 review 的全面复核日期保持为空，缺值不能充当已复核证明。watch 的地址／重定向周期与内容周期按[来源实体](../model/entities.md#来源记录)分别保存，不能并入人工复核周期；每 3 个月的链接检查仍是独立事项。

术语接口没有获准的复核周期、阈值或自动动作。不得把 6、12、20、24 个月、30 天或任何现行 `candidate` 阈值继承给术语义务。

## 触发与动作

指标达到阈值后只触发有权限的复核或提案。动作只允许以下集合：**批准、废弃、删除、拆分、合并、找依据、复核来源、注明不覆盖、发版**。每个动作所属的决策权级别见[治理](governance.md)。

| 指标达到阈值 | 动作 |
|---|---|
| `candidate` 概念记录达到批准条件 | 批准：`candidate` → `active`（Z39.19 §11.1.6 approved） |
| `unassigned` 概念记录被引用 | 批准：`unassigned` → `active` |
| 本地 `candidate` 概念记录引用为 0 连续两次审核 | 只取得删除资格；AI 列清单，人批准后才能删除。其他状态和单个表示形式不继承该资格 |
| 某节点下 `self` ≥ 5 或 `candidate` 记录 ≥ 5 | 拆分：该节点需要下一级类目；先找文献依据，有依据才建 |
| “其他”类目下位 ≥ 3 | 拆分：寻找正式类目；找不到的保留在“其他”并写明 |
| 某顶层未标引占比长期不变 | 注明不覆盖：在顶层概念的 `scope` 写明原因；或承认尚未覆盖，不修改结构 |
| 过度使用的概念 | 拆分为更具体的概念，或增加下位概念（Z39.19 §11.3.1.3） |
| 两个概念被判断为同一个 | 合并：保留一个，另一个转为 `deprecated` 并记录 `replaced_by` |
| `self` 断言 | 找依据：核对来源文字；核对逐值支持范围，采纳后更新 basis 与对应 assertions，再按状态门禁处理 |
| 来源复核到期或发布新版 | 复核来源，见下文 |
| 链接失效 | 找官方新地址，其次 DOI／arXiv，最后 archive.org 快照 |
| 一批批准、废弃、来源改版后的增删改 | 发版，见[词表版本](../model/versioning.md)；只补 `scope`、`alt`、`match` 不触发 |

观察、索引、义务和工具通过都不是新动作。它们不能自动批准、废弃、删除、拆分、合并、改来源、改术语或发版，也不能把第二级或第三级事项降为第一级。

### 候选的产生

输入线索与 `candidate` 概念记录按以下顺序处理。

1. 脚本在 Git 中动态取得 Markdown 清单，识别带来源上下文的字符串或名词短语。标题、加粗内容和中文引号纳入；代码围栏、行内代码、链接目标和路径排除；规范化只使用明确批准的规则。
2. 脚本把识别结果与现行登记和三份现行词表中已登记的首选、替代和隐藏标签比较。术语登记读取先完整核对 terms/state，再使用获准现行形式及原模型标签；layout 的历史纠正标签不作为准用形式。
3. 已匹配结果按概念 ID 复核；未解析字符串留在 `report-only` 输出中，并分别记录独立字符串数、总出现次数、文件数、精确位置和上下文。
4. 人工可以从未解析结果或其他材料中提名。提名后先判断目标概念，再核验表示形式的采用依据。
5. 需要新增主题概念时，只有概念判断和依据核验完成后，才建立 `status: candidate` 的概念记录；经核验的表示形式作为现行记录标签保存。输入若表示命名实体，另按[命名实体词表](../model/entities.md)处理。

未被提名的字符串留在报告中，等待后续复核。未命中的检索同样只提供带上下文的线索；是否进入概念记录仍由人工判断。通用 `origin` 不作为主题目标字段，也不由候选识别结果补写。

348 条术语迁移账本只保存冻结审查和消费者去向。`keep`、`defer`、`remove` 及其当前去向不创建主题候选或术语候选，不取得 designation 准入，也不授权删除。本批术语记录与独立状态按具体值决定实施；编辑源与列明的术语生成、参考消费者已在规定验收后切换，委托和正式义务不随之启用。

### 候选的审核

批准 `candidate` 概念记录前，按 Z39.19 §11.3.1.1 的四问审核。

1. 目标概念已由一个现有概念覆盖，或可由多个现有概念组合表达吗？如果可以，不新建概念记录，转入独立的表示形式审核。
2. 目标概念是否需要 `scope`？
3. 经准入核验的首选、替代和隐藏标签怎样记录，`label.zh`、`label.en` 和 id 是否符合现行规则？
4. 目标概念与现有概念之间的 `broader`、`related` 怎样建立？

概念覆盖判断和表示形式审核不能合并。同义表示不能制造概念缺口，同形异义也不能制造概念覆盖；本节接受程序中的 `candidate` 状态只作用于现行概念记录，不作用于单个表示形式，也不替代术语记录自己的采纳与状态门禁。

### 来源的复核

来源复核按字段、材料与实际影响处理，不从页面访问成功推断外部状态。[来源数据批次](../../decisions/source-data-batch.md)允许 source_status 省略，含义仅为“外部状态未核实”；它不是 current、不适用或 unknown。version 必有但可为 null，含义仅为“未登记可核实版本”，不表示发布者没有版本。旧值留在迁移 history.before，不能以当天日期补齐。本批全面复核日期为空，周期与可用性、重定向观察配置只表示已采纳维护选择；替代对象为空只表示未登记，不表示已确认没有替代。

1. 确认材料身份、版本及定位，检查引用事实与本库实际使用部分。
2. 有新版时读取变化与替代信息，分别判断 version、source_status、replaced_by 及下游引用。状态未核实可以省略，版本未登记可核实值可以为 null；已填写状态仍须发布者依据与精确采纳，不填默认 current，不删除已有合格结论。
3. 使用反向索引定位 basis、source、match、external_group 和语言引用，逐项判断影响；索引命中本身不是修改结论。隔离清单另行查阅，正式索引无边不能证明历史无引用。外部分组只证明组身份，现有数组的缺项和顺序差异仍须独立复核。缺整源外部状态不自动否定具体材料，但每条关系仍须证据和采纳；依赖外部现行状态的操作继续阻断，无版本 de-facto 仍无 structure 资格。
4. 角色资格变化与具体关系变化分别提出决定；来源撤回不自动批准替代来源，不删除原记录。
5. 经相应权限采纳后更新字段依据及必要 history。review.checked 只记录实际完成的复核，不能批量改为当天；旧顶层 checked 留在迁移历史。

链接存活、内容变化、发布方状态与项目使用批准分开。archival 的内容复核与地址观察也分开，固定内容须有实际版本与哈希，不能仅凭档级省略引用核对日期。

watch 的 locator 表示观察地址，signals 指定 availability、redirect、version、revision、replacement、withdrawal；cadence_months 分别保存 availability、redirect、content。旧字符串入口不能自动成为已核观察条目。发布方详情、状态页、版本说明及 DOI 可提供不同范围的材料；镜像可辅助定位，不能取代必须由发布方支持的状态结论。

| 层次 | 效力 | 边界 |
|---|---|---|
| 观察 | 提供地址或内容变化线索 | 固定夹具不确认真实事实；live 与正式周期运行未由字段合同开放 |
| 索引 | 提供可能受影响位置 | 项目 assertions、local_analysis 与历史值不产生外部引用边 |
| 义务 | 保存已有正式输入下的复核工作项 | 正式义务尚未建立时不得虚构目标、结论或发布阻断 |
| 正式修改 | 根据材料与采纳决定修改获准字段 | 不自动改变 tier、身份、用途、关系或术语 |
| 严格切换 | 同一快照使用 v2 数据和消费者 | 必需证据与整批验收未完成不得合并，不增加兼容读取 |

来源变化可在实际正式对象存在时通过稳定 ID 提出术语复核范围；术语具体数据由其采纳决定控制，来源变化本身不创建术语义务、委托或新记录。恢复只使用明确范围的 Git revert，正式 vault 与 Git 忽略输出不属于可由仓库 Git 恢复的范围。

## 审计追踪

审计追踪按下表分层，[治理](governance.md)只引用本节。正式审计只追加。

| 层 | 记在哪 | 记什么 |
|---|---|---|
| 对象 | 概念和实体的现行 `history` | 每次状态变化的日期、内容和原因（Z39.19 §11.3.2.2 历史注释） |
| 版本 | `data/vocab/CHANGELOG.md` | 每版新增、废弃、改名和来源更新；只追加 |
| 规则 | `docs/decisions/` | 治理规则本身的变更；ADR 只追加 |
| 维护动作 | `data/vocab/CHANGELOG.md` 当前版节 | 每次定期复审执行的动作 |
| 指标快照 | `data/audit/maintenance/signals.yaml` | 历次定期复审指标、编辑审核日期和治理年审日期 |
| 来源迁移 | `data/audit/migrations/source-v1/`、[来源收尾](../../decisions/source-completion.md) | 六份原基线账本保留历史审计；收尾决定另保存隔离关系与本批处置，不重写旧账本 |
| 术语迁移 | `data/audit/migrations/term-v1/terms.tsv` | 348 条冻结审查和消费者去向；只作 audit-only 继承 |

注明不覆盖也是审计追踪。未安放的内容可以被承认，但必须记录。

本批来源与术语记录的 history 按真实采纳和实施事件保存，记录准入与全局 publication 分开，不补造历史日期。正式义务及持久正式索引未启用；固定夹具探测、正文报告和其他 ignored 输出只提供执行证据，不取得正式状态、决定、指标快照或只追加对象历史的效力。

## 定期复审

| 时点 | 动作 |
|---|---|
| 影响模型、生成或引用的改动后 | 根据实际失败风险运行严格来源与主题校验、必要链接检查；不因无关文档改动重复全量回归 |
| 每月 | de-jure 新版观察安排保留；当前只实现固定夹具，`--live` 禁用，故不执行真实来源周期观察 |
| 每 3 个月 | 外部链接存活检查安排保留；它与每月地址或新版观察分开，不能用固定夹具结果替代 |
| `candidate` 记录攒到 20 个，或距上次编辑审核满 12 个月 | 编辑审核；同时读取指标表，对照触发表执行动作；用 `--record` 写快照 |
| 按 `tier` | 人工复核来源 |
| 动作攒成一批 | 发版 |

人工操作只在定期复审时进行；脚本可以随时运行，指标表在定期复审时读取。来源 live transport 和探测输出契约闭合前，不执行真实来源周期探测，也不把夹具信号写入正式字段。

当前不运行术语定期复审。术语义务接口没有正式数据、周期或阈值；正文诊断可以随时生成报告，但命中不自动触发正式动作。

## 指标表

`check-topics.py` 在校验之外输出现行指标表，每个指标一行：当前值、上次值、阈值和是否触发。历次值保存在 `data/audit/maintenance/signals.yaml`，定期复审用 `--record` 追加快照。每个顶层的未标引数和每个字段的 `self` 数是其中两组。脚本目前只计算词表内部指标。

来源和术语反向索引、义务接口、迁移账本、固定夹具观察与正文诊断都不写 `data/audit/maintenance/signals.yaml`，也不冒充正式指标快照。工具可以报告机械状态，不能因此批准对象或执行动作。

## 应用映射

每个 target 的 `Application Profile` 说明怎样读取内容字段、取得检索记录和计算引用次数，见[内容模型](../model/content-model.md)“应用映射”。本文只规定指标、阈值、触发和动作；profile 设计或导出 artifact contract 不是运行记录。

完整内容应用的 target、校验器和报告生成器已经实现；已观察到正式 vault 有 draft 内容，消费者没有正式激活，查询日志和回流接口也不存在，因此这些能力当前不提供指标输入。[Obsidian 映射](../targets/obsidian.md)中的具体表示规则留在 target 内，不因代码、生成物、空库报告或本地编辑而取得消费者运行证据。

派生报告只提供带位置和上下文的事实、指标和适用阈值触发，供人工复核；报告本身不批准、废弃、删除、拆分、合并、找依据、复核来源、注明不覆盖或发版，也不修改状态、关系、designation、来源或项目决定。术语参考输入须先通过完整校验和规定的 publication 门禁，不能由生成能力存在推导启用；委托仍未开放；仓库 Markdown 正文诊断也不是外部知识库的导出、检索记录或回流。内容计数继续等待正式消费者的可审计输入，不因应用能力存在或空库报告生成而提前触发。

## 收录依据

本文件的来源复核回答“事实从哪里来、为什么可信”；[词表的建设与维护](../../concepts/vocabulary-construction.md)中的 warrant 回答“某个 designation 为什么可以被采用”。处理来源材料时，还要区分来源中的字符串、字符串所表示的概念、现有概念是否覆盖目标概念，以及表示形式能否被项目采用。

来源中出现一个字符串只提供文献依据线索。人工仍须判断目标概念和现有覆盖，再独立审核表示形式。来源分级本身采用组织依据，即本库获取和信任知识的方式；它不能代替具体概念、形式或断言的核验。观察、索引和义务同样只能缩小复核范围，不能替代这些判断。

## 待定事项

- 阈值表中标“本库”的全部数字在首轮维护后校准。
- 名词短语采用哪种抽取方法；中英混排文本怎样分词。
- 候选术语接口何时取得正式编辑源、委托、消费者和生命周期效力；当前不创建相应数据。
- 内容单元的 `subject`、`type` 是否记录 `basis`，还是由引用计数代替。
- 尚缺材料的具体字段如何取得可核定位、逐值支持范围与采纳；严格结构本身不补足这些事实。
- 注明不覆盖的节点在 `scope` 中怎样写。
- 来源 live transport、探测输出契约、真实周期运行、正式义务和正式索引何时闭合；固定夹具实现不回答这些问题。
- 内容引用和检索计数在真实内容消费者提供可审计输入前不触发；现行词表参考导出不满足该条件。
