# 验证投入

状态：已采纳，2026-08-31。决定记录只追加不修改；推翻时新建一条并把本条标为“被替代”。

## 背景

来源治理和术语治理的实施计划曾为每个任务安排完整回归、独立审查和细粒度测试。多项检查重复证明文件存在、字段数量、固定常量或已经由模式、哈希和更强端到端门禁覆盖的事实；这些检查增加执行时间，却没有相应降低语义越权、身份丢失、数据损坏或切换失败的风险。

ISO 19011:2026 把基于证据的方法和基于风险的方法列为审核原则，并要求审核方案考虑风险与机会。本库据此按失败风险配置审查与测试投入，不用审查次数或测试数量代替有效证据。

## 决定

1. 每项拟议审查或测试先写明目标失败、失败后果和该检查提供的独有证据。不能指出可信失败，或同一失败已由更强门禁覆盖时，不设计、不执行。
2. 必须保留能够发现语义效力变化、决策权越界、稳定身份丢失、迁移数据损坏、生成不确定、共享接口断裂、不可逆删除、正式切换失败或回滚失败的检查。
3. 文件存在、固定常量回显、重复计数、包装函数透传、实现细节、相同输入的重复正例和已经由 schema、哈希、写集或端到端检查覆盖的事实，不单独建立测试或独立审查。
4. TDD 只用于本决定保留的行为测试。文档、静态配置、确定性生成物和纯机械迁移优先使用模式校验、解析、哈希、差异和一次端到端验证，不为 RED／GREEN 形式另造低价值测试。
5. 完整回归只在接口闭合、迁移闭合、完整候选、正式切换和回滚等风险边界运行。普通任务运行与自身变化直接相关的定向检查，不重复全库回归。
6. 独立审查只用于需要第二判断者的语义、权限、完整候选或正式切换风险。测试通过、计数、格式、哈希和写集等机械事实由命令证明，不交给第二代理重复确认。
7. 已发生的真实缺陷若现有高价值门禁不能稳定复现，新增最小回归测试；修复无关缺陷时不顺带扩张测试范围。

## 后果

- 实施计划不设置测试数量目标，也不把覆盖率或测试条数当作完成标准。
- 删除低价值测试须同时删除对应计划步骤、夹具、审查和重复回归，不保留失去消费者的测试基础设施。
- 验收报告列出保留门禁及其目标风险，并说明未设计测试的边界；不要求为每个函数、字段或任务各有一个测试。
- 本决定不降低来源依据、术语准入、身份对账、迁移完整性、确定性生成、写集、切换和回滚的既有门禁。

## 依据

- [ISO 19011:2026](https://www.iso.org/standard/19011) §4.7、§4.8：基于证据的方法与基于风险的方法；§5.3：审核方案的风险与机会。
- 人的决定：“这个仓库以后也一样把价值不高的审核都不需要”“TDD 测试也一样，价值不高的也不需要设计和执行”。
