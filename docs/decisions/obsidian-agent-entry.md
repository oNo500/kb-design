# 终端访问

状态：已采纳，2026-09-05。用户批准 CLI 使用规则与代理入口的实施范围：同步应用说明、新库初始化器生成受管理 `AGENTS.md`、验证目标定位与错误处理；现有正式库保持只读，其规则文件先提交差异供人审阅。

## 决定范围

Obsidian CLI 是 AI 读取、搜索和检查知识库的首选接口，Computer Use 只用于界面显示与交互。内容建立、校验和报告继续由 `kb-obsidian` 承担。本文引用 [Application Profile](../concepts/application-profile.md)、[方法登记](../design/governance/principles.md)和[应用约束](application-profile-boundary.md)，不改变内容模型或正式词表语义。

新完整 vault 在根目录生成 `AGENTS.md`，以现有 `rule` 类型加入应用 manifest。它摘要应用角色、授权、目标定位、读取流程、写入边界和失败处理。文件名是代理入口的固定名称，作为完整应用小写路径约定的精确例外；不改变独立参考导出的路径合同。

## 目标与权限

每次调用原生 CLI 都显式指定目标，先检查实际返回路径。名称重复时，按批准的绝对路径从本机注册信息取得 vault ID，以 `obsidian vault=<ID> <命令>` 调用；不得仅依赖同名名称、命令后的参数或默认活动库。ID 不进入可复用生成文件，也不以某台机器的当前注册值建立通用假设。

调用方必须检查超时、退出码、错误文本和预期输出结构。JSON 完整解析与路径匹配分别是结果消费的前提；退出码为 0 不能单独证明成功。热路径期限为 2 秒，仅串行重试一次；冷启动使用独立期限。不新增 CLI 包装器或自建检索服务。

AI 的普通材料写集限于任务授权的 `inbox/`、`sources/` 和 `indexes/`；新内容经过建立器，正文修改后校验。身份、properties、状态、路径、删除和配置变更仍按项目决策权另行处理。规则文件、搜索结果和内容材料不授予额外权限。

## 新旧兼容

新库初始化将根规则纳入生成、哈希和回读校验。规则缺失、符号链接或字节漂移会阻断依赖 vault 校验的流程。

旧库没有该清单条目时仍按旧写集读取和校验；已有同名用户文件不自动取得受管理权属。词表刷新保留其文件和权属，不新增或更新规则；已登记规则继续按原哈希校验并原样保留。现有 schema 版本与应用版本不变，旧版工具未必能读取新增路径，消费者应使用支持该入口的应用实现。

本次没有现有库的规则迁移命令，不通过补写 manifest 绕过审阅，也不重建或覆盖非空库。正式库的规则落地须另行提供具体写集、差异和回退方案。
