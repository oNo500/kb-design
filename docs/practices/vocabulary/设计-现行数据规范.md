# 现行数据规范

本篇保存第 3 版 RDF／SKOS 词表的现行数据合同，包括资源身份、字段、值、关系、来源依据和校验要求。它用于判断数据是否符合约定；实现覆盖、历史构建和迁移经过分别记录在[工程能力](设计-词表工程能力.md)与[历史记录](../../../work/reviews/2026-09-19-vocabulary-baseline.md)。

## 适用范围

合同适用于自有主词表、组织声明、领域分图及未归入领域分组的数据。来源原件和来源图按来源原貌保留，不直接套用自有主图的归属要求；旧 YAML 数据继续按[主题词表设计](设计-主题词表.md)读写。

整体选择见[整体设计](../../model/vocabulary/设计-词表整体设计.md)，多语策略见[多语言词表](../../model/vocabulary/设计-多语言词表.md)。第 3 版仍以普通 SKOS 文字标签维护名称；已采纳的 XL 独立名称及管理记录目标见[资源与字段](../../model/vocabulary/设计-词表资源与字段.md)。目标设计另见[词表数据规范](../../model/vocabulary/设计-词表数据规范.md)；本合同继续服务现行输入，目标要求须经实施和迁移验收后切换。

来源快照保存来源事实，组织配置和本地编辑保存项目选择，采纳记录保存效力依据。生成器执行转换并留痕，不直接编辑发布后的 Turtle。字段合法、校验通过和具体语义采用分别判断。

## 词表结构

自有主图使用一个 `skos:ConceptScheme`。其中每个概念通过 `skos:inScheme` 关联该词表；原来源的 Scheme、身份和元数据在独立来源图及对账记录中保留，不能混成多套自有归属。

领域顶层使用 Concept，领域分组使用独立的 Collection，两者不能共用 URI。分组通过 `skos:member` 引用成员，不据成员关系生成上下位。一个概念可进入多个分组；未分组的已收录概念继续保留。领域范围及成员按[已采纳配置](../../../data/inputs/vocabulary/knowledge-system.json)执行。

来源按明确的选择规则进入未编辑基线，再应用本地编辑形成主图。完整原件与来源 Turtle 保留，过滤、排除、新增及修改均须能从记录追溯；具体执行见[维护设计](../../model/vocabulary/设计-词表维护.md)。领域分图是主词表的派生子集，不是独立词表，也不扩大原收录范围。

## 节点类别

主节点使用稳定 IRI，可采用来源 HTTP URI 或既有 `urn:`。名称、字段位置和领域变动不重新分配概念身份；标识是 RDF 节点身份，不再增加同义的 `id` 文字字段。

| 用途 | 识别条件 | 合同 |
|---|---|---|
| 词表 | 显式 `rdf:type skos:ConceptScheme` | 自有主图中只有一个自有词表，不能同时是概念或集合 |
| 概念 | 显式 `rdf:type skos:Concept` | 允许不冲突的附加类型，不能同时是词表或集合 |
| 分组 | 显式 `rdf:type skos:Collection` | 保留合法附加类型，成员关系不等于概念层级 |
| 任务记录 | 来源的 `dcterms:type "task"` 及显式 `rdfs:Resource` | 不把其他 Resource 一律识别为任务，也不转为主题概念 |
| 辅助记录 | 说明资源或文档元数据资源 | 按其属性和用途核对，缺少类型声明不自动成为错误 |

来源说明中的空白节点及嵌套结构可以保留；主节点使用 IRI 是项目选择，不是 SKOS 排斥空白节点。普通集合不因文件排列而取得顺序；采用有序集合时须使用目标设计中的成员列表合同及相应迁移，不能给普通集合补造顺序。[SKOS 类型与集合](https://www.w3.org/TR/skos-reference/)

## 顶层组织

组织配置以 `hierarchy.uri` 指定领域概念，以 `hierarchy.roots` 指定挂接入口，以 `vocabulary.top_concepts` 指定顶层。生成结果包括顶层声明、入口到领域的 `broader` 及相应逆关系；配置哈希定位选择，不能替代挂接的语义依据。

领域概念使用独立于来源概念和 Collection 的 URI，不能有上位。入口必须存在于选择结果且属于对应领域组；不存在时构建失败，不按名称替换或静默跳过。同一来源概念可挂到多个领域，原身份和内部关系保留。

只连接明确采用的入口。分组成员继续按自身规则确定，不由新层级重新推导；无父节点不自动成为指定顶层，未连接概念仍可通过搜索、索引或分组访问。项目入口不冒称来源给出的上位，也不证明领域覆盖完整。

`selection.ancestors` 只加入明确列出的来源祖先。每项须是原来源中入选概念的真实祖先，不展开其其他后代，也不自动收录全部祖先；关系沿用来源，领域挂接仍独立声明。

## 通用约定

### 值与数量

数量按单个主体的单个属性统计，与观察到的最大数量无关。

| 表示 | 合同 |
|---|---|
| `1`、`1..n` | 恰好一个、至少一个；类型、身份及归属为结构要求，名称的来源缺项按校验分级处理 |
| `0..1`、`0..n` | 可选单值、可选多值；缺少时省略，不用空字符串占位 |
| 标签文字 | 非空 RDF 文字及语言标签，按语言与名称规则处理来源兼容值 |
| 普通文字 | 代码、编号、来源类别或版本等 RDF 文字，不强加语言标签 |
| 说明值 | 标签文字、说明资源或文献引用；保留来源兼容文字、已有 IRI、空白节点及嵌套结构 |
| 日期值 | 合法 `xsd:date` 或 `xsd:dateTime`，不补猜时区或虚构时间精度 |

多值分别写为三元组，不用逗号拼接。数据类型、语言和文字都是值的组成部分，不能在转换中无记录地压成普通字符串。

### 语言范围

自有输出保留 `en`、`zh` 及合法的扩展标签。其他语言文字留在来源原件与来源副本，过滤去向须有记录。该范围是项目选择，不是 BCP 47 的全部语言范围。

保留完整标签，比较时忽略标签大小写；不把 `zh`、`zh-Hans`、`zh-Hant` 合成一个值。未标语种的内容文字保留并报告，不默认英文、不按文字外观补标签。代码、编号、日期等非语言数据不因无语言标签报缺项。

标签语法、IANA 登记有效性和项目允许范围分别核对，前缀匹配不能证明完整标签有效。标准依据和转换要求见[语言标记](../../model/vocabulary/设计-多语言词表.md#语言标记)，当前检查覆盖见[工程差异](设计-词表工程能力.md#多语差异)。

过滤不能删除概念身份、关系或整条记录；没有可用名称或本地说明正文时保留对象并报告。报告须包含各语言过滤数量及缺项位置。缺译不自动触发翻译或采纳，当前中文批译继续输出 `zh`，不通过改标签完成翻译或简繁转换。

### 名称规则

第 3 版的规范名称以普通 `skos:prefLabel` 为维护入口。同一主体在每个完整语言标签下最多一个首选名；`altLabel` 与 `hiddenLabel` 可有多个值，三种角色的完整文字值集合两两不相交。不同完整语言标签可分别有首选名，不能只比较文字而忽略语言。[SKOS 标签约束](https://www.w3.org/TR/skos-reference/#labels)

首选形式与其他入口须有来源或项目依据。保留有依据的限定文字、拼写、缩写及词形，不一律改为全称、复数、小写或首字母大写。限定文字属于名称，范围说明使用 `scopeNote`；临时显示来源后缀不改变标签原值。

不同概念同语言同名时保留独立 IRI 并诊断歧义，不自动合并或强制消重。跨语言共同表达一个概念须按[概念对应](../../model/vocabulary/设计-多语言词表.md#概念对应)核对；近义或宽窄名称的检索归并必须有用途边界，不能作为跨语境严格同义或跨来源合并的依据。

复合表达保留组合及条件，不按空格或 AND 自动拆分，也不把多个组成词逐一改成别名。USE／UF 的两个显示方向由标签及规则表达，不另建独立维护字段。任务名称仍使用来源的 `rdfs:label`，不为外观一致改成概念名称。

自有词表名称与领域名称分别明确；领域名称可用于对应的 Concept 和独立 Collection，不能全部写成自有词表首选名。来源标题保留原归属，自有 `dcterms:title` 仅在兼容需要时从首选名派生。名称选择与等价范围见[首选词](../../model/vocabulary/概述-首选词与名称形式.md#名称选择)和[等价关系](../../model/vocabulary/概述-等价关系.md#等价的范围)。

## 词表字段

自有词表的范围说明须能解释用途、收录、排除及未分组数据的处理，不能只给出名称或分组数量。

| 属性 | 数量 | 值类型 | 字段约定 |
|---|---|---|---|
| `rdf:type` | 1..n | IRI | 包含 skos:ConceptScheme，不同时作为概念或集合 |
| `skos:prefLabel` | 1..n | 标签文字 | 自有词表规范名称的唯一维护入口 |
| `skos:scopeNote` | 1..n | 说明值 | 明确收录范围、排除情况和使用边界；是项目的词表级要求，不强加给每个来源词表 |
| `dcterms:description` | 0..n | 标签文字或来源原有文字 | 补充用途或一般介绍，不重复抄写范围说明 |
| `skos:note` | 0..n | 说明值 | 不适合归入更具体说明属性的其他信息 |
| `skos:historyNote` | 0..n | 说明值 | 自有词表范围或组织原则的重要历史变化 |
| `skos:changeNote` | 0..n | 说明值 | 从版本及维护记录派生的具体变更说明 |
| `skos:hasTopConcept` | 0..n | Concept IRI | 自有顶层概念的主要维护入口，检查本词表成员资格；领域集合不是顶层概念 |
| `dcterms:source` | 0..n | IRI | 自有词表引用的来源资源，逐项采用范围仍由配置和依据记录说明 |
| `dcterms:created` | 0..1 | 日期值 | 自有词表建立时间，不继承为任一来源词表的创建时间 |
| `dcterms:modified` | 0..1 | 日期值 | 自有词表记录的修改时间，不等同于每次重建时间 |
| `dcterms:language` | 0..n | IRI | 实际提供的中英文语言标识，与输出配置一致 |
| `owl:versionInfo` | 0..n | 普通文字 | 自有词表版本说明；来源版本和生成工具版本分别记录 |

## 概念字段

下列基数针对自有主图。联合查询来源图时出现额外来源归属，不按主图单一归属规则误报。

| 属性 | 数量 | 值类型 | 字段约定 |
|---|---|---|---|
| `rdf:type` | 1..n | IRI | 必须包含 `skos:Concept`；允许其他不冲突的来源类型 |
| `skos:inScheme` | 1 | 自有 ConceptScheme IRI | 自有主词表中的概念统一属于同一词表；分组成员用 Collection 的 member 表达，层级归属用概念间的 broader 表达，原来源归属在来源图及对账记录中保留 |
| `skos:prefLabel` | 1..n | 标签文字 | 按名称规则；来源缺名保留为警告，项目新增节点必须有名 |
| `skos:altLabel` | 0..n | 标签文字 | 替代名称，不因此建立另一个概念 |
| `skos:hiddenLabel` | 0..n | 标签文字 | 检索用写法，不自动作为显示首选名 |
| `skos:notation` | 0..n | 普通文字 | 来源分类代码；保留数据类型与原值，不当作概念 URI |
| `dcterms:identifier` | 0..n | 普通文字 | 来源或登记标识；不假定跨来源全局唯一 |
| `skos:definition` | 0..n | 说明值 | 定义或定义资源引用，不限定为一个字符串 |
| `skos:scopeNote` | 0..n | 说明值 | 范围及使用说明，不自动升级为定义 |
| `dcterms:description` | 0..n | 标签文字或来源原有文字 | 一般描述；保留其与定义、范围说明的区别 |
| `skos:note` | 0..n | 说明值 | 一般说明，不自动确定更具体的说明类别 |
| `skos:editorialNote` | 0..n | 说明值 | 编辑提醒，不代替历史、具体变更记录或采纳授权 |
| `skos:historyNote` | 0..n | 说明值 | 名称、含义或使用范围的重要历史变化，帮助解释旧内容的标记 |
| `skos:changeNote` | 0..n | 说明值 | 细粒度维护变更；从结构化变更记录生成说明或引用，不重复维护第二份事件历史 |
| `owl:deprecated` | 0..1 | xsd:boolean | 有明确依据时标记停用；缺少该属性不证明已经采纳或经过审查 |
| `dcterms:isReplacedBy` | 0..n | Concept IRI | 旧概念指向替代概念，允许多个目标；不等于概念等价或自动重标引 |
| `dcterms:replaces` | 0..n | Concept IRI | 替代概念指向旧概念的派生反向表达，不单独维护 |
| `skos:broader` | 0..n | Concept IRI | 自有直接层级的主要维护方向，允许多父；来源反向边也须纳入归一与对账 |
| `skos:narrower` | 0..n | Concept IRI | 从上位关系派生的下位表达；编辑反向表达时同步修改同一条上位关系，不允许两套互相独立的值 |
| `skos:related` | 0..n | Concept IRI | 相关关系；不得与同一对概念的层级可达关系重叠 |
| `skos:topConceptOf` | 0..1 | 自有 ConceptScheme IRI | 由 hasTopConcept 派生的顶层归属；不能指向领域集合，不单独维护 |
| `dcterms:isPartOf` | 0..n | IRI | 部分关系；不自动改成 `broader`，不要求目标一定是概念 |
| `dcterms:source` | 0..n | IRI | 引用来源资源；不能代替逐字段、逐关系的生成对账 |
| `prov:wasDerivedFrom` | 0..n | IRI | 派生依据，可关联来源页等资源；保留定位 |
| `dcterms:created` | 0..1 | 日期值 | 所描述概念记录的创建时间；来源与项目记录分别追溯，不以本次生成时间代替 |
| `dcterms:modified` | 0..1 | 日期值 | 所描述概念记录的修改时间；不以构建时间覆盖，也不代替变更原因 |
| `dcterms:type` | 0..n | 普通文字 | 仅兼容保留来源记录类别；不要求自有概念重复写 concept，不替代 RDF 类型或分面分类 |

IRI、identifier 与 notation 分别表示对象身份、来源标识和分类代码，不因部分值相同全局合并。definition、scopeNote 与 description 的职责也分别保留；说明可用文字、资源或文献引用，不为了字符串接口删除说明对象。[SKOS 说明属性](https://www.w3.org/TR/skos-reference/#notes)

## 分组字段

分组使用统一字段合同，成员和显示方式按用途确定。

| 属性 | 数量 | 值类型 | 字段约定 |
|---|---|---|---|
| `rdf:type` | 1..n | IRI | 包含 `skos:Collection`；保留来源附加的合法类型 |
| `skos:prefLabel` | 1..n | 标签文字 | 分组名称，按名称规则；来源缺名保留警告 |
| `skos:altLabel` | 0..n | 标签文字 | 分组的替代名称 |
| `skos:hiddenLabel` | 0..n | 标签文字 | 分组的检索写法 |
| `skos:notation` | 0..n | 普通文字 | 来源分组代码 |
| `skos:scopeNote` | 0..n | 说明值 | 分组的用途、纳入范围、排除情况和与相邻分组的区别；可引用明确的组织规则 |
| `skos:historyNote` | 0..n | 说明值 | 分组范围的重要历史变化 |
| `skos:changeNote` | 0..n | 说明值 | 从维护记录派生的成员或结构变更说明 |
| `dcterms:source` | 0..n | IRI | 分组依据的来源资源，仍需在对账中明确采用的范围 |
| `prov:wasDerivedFrom` | 0..n | IRI | 分组或成员选择所依据的具体来源记录、规则或版本 |
| `skos:inScheme` | 0..1 | 自有 ConceptScheme IRI | 自有领域分组必须关联唯一自有词表；继承分组可关联该词表。来源原有归属另行保留，集合使用该属性不应被错误拒绝 |
| `skos:member` | 0..n | Concept 或 Collection IRI | 可以包含概念或嵌套集合，不用于表达上下位语义 |
| `iso-thes:subGroup` | 0..n | Collection IRI | 保留来源表达；自有细分需要输出时由已确定的 superGroup 关系派生，不转成概念层级 |
| `iso-thes:superGroup` | 0..n | Collection IRI | 需要此种分组细分时的主要维护方向；不能仅凭类似名称就认定它与 member 完全相同 |
| `dcterms:modified` | 0..1 | 日期值 | 来源分组的修改时间 |

分组须能通过范围说明或结构化规则解释成员依据，不要求每个成员重复一段说明。自有领域成员引用本词表概念；嵌套子集合必须能在本次数据中定位。成员可进入多个组，不复制概念；来源组同名不证明组身份相同。

空组保留并提示，不自动补成员。集合不能作为概念上下位、相关或映射关系的端点；组间细分不自动等同嵌套 member，组代码也不与概念代码合并身份空间。

## 映射字段

映射是可选合同，可放在独立图中，依据与采用状态由结构化记录保存。采用范围和应用条件见[映射记录](../../model/vocabulary/设计-词表数据规范.md#映射记录)。

| 属性 | 数量 | 值类型 | 对应含义 |
|---|---|---|---|
| `skos:exactMatch` | 0..n | Concept IRI | 在广泛检索应用中可高度确信互换的对应；具有传递性，不等于 owl:sameAs，不合并双方全部属性 |
| `skos:closeMatch` | 0..n | Concept IRI | 在部分检索应用中足够接近、可以互换的对应；不是“不确定”的占位值，不作传递推导 |
| `skos:broadMatch` | 0..n | Concept IRI | 本端概念对应另一词表中更宽的概念，方向必须明确 |
| `skos:narrowMatch` | 0..n | Concept IRI | 本端概念对应另一词表中更窄的概念；与 broadMatch 互反，不维护冲突的两套决定 |
| `skos:relatedMatch` | 0..n | Concept IRI | 跨词表的相关对应，不代替等价或宽窄判断 |

目标可由独立来源图描述，但 IRI 必须能通过明确的来源记录定位，不要求校验器联网补全。原样复用同一 IRI 不增加自身 exactMatch。候选、暂缓、不采用及未确定关系不作为有效映射输出；明确自动规则只在原授权范围内复用。

映射须同时满足标准语义和项目使用条件。对称、互反及传递推导按[统一校验合同](../../model/vocabulary/设计-词表数据规范.md#标准一致性)检查，不由 RDF 关系自动产生跨用途、反向或中转使用许可。[SKOS 映射](https://www.w3.org/TR/skos-reference/#mapping)

## 来源兼容字段

来源描述仍附着于原对象，不是所有自有节点都要填写的字段。自有词表只有在相应信息独立、明确时才能使用，不能汇总来源而自动取得其创建者、许可、格式或版本。

| 属性 | 数量 | 值类型 | 保留与转换约定 |
|---|---|---|---|
| `dcterms:title` | 0..n | 标签文字或来源原有文字 | 来源标题保留；自有输出仅在兼容需要时从 prefLabel 派生同值标题，不独立维护 |
| `dcterms:identifier` | 0..n | 普通文字 | 发布者词表标识，不替代 IRI |
| `dc:creator` | 0..n | 普通文字 | 来源创建者名称，不自动成为自有词表创建者 |
| `dc:contributor` | 0..n | 普通文字 | 来源贡献者名称 |
| `dc:publisher` | 0..n | 普通文字 | 来源发布者名称 |
| `dc:subject` | 0..n | 普通文字 | 来源主题描述，不据此创建本地分类关系 |
| `dcterms:conformsTo` | 0..n | IRI；兼容来源原有文字 | 来源遵循标准的声明；自有新增声明须有实际依据 |
| `dcterms:format` | 0..n | IRI | 来源载体或格式的标识，不冒称当前自有输出格式 |
| `dcterms:isRequiredBy` | 0..n | IRI | 依赖该资源的对象，不作为概念层级 |
| `dcterms:license` | 0..n | IRI | 来源许可资源，不因转换擅自变更或当作整个自有词表的许可 |
| `dcterms:replaces` | 0..n | IRI | 来源资源的替代声明，区别于概念级替代，不跨对象种类混用 |
| `dcterms:rights` | 0..n | 普通文字或有依据的权利声明 IRI | 来源权利说明 |
| `dcterms:rightsHolder` | 0..n | IRI；兼容来源原有文字 | 来源权利持有者，不为转换名称而制造实体记录 |
| `dcterms:subject` | 0..n | IRI | 来源明确引用的主题，与文字形式的 dc:subject 分开保留 |
| `dcterms:type` | 0..n | 普通文字 | 来源类别信息，不冒充 RDF 类型或本地分类决定 |

来源的 created、modified、language 和 versionInfo 同样保留原归属，不能覆盖自有元数据。来源语言声明与生成文字范围分别报告；保留前者不放宽输出语言范围。`dc:` 与 `dcterms:` 不做全局字符串替换，旧文字兼容不等于符合 DCMI 的全部资源类型语义。[DCMI Metadata Terms](https://www.dublincore.org/specifications/dublin-core/dcmi-terms/)

## 任务字段

以下为来源任务记录的兼容合同。任务可作为关联对象保留，但不进入概念上下位树，也不因此扩展任务测量断言或实验条件模型。

| 属性 | 数量 | 值类型 | 字段约定 |
|---|---|---|---|
| `rdf:type` | 1..n | IRI | 保留当前来源的 `rdfs:Resource` 声明，不新增未经依据确定的任务类 |
| `dcterms:type` | 1..n | 普通文字 | 当前任务包含来源值 `task`，用于本阶段的目标识别 |
| `rdfs:label` | 1..n | 标签文字 | 任务名称；当前来源空名记录保留并警告，新增记录不得空名 |
| `dcterms:identifier` | 1..n | 普通文字 | 来源任务标识，支持核对与更新 |
| `dcterms:source` | 1..n | IRI | 来源任务记录的定位 |
| `dcterms:description` | 0..n | 标签文字或来源原有文字 | 任务描述，缺少时不编造 |

## 辅助字段

辅助记录按说明或元数据用途核对，不因缺少类型声明另造 RDF 类。

| 属性 | 数量 | 值类型 | 适用对象与约定 |
|---|---|---|---|
| `rdf:value` | 本地说明为 1..n | 标签文字或来源原有文字 | 本地说明正文，允许多语言；语言过滤后无可用正文时保留记录与引用并报告缺项 |
| `dcterms:created` | 0..1 | 日期值 | 说明记录创建时间 |
| `dcterms:modified` | 0..1 | 日期值 | 说明记录修改时间 |
| `dcterms:source` | 0..n | IRI | 说明或元数据的来源 |
| `owl:imports` | 0..n | IRI | 来源文档的本体引用；读取与校验不得据此自动联网加载其他图 |

说明属性指向本地说明资源时核对正文和已有元数据；指向外部文献时检查引用形式与已有定位，不强制其在本文件中具有 rdf:value 或 rdf:type。类型、属性、许可及标准等仅作引用对象时，不按缺字段的词条处理。

## 关系维护

主要维护方向与派生表达分别确定，不能建立两套互相独立的人工输入。

| 关系或表达 | 主要维护入口 | 派生与校验要求 |
|---|---|---|
| 直接层级 | `skos:broader` | 导入时同时识别原 broader 和反向 narrower，归一后对账；需要时生成 narrower，不能只删除源 narrower 导致关系丢失 |
| 顶层归属 | `skos:hasTopConcept` | 确定统一词表顶层后派生 topConceptOf；源中的两个方向均保留依据，不把“无 broader”自动当作顶层 |
| ISO 来源分组细分 | `iso-thes:superGroup` | 在确需此类细分时归一原两向关系，按需派生 subGroup；不和 member 或概念层级混为一谈 |
| 概念替代 | `dcterms:isReplacedBy` | 从旧概念指向新概念，反向 replaces 派生；不将替代关系当成等价映射 |
| 相关关系 | `skos:related` | 同一对概念的联系只作一次决定；双向查询或输出由程序保证，不建立另一种“反向相关”字段 |

导入同时识别原关系的两向表达，归一后保留依据；派生冗余由程序生成并核对。词表归属、集合成员和概念关系的职责互不替代。

层级可表达种属、实例或符合条件的整体部分。来源明确给出细分时保留；仅有 BT／NT 时不猜细分，也不因 isPartOf 自动增加 broader。学科与研究对象、共现或目录嵌套都不能独自证明层级。[层级关系](../../model/vocabulary/概述-层级关系.md#成立条件)

related 与层级可达关系互斥。同级可以有明确的相关关系，但不能全部自动相连。层级环、自相关和集合循环按适用规则诊断；本地新增与固定来源异常分别处理，不冒称 SKOS 普遍禁止所有环或自关联。[相关关系](../../model/vocabulary/概述-相关关系.md#成立条件)

## 依据记录

已有来源清单、转换对账及采纳记录须能定位下列信息，不要求每个概念重新人工填写一份来源证明。

| 信息 | 记录要求 |
|---|---|
| 所支持的对象 | 概念 IRI；涉及名称、定义或关系时，明确属性及具体值或目标 IRI |
| 文字值身份 | 保留完整文字、语言标签及数据类型，不能只存一个无语种的名称字符串 |
| 来源身份 | 来源记录 IRI 或记录标识、固定版本和文件哈希；已有页码、XML 记录、JSON 定位等同时保留 |
| 处理依据 | 原样继承或转换命中的规则及版本；本地选择或调整需要记录具体理由 |
| 名称采用依据 | 区分来源首选形式与项目选择，说明采用哪个表达及其依据，不把概念整体来源自动当成每个译名的证据 |
| 变更与效力 | 变更前后值、时间及已有的决定或授权记录；来源事实、项目判断和未确定项分别可辨 |

记录可以与主图分开保存。原样继承由来源、完整语句、快照和规则证明；dcterms:source 的来源引用与 prov:wasDerivedFrom 的派生含义分别保留，不要求每个节点重复写同值属性。[PROV-O](https://www.w3.org/TR/prov-o/)

文字值须包含语言与数据类型；概念整体来源不自动证明每个名称、定义或关系。词频、相似度和来源出现次数只提供线索，不替代[选词依据](../../model/vocabulary/概述-选词依据.md#三类依据)和具体采用，也不据此设无依据的统一权重。

## 历史与停用

historyNote 说明名称、意义或用法的重要历史，changeNote 表示细粒度变更，editorialNote 提供编辑提醒。结构化事件已有记录时，changeNote 派生摘要或引用该记录；不维护两份独立历史，不补造从未发生的变更。日期、构建哈希和文字差异不能替代含义变化的判断。

同一含义的改名保留 IRI，旧名称按依据处理。明确停用可写 `owl:deprecated true`，保留原 IRI、旧引用与历史；缺少该属性不证明已审核或已采纳。有后继对象时使用 isReplacedBy，拆分允许多个目标，替代不等于等价或自动重标引。

没有内容、使用频率为零或未归入领域组，不是停用或删除依据。停止收录、来源退出、停用及合并拆分按[退出合同](../../model/vocabulary/设计-词表维护.md#概念退出)分别记录，旧引用按[历史读取](../../governance/maintenance/设计-词表版本.md#历史读取)处理；不新增混合所有效力的 status 字段。[OWL 停用注释](https://www.w3.org/TR/owl2-syntax/#Annotation_Properties)、[替代属性](https://www.dublincore.org/specifications/dublin-core/dcmi-terms/terms/isReplacedBy/)

## 校验分级

检查图范围、必要推导和各入口的一致要求见[统一校验合同](../../model/vocabulary/设计-词表数据规范.md#校验范围)。下表规定处理级别，不把校验器当前覆盖当作规范的全部要求。

| 级别 | 检查内容 | 处理要求 |
|---|---|---|
| 结构与语义错误 | 非法主节点身份、不相容类型、关系端点错误、同语言多个首选名、标签互斥冲突、相关与层级冲突 | 本次生成新增时阻止发布，保留旧 `current` |
| 项目合同错误 | 自有词表数量不是一个、概念缺少唯一自有归属、领域集合被用作概念上位或顶层、主要维护方向与派生结果不一致、项目新增节点缺少必需信息、新生成字段为空、生成文字超出允许语言、结构或字段转换没有对账依据 | 对相应生成结果报错；来源兼容问题单独报告，不能假称已经符合新规范 |
| 来源缺项与兼容 | 已有概念或任务缺名、内容文字未标语种、说明引用无本地正文、表中标记的旧值形式 | 保留来源对象并警告，不猜测补齐、不无声丢弃 |
| 消歧与维护提示 | 不同概念同语言同名、分组缺少可解释的范围依据、旧概念有替代目标但未明确旧内容处理方式 | 保留并定位问题，不自动合并、改名、删除或重标引，不触发全量人工审查 |
| 可选信息缺失 | 没有替代名、没有定义、没有中文、没有关系、没有时间信息或没有发生过历史变更 | 本身不构成违规；可作为完整性报告，不能据此阻止正常生成 |

来源已有错误仍记录为错误，并绑定明确的来源版本和具体三元组；不能笼统永久豁免首次错误。新来源、规则或相关值变化产生新的诊断，不能沿用旧例外而不复核。

SHACL 用于身份、类型、数量、语言及对象约束；图冲突、来源哈希、完整对账和发布条件分别检查。`sh:uniqueLang` 与语言要求共同使用，不能以整个属性的 maxCount 1 替代按语言唯一。规则入口见 [shapes.ttl](../../../data/inputs/vocabulary/shapes.ttl)及[工程校验覆盖](设计-词表工程能力.md#校验覆盖)。[SHACL 规范](https://www.w3.org/TR/shacl/)

校验结果定位节点、属性、问题值、规则及来源版本，区分错误和警告；关键结果直接报告，完整记录随产物保留。引用检查使用已有材料，不由 URI 检查自动扩展联网抓取。

## 扩展边界

来源额外标准属性、发布者属性和合法附加类型保持可追溯，不用全局闭合字段表静默丢弃。项目新增字段、值类型或节点类别先明确合同；无法投影的信息保留来源及转换去向，不以临时自造字段绕过约束。输出语言限制同样适用于扩展属性。

分面、数组、划分特征与概念组按用途采用，不给所有概念强加 facet。先组、后组及组合关系不变成每个概念的必填布尔字段，也不能被普通相关关系或多个别名替代。表示、转换、校验与消费条件必须共同明确。

XL 名称、组合消费及有序集合的目标合同见[资源与字段](../../model/vocabulary/设计-词表资源与字段.md)，普通标签到 XL 的登记衔接见[名称编辑](../../model/vocabulary/设计-词表维护.md#名称编辑)。新表示需明确版本、迁移、依据和回退后才能进入当前接口；正式术语的编辑源不随之改变。

文章数量、学习进度及检索评价属于内容或应用层，不成为概念必填字段。兼容保留任务和元数据，也不把其全部属性要求到所有概念上。

## 交付与版本

产物固定输入、来源版本、生成规则及工具版本，并能回查过滤、本地变更、字段转换和未投影信息。来源 Scheme 元数据保留原对象；自有词表与分组的身份、名称及成员转换分别对账。原 Scheme 与迁移后的 Collection 使用不同稳定身份，不能将原 IRI 原地改成另一种对象，也不用 exactMatch 表达这种替代。

发布文件不得原地编辑；主图、分图及管理记录从同一固定版本读取。发布、历史引用及完整回退按[词表版本](../../governance/maintenance/设计-词表版本.md)执行，具体文件集、生成与恢复入口见[工程能力](设计-词表工程能力.md)。

旧 YAML 消费者及外部知识库按独立决定切换。图合法不证明语义已采纳，输出数量不证明领域覆盖完整，工程实现不自动取得正式发版或消费权限。

## 语言接口

原有逐项采纳接口继续保留，但不用于当前快速 AI 批译。它使用 `data/inputs/vocabulary/labels.zh.ttl`、`label-adoptions.json` 和现有书目；组织配置的可选 `labels` 项指定 `file`、`adoptions`、`bibliography` 路径。

该接口中，标签文件是补充中文的编辑源；采纳 JSON 使用 schema_version 1 和 records，每条包含 id、accept、uri、property、language、label、original、basis，可带 reason。只有 accept=true 且与标签具体值一一匹配的记录生效；original 由 `kb-vocab label-context` 生成，绑定对象类型、英文标签和完整本地说明。上下文变化会阻断这个旧接口的构建，**不作为批量增量同步自动重译的规则**。

旧接口按[语言依据结构](../../model/terminology/决定-语言依据结构.md)区分外部第 1–4 级与模型第 5 级。外部 references 使用书目 ID 和定位，第 4 级至少两个不同来源；模型记录 name、date、rationale、approval，并标明外部用法未核实。结构校验不认证授权真实性、语义对应或来源独立性。历史保留为 accept=false，来源已有名称不按读取顺序覆盖。

旧接口的 build-system 在校验前合并标签，领域分图共享结果；从 manifest 第 5 版起保存标签、采纳和书目快照，支持搬动后的重放及版本回滚。其逐项 provenance 与当前批次元数据分开，不能仅凭旧接口输入为空判断批次翻译没有产出。

## 版本接口

旧 YAML 词表继续使用现有 `version` 块，日期版本号可以沿用。一次联合发布覆盖哪些文件，应由该次发布清单确定，不以固定的词表份数定义全部发布。示例仅说明已有字段，不迁移现行数据：

```yaml
version:
  id: "2026.08.2"  # 年、月及同月发布序号
  date: 2026-08-23
  note: 记录本版实际变更
```

RDF 构建通过版本目录、构建标识及 manifest 固定实际文件集。`current` 是可切换入口，不是历史版本标识；`owl:versionInfo` 等说明也不替代文件清单和哈希。已经发布的同一版本不得原地改写；即使只修订名称、范围说明或映射，形成新产物时也须保存新的构建快照。

旧 YAML 的发布历史继续由 `data/vocab/CHANGELOG.md` 按实际发布文件记录新增、停用、替代、改名和来源更新，只追加。RDF 的版本差异、来源与本地编辑快照、转换记录及发布清单各保留原职责；细粒度维护事件与整体发布摘要互相引用，不维护两套独立事实。
