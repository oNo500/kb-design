# 词表工程能力

词表工程将固定来源转换为自有词表，并提供校验、版本保留和应用读取能力。本文按 2026-09-19 核到的代码说明已有能力与限制；业务约定见[整体设计](../../model/vocabulary/设计-词表整体设计.md)和[维护约束](../../model/vocabulary/决定-词表维护约束.md)。代码存在不等于当前服务已加载或迁移已验收。

## 能力分工

| 环节 | 实现位置 | 已有能力与边界 |
|---|---|---|
| 来源取得与核对 | `kb-sources` | 下载清单、原件快照、取得记录及文件校验；不证明来源权威性或知识覆盖完整 |
| 结构提取与转换 | 提取器及 `kb-vocab import-*` | 原生结构直接读取，文献提取后转换；原始身份、关系和异常分别留痕，不把章节自动当概念层级 |
| 自有词表生成 | `build-system` | 按选择规则收录来源概念，应用组织配置与本地编辑；来源副本完整保留，同名概念不自动合并 |
| 数据校验 | 图校验、SHACL、来源对账及身份检查 | 已覆盖多项结构约束；映射语义仍有入口差异，见[维护缺口](#维护缺口) |
| 本地维护 | `sync`、`edit`、`resume` | 来源同步、批量编辑、三方比较、冲突解决及失败重试；编辑意图不自动取得语义采纳 |
| 版本与恢复 | 发布、重放及环境归档模块 | 固定版本、切换入口、差异报告和可搬动重放输入；环境恢复仍需相容 Python 和依赖获取条件 |
| 查询与映射审查 | `show`、`find`、`query`、`review` | 查询诊断及独立映射流程；不要求全量映射，不代替语义判断 |
| 应用同步 | `maintenance_apps.py` 与 Skosmos 脚本 | 导入、导航和元数据同步，记录状态并支持实时核对；与词表发布不构成共同事务 |

`kb-sources` 负责原件，`kb-vocab` 负责 RDF／SKOS 表示与生成，应用负责消费。`kb-core`、`kb-topics` 继续服务 YAML 路径；RDF 产物不会自行迁移旧数据或启用 Obsidian 内容消费。

## 生成流程

领域与来源按具体决定选择，二者可以多对多对应。当前分组继承关系由[组织配置](../../../data/inputs/vocabulary/knowledge-system.json)保存；仅作参考的分支不据此产生成员。内容填充优先级与来源收录范围分别决定。

| 阶段 | 输入与处理 | 保留的结果 |
|---|---|---|
| 范围与来源 | 明确领域用途、概念粒度和适用来源 | 采纳范围及配置 |
| 来源固定 | 取得原件，记录地址、版本与哈希 | 不直接修改的来源快照 |
| 解析与转换 | 原生结构直接读取；PDF、API 等由相应适配器处理 | 独立来源 Turtle、定位和转换诊断 |
| 收录筛选 | 按根、下位及明确祖先等规则选择贡献 | 完整来源副本、选择结果及排除去向 |
| 组织与编辑 | 规范化允许语言和关系表达，形成基线并应用本地编辑 | 自有主图、领域概念与集合、编辑影响及冲突 |
| 校验与对账 | 核对结构、身份、来源语句及实际投影 | 检查结果、警告和未投影信息；覆盖限制见下文 |
| 版本发布 | 固定输入和产物，验证后切换入口 | 版本目录、差异、恢复材料及 current |
| 应用加载 | 从明确版本生成和加载图、导航、语言展示 | 每个应用的结果及实际加载证据 |

本地编辑在选择后的基线上执行，冲突阻止发布；不把来源完整保存解释成主图收录全部来源概念。已有来源 Turtle 可以直接重建，不必重复解析原件。失败时保留可用版本和历史，来源语义异常不以静默删改掩盖。

IEEE 的 PDF 提取、MSC2020 的 TSV、ERIC 的 XML／ZIP、Cognitive Atlas 的 API 转录及 PhilPapers 的缓存 JSON 分别经过适配。格式和版本条件见[来源准备](指南-词表工具链.md#来源准备)与[来源转换](指南-词表工具链.md#来源转换)；缓存或哈希不证明已核实官方版本。当前 PhilPapers 的第三方缓存限制继续保留。

## 输入与产物

| 对象 | 位置或职责 | 维护方式 |
|---|---|---|
| 来源事实 | 原件及取得记录 | 新版本保存新快照，保留原件与哈希 |
| 来源及组织选择 | `data/inputs/vocabulary/sources.json`、`knowledge-system.json` | 保存来源、收录范围、领域分组及层级选择；语义依据另按采纳记录核对 |
| 本地编辑 | `local-edits.json` 及操作快照 | 保存编辑前来源值、目标值、修订与历史，不直接改生成物 |
| 约束 | `shapes.ttl`、图检查及数据规范 | 记录规则版本与适用范围，不通过放宽检查掩盖错误 |
| 来源转换结果 | `packages/kb-vocab/output/` | 导入器生成独立 Turtle 及转换记录 |
| 自有词表版本 | `output/vocabulary/versions/<build-id>/` | 保存主图、来源、输入、差异、对账和恢复材料 |
| 当前入口 | `output/vocabulary/current/` | 读取前固定所指版本；历史引用按独立合同处理 |
| 操作与应用结果 | 词表操作目录、Skosmos 同步记录 | 分别报告词表发布、各应用加载和失败状态 |

自有词表使用一个 ConceptScheme，领域顶层 Concept 与 Collection 使用独立身份。未归入领域分组的已收录概念继续属于自有词表；分组覆盖率不等于概念收录完整率，也不证明学科知识覆盖完整。

## 变更边界

来源、范围、关系和具体值按[治理](../../governance/decision-making/设计-治理.md)采纳，工程执行该范围内的转换。包归属、`review` 中的操作者或授权文本不构成身份认证及自动授权。

新来源版本保存新快照；实现变更遵循已采纳设计并保存迁移说明；实践问题单独记录，设计变更须经标准研究和相应决定；当前版本切换保留可回退材料。输出排除与历史物理清理分开，`output/` 中的持久数据不作为构建缓存清空。旧引用、名称登记及退出事件按[词表维护](../../model/vocabulary/设计-词表维护.md)和[词表版本](../../governance/maintenance/设计-词表版本.md)处理。

## 依赖维护

现有工具使用 BeautifulSoup、pdfplumber／pdfminer.six、RDFLib、defusedxml、pySHACL、JSON Schema 和 PyYAML 等库。workspace 使用统一 `uv.lock`；引入或升级依赖前按项目约定核对维护、安全及体积影响。

[环境归档](../../../packages/kb-vocab/src/kb_vocab/environment.py)保存实际工具代码、Python 与平台信息、运行依赖版本和恢复脚本；可取得 workspace 锁文件时一并保存。恢复仍依赖可用的 Python、uv 和包下载，不是离线操作系统镜像，不宣称完整可复现构建或崩溃持久性。

## 校验覆盖

下表记录现有入口的实际覆盖，不能据其中一个入口通过推断完整标准一致性。

| 入口 | 已有检查 | 限制 |
|---|---|---|
| [通用图校验](../../../packages/kb-vocab/src/kb_vocab/validation.py) | 显式类型、普通标签角色、层级及相关关系冲突 | 不执行完整推理，未共享映射审查的 S46 检查 |
| [SHACL](../../../packages/kb-vocab/src/kb_vocab/shacl_validation.py) | 现有字段形状、类型、数量和语言等项目约束 | 使用 `inference='none'`，不能由通过结果推出所有 SKOS 语义已检查 |
| [映射审查](../../../packages/kb-vocab/src/kb_vocab/review.py) | 将映射关系投影参与图检查，并检查精确映射与宽窄、相关映射冲突 | 独立映射流程，不等于所有构建与编辑入口已经执行同样检查 |

2026-09-19 的内存样例中，同一对端点同时具有 `exactMatch` 和 `broadMatch`，通用图校验与 SHACL 未报错，映射审查报告 S46 冲突。该证据说明入口覆盖不一致，不表示当前正式词表包含此冲突。目标见[统一校验合同](../../model/vocabulary/设计-词表数据规范.md#校验范围)。

## 多语差异

以下沿用 2026-09-19 的代码核对，区分现有行为与[多语言目标](../../model/vocabulary/设计-多语言词表.md)。

| 环节 | 当前行为 | 尚未满足的目标 |
|---|---|---|
| 语言范围 | [归一器](../../../packages/kb-vocab/src/kb_vocab/normalization.py)按标签首段保留 `en`／`zh`，其他语言留在来源副本 | 不能代替完整标签语法及按固定 IANA 注册表的登记校验 |
| 标签角色 | 图校验按忽略大小写后的完整标签检查普通首选名，检查三种角色值冲突 | XL 投影与统一名称登记尚未接入 |
| 翻译任务 | [提取器](../../../packages/kb-vocab/scripts/extract-translation-tasks.py)遇到任一中文标签即跳过；英文优先 `en`，其余按既有排序选取 | 未按完整目标标签分别补缺，不读取完整历史译文库，也不是通用 RFC 4647 Lookup |
| 翻译合并 | [合并器](../../../packages/kb-vocab/scripts/merge-translation-batch.py)核对任务、源文字、实际源语言、基准和写集，输出 `@zh` 并保留批次依据 | 不支持通用目标标签，也不承担跨版本语义复核；既有输出不能自动视为 `zh-Hans` |
| 显示与复核 | 中文流程有英文回退；[复用代码](../../../packages/kb-vocab/src/kb_vocab/display.py)清理退出对象、避让基准中文并比较 `@en`，[应用同步](../../../packages/kb-vocab/src/kb_vocab/maintenance_apps.py)沿用该结果 | 仍以 `english_changed` 排除旧译文；统一 Lookup、完整变体与语义复核、目标适用性提示尚未接入 |

上述差异不能通过修改旧标签或扩大语种范围绕过。名称登记、任务选择、校验和显示需共同核对；双语文件存在不证明多语言消费已经完整支持。

## 维护缺口

| 缺口 | 具体后果与目标 |
|---|---|
| 校验入口差异 | 普通图校验、SHACL 与映射审查的覆盖尚未统一，不能以局部检查放行其他入口遗漏的冲突 |
| XL 与编辑衔接 | 统一名称登记、普通标签兼容输入、翻译关联和登记快照回退尚未接入 |
| 旧引用读取 | 归档和输出排除已经存在，退出提示、指定版本及未指定版本的统一读取仍需实现 |
| 译文与语义复核 | 展示仍以 `english_changed` 排除旧译文；新版适用性、直接依赖影响及带用途映射消费尚待接入 |

实现覆盖与缺口统一在本篇维护。操作合同见[词表维护](../../model/vocabulary/设计-词表维护.md)，中文批次合同见[翻译流程](../../model/vocabulary/设计-多语言词表.md#翻译流程)。停用及替代属性已在现有字段校验和来源保留中使用，通用维护事件摘要、旧引用读取和内容迁移仍分别待接入。

[维护接入计划](../../../work/archive/plans/2026-09-19-vocabulary-maintenance.md)按原文归档，保存当时列明的实施及验收结果，不作为下一阶段待办或当前服务状态证明。

## 维护接口

以下保存当前普通标签维护接口；操作命令集中见[词表工具链](指南-词表工具链.md)。

### 数据职责

| 文件 | 职责 |
|---|---|
| `data/inputs/vocabulary/maintenance.json` | 配置入口、输出位置及应用目标 |
| `sources.json` | 当前希望同步的来源、已有 Turtle 和可选刷新流程；移除条目即表示该来源退出 |
| `knowledge-system.json` | 自有词表和领域分组规则；同步器派生实际来源指纹及有效分组引用 |
| `local-edits.json` | 本地编辑的唯一当前记录，含修订号、编辑前的来源值和修改历史 |
| 构建的 `upstream.ttl` | 本次来源及组织规则形成的未编辑基线 |
| 构建的 `vocabulary.ttl` | 应用本地编辑后的一份当前词表 |
| `local-effects.json` | 本地新增、删除、字段变化与来源退出造成的引用清理 |
| `output/vocabulary/operations/` | 操作请求、输入快照、状态、冲突与应用结果 |

原始文件、旧构建和已退出来源的历史快照不是本地编辑目标。物理清理与停止同步分开；同步器不会因为清单变化直接清空历史目录。

### 来源选择

来源条目可配置 `selection`，其中 `roots` 是准确的来源概念 URI，`descendants` 决定是否包含全部下位概念。未配置时保留该来源的全部概念。根概念不存在时拒绝构建，不按名称猜测替代项。

过滤只作用于该来源进入自有词表的贡献，原始 Turtle 副本保持完整；其他来源仍支持的同一 URI 不随之删除。指向不再收录概念的关系按规则移除，去向写入 `source-selection.json`，再对过滤结果执行正常转换对账。领域成员由完整来源结构与选择范围共同确定。

当前 ERIC 采用[收录范围决定](../../model/vocabulary/决定-ERIC收录范围.md)：15 个根概念及全部下位概念，当前共 44 个概念。改变选择范围不会把已经刷新的来源退回旧快照。本地编辑仍在选择结果上应用；引用被排除节点的本地修改会报告冲突。

### 编辑粒度

编辑文件是 JSON 操作数组。概念、集合及其字段使用 RDF URI；值使用 RDF 的 N3 写法，由 RDFLib 解析。支持中英文文字、URI、类型化字面值和批量操作，不使用任意 SPARQL UPDATE。

| 操作 | 对象 | 含义 |
|---|---|---|
| `create` | Concept 或 Collection | 显式创建本地节点，提供稳定 URI、类型和字段 |
| `set` | 属性，可限定语言 | 替换选定属性或语言的全部值 |
| `add` | 属性值 | 增加名称、关系或分组成员等值 |
| `remove` | 属性值 | 移除指定值，保留其他值 |
| `delete` | 节点 | 从本次输出排除节点及图内引用，持久保存删除意图；不等于来源停用或旧内容已迁移 |

例如从集合中移除成员只删除 `skos:member`，不会删除概念。关系变更同时维护已定义的反向表达。主体 URI 不能通过字段修改；类型和词表归属由创建及生成管理。匿名资源不作为直接编辑身份，复杂说明资源应使用稳定 URI。

编辑记录只说明本地意图和来源，不自动证明术语准入或外部事实成立。界面将本地新增名称标为本地编辑；不会把它标成来源原文、已核外部术语或 AI 翻译。

### 冲突与恢复

失败操作保存 `conflicts.json` 和 `incoming.ttl`，冲突绑定编辑内容指纹，过期结果不能覆盖后续修改。解决选项 `local` 更新字段或节点的比较基线并保留本地意图，`source` 撤销对应编辑；目标或关系不存在时仍须显式处理，不能用选择本地值制造有效身份。

当前编辑修订原子写入；应用同步在词表发布后执行，失败记为 `application-failed`，重试复用已准备来源和构建，仅在实时核对一致时跳过导入。不同应用不与词表入口共同切换。异常进程可能留下写锁，清理前确认没有活动写入者；这些能力不构成操作系统崩溃持久性保证。

## 中文批译

现行批译限定英文输入和中文 `zh` 输出，沿用原批次授权；语言模型与译文适用性要求见[多语言词表](../../model/vocabulary/设计-多语言词表.md)，代码差异见[多语差异](#多语差异)。

### 翻译范围

当前批译只处理现有 Concept、Collection、ConceptScheme 缺失的中文首选名，不翻译别名、定义、范围说明或任务记录。AI 初译用于展示，暂不要求逐项核对权威中文术语；后续可针对指定对象补充来源或修订译文，不自动取得正式术语准入效力。

任务从已有英文名称取得输入，保留实际源语言标签，输出目标固定为 `zh`。不将既有结果改标为 `zh-Hans`；其他源语种或目标语种须另有采用依据。

### 基准与产物

`output/vocabulary/current/vocabulary.ttl` 是翻译的唯一基准，由词表生成器维护对象身份、英文名称、关系和分组。每次翻译固定其版本与哈希，不反向修改基准，也不删除其中已有中文。

| 记录或产物 | 职责 |
|---|---|
| 任务目录中的 `tasks.json` | 从基准提取对象 URI、字段、英文原文及任务 ID，不能自行新增词表对象 |
| 批次输入与输出 | 输入提供待译词汇及必要上下文；输出按任务 ID 提供中文或保留原文的结果 |
| `translations.zh.ttl` | 从当前有效译文生成的中文增量，不人工维护第二份译文 |
| `vocabulary.multilingual.ttl` | 当前基准与中文增量合并的双语产物，不覆盖英文基准 |
| `label-provenance.json` | 目标词表、基准哈希、批次元数据及标签到批次的关联 |

对象对应以稳定 URI 为准，字段和目标语言限定具体译文。名称相同不表示对象相同，不按英文名称或文件排列位置复用。

### 批次元数据

每批保存一份翻译者类型、实际模型标识、agent、输出文件写入时间、输入输出哈希及所用基准版本；每条中文只关联批次，不重复填写模型与时间，不建立逐条审批流程。

执行程序记录实际调用的模型和 agent，不让 agent 猜测；补做批次保留各自归属。复用时保留原批次及证据版本，新双语产物另记本次合并基准，不能用合并时间或最新来源版本改写原翻译记录。后续外部资料及修订依据关联具体对象和字段，不提升整批译文的依据等级。

### 合并与展示

当前批次合并核对基准、任务 ID、对象 URI、字段与译文，保留原文的条目不输出空中文或英文 `@zh`。普通标签增量与基准合并后形成双语文件，应用可显示中文、英文或对照；任务选择、统一 Lookup 和跨版本复用的限制见多语差异。

目标合同要求名称登记、译文与适用性记录能够共同追溯并成套交付，待复核提示随名称显示；这些要求不因现有双语文件生成而视为实现。逐项采纳的旧输入另见[语言接口](设计-现行数据规范.md#语言接口)，不与批次依据混用。操作见[翻译脚本](../../../packages/kb-vocab/scripts/README.md)。

## 建设安排

来源收录与内容建设按原批准范围执行。以 CS2023、IFLA、CWPA、tekom 等材料进行后续知识覆盖建模仍暂缓；材料用于其他已核规则不等于覆盖建模已经完成。计算机科学、认知科学和哲学的内容填充优先级不自动扩大或裁剪词表收录。

## 方案范围

当前中英文展示缺中文时回退英语，属于本消费配置的默认选择。通用设计要求先完成语言优先列表，再执行消费方声明的默认行为；不同语种或用途不自动继承英语默认。现有匹配能力仍以[多语差异](#多语差异)为准，本次没有改变运行设置。

现有来源同步沿用基准、来源新值和本地目标值的三方比较；这是具体协调方案，不代表不同字段的修改必定语义独立。按修订后的目标，自动协调结果还须经过完整约束与必要语义核对，现有覆盖见[校验覆盖](#校验覆盖)。

基于固定输入生成新词表或多语言产物，是现行文件流程的一种实现方式。其他方式若满足内容、版本、退出清理与恢复要求，也可作为后续方案；本次没有切换生成方法。同值兼容标题继续按现行输出合同处理，不再作为通用模型要求。

## 文件交付

文件方案承接以下交付要求；它们用于说明文件型来源和产物，不要求所有 RDF 数据来源或发布都必须采用同一种物理形式。

| 对象 | 文件方案需要记录的信息 |
|---|---|
| 来源快照 | 来源身份及版本、实际取得条件、原件或归档位置、保存内容的完整性证据；缺项明确记录 |
| 字节摘要 | 哈希算法、实际覆盖的文件或字节及摘要；字节相同不代替语义正确，图等价也不等于字节相同 |
| 发布文件 | 完整文件清单、逐文件摘要、实际采用的输入与规则、校验及转换记录 |
| 恢复材料 | 适用版本、原位置与回放位置的对应，以及读取或恢复条件 |

现行清单及回放材料按[现行数据规范](设计-现行数据规范.md#版本接口)和[工具链](指南-词表工具链.md#归档重放)使用，已有能力及限制仍以上文记录为准。上述分工不增加当前接口字段，不将目标要求写成已经实现的事实。
