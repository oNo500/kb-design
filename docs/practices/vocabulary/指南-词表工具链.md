# 词表工具链

本指南说明当前 RDF 词表的准备、同步、编辑、查询、恢复和应用加载。命令从仓库根目录执行；大写参数表示需替换的实际路径或标识。操作以已授权的来源、编辑和发布范围为前提。数据合同见[数据规范](设计-现行数据规范.md)，实现限制统一见[工程能力](设计-词表工程能力.md)。

## 执行起点

| 需要完成的工作 | 入口 |
|---|---|
| 查看维护状态或未发布编辑 | `kb-vocab status`、`kb-vocab edit list` |
| 来源清单、选择范围或组织配置已变 | `kb-vocab sync` |
| 取得并转换某个来源的新版 | `kb-vocab sync --refresh-source NAME` |
| 只应用本地编辑 | `edit apply`；已暂存的编辑用 `sync --local` |
| 操作失败后继续 | `kb-vocab resume`；冲突先作明确处理 |
| 从固定输入生成候选 | `build-system --output NEW_BUILD_DIR` |
| 核对或加载选定版本到 Skosmos | `sync-current.py --build BUILD_DIR` |
| 重放或回退旧版本 | 归档重放、版本回退两节 |

日常维护使用 `sync` 与 `edit`，由维护器准备来源指纹、固定输入并记录操作。低层构建用于已经固定的输入，不自动完成来源刷新和应用同步。

## 准备与配置

安装项目固定的开发依赖：

```sh
uv sync --all-packages --locked
```

| 配置 | 职责 |
|---|---|
| `data/inputs/vocabulary/maintenance.json` | 维护工作区、组织配置、输出根目录及应用目标 |
| `sources.json` | 当前采用的来源、文件、刷新适配器与收录规则 |
| `knowledge-system.json` | 自有词表、领域、语言、来源指纹及本地编辑位置 |
| `local-edits.json` | 维护命令生成的本地编辑记录及修订历史 |
| `shapes.ttl` | 构建使用的字段形状及结构约束 |

路径按所属配置文件解析，来源数量以当前清单为准。编辑和 `sync --local` 需要一个已验证并归档的当前构建；首次准备使用 `sync`。其他工作区通过 `--workspace WORKSPACE_FILE` 指定；在 `edit` 中该选项放在动作名之前。

## 日常同步

```sh
uv run kb-vocab status
uv run kb-vocab sync
uv run kb-vocab sync --refresh-source ERIC
uv run kb-vocab sync --local
```

普通同步按来源清单和已登记流程准备输入；`--refresh-source` 可重复指定准确来源名称。`--local` 不下载或解析原件，使用当前归档的来源和组织配置，只应用最新本地编辑。需要采用新的来源选择或组织配置时使用普通 `sync`。

同步默认更新配置中的应用；只发布词表而跳过应用时加 `--no-apps`。词表切换与应用完成分别报告，命令成功不等于新名称或关系已经取得语义采纳。

## 本地编辑

编辑文件是 JSON 操作数组，支持 `create`、`set`、`add`、`remove`、`delete`。主体和属性使用 URI 或已知 RDF 前缀，值采用 N3 写法；语言限定使用完整标签。示例中的 URI 和文字须替换为实际对象：

```json
[
  {
    "op": "set",
    "subject": "urn:example:concept",
    "predicate": "skos:prefLabel",
    "language": "en",
    "values": ["\"Updated name\"@en"]
  }
]
```

```sh
uv run kb-vocab edit apply EDITS_FILE --reason "修改依据" --dry-run
uv run kb-vocab edit apply EDITS_FILE --reason "修改依据"
uv run kb-vocab edit list
uv run kb-vocab edit undo EDIT_ID --reason "撤销原因"
```

预览不保存编辑或发布；正式应用先保存意图，再从归档基线生成。需要分批暂存时加 `--record-only`，最后执行 `sync --local`；`--expected-revision NUMBER` 检查并发修订，`--no-apps` 跳过应用。

ConceptScheme 由组织配置维护，类型及归属字段由创建和生成管理；匿名资源不是稳定编辑目标。节点排除不等于来源停用或旧内容已经迁移。详细约束见[编辑粒度](../../model/vocabulary/设计-词表维护.md#编辑粒度)。

## 冲突与重试

`status` 显示操作状态、本地修订与已发布修订。发生冲突时，从操作目录的 `conflicts.json` 选择具体记录：

```sh
uv run kb-vocab edit resolve CONFLICTS_FILE --id EDIT_ID --choice local --reason "保留依据"
uv run kb-vocab resume
uv run kb-vocab resume --operation OPERATION_ID
```

`local` 更新比较基线并保留本地意图，`source` 撤销对应本地编辑。目标或关系已经消失时不能靠选择本地值制造有效身份，应调整引用、建立获准的本地对象或撤销编辑。多项冲突可先加 `--record-only`，处理后再继续。

重试复用仍匹配输入的已准备来源；`application-failed` 时只重试应用阶段。如果 `current` 已经改变，旧应用操作不能直接恢复，应明确选择要同步的构建。失败不会自动删除本地意图或历史版本。

## 来源准备

已有适配器能处理的刷新优先走统一维护入口。新增来源或单独检查转换时，分别保存取得、解析和导入产物。

```sh
uv run kb-sources fetch --manifest MANIFEST_FILE --output SNAPSHOT_ROOT
uv run kb-sources verify SNAPSHOT_DIR
uv run kb-sources extract SNAPSHOT_DIR --file-id FILE_ID --output EXTRACTION_DIR
uv run kb-sources extract-all --snapshot SNAPSHOT_DIR --output EXTRACTION_DIR
```

`verify` 用于标准下载快照，不用于手动取得记录或自有词表构建。手动材料保留原件、地址和哈希。原生 Turtle、XML、TSV、JSON 及相应压缩包直接交给适配器；文献提取只提供结构和定位，不自动建立概念层级。

IEEE 和 Cognitive Atlas 使用专用入口：

```sh
uv run kb-sources extract-ieee --acquisition ACQUISITION_FILE --output EXTRACTION_DIR
uv run kb-sources fetch-cognitive-atlas --manifest MANIFEST_FILE --output BUNDLE_DIR
uv run kb-sources export-cognitive-atlas BUNDLE_DIR --output TRANSCRIPTION_DIR
```

IEEE 解析需匹配适配器支持的版式；如使用已有第三方对照材料，`--reference-csv` 与 `--reference-taxonomy` 成对提供。未分配文本及退出码 `2` 不能按完整成功处理。Cognitive Atlas 可复用已校验批次，但分批取得不保证远端事务快照。

批量提取可重复指定 `--snapshot`；使用 `--sources` 扫描时若存在多个可选版本，改用明确列表。来源升级使用新目录，图片及 OCR 不在当前提取路径内。适配范围以[来源工具](../../../packages/kb-sources/README.md)及具体获取记录为准。

## 来源转换

| 来源 | 入口及输入 |
|---|---|
| IEEE | `import-ieee`，专用提取 JSON |
| ERIC | `import-eric`，XML 或 ZIP |
| MSC2020 | `import-msc`，来源分类表 |
| PhilPapers | `import-philpapers`，来源分类 JSON |
| Cognitive Atlas | `import-cognitive-atlas`，已验证转录 |
| 其他已支持适配器 | 按实际输入调用；适配器存在不等于来源已加入当前清单 |

```sh
uv run kb-vocab import-msc SOURCE_FILE --output NEW_SOURCE_DIR
uv run kb-vocab import-eric SOURCE_FILE --identities OLD_SOURCE/vocabulary.ttl --output NEW_SOURCE_DIR
```

IEEE、ERIC 和 Cognitive Atlas 的更新均可用 `--identities` 指定上一份来源 Turtle 及其相邻 manifest，不能用合并主图代替。ERIC／IEEE 按准确来源名称复用，Cognitive Atlas 按来源 ID 复用；旧键缺失或类型改变会停止，不能据此自动判断改名、合并或拆分。首次导入不带旧身份，输出目录须不存在。

来源导入成功与获准替换已有处理结果是不同步骤。核对新旧差异、固定冲突规则的版本适用性及项目采用范围后，再调整输入；历史原件和转换记录保留。其他导入命令见[词表工具](../../../packages/kb-vocab/README.md#命令用法)。

## 独立构建

需要从固定配置生成候选、不切换当前入口时：

```sh
uv run kb-vocab build-system --config CONFIG_FILE --output NEW_BUILD_DIR
```

已明确要发布固定输入时：

```sh
uv run kb-vocab build-system --config CONFIG_FILE --output-root OUTPUT_ROOT
```

两种输出选项互斥；`--build-id BUILD_ID` 只与 `--output-root` 配合。低层构建使用配置中的来源和指纹，日常源更新由 `sync` 准备，不手改发布文件。构建失败保留旧入口；独立构建不自动加载应用。

结果中核对 manifest、报告、转换对账、身份差异及警告。独立 `validate` 不覆盖完整发布检查，现有检查也不等于全部目标约束已经实现，具体见[校验覆盖](设计-词表工程能力.md#校验覆盖)。

## 应用同步

维护命令默认同步配置中的应用。需要单独核对或加载指定构建时，从仓库根目录执行：

```sh
uv run python apps/skosmos/sync-current.py --build BUILD_DIR --check
uv run python apps/skosmos/sync-current.py --build BUILD_DIR
uv run python apps/skosmos/sync-translated.py DISPLAY_DIR
```

`--check` 核对记录、文件哈希及远端图，不重新导入图；服务准备见[Skosmos 说明](../../../apps/skosmos/README.md)。中文入口要求已有合法的 `bilingual-display` 产物，不把英文构建目录当成中文展示目录。

单个应用同步失败会尝试恢复原图及配套文件；恢复结果须从 `sync-status.json` 和错误中确认，`recovery_failed` 不能当成功。各应用与词表发布不构成共同事务。源哈希、导航和标签元数据一致才证明该次加载完成，历史记录文件存在不提供这一证明。

## 归档重放

具备可重放配置的归档使用包内输入，整个版本目录可以搬动后重建到新目录：

```sh
uv run kb-vocab build-system --config ARCHIVE_DIR/inputs/config.json --output NEW_BUILD_DIR
```

`original-config.json` 保存原配置，`inputs/config.json` 保存包内重放路径；二者不能互换。重放输出必须是新目录，默认不切换 `current`。只有具备相应文件集的归档适用，旧归档按其原合同处理。

需要使用归档保存的工具和依赖环境时：

```sh
python3 ARCHIVE_DIR/recovery/restore.py NEW_ENV_DIRECTORY
NEW_ENV_DIRECTORY/bin/python ARCHIVE_DIR/recovery/run.py build-system --config ARCHIVE_DIR/inputs/config.json --output NEW_BUILD_DIR
```

环境目录必须不存在且位于归档之外；恢复依赖 uv、相容 Python 及包获取条件。目标是相同 RDF 图，不宣称跨环境字节一致、离线系统镜像或崩溃持久性。

## 版本回退

```sh
uv run kb-vocab activate-system --output-root OUTPUT_ROOT --version BUILD_ID
```

版本标识须对应该根目录下保留的构建。切换后，用选定历史版本的目录单独同步应用；相应中文展示也须与该基准匹配。普通 `sync` 会按期望配置重新计算，不作为历史版本导入的替代。

回退入口不删除编辑记录或后续决定。再次维护前核对本地修订与所选基线；旧引用和完整版本的处理按[版本合同](../../governance/maintenance/设计-词表版本.md)。

## 查询与诊断

```sh
uv run kb-vocab find VOCABULARY_FILE SEARCH_TEXT
uv run kb-vocab show VOCABULARY_FILE CONCEPT_URI
uv run kb-vocab query VOCABULARY_FILE --query-file QUERY_FILE
uv run kb-vocab diff OLD_VOCABULARY_FILE NEW_VOCABULARY_FILE
uv run kb-vocab validate VOCABULARY_FILE
```

`show` 支持 URI 或精确名称，同名时使用 URI；SPARQL 仅允许本地只读 SELECT，不允许 SERVICE、FROM 或 UPDATE。字段盘点入口为 `packages/kb-vocab/scripts/profile_vocabulary.py`，输出新诊断目录。诊断不形成语义采纳，已有构建证据覆盖的检查不重复执行。

跨来源 `review` 是独立可选流程，不是生成的前置条件，也不承担自动 AI 语义判断。命令细节见[对应审查](../../../packages/kb-vocab/README.md#对应审查)。

## 失败定位

| 现象 | 核对与处理 |
|---|---|
| 原件或提取失败 | 核对取得记录、版本、格式及哈希，保留旧材料；不把部分成功当全量成功 |
| 身份或固定规则不匹配 | 保留新旧结果，处理具体对应及规则适用性后再更新输入 |
| 本地冲突 | 读取操作的冲突记录并逐项处理；不修改归档来消除冲突 |
| 构建失败 | 阅读校验与对账结果，修正输入或实现；旧当前版本保持 |
| 应用失败 | 先确定词表是否已发布，再用 resume 或明确版本的应用入口处理 |
| 遗留写锁 | 确认没有活动写入者后再清理，不在并发操作仍运行时移除 |

维护中的 `failed`、`conflict`、`application-failed` 退出码为 1；独立校验失败同样返回非零。查看实际状态和结果，不仅凭文件生成或进程结束判断完成。该工具链不自动迁移旧 YAML 消费者或写入外部正式知识库。
