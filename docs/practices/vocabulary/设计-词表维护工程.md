# 词表维护工程

词表维护负责来源、本地记录、名称、属性及版本，输出可核对的 RDF 交付。Obsidian 的配置、目录、页面和视图由[产物维护](../../applications/obsidian/设计-产物维护.md)负责；文章引用由内容维护处理。三者可以依次执行，但分别记录目标与结果。

本篇适用于独立 RDF 开发路径，分工依据见[职责分离](../../development/决定-维护职责分离.md)。概念、名称、实体、语言和状态的业务要求仍以[词表维护](../../model/vocabulary/设计-词表维护.md)、[数据规范](../../model/vocabulary/设计-词表数据规范.md)及[实体设计](../../model/entities/设计-命名实体词表.md)为准。工程采纳不批准新实体事实、候选转正或正式发布。

## 处理范围

| 工作 | 输入 | 输出 |
|---|---|---|
| 旧资料收录 | 现有编辑源及身份对应 | 原件快照、RDF、状态、依据与未投影信息 |
| 版本比较 | 两份固定 RDF | 按对象、属性列出的新增和移除值 |
| 本地修改 | 基准、具体修改、理由及授权引用 | 可审阅计划及通过适用检查的新交付 |
| 冲突核对 | 原基准、当前来源及本地意图 | 相容结果或明确冲突；不静默覆盖 |

采用旧工具的字段差异与基准比较机制，不照搬普通标签限定、整套生成配置或应用同步器。当前维护包集中实现有独立输入输出的数据步骤；通用工作流调度、跨来源合并、关系结构调整、停用及正式发版不因这些步骤存在而自动启用。

## 数据权属

`data/vocab/entities.yaml` 继续是旧实体记录的编辑源。导入将原记录转换为独立交付，不复制成第二个可以独立改写的实体库，也不修改原 YAML。原来的局部 ID、目录身份、状态、依据、历史与外部对应均须能回查。

实体的当前消费入口统一为一份 RDF，CCS 实体交付与旧实体导入交付都作为其来源输入。按[实体统一使用](../../model/entities/决定-实体统一使用.md)，基本字段齐全的记录可以先用，原 candidate 状态或事实未核说明不单独阻断；这不要求修改原状态，也不恢复已明确停用的记录。

实体和名称的 IRI 由持久登记与原来源身份对应，首次分配后持续复用。名称文字变化不重新分配同一表达的身份；同文名称和同名对象不自动合并。登记不是名称正文的另一个编辑源。

旧 `subjects` 只说明其原词表中的归属，不按文字自动映射到 CCS；旧 `match` 不自动改成 `owl:sameAs`。本地记录的 candidate、active 是原项目状态，不能冒充外部对象状态或 `owl:deprecated`。无法完整投影的字段保留原件位置及原因，不把转换成功说成语义已核实。

本地改动通过显式计划作用于固定基准，生成新目录。来源原件和已完成交付不原地覆盖；已经存在的输出只有在全部输入、计划和产物摘要相符时才可复用。

## 变更记录

计划至少定位对象、属性、必要的语言和名称身份，保存修改前后值、基准、理由、依据及授权。RDF 值保留文字、语言、数据类型或 IRI，不把整个图中的同文字符串一起替换。

SKOS-XL 的名称文字和资源到名称的角色分别处理。修改 literalForm 时保留 Label IRI，核对全部使用位置及普通标签投影；不能让普通标签成为与 XL 相互矛盾的第二个编辑源。首选与别名文字冲突必须报告。

字段差异以 RDF 结构比较为依据，序列化顺序和空白节点的临时名称不直接算业务变更。差异只是事实清单，不推断含义改变、合并或拆分。

## 冲突与恢复

应用计划时再次比较原基准、当前输入及预期值。无关字段变化不必重做全部步骤，但目标字段、共享名称及相关不变量必须重新核对。无法解释的差异保留为冲突，不任取来源值或本地值。

读取与计算结果可在输入、规则、工具及依赖版本相符且产物完整时复用。写入中断先核对实际结果；输出目录存在不等于操作成功，同一计划不得重复分配身份。未完成或损坏的交付不能成为后续输入。

有效确认可以按原范围复用；修改了候选对象、具体值或采用范围时，旧确认不能直接套用。Git 提交、工具退出成功、校验通过及语义采纳分别保留其效力。

## 版本交付

```text
固定输入 → 准备修改 → 比较与检查 → 核对授权 → 新目录交付
                 |
               发现冲突 → 保留证据 → 修订计划
```

交付包含 RDF、原输入、身份对应、原状态、实际修改、规则及检查结果，并提供文件摘要。未执行的实体事实核验、全图条件或语义审查必须明确列出。仅有元数据齐全不能证明这些检查已完成。

词表维护在交付处结束。应用可以显式选择该版本，但词表命令不会调用 Obsidian 刷新、改变应用配置或补写文章引用。失败恢复也不得通过回退文章来恢复词表。

## 维护工具

`packages/kb-vocab-maintenance/` 提供旧实体收录、字段比较和本地修改步骤。RDF 解析与结构比较复用 RDFLib，适用规则复用既有校验；具体命令及实际覆盖见[包说明](../../../packages/kb-vocab-maintenance/README.md)。

旧 `kb-vocab` 继续服务其原生成路径，不因复用机制而成为新数据的编辑入口。完整调度框架与跨进程人工等待仍需按独立实施范围验收，不能把当前局部幂等处理宣称为整条流水线完成。

## 当前入口

当前实体读取入口为 `output/vocabulary/entities/current/entities.ttl`，指向 `versions/` 中一份完整交付。生成输入由 `data/inputs/vocabulary-maintenance/entities.json` 固定，原件与各自状态随交付保存。

基本字段合格的实体列入该版本的可用清单，原状态另行保留；应用适配须遵守这一具体使用决定。当前入口只在完整性核对后显式切换，旧版本保留，普通目录或不完整产物不得覆盖为当前版本。

## 归档去向

此前将词表维护、应用刷新和文章补引用串成同一职责的提案已[归档](../../../work/archive/specs/2026-09-23-maintenance-mixed/提案-词表维护流水线.md)。其中对象、依据、确认、任务结果及恢复要求由本篇承接；应用安装和配置转入[产物维护](../../applications/obsidian/设计-产物维护.md)，文章登记及引用仍遵循[内容使用](../../applications/obsidian/提案-词表使用与维护.md)。归档不修改此前的历史决定。
