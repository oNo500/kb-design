# 项目概述

kb-design 用于建立和维护个人知识体系的组织规则。它把内容描述、主题分类、术语、来源依据和维护规则放在同一个项目中，使知识内容能够依据一致的模型组织，并在具体应用中使用。

## 项目由来

项目从已有知识内容之外开始设计。[原始说明](../README.md)记录了这一选择的原因：此前的尝试容易受现有知识限制，看不到尚未覆盖的领域。独立建立组织结构，是为了检视知识范围，同时以已有规范和事实标准作为设计依据。

## 核心问题

知识内容的组织需要分别回答以下问题。

| 问题 | 对应设计 |
|---|---|
| 一条内容怎样获得稳定身份，并表达主题、类型与引用？ | [内容模型](model/content/设计-内容模型.md) |
| 同一主题怎样统一表示，不同主题怎样建立层级与关联？ | [主题词表](model/vocabulary/索引-主题词表.md) |
| 产品和组织的身份怎样与知识主题分开？ | [命名实体词表](model/entities/设计-命名实体词表.md) |
| 一个名称具体指什么，定义和译名凭什么采用？ | [术语数据库](model/terminology/概念-术语数据库.md)、[术语表](参考-术语表.md) |
| 外部材料支持了哪个具体判断，谁能批准变更？ | [来源用途登记](model/sources/设计-来源用途登记.md)、[治理](governance/decision-making/设计-治理.md) |

## 项目范围

本仓库维护模型、规则、词表和应用工具。正式知识库位于仓库外的 `~/Documents/kb-vault/`，保存实际知识内容。

共享模型规定内容与词表的含义、身份和关系；应用适配规定这些对象在具体工具或表示规范中的使用方式。更换应用时，共享模型的定义保持独立，具体表示另行设计，见[设计与应用分离](applications/shared/决定-设计与应用分离.md)。

## 应用关系

Obsidian 是当前知识库的承载工具，其属性、链接、文件和视图由[适配设计](applications/obsidian/设计-Obsidian%20映射.md)规定。词表预览则服务于仓库维护，读取工作区数据供查阅。

DITA 在现有内容模型中提供内容单元和文档类型的设计参照。它也可以成为未来的内容表示目标；采用这些参照不代表已经实现 DITA 输出。
