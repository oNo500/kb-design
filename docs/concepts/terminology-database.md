# 术语数据库 (Terminology Database)

## 定义

术语数据库是用于创建、处理和使用高质量术语的数据库；其设计原则可以不依赖具体实现和使用场景。ISO 26162-1:2019 的公开摘要把适用范围扩展到分布式、多语术语管理，也说明同样原则可以用于较小方案，但没有公开字段、关系、基数或实现格式。

术语数据库管理的不是一张字符串清单。记录首先区分概念，再按语言组织表示该概念的术语，同时保存支持定义、形式和对应关系的材料，以及各对象的状态和历史。

## 解决的问题

| 问题 | 本库场景 | 处理方式 |
|---|---|---|
| 概念与形式混在一起 | 相同写法在不同位置表示不同对象 | 先确认概念身份，再登记形式 |
| 多语形式直接配对 | 中英文形式在检索结果中并列 | 分别核实形式，再核实共同概念 |
| 一项来源替代全部依据 | 定义有出处，形式或多语对应没有出处 | 每项判断分别关联支持材料 |
| 不同对象共用一个状态 | 概念仍在复核，其中一个术语已有使用地位 | 区分概念进度与术语管理状态 |
| 修改覆盖旧信息 | 新形式替代旧形式，既有内容仍使用旧形式 | 保留变化日期、替代关系和历史 |

Markdown 表格可以呈现整理结果，但单张平表难以稳定表达一个概念下多种语言、每种语言下多个术语，以及定义、形式、对应和状态各自的依据与历史。术语数据库提供的是这些对象之间的结构，不是某种显示或交换版式。

## 记录层次

术语数据库至少需要区分概念、语言和术语三个层次。

| 层次 | 区分的对象 | 本库场景 |
|---|---|---|
| 概念 | 被表示的概念及概念层描述 | 先确定记录讨论的是哪个概念 |
| 语言 | 同一概念中按语言组织的内容 | 分开保存各语言中已有依据的内容 |
| 术语 | 某种语言中的具体形式及其管理状态 | 分别处理优先、允许或历史形式 |

这个分层来自术语数据库自身的管理需要。某个交换格式也使用相似层次，不能反过来证明内部数据库应复制它的元素名、字段或约束。

## 多语对应

多语对应分别回答是不是同一概念、每种语言中有哪些形式，以及什么材料支持这些形式对应。ISO 25964-1:2011 §2.13 的 `cross-language equivalence` 连接不同语言中表示同一概念的术语；“同一概念”是对应成立的条件，不是看到两个相似标签后的结论。

标准采标关系、机器翻译和相似标签都只能提供检索线索，不能单独证明两个形式表示同一概念。没有足够依据时，应保留已有依据的原语言形式和未解决问题，不把推测写成多语对应。

## 状态层次

状态首先区分描述对象：一类描述概念记录的整理和维护进度，另一类描述某个术语在特定语言中的使用地位。概念进入某个工作阶段，不表示其中每个术语具有相同地位；术语被替代，也不表示所指概念消失。

TBX-Basic 的公开材料在术语层列出 `administrativeStatus` 的四个值。这只证明该公开方言能表达相应术语管理地位，不提供本库概念工作流、审批角色或状态转换规则。

## 维护要求

ISO 26162-3:2023 的公开摘要把术语数据集合的内容、数据质量评价、互操作性和持续改进列为重点，但没有公开维护程序、评价指标、角色或阈值。

Z39.19 §11.1.4 要求获准进入词表的每个 term 建立单独记录，并列举 term、所咨询的来源、范围注释、关系和历史注释等可记录内容；§11.3 至 §11.3.2.2 说明新增、修改和删除需要维护，并要求记录变化日期、责任人和必要历史。

交换物不能代替内部维护记录。外部数据类目与内部字段名称相似，不等于两者语义相同，也不能据此声称内部依据、决定和历史可以无损交换。

## 交换框架

ISO/TR 24633-1:2026 把 ISO 30042:2019 规定的 TBX 描述为表示术语数据的框架。TBX 由两个相互作用的部分组成：所有 TBX 方言共用的 TBX core structure，以及定义 data category modules 的形式机制。

| 对象 | 职责 | 不能等同于 |
|---|---|---|
| TBX | 表示术语数据的框架 | 单一 XML schema 或单一方言 |
| TBX core structure | 所有 TBX 方言共用的结构和数据类目 | core structure schema 或 TBX-Core dialect |
| data category module | 限定补充数据类目及其层次 | 核心结构或方言全部约束 |
| schema | 形式化表达可接受结构和内容的约束 | 被表达的模型或方言本身 |
| TBX dialect | 同时服从核心结构、数据类目模块和其他相关约束的标记语言 | 仅有核心结构或仅有模块 |

ISO 30042:2019 的公开摘要还说明该标准描述元模型、数据类目和 DCA／DCT 两种 XML 表示样式，并规定定义 TBX 方言的方法。收费正文未取得，因此不能从摘要补写完整元素、属性、基数、数据类目或一致性要求。

## 表示样式

DCA 和 DCT 是 TBX 数据的表示样式，不是方言。

| 样式 | 公开定义的说明性转述 | 示例 |
|---|---|---|
| DCA | 大多数数据类目写成模式所声明 XML 元素上 `type` 属性的值 | `<termNote type="partOfSpeech">adjective</termNote>` |
| DCT | 大多数数据类目写成 XML 元素名 | `<partOfSpeech>adjective</partOfSpeech>` |

两种样式回答数据类目“怎样写”，方言回答“允许哪些数据类目、允许在哪些层次出现、还须满足哪些约束”。同一方言可以同时提供 DCA 和 DCT 表示，因此选择样式不能推出方言，选择方言也不一定唯一确定样式。

## 方言边界

ISO/TR 24633-1:2026 的公开定义要求 TBX dialect 同时满足三项条件：按 TBX core structure 验证；只允许选定数据类目模块在指定层次许可的数据类目；遵守核心结构和模块之外仍需满足的相关约束。

TBX-Basic 是一个公开 TBX 方言，不是 ISO 30042 本身。LTAC Global 的版本页把 1.2.1 记为 2023-02-09 的方言发行版，并说明该版由 RNG 承担核心数据模型约束、Schematron 承担方言特有约束。公开方言、可下载和可验证都不能单独证明它适合本库。

在选择 TBX-Core、TBX-Min、TBX-Basic、其他公开方言或自定义方言前，必须先有真实接收方、交换任务、必需值清单、语言与状态要求、可接受损失和验证要求。DCA 或 DCT 也须由目标接口要求决定。

## 本库问题

当前本库没有具名 TBX 接收系统、导入方、文件交付对象或互操作失败案例；正式术语数据、正式发布快照和生产 TBX 消费者也尚不存在。因此现在只能研究 TBX 概念，不能选择方言、样式、字段映射或导出实现。

后续设计前至少回答：交换物交给谁、接收方执行什么动作、JSON 快照为何不足、交换哪些概念和语言、是否需要稳定 ID 与历史形式、哪些治理信息必须留在内部、未知字段怎样处理、接收方要求哪个 TBX 版本与方言。
