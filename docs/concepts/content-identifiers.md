# 标识符 (Identifier)

## 定义

标识符是在给定语境内对一项资源的无歧义引用。[DCMI Identifier](https://www.dublincore.org/specifications/dublin-core/dcmi-terms/terms/identifier/) 给出这一语义；标识符的作用是让系统持续指向同一项资源，不是描述资源叫什么、放在哪里或何时形成。

例如，一篇内容的标题从“查询方法”改为“受控词表的查询方法”时，读者看到的名称可以变化，引用它的标识符仍可保持不变。标题修改与资源身份修改是两件事。

## 相邻信息

标识符与名称、标题、路径、排序信息和时间信息分别回答不同问题。

| 信息 | 回答的问题 | 变化示例 |
|---|---|---|
| 标识符 | 引用的是哪一项资源 | 标题修正后仍引用同一内容 |
| 名称 | 人怎样称呼对象 | 采用的名称可以纠错或替换 |
| `title` | 当前怎样向读者显示内容 | 标题可以随表达改进而修改 |
| `path` | 当前从哪里取得表示文件 | 文件可以移动，引用对象不因此改变 |
| 排序信息 | 多项资源按什么次序排列 | 可以按标题、时间或另一个键排序 |
| 时间信息 | 资源何时创建、修改或发布 | 时间变化不创建新的资源身份 |

路径可以包含标识符，排序键也可以来自标识符，但这种表示或计算关系不把两者变成同一概念。例如，标识符为 `resource-1` 的资源可以先由 `notes/resource-1.md` 表示，再移到 `archive/resource-1.md`；路径变化不改变标识符所指的资源，也不表示资源身份必须由文件名决定。

## 性质边界

标识符的唯一性只说明在约定语境内能否避免把两项资源混为一项。不可猜测性说明值能否被预测；排序说明比较值时能否得到所需顺序；不透明性说明应用是否避免依赖值的内部组成。这些性质不能相互替代。

例如，UUIDv7 可以在不解析内部字段时按 bytes 排序，同时仍包含 Unix Epoch 时间。把值作为不透明对象处理，是应用行为；它不会删除值中已有的时间信息。UUIDv4 的随机来源也不使每个 UUID 自动成为访问凭据。[RFC 9562 阅读笔记](../references/rfc-9562.md)记录了这些条款边界。

## 使用边界

资源模型在采用一种标识符规则前，需要分别规定发放方式、唯一语境、稳定条件、表示格式和碰撞处理。应用可以把已取得的标识符绑定到字段或路径，但不能从标题、显示文本、文件名、排序位置或时间值反推资源身份，除非应用无关模型已经批准相应规则。

本文不选择名称派生值、UUID 版本、前缀或其他现行项目形式。具体规则的采用属于项目决定，来源事实和应用 binding 都不能代替该决定。
