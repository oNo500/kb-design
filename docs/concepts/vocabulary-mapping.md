# 词表映射 (Vocabulary Mapping)

## 定义

词表映射是在不同词表的概念之间建立对应关系。ISO 25964-2:2013 §3.39–3.41 分别说明建立关系的动作、过程和产物；一条映射可以连接一个词表中的概念与另一个词表中的一个或多个概念。这些定义已在免费样本中核对。

例如，两个词表都讨论关系数据库，名称相似只是查找线索；只有比较各自的定义和范围，才能判断是否对应，以及应使用哪种关系。映射解决跨词表检索和关联问题，不为本地概念自动补足依据。

## 解决的问题

映射保留两个词表各自的身份和组织方式，同时说明具体概念之间的联系。

| 问题 | 例子 | 映射的作用 |
|---|---|---|
| 不同名称可能指向同一概念 | 两个词表采用不同标签 | 核对范围后关联概念，不只比较字符串 |
| 相近名称的范围不同 | 一边讨论整个领域，另一边只讨论其中一部分 | 记录对应方向，避免按等价关系扩大检索 |
| 外部词表发生变化 | 某条目的范围或标识改变 | 按条目标识和所用版本定位受影响关系，再复核 |
| 多个系统需要联合检索 | 内容分别使用不同词表标引 | 利用已核关系连接检索入口，保留来源区别 |

名称依据、概念范围和映射依据分别回答不同问题。同名不能证明等价，指向权威词表也不能替代本地概念的准入。

## 映射的类型

本库的来源用途合同使用以下五种关系。表中方向均从本地概念指向外部概念；这是现行项目表示，不是对 ISO 25964-2 未读正文的逐条转述。

| 关系 | 本库含义 | 判断重点 |
|---|---|---|
| `exactMatch` | 同一概念，可以互换；具有传递性 | 对应范围和互换条件有依据 |
| `closeMatch` | 基本同一，不具有传递性 | 有近似对应依据，不能只因为无法判断就采用 |
| `broadMatch` | 外部概念更宽 | 本地范围与外部范围的包含方向 |
| `narrowMatch` | 外部概念更窄 | 外部范围与本地范围的包含方向 |
| `relatedMatch` | 概念相关 | 具体语义联系，不由名称相近推出 |

例如，若 A 与 B、B 与 C 都建立了 `exactMatch`，传递性会使 A 与 C 也得到对应结论；连续的 `closeMatch` 则不能这样推导。因此，一条精确映射的影响可能超出直接相连的两个条目，建立时须考虑这种后果。

ISO 25964-2 §3.23 将 differentiated mapping 定义为区分映射类型和质量的方法；§3.27 的 equivalence mapping 定义涉及被视为范围相同的概念。样本中的定义不能替代后续章节，也不能单凭目录确定 ISO 各种等价程度与 SKOS 属性的一一对应。

## 词表互操作

映射前先确认两端各自描述什么。主题概念的范围对应，与具体对象的身份对应，需要不同的判断。

例如，“关系数据库”是主题概念，PostgreSQL 是具体软件。软件与 Wikidata 条目的对应要核对是否同一个体；不能因为它属于某个主题，就把软件与主题记录成等价关系。ISO 25964-2 §3.50 已核定义也将名称规范表的对象限定为特定个体，而非类。

本库保存本地记录指向外部条目的映射。每个外部条目仍保留其体系身份，两个外部体系都与本地概念有关，不意味着两者自动等价。联合检索能否经过本地概念继续扩展，取决于具体关系的语义。

## 外部词表用法

映射、复制结构和计算派生概念组承担不同职责。下表概括现行项目条件，具体来源、对象和用途仍按来源用途登记核对。

| 用法 | 本地结果 | 条件 | 维护 |
|---|---|---|---|
| 映射 | 记录上的 `match` | `mapping` 已批准；外部条目可定位，每条关系有具体依据 | 外部变更后复核关系 |
| 复制结构 | 本地结构及实际派生记录 | `structure` 与 `mapping` 已批准；满足来源档级、版本、划分特征和复制范围约束 | 分别核对分组与成员依据 |
| 派生概念组 | 从现有映射计算的视图 | `group` 与 `mapping` 已批准；使用本库已有映射 | 从映射确定性计算 |

例如，按某个外部词表组织浏览入口时，可以从已有映射计算一个概念组。这个组只能呈现已经建立的对应，不能显示尚未建立的缺口，也不创建新的主题或批准复制外部结构。

`source` 说明实际派生自哪里，`match` 说明与哪个条目形成何种对应，数组成员则体现本地组织选择。三者的依据不能互相替代。没有复制外部结构，也可以按获准用途建立映射；映射数量增加或某个组经常被使用，都不自动批准新的用途。

## 知识库用法

文献身份、用途批准和具体关系分开管理。例如，一条本地概念到外部词表的映射中，所用材料的版本与地址由参考文献目录保存；能否用于映射由来源用途登记控制；两个概念如何对应，由映射旁的依据说明。

1. 先将带上下文的字符串解析到概念。发现材料不自动产生概念、名称、映射或 `candidate` 状态。
2. 核对所选材料、外部条目及获准用途，再比较两端的范围。没有足够依据时保留未核结论，不用 `closeMatch` 代替判断。
3. 映射分别保存 `registry`、`item`、`rel` 与 `basis`。可变材料保留真实核对日期；版本和文献身份不重复放入用途记录。
4. 外部体系改版时，根据条目标识、范围和所用材料定位受影响关系并复核。标识相同不保证含义未变。
5. 具体软件等对象按实体身份规则核对。普通笔记引用官方文档可保留正文链接，不因此建立设计书目或用途记录。

文献登记不批准用途，用途批准不确认每条映射；机器校验只能检查表示是否符合合同，不能完成概念对应判断。
