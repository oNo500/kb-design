# 概念文写作约定

适用于 `docs/concepts/` 下的每一篇文章。

## 约束的边界

这份约定的目的是让文章**看得懂、信得过**，不是限制写法。分两档：

- **硬规则**（标 ★）：只有 5 条，任何文章都遵守。它们保证读者不被误导、不被累着
- **默认做法**（其余全部）：是“没有更好想法时的起点”。一个概念如果用别的结构讲得更清楚，就用别的结构，在文末加一行“偏离约定：……，原因……”即可

判断标准只有一个：读者读完能不能正确理解这个概念。约定服务于这个目标，不反过来。

## 硬规则

1. 标题单看能知道这节讲什么
2. 每个抽象概念至少配一个例子
3. 事实性断言能在“权威来源”里找到出处
4. 外部事实核对原文后才提交；本阶段只用已有离线资料，未核实内容如实标明；经授权的模型知识译名按[治理](../design/governance/governance.md#译名)登记，不冒充外部事实
5. 链接用 `[标题](url)`，不写裸链接

## 标题的默认规则

全库标题规则见 [docs/design/governance/writing.md](../design/governance/writing.md)；本节只列概念文特有的。

- 2–8 字的名词短语，不用冒号，不写成句子
- 主语由文章标题隐含，小节标题只说“什么的什么”，不重复主语
  - 好：`词表结构`、`概念关系`
  - 差：`形式`（主语不明）、`概念之间有哪些关系`（写成句子）、`四层树结构`（包含参数）
- 文章标题格式：`# 中文名 (English Name)`

## 每节的默认规则

1. **第一句回答标题**。节首段直接给结论或定义，不铺垫、不讲历史
2. **先大白话，再术语**。新术语先用一句日常语言说清，再给英文名和缩写
3. **有例子才算讲清楚**。每个抽象概念至少一个例子；例子统一用本知识库的场景，贯穿全文用同一组（如 PostgreSQL、`status` 字段），不用图书馆、医学等陌生领域
4. **多项并列用表格**。列数 ≤ 4
5. **展示格式用代码块**。符号、记法、样例直接给代码块，不用文字描述“形如……”
6. **一节一件事**。并列的子概念拆成并列小节，小节内部结构一致：是什么 → 缩写读法 → 样例 → 作用
7. **断言有来源**。事实性陈述（标准分几层、某标准正在修订）必须能在“权威来源”节找到对应链接
8. **节末给落点**。概念讲完，最后一句说对本知识库实际怎么选

## 默认分节

| 节 | 必须包含 | 不包含 |
|---|---|---|
| 定义 | 一句话定义 + 权威定义出处 | 历史、分类 |
| 解决的问题 | 问题 → 例子 → 处理方式 的三列表 | 方案细节 |
| 结构 / 关系类 | 对比表或并列小节 + 统一例子 + 落点建议 | 标准条款号 |
| 在知识库中的用法 | 具体落地形态 + 治理提醒 | 工具选型 |
| 权威来源 | 标准 / 教材 / 实例 三类 | 博客、百科、二手转述 |

按需增删。“权威来源”受硬规则 3 约束必有；其余节看概念需要。

## 索引位置

[README](README.md) 的文章关系树按“知识组织”归类。新文章挂在哪，判据是：假如只有一份词表，这个概念还有没有意义。有，它讲的是一份词表内部的事，放在受控词表之下；没有，它讲的是词表之间或词表之外的事，与受控词表并列。不属于知识组织的（如方法论）另起一棵。

## 链接规则

全库规则见 [docs/design/governance/writing.md](../design/governance/writing.md)。

- 一律 `[标题](url)`，标题即链接文字；不写裸链接，不写“点这里”
- 标准写全称和年份：`ISO 25964-1:2011`、`GB/T 13190.1-2015`
- 标准如有修订中的新版，标注状态和预计时间
- 链接以已有离线原文或核对记录为依据；本阶段不联网或新增下载，未访问的链接不宣称已访问
- 模型知识译名按[语言依据结构](../decisions/structured-label-basis.md)保留模型、日期、判断与授权，明确外部用法未核实；该例外不扩及概念定义或事实性断言
