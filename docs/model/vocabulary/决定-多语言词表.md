# 多语言词表

状态：已采纳，2026-09-19。用户认可标准对照与文档分工，并要求同步词表整体设计和数据规范。正文见[多语言词表](设计-多语言词表.md)；本决定采纳设计，具体代码与迁移仍需实施和验收。

## 采用内容

| 事项 | 采用选择 |
|---|---|
| 设计职责 | 多语言词表统一语言策略、概念对应、名称及说明、语言匹配和术语衔接；中文标签只规定当前中文处理流程 |
| 概念与语言 | 同一含义共享概念，名称分别记录语言；跨语言差异按依据处理，不凭翻译、同名或语言标签自动合并 |
| 覆盖范围 | 保留来源全部语言；自有输出继续限定现行中英文标签范围，允许缺译，不强求各语言覆盖和结构完全对应 |
| 语言标签 | 按 BCP 47 区分语法、登记有效性及项目允许范围；保留完整标签和来源，不猜测 `zh` 的文字系统 |
| 匹配与显示 | 语言筛选采用 Basic Filtering，单个名称选择采用 Lookup；完成请求列表后保留英文回退，仍无名称时显示标识及缺项 |
| 编辑衔接 | 名称身份、修订、翻译依据和版本沿用维护约束，不新建平行登记或术语编辑源 |
| 实现边界 | 当前 `zh` 批译、术语库的语言值域及既有数据保持；目标规则与第 3 版差异分别标注 |

## 依据范围

业务范围依据 ISO 25964 官方说明和公开模型，方法比较采用已核 IFLA 官方指南；数据表示采用 RDF／SKOS／SKOS-XL，语言标签与匹配采用 RFC 5646、RFC 4647 和 IANA 注册表。实际核读位置及未核 ISO 正文范围见[标准依据](设计-多语言词表.md#标准依据)。

语言启用范围、允许缺译、默认回退和接口分工为项目选择，不冒充标准的统一要求。现有[整体设计](决定-词表整体设计.md)和[维护约束](决定-词表维护约束.md)继续适用。
