# 词表整体设计

状态：已采纳，2026-09-19。采纳记录见[整体设计决定](决定-词表整体设计.md)，现行规则见[整体设计](设计-词表整体设计.md)。以下保留采纳前的方案和论证，实施状态另按现行设计核对。

## 整合方式

建议采用“统一收录，按需整合”：保留独立来源快照，在一份自有词表中组织已选概念；只有经过具体判断的概念才合并或建立映射。

| 方案 | 收益 | 代价与适用性 |
|---|---|---|
| 全量建立本地概念并重组 | 可以统一全部身份、名称和层级 | 需要逐项承担概念对应、分类和来源更新责任，不适合作为导入前提 |
| 各来源独立，统一检索 | 保留各自体系，来源更新简单 | 没有统一的本地概念组织与名称选择，不能完整满足综合词表用途 |
| 统一收录，按需整合 | 延续现有主词表，并逐步协调交叉内容 | 需要明确区分“已收录”和“已确认同一概念”；建议采用 |

这项选择承接[现有词表结构](设计-词表数据规范.md#词表结构)和[来源收录决定](决定-来源收录范围.md)。一个 `ConceptScheme` 说明自有组织范围，不证明各来源已经形成完全相同的概念结构。

身份按以下情形处理。

| 情形 | 建议处理 |
|---|---|
| 原样收录来源概念，含义不变 | 复用来源概念身份，保留来源版本及采用的具体值 |
| 同名但尚未确认同义 | 保留各自身份，显示来源或范围帮助选择 |
| 已确认两个来源概念对应，但无需合并 | 建立有依据的映射，双方记录继续独立 |
| 需要形成一个本地概念，或本地含义与来源不同 | 经过具体采纳建立本地身份，分别保存与来源的关系；不修改来源图 |
| 合并或拆分已经被笔记引用的概念 | 保存旧身份、变更理由和后继对象；逐项复核旧引用，不用 `exactMatch` 代替迁移决定 |

整合不是导入时的强制步骤。概念是否相同必须比较定义、范围、关系和用途，字符串相似度只提供候选。对纯拼写或显示变化，不增加新的概念身份。

## 关系与导航

建议分别维护概念关系、来源结构和浏览组织；应用可以共同展示，但不能互相推导。

| 内容 | 表达及依据 | 不产生的关系 |
|---|---|---|
| 概念上下位 | `broader`／`narrower`；核对种属、实例或符合条件的整体部分 | 目录位置不能独自证明上下位 |
| 概念相关 | `related`；说明明确联系及检索作用 | 共现或共同上位不自动产生相关关系 |
| 来源目录或枚举 | 保留来源的节点、成员、顺序和原关系种类 | 导入为可浏览结构不自动变成语义层级 |
| 领域或专题分组 | 集合成员及纳入依据，可跨分支 | 集合与成员之间不生成 `broader` |
| 数组与节点标签 | 保留划分依据、上层连接和显示位置 | 节点标签不成为可标引概念 |

原因是词表要同时服务检索和浏览。混用关系后，沿上位概念扩展检索可能把“有关联”误当成“属于其范围”。判据沿用[层级关系](概述-层级关系.md#成立条件)、[相关关系](概述-相关关系.md#成立条件)和[分面与分组](概述-分面与分组.md#组织职责)。

现有领域 Concept、独立 Collection 及已采纳挂接继续保留。`hierarchy.roots` 能指定要连接的节点，但配置哈希只能定位这项选择，不能替代关系成立的说明。建议对新增、修订的挂接记录语义理由；已有挂接若复核发现只适合导航，再提出具体改动，不直接批量删边或改成集合成员。

来源复制与本地分析仍按[既有分层决定](决定-原样复制与本地分析分层.md)执行。源结构是否值得重新分析与本次如何忠实保存它，是两项不同判断。

## 标准采用

建议以 ISO 25964 检查业务对象与处理条件，以 RDF／SKOS／SKOS-XL 表达数据，以 Turtle 交付。模型选择先于字段编码；标准材料的实际核对范围见[依据与限制](设计-词表资源与字段.md#依据与限制)。

| 标准中的内容 | 建议采用方式 | 表示与未覆盖部分 |
|---|---|---|
| 词表、概念、名称 | 作为核心对象 | `ConceptScheme`、`Concept`、`Label`，使用独立稳定身份 |
| 概念关系、名称等价 | 采用成立条件，不机械套用所有关系 | 核心 SKOS 关系；来源细分类型另存，不能以普通 `broader` 声称完整保留 |
| 定义及其他注释 | 按附着对象、语言和来源维护 | 概念与名称均可有说明；需要独立依据时使用说明资源 |
| 数组、概念组与顺序 | 保留来源已有结构，按实际浏览需求增加本地结构 | 通用 Collection 只表达共同部分；具体类型、连接和顺序必须可追溯 |
| 复合等价与组合映射 | 纳入逻辑模型，不拆成独立别名或等价边 | 保留组合端点和运算含义；选定 RDF 编码前不输出虚假的简单关系 |
| 分面分析、先组与后组 | 作为组织及使用方法，逐用途选用 | 不给所有概念强加分面字段，也不把多词名称自动判为组合 |
| 版本与维护历史 | 复用项目现有来源、编辑和发布记录 | 按标准核对所需信息，不强求所有记录放进一份 RDF 图 |
| 标引、检索和展示 | 形成应用要求与验收场景 | 由应用契约负责，不把查询行为塞进概念字段 |

公开模型和对应表能支持上述对象区分，但不保证转换无损。SKOS-Thes 是可核对的现成扩展：需要具体功能时逐项确认其属性语义、发布状态、校验和消费方式，不整包启用。[NISO 模型入口](https://www.niso.org/schemas/iso25964/schema-intro)、[SKOS-Thes](https://www.dublincore.org/specifications/skos-thes/ns/)

分面、划分特征和手工概念组已有未生效提案。本方案将其需求列入整体设计，但不以“标准包含它”替代具体采纳。对暂未启用的能力，记录缺少的使用场景与表示方案；来源已经提供的信息仍须保留，不因本地暂不使用而删除。

## 名称与版本

建议将概念身份、名称身份和文字版本分别维护。概念表示含义，名称记录表示一个可持续维护的表达，版本保存它在某个时间的具体文字及角色。

| 问题 | 建议选择 | 理由 |
|---|---|---|
| 初次名称标识 | 保留来源 XL 或术语标识；无来源名称身份时，由编辑或导入登记一次性分配本地 UUIDv4 URI | 标识不绑定当前文字或层级，重建只复用，不重新随机分配 |
| 来源仅有文字标签 | 保存来源概念、完整文字值、语言与本地名称身份的初次对应 | 可重放首次导入；之后的文字变化需要连续性证据，不能仅凭相似度匹配 |
| 拼写或格式修订 | 经核对是同一记录时保留名称身份 | 避免一次纠错引发所有引用迁移 |
| 新增同义表达或另一语言形式 | 建立另一名称记录 | 同时使用的表达应能分别保存依据和历史 |
| 首选名与别名互换 | 修改概念到名称的关系，保留名称身份 | 名称角色不等于名称身份 |
| 共用名称的一处用法变化 | 核对全部引用；必要时分立记录 | 防止修改一处而误伤其他概念 |
| 历史文字 | 保存在对应版本和变更记录中 | 同一版本的 `literalForm` 仍只有一个值，不能把历史值混入当前图 |

本地名称 URI 建议使用 `urn:uuid:` 加 UUIDv4。它是拟议的新增名称身份政策，不改写现有概念、集合、内容单元或来源 URI。一次性登记和唯一性检查由实现承担；生成阶段不得用新文字重新计算名称身份。

旧写法是否继续作为别名，要按检索需要和采纳决定判断。被保留为历史信息，不等于继续作为当前名称提供。用户引用名称的某次用法时，保存名称标识及版本；普通主题引用概念标识。

这项选择修正“文字变化一律新建名称”的做法，依据为已读 Part 1 §15.2.4 与 SKOS-XL 单值约束。它不要求所有来源都能自动判断记录连续性；无法确认时保留新旧记录待核。[SKOS-XL](https://www.w3.org/TR/skos-reference/#xl)

## 映射与应用

建议把映射作为带版本和依据的管理记录，SKOS 映射三元组作为其中可表达的语义输出。逐项字段见[映射记录](设计-词表资源与字段.md#映射记录)。

| 选择 | 建议结果 |
|---|---|
| 组织方式 | 选择性直接映射：为实际需要的两端建立对应，不自动通过第三份词表推导新映射 |
| 映射范围 | 只处理实际需要对照或使用的概念；不以全量映射作为综合词表可用的前提 |
| 两端上下文 | 固定源与目标词表及版本，保存采用的概念范围与依据 |
| 用途 | 浏览参照、查询转换和标引转换分别声明；默认不自动改写笔记 |
| 方向 | 明确应用允许的方向；关系属性的对称性不代替反向使用决定 |
| 组合 | 保留交集、并集及嵌套，不能拆成多个独立 `exactMatch`；词表内组合入口与跨词表映射分别记录 |
| 精度 | 保留精确、接近及宽窄判断；未确定是审阅状态，不写成 `closeMatch` |
| 组合使用 | 不自动串接近似映射，也不把多个已批准的局部用法当作一个整体批准 |
| 新版本 | 按实际依赖复核，不因标识仍在就认定映射仍有效 |

选择性直接映射可以先解决具体交叉内容，不要求额外建设覆盖全部来源的映射中心。已采纳的本地概念分别连接所对应的来源概念；这些连接不自动成为跨来源的中转许可。未来若确需中心结构，再核对覆盖范围和连续转换的质量后提出变更。[ISO 25964 范围](https://www.niso.org/schemas/iso25964)

完整映射记录至少能回答“谁与谁对应、依据哪个版本、为何成立、用于什么、允许哪个方向、何时复核”。消费者若只能读取简单 RDF 关系而读不到这些限制，只用于关系浏览，不自动据此重标引或批量扩展查询。

## 来源更新

建议在既有三方值比较之外，增加按本次变化生成的受影响清单。值的差异只能发现变化，不能独自判断含义是否改变。

| 来源变化 | 直接处理 | 需要核对的依赖 |
|---|---|---|
| 拼写、格式或首选角色变化 | 比较名称及角色，确认记录连续性 | 名称依据、检索入口、引用显示；不自动新建概念 |
| 定义、范围或新增别名变化 | 保留新旧内容，判断是否改变概念范围 | 译名、映射、合并判断及使用该范围的分组理由 |
| 上下位或成员变化 | 保留来源差异与原关系种类 | 来源选择闭包、领域挂接、导航和依赖关系上下文的映射 |
| 概念退出、合并或拆分 | 保存旧身份及来源说明 | 本地引用、替代关系和全部关联映射，不自动选择后继概念 |
| 来源版本更新但相关内容未变 | 记录版本比较结果，可按既定规则复用本地判断 | 保留原证据版本，另记本次适用性核对，不伪装成重新审阅 |

受影响清单保存变化来源、直接依赖记录、影响原因及处理结果。沿记录中的明确依赖查找，不扩大成所有语义邻居的全量重审。消费者是否启用另按既有决定；本方案不建立正式义务、长期查询日志或持续监控任务。

### 译文复核

[词表维护](设计-词表维护.md#发布与恢复)规定英文已变时不沿用旧译文；[中文标签](设计-中文标签.md#增量同步)规定标识未变时保留旧译文、不自动重译。两处表述需要统一，建议采用以下区分。

代码核对显示，[展示复用](../../../packages/kb-vocab/src/kb_vocab/display.py)确实在英文首选名集合变化时，以 `english_changed` 排除该译文；[应用同步](../../../packages/kb-vocab/src/kb_vocab/maintenance_apps.py)会调用这一路径处理已有双语展示。它使用批次译文及其元数据，不是旧 `label-adoptions` 接口。因此，这里存在实际复用路径与较新中文标签设计之间的差异，需要同时明确文档与实现的目标规则。

| 情形 | 建议规则 |
|---|---|
| 对应概念未变，仅关系或分组调整 | 保留译文与原批次依据 |
| 英文文字修订，尚无含义变化证据 | 保留译文，不自动重译；记录基准变化及原依据 |
| 定义或范围变化，译文适用性未确定 | 保留原译文和历史，展示时明确待复核；不能称为已确认适用于新版 |
| 已有审查结论确认译文不再适用 | 从当前有效名称中退出，按原文回退或使用另行采纳的译文；不删除历史 |
| 原概念身份退出或无法确定对应 | 不把旧译文按同名迁到新概念 |

复核针对变化造成的适用性问题，不要求全量重译，也不把原批次 AI 译名提升为权威术语。该规则涉及两份现行设计，须在采纳时同步修订，不能只改其中一篇。

## 规则归属

建议把项目选择限制在标准无法替项目决定的部分：收录范围、具体语义采纳、身份政策、转换取舍、消费者行为及发布要求。已有标准结构和成熟实现优先复用。

| 内容 | 唯一职责位置 | 与其他文档的关系 |
|---|---|---|
| 标准事实与阅读范围 | 阅读笔记 | 保留原文位置及限制，不批准项目值 |
| 概念含义与判断方法 | 概述和概念文 | 供设计引用，不重复抄入字段表 |
| 整体选择 | 本提案经采纳后的整体设计与决定 | 规定整合、组织、身份及应用边界 |
| 资源、字段及表示 | 词表资源与字段 | 落实整体选择，不独立决定整合策略 |
| 当前运行合同与迁移差异 | 词表数据规范 | 记录实际支持与版本边界，迁移后更新，不以目标设计冒充现状 |
| 同步、冲突及恢复 | 词表维护 | 处理执行与失败，不代替语义决定 |
| 翻译及批次依据 | 中文标签 | 管理译文产生、复用和展示，与名称身份通过明确对应连接 |
| 术语准入 | 术语设计及具体采纳 | 保持 `data/vocab/terms.yaml` 的编辑权，避免第二份术语库 |

采用某项扩展前，记录需求、现有模型不足、候选标准表示、信息损失和消费者要求。没有这些条件，不增加通用状态字段、任意关系类型或另一套审批机制。存储实现和库选型留给实施方案，但不得改变已经选定的语义。

## 兼容与采纳

以下列出建议与既有规则的关系，便于逐项审阅。

| 事项 | 与现有规则的关系 | 采纳后的动作 |
|---|---|---|
| 一份自有词表、来源独立保留 | 延续现有数据规范 | 保持现有来源范围与身份，不执行全量重建 |
| 区分语义层级和导航分组 | 延续既有区分，补充挂接理由 | 只为具体新增或修订补依据，不直接推翻已有领域挂接 |
| 新名称 UUIDv4 及身份连续性 | 新增目标身份政策 | 明确导入登记、旧标签对应、版本读取与校验后再迁移 |
| 带用途、版本和组合的映射记录 | 完善目标模型 | 对应既有采纳记录，明确 RDF 投影和消费条件 |
| 译文保留与新版适用性分开 | 统一两份文档的冲突表述 | 同步修订维护与中文标签设计，明确展示和复核行为 |
| 数组、分面和手工概念组 | 不自动改变已有决定和未生效提案 | 按实际来源或应用需求提出具体采用范围 |
| 原 YAML、RDF 管线与外部知识库 | 保持各自编辑和消费边界 | 实施前逐一列出迁移对象、引用影响及回退，不自动切换 |

建议将七项整体选择作为一组审阅；具体来源收录变化、概念合并、领域关系取值及草案生效仍按各自权限采纳。文件职责调整也需随采纳明确，不能让整体设计与字段文长期保留两份可独立修改的同义规则。

## 验收与迁移

实施按四个阶段准备，每个阶段都提供可核对结果，而不以文档存在或字段数量认定完成。

| 阶段 | 必须证明的内容 | 独有证据 |
|---|---|---|
| 模型核对 | 七项选择一致，标准事实、项目选择和未决定项可区分 | 选择与字段、来源、消费者的逐项对应 |
| 真实样本 | 已有来源结构能表示；不支持的信息有明确去向 | 普通概念、同名异义、名称修订、数组、组合及映射样本；没有真实样本的能力不称已验证 |
| 迁移与回退 | 旧身份、名称依据、历史和引用不丢失 | 前后差异、标签身份对应、未投影信息清单及回退结果 |
| 应用验收 | 浏览、检索或标引按声明用途工作 | 真实笔记和查询的失败样本；单向映射不得被反向误用，退出名称不得继续当有效值 |

优先检查会改变身份、语义或引用的失败。解析、schema 和已有端到端检查覆盖的机械事实不重复设计测试；无需为纯文档形式新增测试套件。

## 材料限制

本提案依据已登记的 ISO 25964、ISO 704、Z39.19 方法及公开 RDF／SKOS 标准，不作完整标准符合性声明。ISO 25964 的第三方可读文本与官方模型用于交叉核对；Part 1 尚缺可逐页核验的完整原 PDF，Part 2 可访问内容缺印刷页 79—99。具体核对位置见[设计依据](设计-词表资源与字段.md#依据与限制)。

这些限制不妨碍确定上述项目职责，但缺页涉及的术语互操作细节不能据目录补写。未验证的 RDF 扩展、机器字段和迁移能力应作为实施前要闭合的事项，不冒称已有现成的完整方案。
