# 多语言词表

本专题完整规定语言策略、跨语言概念对应、翻译、译文复用及显示选择。名称的类型、字段和角色约束见[数据规范](设计-词表数据规范.md#语言与名称)，身份分配与编辑见[维护设计](设计-词表维护.md#名称编辑)。

## 设计范围

同一概念可以有不同语言的名称，概念关系由含义决定。切换显示语言改变名称选择，不复制概念身份或另建一套上下位关系；含义不能对应时，须先核对概念区别。[SKOS Primer §2.2.1](https://www.w3.org/TR/skos-primer/#secpref)

语言是名称或说明的信息，RDF 不要求为每种语言建立一个 Concept 或专用语言资源。翻译所选的源语言也不天然取得概念裁决权。来源原文、项目采用及模型判断分别保留依据。

## 语言策略

| 事项 | 设计要求 |
|---|---|
| 来源保留 | 保留来源全部语言、原附着对象及版本 |
| 语言启用 | 分别明确收录、输出、翻译和消费范围，按相应权限采用；模型可表达不等于获准启用 |
| 名称覆盖 | 允许缺译，不要求所有概念和字段同时具备全部语言；记录缺项，不造词或删概念 |
| 结构对应 | 共享含义已对应的概念结构；有实质差异时保留独立概念及映射，不强求语言间数量和关系完全对称 |
| 翻译范围 | 明确源语种、目标语种、字段和使用目的，不能以缺译为由自动扩展任务 |

允许缺译和不强求对称是项目选择，服务于不同来源和不同完成程度的整合。IFLA §3.2、§3.3.6 提供结构与等价情况的比较，不替项目决定采用语言或要求所有译文齐备。[IFLA 指南](https://www.ifla.org/files/assets/hq/publications/professional-report/115.pdf)

## 语言标记

语言标签依 BCP 47，即 RFC 5646 与 RFC 4647；前者规定标签，后者规定匹配。语言、文字系统和地区是不同信息，不能互相替代。

| 标签 | 表达的信息 | 使用边界 |
|---|---|---|
| `zh` | 中文，未明确文字系统或地区 | 不自动等同 `zh-Hans` 或 `zh-Hant` |
| `zh-Hans`、`zh-Hant` | 中文及简体、繁体文字系统 | 分别保存，不靠修改语言标签完成简繁转换 |
| `zh-CN` | 中国地区使用的中文 | 地区标签本身没有明确写出文字系统 |
| `en-US`、`en-GB` | 不同地区的英语 | 完整标签不同，可分别有首选名 |

比较语言标签时忽略大小写；同标签下的首选名唯一性仍按完整标签检查。名称文字不因标签比较规则而忽略大小写，也不因拼写相近共用身份。[RFC 5646 §2.1、§2.2](https://www.rfc-editor.org/rfc/rfc5646.html#section-2)

校验分别回答三个问题：标签是否符合语法、其登记内容是否有效、是否在项目允许范围内。RDF 要求语言标签符合 BCP 47 语法，不能把 RDF 可解析或前缀匹配当成 IANA 登记有效性证明。登记校验记录所用注册表日期和哈希；已有库能完成的解析与匹配不自行重写。[RDF 1.1 §3.3](https://www.w3.org/TR/rdf11-concepts/#section-Graph-Literal)、[RFC 5646 §2.2.9](https://www.rfc-editor.org/rfc/rfc5646.html#section-2.2.9)、[IANA 注册表](https://www.iana.org/assignments/language-subtag-registry/language-subtag-registry)

新生成标签按明确的目标语言及适用规范形式登记；来源标签保留原始依据。大小写之外的标签替换、废弃子标签的 Preferred-Value 替换及文字规范化须有转换记录，不能借规范化自动改变收录范围或名称身份。未标语种的来源文字保留并提示，不能按文字外观补猜语言。[RFC 5646 §4.5](https://www.rfc-editor.org/rfc/rfc5646.html#section-4.5)

## 概念对应

把两个名称放在同一概念下，须核对它们在所采用范围内的含义及使用依据。语言不同本身既不要求新建概念，也不能证明可以共用概念。

| 情形 | 本项目的处理 |
|---|---|
| 表达同一概念 | 在同一概念下分别登记名称与语言，各自保留依据 |
| 近似、范围更宽或更窄 | 保留差异与适用条件；未确认可用于同一概念前，不直接挂作译名。已有独立概念需要对应时走映射判断 |
| 需要多个概念共同表达 | 保留组合及使用条件，不拆成多个独立别名或 `exactMatch`；见[组合材料](设计-词表数据规范.md#组合材料) |
| 没有合适名称或对应未确定 | 保留已有概念及缺项原因；不为凑齐语言自动造词、删概念或填 `closeMatch` |

这些处置采用现有概念、名称准入与映射规则。IFLA §3.3.6、§4 提供语言间等价及从已有词表合并、映射的方法比较；其中按特定结构放宽等价、借词或造词的方案不自动成为项目许可。[IFLA 指南](https://www.ifla.org/files/assets/hq/publications/professional-report/115.pdf)

## 名称与说明

名称是否可以附在同一概念下，由概念对应及采用依据决定；首选名、别名和隐藏名按各语言的实际用法判断，不能把一种语言的全部别名机械翻译为另一种语言的别名。

| 内容 | 语言处理 |
|---|---|
| 概念名称 | 区分实际语言与具体表达，保留来源未标语种的缺项；名称身份与角色按统一规范管理 |
| 词表与集合名称 | 保留来源语言、说明及依据；普通标签或独立 XL 名称按[名称规则](设计-词表数据规范.md#语言与名称)使用 |
| 定义、范围与其他说明 | 保留原附着对象、文字语言和依据；译文关联原说明及版本，不扩写概念范围 |
| 来源类别、编号与日期 | 作为非语言数据处理，不强加语言标签或翻译 |

## 翻译依据

来源自带名称、已核外部用法、人工判断和模型初译分别留痕。语言标签合法不证明译文正确，翻译结果不自动取得正式术语资格。模型译名与批次授权限于具体批准的语言、对象和用途。

翻译以固定版本的源描述为依据，使用概念含义、范围、现有名称和相关来源作为上下文。只有字符串不足以判断概念对应时保留问题。模型提供文字或判断，名称身份由统一登记维护，概念及名称的语义采纳仍按相应权限作出。

任务、译文、批次与复核记录的字段和关联统一见[译文与复核](设计-词表数据规范.md#译文与复核)。共用依据可按批引用，单条译文的修订和适用性仍分别可查。

## 翻译流程

| 环节 | 条件与结果 |
|---|---|
| 任务确定 | 固定对象、字段、源描述和目标语言；不因翻译新增概念或改变对象类型 |
| 译文形成 | 给出有依据的译文或保留原文的结论；缺译与保留原文分别记录，不输出空译文，也不把原文改标为目标语言 |
| 结果登记 | 关联任务、译文和所需名称身份；与导入、人工编辑共用[名称登记](设计-词表维护.md#名称编辑) |
| 文字修订 | 明确要修改的名称或说明，按维护规则区分同一记录修订与新增表达 |
| 适用性复核 | 核对既有译文与新的源描述；形成适用性结论，保留原翻译依据 |
| 展示交付 | 使用相容的词表、名称、译文和复核记录，按本篇显示规则提供名称、依据性质及必要提示 |

译文与来源名称冲突时报告具体对象、表达和依据，不按读取顺序或模型结果覆盖来源。需要修订的对象由明确任务指定；源版本更新不等于全量重译。重试与重复合并沿用既有身份分配，实际模型、执行者和时间据实记录。

## 增量同步

保留译文记录与确认它适用于新版分别处理。已有译文不自动重译；需要修订时单独指定。下表的退出与失效条件优先于一般复用条件。

| 源描述与已有译文的差异 | 同步行为 |
|---|---|
| 原对象退出或 URI 改变 | 从新产物中退出旧对象的译文，保留历史；不按同名迁给新对象 |
| 已有审查结论确认译文不再适用 | 从当前有效名称中退出，回退原文或使用另行采纳的译文；不删除历史 |
| 对象仍在，但定义或范围变化导致适用性未确定 | 保留译文和原依据，展示明确待复核，不宣称已确认适用于新版 |
| 对象仍在，源语言文字修订且尚无含义变化证据 | 保留译文，不自动重译；记录基准变化及原依据 |
| 仅关系或分组变化，对应概念未变 | 使用新结构并复用译文，不因位置变化重译 |
| 对象仍在且译文上下文未变 | 按 URI 复用译文和批次元数据，不再次调用模型 |
| 源描述与历史结果均缺目标语言译文 | 提取为增量翻译任务；已明确保留原文的处理不自动重复尝试 |

来源自带目标语言名称不由模型译文自动覆盖。它与历史译文不同或存在多种适用结论时，报告具体冲突，不以读取顺序取舍。

复用保留原批次及原证据版本，本次核对结果另行关联。待复核提示只说明适用性未确定，不把原来的模型判断提升为已核外部术语。范围变化对相关译文的影响按[来源更新](设计-词表维护.md#来源更新)定位，不要求无关条目全量重译。

退出仅影响新生成的目标语言及多语言产物，不删除源描述、来源材料或历史批次。新产物须准确反映所选版本、有效译文和退出结果，不能因只追加旧数据而残留失效内容。结果可通过重建或满足相同约束的增量更新形成；交付前按[统一校验](设计-词表数据规范.md#校验范围)和[版本合同](../../governance/maintenance/设计-词表版本.md#发布与回退)核对。

## 匹配与显示

语言筛选和显示名称选择采用不同机制。消费方须明确语言优先列表、可用名称范围及未匹配时的默认行为。

| 用途 | 采用机制 | 约定 |
|---|---|---|
| 按语言筛选名称 | RFC 4647 Basic Filtering | 使用明确语言范围；`zh` 可匹配 `zh-Hans` 等扩展标签，结果可以有多个 |
| 选择单个显示名称 | RFC 4647 Lookup | 在适用的首选名中依语言优先列表查找；按标准缩短请求标签，不猜测更具体的文字系统或地区 |
| 未匹配到名称 | 消费方声明的默认策略 | 完成整个优先列表后再执行；声明默认语言、标识回退、缺名提示或其他明确结果 |

本项目的单项显示请求使用具体语言标签的有序列表，不用通配范围任意挑选名称。同一完整标签下多个不同的首选文字值是冲突，不能靠文件排序解决。返回文字保留实际语言标签；默认处理不改标签，也不把隐藏名当作默认显示名。[RFC 4647 §3.3.1、§3.4、§3.4.1](https://www.rfc-editor.org/rfc/rfc4647.html#section-3)

下表中的 `en` 是请求列表明确包含的偏好，不代表所有消费方都固定回退英语。

| 请求顺序 | 可用首选名的语言 | 结果 |
|---|---|---|
| `zh-Hant-HK`、`en` | `zh-Hant`、`zh`、`en` | `zh-Hant` |
| `zh-Hant-HK`、`en` | `zh`、`en` | `zh`，保留未明确文字系统的事实 |
| `zh`、`en` | `zh-Hans`、`en` | `en`；需要简体名称时应明确请求 `zh-Hans` |

名称搜索可以使用首选名、别名和隐藏名，返回概念身份并说明命中入口。语言匹配不证明名称同义，不自动执行简繁转换、概念合并或跨词表扩展；映射消费仍检查用途和方向。继续显示待复核译文时，适用性提示须随名称提供。

同文的不同名称记录可以显示一次文字，但仍保留到各记录和依据的关联。展示须能辨明实际语言、依据性质和待复核状态；显示去重不合并身份，也不成为批量修改依据。文字投影及角色冲突按[名称约束](设计-词表数据规范.md#语言与名称)统一检查。

## 术语衔接

词表与术语库都区分概念及名称，但各自承担不同的采纳和编辑职责。对接须分别核对概念对应、完整语言标签、名称依据及状态，不能按同形文字合并身份或转移编辑权。[术语设计](../terminology/设计-术语.md)

通用 `zh` 不能无依据地分配到 `zh-Hans` 或 `zh-Hant`。接收方语言范围更窄时，应记录不能确定的信息及处理条件，不通过改标签消除差异。各自既有标识保留，RDF 表示不建立第二份正式术语编辑源。

## 标准依据

表示及名称约束采用 [SKOS／SKOS-XL](https://www.w3.org/TR/skos-reference/)；语言标签采用 [RFC 5646](https://www.rfc-editor.org/rfc/rfc5646.html)和 [IANA 注册表](https://www.iana.org/assignments/language-subtag-registry/language-subtag-registry)，匹配采用 [RFC 4647](https://www.rfc-editor.org/rfc/rfc4647.html)。跨语言方法比较采用 IFLA §3.2、§3.3.6、§4。

语言启用、允许缺译、消费方的默认处理、身份登记及翻译职责属于项目选择。ISO 25964-1 第 9 章尚未完成权威全文逐条核验，未核条款不作为新增规则的唯一依据；材料阅读边界统一见[标准依据](设计-词表整体设计.md#标准依据)。
