# 概念与实体分工

状态：已由用户在本任务中确认范围并要求执行。级别：L2。日期：2026-09-20。

## 适用范围

梳理概念词表与实体记录的职责、收录判断和关联。文档类型、体裁和载体不在本次范围；不将前序对话中误解的“两份词表”写成整个项目的词表数量限制。

## 采用内容

- 概念词表管理概念的名称、定义、别名、翻译和关系。主题标引与分类浏览可以引用同一概念，不另建重复概念记录。
- 实体记录管理具体人物、组织、项目、产品等对象的身份和属性；举例不批准新增 kind 或具体条目。
- 按所描述对象及用途判断记录职责，不把“实体、术语、专名”作为三个互斥选项。词表概念与名称分别识别。
- 具体对象可以成为主题；需要独立维护该主题概念与对象事实时，分别维护身份并按明确含义关联。相关主题、主题专指对象和实体间事实不能互相替代。
- 不由本次梳理另建术语库，也不删除既有术语、来源、文献或其他受控记录。数据、类别、状态、人员边界与正式消费者仍依具体采纳。

## 依据与选择

[SKOS Primer §2、§3.3、§5.1](https://www.w3.org/TR/skos-primer/)说明概念、名称、标引与非概念资源命名；[SKOS Reference §8、§10](https://www.w3.org/TR/skos-reference/)规定概念关系与映射；[RDF Schema §3.3](https://www.w3.org/TR/rdf-schema/#ch_type)定义实例与类的关系。这些标准不规定项目必须分成几张表。

按管理用途分别维护概念和实体身份是本次项目选择。主题专指实体的具体交换属性未在本次采纳；不自行创造属性，也不借用概念等价或资源同一关系填空。
