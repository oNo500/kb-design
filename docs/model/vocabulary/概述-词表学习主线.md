# 词表学习主线

> **【原文背景｜项目文档整理】** 这一段保留原会话中的项目观察，不是标准定义。

前面的工作完成了目录和命名整理，概念之间的关系、阅读顺序和内容的一致性，还没有系统梳理。 当前索引能找到文件，但不足以帮助你形成对词表的整体认识。

> **【学习框架｜作者归纳】** 以下阅读顺序用于组织学习，不是标准规定的实施步骤。

你需要的应当是一条这样的学习主线：

词表的用途 → 基本构成 → 结构类型 → 组织方法 → 实际使用 → 建设维护 → 互操作与扩展。

先把这条主线讲清楚。

## 词表在知识组织中的作用

> **【通用基础｜Z39.19 范围内】** 关系按具体类型采用，不表示每份受控词表都必须具有层级或相关关系。

在知识体系的组织中，词表负责明确：采用哪些概念、这些概念叫什么、彼此怎样关联，从而支持一致的描述、标引和检索。

“词表”这个词本身很宽泛。你当前项目主要讨论的是受控词表：名称和概念经过选择，并按照明确规则持续管理。[NISO 指南](https://www.niso.org/publications/ansiniso-z3919-2005-r2010)的范围就包含词表的内容、结构、建设、测试和维护。

## 需要掌握的知识范围

> **【学习框架｜跨范围导航】** 本表同时列出共同基础、叙词表规则与扩展知识；“基本构成”这一行仅针对叙词表，多语对应及 SKOS 也不属于单语标准的全部通用要求。

| 学习部分 | 核心问题 | 涉及的概念与信息 |
| --- | --- | --- |
| 基本构成 | 叙词表的核心构成是什么？ | 概念、表达概念的词、关系 |
| 识别与说明 | 怎样识别、解释和维护这些要素？ | 标识符、定义、范围注释、来源、历史 |
| 名称控制 | 同义、歧义、多语名称怎样处理？ | 首选名、替代名、隐藏标签、限定说明 |
| 概念关系 | 概念之间如何连接？ | 上位、下位、相关关系、多上位关系 |
| 结构类型 | 词表可以组织成什么形式？ | 列表、同义词环、分类法、叙词表 |
| 组织方法 | 怎样划分、分组和组合概念？ | 分面、划分特征、数组、节点标签、概念组、先组与后组 |
| 实际使用 | 怎样用词表描述和查找内容？ | 标引、查询匹配、检索扩展、浏览 |
| 建设维护 | 怎样收录、调整并检验词表？ | 收录依据、范围、粒度、变更、历史、效果评价 |
| 互操作 | 多份词表怎样共同使用？ | 概念映射、多语对应、交换与发布 |

这张表里的项目不是同一层次的“词表种类”。这是现有文档特别需要讲清楚的地方。

> **【通用基础｜Z39.19 的结构分类】** 此处比较四种结构，各行描述各自能力，不是共同必备条件。

例如，四种结构可以这样区分：

| 结构 | 主要作用 |
| --- | --- |
| 列表 | 明确允许使用哪些值 |
| 同义词环 | 搜索一种写法时，也能找到其他等价写法对应的内容 |
| 分类法 | 用层级关系组织概念 |
| 叙词表 | 同时控制名称，并表达层级关系和相关关系 |

这是 NISO 指南采用的结构划分。其中，同义词环主要用于检索，并不是必须经过的“升级阶段”。[标准 §5.4](https://groups.niso.org/higherlogic/ws/public/download/12591/z39-19-2005r2010.pdf)

## 叙词表的核心构成

> **【类型规则｜叙词表，依据 ISO 25964-1】** 以下“概念—词—关系”说明不能直接作为所有受控词表的必备结构。

叙词表的核心构成是：概念、表达概念的词，以及它们之间的关系。NISO 对 ISO 25964-1 的官方说明明确使用了 concepts, terms and relationships 这三个要素。[官方说明](https://www.niso.org/schemas/iso25964)

> **【教学例子｜叙词表】** 表格是解释性整理，数据库例子不是标准原例。

| 核心要素 | 是什么 | 例子 |
| --- | --- | --- |
| 概念 | 词表要表达的意义 | 关系数据库这一类别 |
| 词 | 用来表达概念的一个或多个词语 | “关系数据库”“relational database” |
| 关系 | 组织概念及其表达形式的联系 | 同一概念的不同表达；概念之间的上位、下位和相关关系 |

> **【类型规则｜叙词表】**

其中，关系需要进一步区分：

- 表达形式之间：哪些词表达同一概念，哪个是首选表达。
- 概念之间：哪些概念更宽、更窄，或者存在相关联系。

## 识别与说明信息

> **【类型规则｜叙词表的记录说明】** 承接前一节，区分核心要素和描述信息；下表不是所有词表的统一必填字段清单。

标识符、定义、范围注释，则属于识别和说明这些要素的信息：

| 信息 | 作用 |
| --- | --- |
| 标识符 | 明确引用哪个概念或记录，避免依赖可能变化的名称 |
| 定义 | 解释概念是什么 |
| 范围注释 | 说明覆盖范围及使用限制 |
| 来源、历史等管理信息 | 说明依据，并支持后续维护 |

> **【表示模型｜SKOS】** 此处说明机器表示，不能反推为 Z39.19 对所有词表的字段要求。

SKOS 将这些分别表达为概念身份、标签、说明属性和语义关系，并提供词表整体及概念集合的表示。[SKOS Reference](https://www.w3.org/TR/skos-reference/)

> **【学习说明｜以叙词表为例】**

因此，理解顺序应当是：先认识“概念—词—关系”，再认识如何标识、解释和维护它们。

> **【通用基础｜Z39.19 范围内】** 以下回到不同结构之间的区别。

这个构成说明适用于叙词表。简单列表通常不表达关系，同义词环主要组织检索中的等价表达，不能要求所有词表都具有完整的叙词表结构。[NISO 指南 §5.4](https://groups.niso.org/higherlogic/ws/public/download/12591/z39-19-2005r2010.pdf)

## 扩展概念怎样放回整体

> **【适用范围｜组织方法与分组构件】** 这些内容按具体结构和用途选用，不是所有受控词表共同必备的组成。

分面、数组和概念组，回答的是不同的组织问题：

- 分面：从哪些不同方面分析和组织概念。
- 划分特征与数组：某个上位概念之下，按什么依据划分同级概念。
- 节点标签：怎样说明分组依据，而不额外建立一个用于标引的概念。
- 概念组：为了某个用途选出一批概念，保留它们原有的关系。

> **【互操作｜ISO 25964】** 此处转入叙词表建设及跨词表互操作的标准范围。

理解这些以后，再学习词表之间的映射。ISO 25964 分别处理叙词表建设及与其他词表的互操作，说明这本来就是两个相连、但职责不同的领域。[ISO 25964 官方说明](https://www.niso.org/schemas/iso25964)

> **【表示与扩展｜SKOS 及相邻模型】** 本段区分表示模型与进一步的建模能力，不增加 Z39.19 的结构类型。

SKOS 则提供机器可读的表达模型，表示概念、标签、说明、关系、集合和映射。它属于表示与交换这一层。本体与知识图谱涉及进一步的建模能力，应放在相邻主题中比较，不能简单理解为“词表最后都会升级成知识图谱”。[W3C SKOS Primer](https://www.w3.org/TR/skos-primer/)

## 维护应当贯穿其中

> **【通用基础｜Z39.19 范围内】** 维护动作依实际对象与结构判断，不表示每份词表都有全部关系类型。

词表维护不仅是增加词条，还包括改名、调整范围、合并或拆分概念、修正关系，以及处理这些变化对既有内容检索的影响。修改后的词表能否继续找到原有内容，是维护的重要问题。[NISO 指南 §11.3](https://groups.niso.org/higherlogic/ws/public/download/12591/z39-19-2005r2010.pdf)

> **【原文背景｜项目文档整理】** 以下是对文档整理的建议，不是词表标准的规定。

对项目文档而言，也需要维护这条知识主线：总览说明概念关系，各篇解释一个明确问题，项目设计再说明实际采用了什么。现在最需要补的是一篇能独立读懂的词表总览，以及由它组织的学习路径；现有文章应围绕这条主线检查缺口、重复和混淆，而不是继续只调整文件位置。
