# 词表总览

词表在知识组织中解决名称不一致、含义不明确和检索入口分散的问题。维护者选择需要表达的概念，管理其名称，并按用途决定是否建立关系，使不同内容能够通过共同的主题入口被找到。

本文讨论用于知识组织与信息检索的受控词表。“受控”意味着收录和使用的名称有明确约定，并有维护程序。理解它需要依次区分概念、名称、结构、使用和维护；分面、映射及知识图谱分别在不同位置扩展这些能力。下文的数据库例子用于说明关系，不表示本项目新增了相应记录或映射。

## 词表用途

假设一些内容使用完整名称“数据库管理系统”，另一些使用缩写 DBMS。只搜索一种写法，可能漏掉另一种写法下的内容。词表可以把这些入口关联到相应概念，再由检索系统使用这层对应。

反过来，遇到“模型”这样的名称，还需要区分数据模型与其他语境中的模型。形式相同不能直接认定概念相同，形式不同也不能直接认定概念不同。

词表因此参与知识体系的组织，但并不替代内容中的解释、论证和证据。它提供可共同使用的概念与检索入口；具体内容通过标引与这些概念建立联系。

## 基本构成

概念是所表达的意义，名称是表达意义的文字。采用概念记录的数据模型时，还需要区分标识符、说明和关系。以“关系数据库”为例，各部分回答不同问题。

| 部分 | 回答的问题 | 示例 |
|---|---|---|
| 概念 | 所指的是什么？ | 关系数据库这一类别 |
| 名称 | 用什么文字表示？ | 中文名称、英文名称及经过核对的其他写法 |
| 标识符 | 名称变化后怎样继续引用？ | 独立于显示名称的稳定 ID |
| 说明 | 包括什么、不包括什么？ | 定义、范围注释和适用示例 |
| 关系 | 与其他概念怎样联系？ | 与数据库类别的上下位联系，以及与其他主题的相关联系 |

首选名称用于统一表达，替代名称提供其他入口，隐藏标签可帮助处理不宜显示但有助于查找的写法。多语词表可以按语言分别管理名称；增加译名之前仍须确认它们表达相应概念。[SKOS Primer §2](https://www.w3.org/TR/skos-primer/)

记录中保留来源与变更说明，才能分辨“换了名字”和“改变了含义”。例如，关系数据库的首选名称改变，可以保持概念身份；若范围被重新划分，就需要重新判断原有引用和关系。

## 结构类型

词表采用什么结构，取决于要控制名称、组织层级，还是扩展检索。ANSI/NISO Z39.19 区分以下结构；它们不是每个项目必须依次经历的阶段。

| 结构 | 主要组织方式 | 用途示例 |
|---|---|---|
| 列表 | 平铺列出允许值 | 选择内容的语言或格式 |
| 同义词环 | 将检索时视为等价的词关联起来 | 输入缩写时同时搜索对应全称 |
| 分类法 | 用层级组织概念 | 从数据库类别向下浏览不同类型 |
| 叙词表 | 同时管理名称、层级和相关关系 | 按主题查找，并沿已定义关系扩展 |

同义词环主要服务检索，不要求像标引用叙词表那样选定一个首选词。结构丰富也会增加维护工作；若任务只需要选择一个值，增加层级和相关关系未必有用。[NISO 指南 §5.4](https://www.niso.org/publications/ansiniso-z3919-2005-r2010)

这组结构比较不穷尽知识组织中的所有名称。分类表、名称规范表等还有各自的对象与用途；ISO 25964 第 2 部分分别讨论它们与叙词表的互操作。判断一份资源时，需要同时看用途、对象和结构，不能只根据它是否画成树来归类。

## 概念关系

名称之间的等价与概念之间的关系必须分开。经核对的全称和缩写可以作为同一概念的入口；“数据库”与“关系数据库”则是不同范围的概念。

层级关系也需要判断具体含义。某类别的一种、某类别的具体实例、某整体的组成部分，分别对应种属、实例和整体部分的判断。不能只看到目录嵌套或“包含”两个字，就认定存在合法的上下位关系。

相关关系表达有意义的语义联系，不等于两个词曾在同一篇文章里出现。一个概念有多个上位关系时，身份仍可保持一个；在不同导航分支中出现不要求复制概念记录。NISO 指南 §8.3 区分层级关系，§8.4 讨论相关关系。[标准原文](https://groups.niso.org/higherlogic/ws/public/download/12591/z39-19-2005r2010.pdf)

## 组织方法

分面、数组和概念组用于处理不同的分组问题，它们并不与“分类法、叙词表”处于同一分类层次。

| 概念 | 组织依据 | 说明性例子 |
|---|---|---|
| 分面 | 按概念的内在类别组织 | 在数据库相关知识中区分对象与活动 |
| 划分特征 | 说明同级概念按什么属性区分 | 按数据模型区分数据库类型 |
| 数组 | 将按同一划分特征组织的同级概念成组 | 上述划分形成的一组同级类型 |
| 节点标签 | 在显示中说明分组依据 | “按数据模型”这一说明行 |
| 概念组 | 为某种用途选出已有概念 | 把备份、恢复及相关概念组成学习用集合 |

节点标签不是供内容标引的概念。概念组也不因成员放在一起就改变其上下位关系。分面分析可以与层级组织配合；它是一种组织方法，不能概括为任何词表都必须先执行的固定步骤。

还要区分词表概念的分组与资料的筛选：把概念按类别组织，是词表结构问题；按主题、语言或格式筛选资料，则是对被描述对象的属性进行组合查询。NISO 指南 §5.3.4 讨论这两种使用语境；概念集合的机器表示另见 [SKOS Reference §9](https://www.w3.org/TR/skos-reference/#collections)。

## 标引与检索

标引把内容与选定的概念联系起来。例如，一篇关于数据库备份的内容可以关联到备份主题；检索时，输入的文字再通过名称入口找到这个概念及其相关内容。概念记录与被标引的文章分别具有身份。[SKOS Primer §3.3](https://www.w3.org/TR/skos-primer/#secindexing)

组合可以发生在不同阶段。预先建立“数据库备份”这样的复合表达，与分别使用数据库、备份并在检索时组合，涉及先组和后组的选择。选择时要考虑是否保留了原有语义，不能假定几个词同时出现就表达了同一个复合概念。

例如，一篇文章同时讨论数据库查询和文件备份，搜索“数据库”与“备份”可能命中它，但它未必讨论数据库备份。这说明组合方便与表达准确需要分别检查。先组与后组的表示问题见 [SKOS Primer §4.4](https://www.w3.org/TR/skos-primer/#seccoordinating)。

## 建设与维护

建设先明确服务范围、使用者、需要描述的内容和所需粒度，再评估能否复用已有词表。文献用法、用户检索表达和组织要求可以提供收录依据；频率本身不能回答名称是否等价或关系是否成立。

维护持续处理新概念、名称变化、范围调整和关系变化。改名可以保留旧入口；概念拆分后，旧内容可能需要重新判断归属；外部词表改版后，映射需要复核。这些动作都要考虑已有内容能否继续被找到，并留下变化理由与历史。建设、评价和维护见 NISO 指南第 11 章。[标准原文](https://groups.niso.org/higherlogic/ws/public/download/12591/z39-19-2005r2010.pdf)

效果评价同时关注查全率与查准率。假设一组内容中有 10 篇相关资料，检索返回 8 篇，其中 6 篇相关：查全率为 6／10，查准率为 6／8。结果数量增加，不一定表示检索更好；还要判断新增的是相关内容还是无关内容。

实际复核可以从三个问题开始：同一主题能否稳定标引，常用搜索能否找到预期内容，词表变更后旧引用是否仍有正确去向。数据格式通过校验，只能覆盖其中的结构问题。

## 互操作与扩展

词表之间的映射说明两边的概念如何对应。即使名称相同，也可能范围不同；即使确认对应，也仍保留各自词表中的身份。映射本身不等于复制外部结构。ISO 25964 第 2 部分专门讨论跨词表互操作。[官方范围说明](https://www.niso.org/schemas/iso25964)

SKOS 是表达和交换这些信息的数据模型，可以表示概念、标签、说明、关系、集合与映射。它不会替维护者判断概念边界，也不是比叙词表更高的一种词表结构。[SKOS Reference](https://www.w3.org/TR/skos-reference/)

其他相邻领域各自解决不同问题：术语数据库着重管理概念、定义、多语形式及其使用状态；元数据规定怎样描述内容；名称规范表管理特定对象的身份与名称；知识体系文献可能提供领域结构和范围材料。它们可以协作，不能只因都出现了名称或层级就合并职责。

当需要表达更丰富的对象关系、约束或推理规则时，再比较本体和知识图谱等建模方式。词表可以参与这些系统，但采用词表不要求最终建立本体或知识图谱。

## 项目用法

kb-design 研究知识体系的组织规则。主题词表在其中承担概念标引和关联职责，具体对象、术语与来源按各自设计维护。本文解释一般概念；项目实际采用的层级、状态、依据和生成规则，分别见[主题词表设计](设计-主题词表.md)与[层级结构](设计-层级结构.md)。

继续阅读时，从[主题词表索引](索引-主题词表.md)选择对应专题。术语的已登记名称与定义见[术语参考](../../参考-术语表.md)，词表与内容字段的连接见[内容模型](../content/设计-内容模型.md)。
