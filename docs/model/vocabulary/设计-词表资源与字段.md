# 词表资源与字段

本篇用同一份 Turtle 示例解释词表的资源、类型、属性和对象关系。它是[整体设计](设计-词表整体设计.md)与[数据规范](设计-词表数据规范.md)的配套例解；字段、数量和校验以规范为准。

## 标准与格式

数据模型、词表规范和文件格式承担不同职责。

| 名称 | 作用 | 本文使用的前缀 |
|---|---|---|
| ISO 25964 | 提供叙词表业务依据，实际采用限于已核材料 | 不指定统一 RDF 前缀 |
| RDF | 通用数据模型，用“主体—属性—值”描述事物及其关系 | `rdf:` 提供类型声明等基础属性 |
| SKOS | 基于 RDF，规定词表中的概念、名称和关系 | `skos:` |
| SKOS-XL | 扩展 SKOS，把名称也变成独立资源 | `skosxl:` |
| BCP 47 | RFC 5646 规定语言标签，RFC 4647 规定语言匹配 | 语言标签不是 RDF 前缀 |
| Dublin Core Terms | 提供标题、描述、来源等通用元数据属性 | `dcterms:` |
| XML Schema 数据类型 | 指定日期、时间等字面值的类型 | `xsd:` |
| Turtle（`.ttl`） | 将 RDF 数据写成文本文件的格式 | 无专属前缀 |

因此，一份 Turtle 文件可以同时使用以上几套属性。前缀只是完整标识的缩写，不决定后面的名称是类型还是属性。[RDF 数据模型](https://www.w3.org/TR/rdf11-concepts/)、[Turtle 语法](https://www.w3.org/TR/turtle/)、[Dublin Core 属性](https://www.dublincore.org/specifications/dublin-core/dcmi-terms/)

## 记录结构

RDF 的一条陈述叫三元组，由主体、属性和值组成。下面三条陈述分别声明类型、连接名称、保存文字。

| 主体 | 属性 | 值 | 含义 |
|---|---|---|---|
| `ex:C01` | `rdf:type` | `skos:Concept` | C01 是一个概念 |
| `ex:C01` | `skosxl:prefLabel` | `ex:L01` | C01 使用名称 L01 作为首选名称 |
| `ex:L01` | `skosxl:literalForm` | `"人工智能"@zh` | L01 的文字是“人工智能”，语言是中文 |

C01 和 L01 是具体资源；Concept 是类，rdf:type 是属性。类和属性也有自己的标识。“资源”是统称，不代表类、属性和具体记录是同一种角色。[RDF 类型声明](https://www.w3.org/TR/rdf-schema/#ch_type)

属性值可以引用资源，也可以是文字、日期等字面值。语言标签或数据类型属于字面值，例如 `"人工智能"@zh` 与 `"人工智能"@en` 是不同值。RDF 还允许空白节点，用于没有独立 IRI 的结构。[RDF 值与节点](https://www.w3.org/TR/rdf11-concepts/#section-Graph-Literal)

一组三元组构成 RDF 图。示例是一份当前数据；项目中的来源、当前词表和历史版本按各自用途组织，图的校验范围见[数据规范](设计-词表数据规范.md#适用范围)。

## 资源类型

核心记录使用下列类型，通过 `rdf:type` 声明；具体采用的扩展另有类型约束。

| 类型 | 标准名称 | 职责 |
|---|---|---|
| 概念体系 | `skos:ConceptScheme` | 组织一份词表 |
| 概念 | `skos:Concept` | 保存含义、名称引用和概念关系 |
| 名称 | `skosxl:Label` | 保存一个名称的文字与语言 |
| 集合 | `skos:Collection` | 将概念或集合放在一起 |
| 有序集合 | `skos:OrderedCollection` | 为集合成员指定顺序 |

概念、概念体系、集合和名称之间的类型互斥；有序集合是集合的子类。集合成员关系不等于概念上下位关系。采用 SKOS-Thes 分组扩展时，ConceptGroup 与 ThesaurusArray 都属于集合，但彼此互斥，专用关系按[集合字段](设计-词表数据规范.md#集合字段)处理。[SKOS 类型与集合](https://www.w3.org/TR/skos-reference/)

## 字段职责

RDF 资源是一条记录所描述的对象；`rdf:type` 声明对象的类型，其他属性保存值或连接对象。字段表中的数量由[数据规范](设计-词表数据规范.md#标准与选择)区分标准条件和项目要求。

| 对象 | 关键属性及用途 | 完整合同 |
|---|---|---|
| 词表 | 普通或独立名称命名，scopeNote 说明范围，hasTopConcept 指定顶层 | [词表字段](设计-词表数据规范.md#词表字段) |
| 概念 | inScheme 表示归属；XL 属性连接名称；broader、related 连接概念 | [概念字段](设计-词表数据规范.md#概念字段) |
| 名称 | literalForm 保存文字与语言；角色由所描述资源到名称的关系表达 | [名称字段](设计-词表数据规范.md#名称字段) |
| 集合 | member 保存成员；OrderedCollection 用 memberList 保存顺序 | [集合字段](设计-词表数据规范.md#集合字段) |
| 说明 | definition、scopeNote 等说明对象；独立说明用 rdf:value 保存正文 | [说明字段](设计-词表数据规范.md#说明字段) |
| 映射与依据 | 对应关系连接概念，配套记录限定版本、用途、方向和依据 | [映射记录](设计-词表数据规范.md#映射记录)、[来源与依据](设计-词表数据规范.md#来源与依据) |

Concept、Label 和 Collection 都是资源，彼此承担不同职责。集合包含一个概念，不会因此变成该概念；名称文字相同，也不会自动使两个名称或概念成为同一资源。

## 派生表达

示例同时给出 XL 名称关系和普通 SKOS 标签。前者指向独立名称记录，后者由该记录的文字生成，使读取普通 SKOS 的应用也能获得名称。

反向上下位、顶层归属和有序集合的 member 也展示了派生表达。程序按[关系约束](设计-词表数据规范.md#关系约束)生成并校验；Turtle 解析器只负责读取三元组，不自动完成这些推导，语句排列也不表示成员顺序。

## 完整实例

以下是可独立解析的 Turtle 文件，展示核心资源类型及常用字段，不包含每个可选字段。`example.org` 标识和内容仅作示例，不作为实际采纳依据。

```turtle
# 前缀分别来自 RDF、SKOS、SKOS-XL、Dublin Core；ex 是示例自己的标识空间。
@prefix rdf:     <http://www.w3.org/1999/02/22-rdf-syntax-ns#> .
@prefix skos:    <http://www.w3.org/2004/02/skos/core#> .
@prefix skosxl:  <http://www.w3.org/2008/05/skos-xl#> .
@prefix dcterms: <http://purl.org/dc/terms/> .
@prefix ex:      <https://example.org/vocab/> .

# ex:C01 展开为 https://example.org/vocab/C01。
# ; 继续写同一主体的属性，, 列出同一属性的多个值，. 结束一组描述。
# # 开始行注释（字符串和 <URI> 内的 # 除外）；@zh 是中文，@en 是英文。

# 词表
ex:V01
    rdf:type skos:ConceptScheme ;       # 声明类型；rdf:type 也可简写为 a。
    skos:prefLabel "示例词表"@zh ;     # 词表名称的维护入口。
    dcterms:title "示例词表"@zh ;      # 此例采用同值兼容标题，标准不要求与首选名相同。
    skos:scopeNote "演示概念、名称与集合的记录方式。"@zh ; # 收录范围。
    skos:hasTopConcept ex:C01 .         # 指定顶层概念，值是概念标识。

# 概念：人工智能
ex:C01
    rdf:type skos:Concept ;
    skos:inScheme ex:V01 ;              # 所属词表。
    skosxl:prefLabel ex:L01, ex:L02, ex:L05 ; # L01、L05 同文但身份不同；L02 是英文名称。
    skosxl:altLabel ex:L03 ;            # 别名，同样指向名称资源。
    skos:narrower ex:C02 ;              # 由 C02 的 broader 反向生成。
    skos:topConceptOf ex:V01 ;          # 由 V01 的 hasTopConcept 反向生成。
    # 普通标签从下面的 XL 名称生成，供只支持普通 SKOS 的软件读取。
    skos:prefLabel "人工智能"@zh, "artificial intelligence"@en ;
    skos:altLabel "AI"@en .

# 概念：机器学习
ex:C02
    rdf:type skos:Concept ;
    skos:inScheme ex:V01 ;
    skosxl:prefLabel ex:L04 ;
    skos:broader ex:C01 ;               # 上位概念，值是概念标识。
    skos:prefLabel "机器学习"@zh .      # 从 L04 生成的普通标签。

# 名称：literalForm 的值是文字；首选名或别名由概念使用的引用属性决定。
ex:L01
    rdf:type skosxl:Label ;
    skosxl:literalForm "人工智能"@zh ;
    dcterms:source <https://example.org/source/a> . # 保留该名称自己的来源。

ex:L02
    rdf:type skosxl:Label ;
    skosxl:literalForm "artificial intelligence"@en .

ex:L03
    rdf:type skosxl:Label ;
    skosxl:literalForm "AI"@en .

ex:L04
    rdf:type skosxl:Label ;
    skosxl:literalForm "机器学习"@zh .

# 另一个来源的同文名称：不因文字相同合并到 L01。
ex:L05
    rdf:type skosxl:Label ;
    skosxl:literalForm "人工智能"@zh ;
    dcterms:source <https://example.org/source/b> .

# 普通集合：只分组，不声明概念层级。
ex:G01
    rdf:type skos:Collection ;
    skos:inScheme ex:V01 ;             # 本集合适用的词表。
    skos:prefLabel "本月关注主题"@zh ;  # 此例用普通标签保存集合名称。
    skos:scopeNote "本月准备整理笔记的主题。"@zh ; # 分组依据。
    skos:member ex:C01, ex:C02 .        # 成员，无指定顺序。

# 有序集合
ex:G02
    rdf:type skos:OrderedCollection ;
    skos:inScheme ex:V01 ;
    skos:prefLabel "阅读顺序"@zh ;
    skos:scopeNote "先读概述，再读具体方法。"@zh ;
    skos:memberList ( ex:C01 ex:C02 ) ; # RDF 列表，C01 在前、C02 在后。
    skos:member ex:C01, ex:C02 .        # 从列表生成的成员关系。
```

L01 与 L05 投影出的中文首选文字相同，所以 C01 只有一个不同的中文首选文字值；两个名称资源及其来源仍分别存在。若其中一个被改为不同中文而两者仍都作首选，就须处理文字冲突。修改目标按名称身份确定，不能把显示去重变成批量覆盖。

## 管理记录

示例展示核心资源和常用字段，管理信息可以另外存放，并引用这里的对象身份。

| 需要追溯的问题 | 规范位置 |
|---|---|
| 某项名称、定义或关系依据哪个来源版本 | [来源与依据](设计-词表数据规范.md#来源与依据) |
| 一次导入或翻译分配了哪个名称身份 | [名称登记](设计-词表数据规范.md#名称登记) |
| 某条译文依据什么，是否适用于新版 | [译文与复核](设计-词表数据规范.md#译文与复核) |
| 变更、退出、发布及加载分别发生了什么 | [维护记录](设计-词表数据规范.md#维护记录) |

这些记录不一律建为 Concept 或 Label，也不要求与主图存成同一份 Turtle。怎样变更见[维护设计](设计-词表维护.md)，怎样定位历史描述见[版本设计](../../governance/maintenance/设计-词表版本.md)。
