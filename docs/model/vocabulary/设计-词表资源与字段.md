# 词表资源与字段

本设计用于从已有词表组织个人综合词表，规定核心资源、字段和维护记录。它不穷尽 SKOS 的全部属性；来源附加字段继续按[词表数据规范](设计-词表数据规范.md)保留。现有管线尚未按本文完成 SKOS-XL 迁移。

## 标准与格式

数据模型、词表规范和文件格式承担不同职责。

| 名称 | 作用 | 本文使用的前缀 |
|---|---|---|
| RDF | 通用数据模型，用“主体—属性—值”描述事物及其关系 | `rdf:` 提供类型声明等基础属性 |
| SKOS | 基于 RDF，规定词表中的概念、名称和关系 | `skos:` |
| SKOS-XL | 扩展 SKOS，把名称也变成独立资源 | `skosxl:` |
| Dublin Core Terms | 提供标题、描述、来源等通用元数据属性 | `dcterms:` |
| Turtle（`.ttl`） | 将 RDF 数据写成文本文件的格式 | 无专属前缀 |

因此，一份 Turtle 文件可以同时使用以上几套属性。前缀只是完整标识的缩写，不决定后面的名称是类型还是属性。[RDF 数据模型](https://www.w3.org/TR/rdf11-concepts/)、[Turtle 语法](https://www.w3.org/TR/turtle/)、[Dublin Core 属性](https://www.dublincore.org/specifications/dublin-core/dcmi-terms/)

## 记录结构

RDF 的一条陈述叫三元组，包含主体、属性和值。下面三条陈述分别声明类型、连接名称、保存名称文字。

| 主体 | 属性 | 值 | 含义 |
|---|---|---|---|
| `ex:C01` | `rdf:type` | `skos:Concept` | C01 是一个概念 |
| `ex:C01` | `skosxl:prefLabel` | `ex:L01` | C01 的首选名称是 L01 |
| `ex:L01` | `skosxl:literalForm` | `"人工智能"@zh` | L01 的文字是“人工智能”，语言是中文 |

C01 和 L01 是具体资源，`skos:Concept` 是类，`rdf:type` 是属性。类和属性也有自己的标识；“资源”是统称，不能据此把类型、字段和具体记录混成同一层。[类型声明](https://www.w3.org/TR/rdf-schema/#ch_type)

属性值可以引用另一资源，也可以是文字、日期等具体值。RDF 将后一类称为字面值：语言标签或数据类型属于值的一部分，例如 `"人工智能"@zh` 与 `"人工智能"@en` 不是同一个值。RDF 还允许空白节点；本设计的主要资源使用稳定标识，列表和来源说明可以保留空白节点结构。[RDF 值与节点](https://www.w3.org/TR/rdf11-concepts/#section-Graph-Literal)

## 资源类型

本设计使用下列类型，具体记录通过 `rdf:type` 声明。

| 类型 | 标准名称 | 职责 |
|---|---|---|
| 概念体系 | `skos:ConceptScheme` | 组织一份词表 |
| 概念 | `skos:Concept` | 保存含义、名称引用和概念关系 |
| 名称 | `skosxl:Label` | 保存一个名称的文字与语言 |
| 集合 | `skos:Collection` | 将概念或集合放在一起 |
| 有序集合 | `skos:OrderedCollection` | 为集合成员指定顺序 |

概念、概念体系、集合和名称之间的类型互斥；有序集合是集合的子类。集合成员关系不等于概念上下位关系。[SKOS 类型与集合](https://www.w3.org/TR/skos-reference/)

## 字段设计

### 通用约定

字段即记录中使用的属性。以下数量按“一个主体、一个属性”统计：`1` 为恰好一个，`1..n` 为至少一个，`0..n` 为可选多值，`0..1` 为可选单值。表中数量是本设计的项目要求，标准本身的关键约束另见[约束与校验](#约束与校验)。

| 项目 | 值或数量 | 要求 |
|---|---|---|
| 资源标识 | 一个稳定 URI 或 IRI | 是资源身份，不是另加的 `id` 文字属性；IRI 支持国际化字符，URI 也可使用 |
| `rdf:type` | 类的标识，`1..n` | 包含对应资源类型，允许其他不冲突的类型 |
| 语言文字 | 文字与语言标签 | 非空；输出语言及来源未标语种的处理沿用[语言范围](设计-词表数据规范.md#语言范围) |
| 说明值 | 文字，或指向说明资源、文献的引用 | 保留来源的文字或嵌套结构，不一律压成字符串 |
| 多值与缺值 | 分别记录各值 | 不用拼接字符串代替多值；可选缺值省略，不填空字符串 |

以下字段要求约束自有主图；来源图保留原始归属。来源已有缺名等问题按兼容规则保留并报告，不能为满足必填要求删除对象或编造内容。

### 词表字段

综合词表使用一个 `ConceptScheme`。词表标题与各学科名称分别记录。

| 属性 | 含义 | 值类型 | 数量 |
|---|---|---|---|
| `dcterms:title` | 词表标题 | 语言文字 | `1..n`，每种语言一个 |
| `dcterms:description` | 收录目的、范围与排除项 | 语言文字 | `1..n` |
| `skos:hasTopConcept` | 明确指定的顶层概念 | 本词表的概念标识 | `0..n` |

### 概念字段

概念使用 `Concept`，名称文字由它引用的名称资源保存。

| 属性 | 含义 | 值类型 | 数量 |
|---|---|---|---|
| `skos:inScheme` | 所属综合词表 | 概念体系标识 | `1` |
| `skosxl:prefLabel` | 首选名称 | 名称标识 | `1..n`，每个完整语言标签最多一个 |
| `skosxl:altLabel` | 别名 | 名称标识 | `0..n` |
| `skosxl:hiddenLabel` | 通常不展示的检索名称 | 名称标识 | `0..n` |
| `skos:definition` | 概念定义 | 说明值 | `0..n` |
| `skos:scopeNote` | 使用范围与限制 | 说明值 | `0..n` |
| `skos:example` | 使用示例 | 说明值 | `0..n` |
| `skos:notation` | 分类编码 | 字面值，保留来源的数据类型 | `0..n` |
| `skos:broader` | 上位概念 | 概念标识 | `0..n` |
| `skos:related` | 非层级关联 | 概念标识 | `0..n` |

定义、范围说明、分类号和关系均须有依据。没有上位关系不自动成为指定顶层；多个上位关系可以并存，但须分别核对，不能直接拼接不同来源的分类。

### 名称字段

名称使用 `Label`。首选、别名和隐藏名称的角色由概念的引用属性表达，不在名称记录上重复设置角色字段。

| 属性 | 含义 | 值类型 | 数量 |
|---|---|---|---|
| `skosxl:literalForm` | 名称文字及语言 | 一个文字值 | `1` |
| `skosxl:labelRelation` | 名称之间的关系 | 名称标识 | `0..n` |

不同语言分别建名称记录。`labelRelation` 本身不说明是否为缩写、全称等具体关系，不能据此猜测关系种类。[SKOS-XL](https://www.w3.org/TR/skos-reference/#xl)

### 集合字段

普通集合使用 `Collection`，有序集合使用 `OrderedCollection`。两者共享名称和范围字段。

| 属性 | 含义 | 值类型 | 数量 |
|---|---|---|---|
| `skos:prefLabel` | 集合标题 | 语言文字 | `1..n`，每种语言一个 |
| `skos:scopeNote` | 分组依据；有序集合还说明排序依据 | 说明值 | 自建集合 `1..n`；继承集合 `0..n` |
| `skos:member` | 普通集合的成员 | 概念或集合标识 | `0..n` |
| `skos:memberList` | 有序集合的成员顺序 | RDF 列表 | 有序集合 `1` |

允许空集合和空列表。有序列表必须有限、完整且无循环；三元组在文件中的排列不代表成员顺序。集合标题直接保存文字，不要求所有标题都建立 XL 名称资源。

### 映射字段

下列字段均为可选多值（`0..n`），从一个概念指向另一词表的概念。

| 属性 | 对方概念与本地概念的关系 |
|---|---|
| `skos:exactMatch` | 在广泛检索应用中可高度确信互换 |
| `skos:closeMatch` | 在部分检索应用中足够接近、可以互换 |
| `skos:broadMatch` | 对方概念更宽 |
| `skos:narrowMatch` | 对方概念更窄 |
| `skos:relatedMatch` | 存在相关关系 |

名称相同不证明概念相同。`closeMatch` 不是待确认标记；`exactMatch` 具有传递性，但不等于把两个资源视为完全同一的 `owl:sameAs`。未确定的关系留在审阅记录中；复用来源同一概念标识时，不制造自身映射。[映射规范](https://www.w3.org/TR/skos-primer/#secmapping)

### 派生字段

以下字段由已有输入生成，不建立第二套人工编辑值。数量按每条资源记录计算。

| 属性 | 值类型与数量 | 生成依据 |
|---|---|---|
| `skos:narrower` | 概念标识，`0..n` | `broader` 的反向关系 |
| `skos:topConceptOf` | 自有词表标识，`0..1` | `hasTopConcept` 的反向关系 |
| `skos:prefLabel` | 语言文字，`1..n`，适用于概念 | XL 首选名称的 `literalForm`；来源缺项另报 |
| `skos:altLabel` | 语言文字，`0..n`，适用于概念 | XL 别名的 `literalForm` |
| `skos:hiddenLabel` | 语言文字，`0..n`，适用于概念 | XL 隐藏名称的 `literalForm` |
| `skos:member` | 概念或集合标识，`0..n`，适用于有序集合 | 成员列表 |

相关关系的反向表达由同一次决定生成。导入时两个方向都要读取，避免遗漏只写在一端的来源关系。派生由生成器或推理器执行，普通 Turtle 解析本身不会自动补齐这些陈述。

## 完整实例

以下是可独立解析的 Turtle 文件，展示全部资源类型及常用字段，不包含每个可选字段。`example.org` 标识和内容仅作示例，不作为实际采纳依据。

```turtle
# 前缀分别来自 RDF、SKOS、SKOS-XL、Dublin Core；ex 是示例自己的标识空间。
@prefix rdf:     <http://www.w3.org/1999/02/22-rdf-syntax-ns#> .
@prefix skos:    <http://www.w3.org/2004/02/skos/core#> .
@prefix skosxl:  <http://www.w3.org/2008/05/skos-xl#> .
@prefix dcterms: <http://purl.org/dc/terms/> .
@prefix ex:      <https://example.org/vocab/> .

# ex:C01 展开为 https://example.org/vocab/C01。
# ; 继续写同一主体的属性，, 列出同一属性的多个值，. 结束一组描述。
# # 开始行注释（字符串和 <URI> 内的 # 除外）；@zh 是中文，@en 是英文。

# 词表
ex:V01
    rdf:type skos:ConceptScheme ;       # 声明类型；rdf:type 也可简写为 a。
    dcterms:title "示例词表"@zh ;       # 整份词表的标题。
    dcterms:description "演示概念、名称与集合的记录方式。"@zh ; # 范围说明。
    skos:hasTopConcept ex:C01 .         # 指定顶层概念，值是概念标识。

# 概念：人工智能
ex:C01
    rdf:type skos:Concept ;
    skos:inScheme ex:V01 ;              # 所属词表。
    skosxl:prefLabel ex:L01, ex:L02 ;    # 中文、英文首选名称，值是名称标识。
    skosxl:altLabel ex:L03 ;            # 别名，同样指向名称资源。
    skos:narrower ex:C02 ;              # 由 C02 的 broader 反向生成。
    skos:topConceptOf ex:V01 ;          # 由 V01 的 hasTopConcept 反向生成。
    # 普通标签从下面的 XL 名称生成，供只支持普通 SKOS 的软件读取。
    skos:prefLabel "人工智能"@zh, "artificial intelligence"@en ;
    skos:altLabel "AI"@en .

# 概念：机器学习
ex:C02
    rdf:type skos:Concept ;
    skos:inScheme ex:V01 ;
    skosxl:prefLabel ex:L04 ;
    skos:broader ex:C01 ;               # 上位概念，值是概念标识。
    skos:prefLabel "机器学习"@zh .      # 从 L04 生成的普通标签。

# 名称：literalForm 的值是文字；首选名或别名由概念使用的引用属性决定。
ex:L01
    rdf:type skosxl:Label ;
    skosxl:literalForm "人工智能"@zh .

ex:L02
    rdf:type skosxl:Label ;
    skosxl:literalForm "artificial intelligence"@en .

ex:L03
    rdf:type skosxl:Label ;
    skosxl:literalForm "AI"@en .

ex:L04
    rdf:type skosxl:Label ;
    skosxl:literalForm "机器学习"@zh .

# 普通集合：只分组，不声明概念层级。
ex:G01
    rdf:type skos:Collection ;
    skos:prefLabel "本月关注主题"@zh ;  # 集合标题直接保存文字。
    skos:scopeNote "本月准备整理笔记的主题。"@zh ; # 分组依据。
    skos:member ex:C01, ex:C02 .        # 成员，无指定顺序。

# 有序集合
ex:G02
    rdf:type skos:OrderedCollection ;
    skos:prefLabel "阅读顺序"@zh ;
    skos:scopeNote "先读概述，再读具体方法。"@zh ;
    skos:memberList ( ex:C01 ex:C02 ) ; # RDF 列表，C01 在前、C02 在后。
    skos:member ex:C01, ex:C02 .        # 从列表生成的成员关系。
```

## 维护记录

词表字段表达内容，维护记录解释内容来自哪里、为何采用、怎样变化。以下为管理字段要求，不是新增 SKOS 属性，也不要求全部写进同一 `.ttl` 文件。标识引用已有记录，不另建重复的来源或审批体系。

### 来源与依据

每条记录有一个稳定标识。下表中未标可选的项目为必需信息；既有来源缺项如实记录，不补造事实。

| 记录 | 字段 | 值与数量 |
|---|---|---|
| 来源版本 | 来源标识、获取地址、原始文件位置 | 各一个引用或地址；离线材料可用明确交付位置代替获取地址 |
| 来源版本 | 获取时间、内容哈希 | 一个实际获取时间；一个算法与摘要组合 |
| 来源版本 | 上游版本、发布日期 | 各可选一个，缺少版本时以获取时间和哈希区分快照 |
| 来源版本 | 许可 | 已有许可记录引用；未核实则明确记录，不推定可再发布 |
| 依据 | 主体、属性、完整值 | 各一个；值保留资源标识，或文字及其语言、数据类型 |
| 依据 | 来源版本、原文位置 | 外部依据至少一个来源版本及对应定位；可定位到记录、字段或页码 |
| 依据 | 处理规则、依据说明 | 一个明确的继承、转换或判断说明；自动规则绑定版本 |

外部依据、模型判断和项目决定分别标明来源性质。模型判断不伪装成外部版本或原文位置，按[语言依据结构](../terminology/决定-语言依据结构.md)保存相应记录。原样继承可以由来源、具体值和已授权规则自动留痕，不要求每项重新人工采纳。

### 采纳与变更

采纳、变更和发布记录也分别使用稳定标识，采用现有治理状态，不另造一套状态值。

| 记录 | 字段 | 值与数量 |
|---|---|---|
| 采纳 | 依据、适用范围 | 一个或多个依据引用；一个明确的适用范围 |
| 采纳 | 决定结果、决定人、时间 | 各一个；决定人或授权记录明确到可核对的主体 |
| 变更 | 受影响陈述、变更前值、变更后值 | 明确主体和属性；前后值各为完整值集合，新增或移除时一侧可为空 |
| 变更 | 原因、时间、授权或采纳记录 | 原因与时间各一个，至少一个适用授权或采纳引用 |
| 发布版本 | 来源版本、本地数据版本、生成工具版本 | 一个或多个来源版本，本地数据和工具各有确定版本 |
| 发布版本 | 发布时间、输出文件与哈希、校验结果 | 一个时间；完整输出清单及各文件哈希；对应校验记录 |

例如，支持“C02 的上位概念是 C01”的依据应定位到 `C02 / skos:broader / C01`，不能只写“C02 来自某份资料”。来源支持名称的出现，也不自动支持把它选为首选名。采纳可引用已有批次授权，处理方式见[中文标签](设计-中文标签.md)。

## 更新与兼容

标识、编辑入口和消费者引用遵循下列要求。

| 情形 | 处理要求 |
|---|---|
| 概念改名或调整关系 | 保留概念标识；相同名称不作为合并依据 |
| 名称身份 | 来源已有 XL 身份优先保留；新分配的标识持久保存，重建时复用 |
| 已发布名称文字改变 | 建立新名称资源并保留旧记录；附加信息变化不更换身份 |
| 名称退出使用 | 退出对应引用关系，不自动改成别名或隐藏名称 |
| 来源更新或退出 | 比较旧来源、新来源和本地值，冲突按规则处理，不静默覆盖本地选择 |
| 来源普通标签转为 XL | 保留概念、标签角色、完整文字值、来源和名称标识的对应关系，用它关联译文与依据 |
| 标题迁移 | 本设计用 `dcterms:title`；从现有 `skos:prefLabel` 迁移时保留原值和依据，兼容输出从同一输入生成 |
| 知识库引用 | 主题引用概念，讨论名称用法时可引用名称；概念拆分、合并后的旧引用需复核 |
| 编辑职责 | 来源快照保留原样，派生文件不手改；正式术语仍以 `data/vocab/terms.yaml` 为唯一编辑源 |

来源创建者、许可与版本保留原归属，不能机械汇总为综合词表的元数据。操作步骤见[词表维护](设计-词表维护.md)，停用与替代见[历史与停用](设计-词表数据规范.md#历史与停用)，术语准入见[术语设计](../terminology/设计-术语.md)。

## 约束与校验

四类检查回答不同问题。解析通过不代表符合词表标准，标准一致也不代表语义判断正确。

| 层次 | 检查与证据 | 失败后果 |
|---|---|---|
| Turtle 语法 | 用解析器检查前缀、引号、标点和列表语法 | 文件无法正确读取 |
| 标准语义 | 检查类型互斥、名称文字值唯一、标签角色冲突、相关与层级可达关系冲突 | 数据不符合所用标准的语义 |
| 项目要求 | 按字段表检查必填、值类型、数量和引用；核对持久身份、来源版本、列表及派生结果 | 发布结果不满足本项目合同 |
| 内容判断 | 对照定义、范围、来源原文与采纳记录判断名称、关系和映射 | 数据能读取但含义错误或缺少依据 |

SKOS 要求同一资源的同语言首选文字最多一个，首选、别名和隐藏文字值两两不重叠；SKOS-XL 的名称资源恰有一个 `literalForm`。本设计进一步限制同语言最多引用一个首选名称资源，因为不同名称资源仍可能保存同一个文字值。

标识稳定、单一自有词表、列表无循环等属于项目要求；层级环按已有质量规则报告，不能把所有项目规则说成 SKOS 的普遍禁令。标准的语义约束也不等于封闭的必填表：校验器需按本设计检查本次数据中的实际值。

来源缺项、额外属性及历史兼容问题按[校验分级](设计-词表数据规范.md#校验分级)分别报告，不无声删除来源数据。本文新增的 XL 和列表约束需要实现对应检查，不能只引用现有校验器就认定已经覆盖。
