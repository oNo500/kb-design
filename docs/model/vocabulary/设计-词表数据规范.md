# 词表数据规范

## 适用范围

本文约定当前 RDF／SKOS 词表管线的节点、字段和校验合同，版本为 3。适用于 `output/vocabulary/current/vocabulary.ttl`、领域分图、组织声明及未归属数据；来源原件与来源 Turtle 快照作为核对依据保留。旧 `data/vocab/topics.yaml` 的合同仍见[主题词表设计](设计-主题词表.md)，不使用本文替代其字段定义。

字段表覆盖盘点发现的 44 种现有属性，并补充历史、停用替代和映射属性的合同。现有字段并集是设计依据，不是功能范围的上限。字段按核心用途、派生表达和来源兼容分别约定，不把所有属性要求到每一个节点上。规范中的项目约束不冒称 SKOS 的普遍要求。文档存在不表示生成器已经满足全部条款，当前差异见[实现状态](#实现状态)。

来源快照是来源事实的 SSoT；组织配置、本地编辑及明确的采纳记录分别保存项目选择、编辑意图和准入依据。本地编辑不等于术语准入。规范化及编辑投影由生成器执行并记录依据，不直接编辑已发布 Turtle。文档编写不批准新的概念、译名、映射或关系。

## 词表结构

自有知识体系采用一份词表，八个领域同时具有顶层概念和分组入口。自有词表使用一个 `skos:ConceptScheme`；顶层领域使用 `skos:Concept`，原领域分组继续使用独立的 `skos:Collection`。两种资源不共用 URI，不把分组成员关系直接改成上下位关系。

| 对象 | 表达 | 职责 |
|---|---|---|
| 自有词表 | 一个 `skos:ConceptScheme` | 统一的概念成员范围、名称规则和版本管理 |
| 顶层领域 | 八个 `skos:Concept` | 作为自有词表明确声明的顶层，通过上下位关系连接经配置确定的来源分支 |
| 领域分组 | 八个 `skos:Collection` | 计算机科学、数学、图书馆与信息科学、写作研究、技术传播、学习科学、认知科学、哲学的分组；允许交叉 |
| 概念 | `skos:Concept` | 保存主题意义、名称与概念关系；跨来源尚未消重的对象保持独立身份 |
| 来源词表 | 五份独立来源及其原有 ConceptScheme | 保存原始范围、归属、关系和版本，作为自有词表的来源依据 |

自有 `vocabulary.ttl` 以一个自有 ConceptScheme 组织概念。五份来源仍在来源快照和来源图中独立保存，不作为另外五套自有体系；主文件里的来源定位通过配套来源清单和对账记录追溯。统一自有词表不表示合并五份来源的身份或元数据。

来源原件和独立来源 Turtle 完整保留；概念按来源清单中的可选收录规则筛选后进入未编辑基线 `upstream.ttl`，过滤去向保存在 `source-selection.json`。本地编辑可以显式排除节点或增加本地节点，差异保存在 `local-effects.json` 和编辑历史中。最终主图中的概念统一属于一个自有词表。领域分组通过 `skos:member` 引用概念，同一概念可以成为多个分组的成员；没有领域分组或内容不会自动排除概念。同步与冲突规则见[词表维护设计](设计-词表维护.md)。

领域分图是同一自有词表的派生子集，不是独立词表。应用可以按分组读取或导出，但分组归属本身是模型数据，不是仅存于界面的目录设置。
## 顶层组织

`knowledge-system.json` 的每个领域可配置 `hierarchy`：`uri` 是独立于分组的稳定概念身份，`roots` 是明确采用的分支概念 URI 列表。领域名称沿用已有中英文名称，`vocabulary.top_concepts` 显式列出顶层领域。生成器写入 `hasTopConcept`／`topConceptOf`、分支到领域的 `broader` 及其逆关系，并以组织配置的哈希定位关系依据。

领域节点不能与来源节点或 Collection 共用身份，不能有上位概念；挂接入口必须存在于当前选择结果且属于对应领域组。同一来源概念可以挂接到多个领域，原有身份与内部关系保留。配置不存在的入口导致构建失败，不自动跳过、不按名称猜测替代节点。

当前只连接已明确的分支入口。八个领域分组的原成员规则保持不变，不由新层级派生。数学连接显式配置的 MSC 大类；图书馆与信息科学为空顶层。未连接概念不自动成为顶层，仍可通过字母索引、搜索或分组访问。领域入口是项目组织选择，不冒称来源指定的上位关系，也不表示领域内部已全部完成组织。


来源收录规则可用 `selection.ancestors` 显式列出需要恢复的来源父节点。每项必须是原来源中现有入选概念的祖先；只加入列出的节点，不展开其其他后代，也不自动把全部祖先收录。关系沿用来源原文，顶层连接仍由领域 `hierarchy.roots` 独立声明。

2026-09-15 的来源路径修复恢复了 27 个 MSC 父节点，并将其中 17 个大类明确连接到数学。处理限于已选择的数学分支，量子物理、生物、教育等跨领域路径及来源缺失关系继续保留待确定状态。

## 节点类别

下面是校验目标的五种用途分组，不是新增五种 RDF 类型。节点已有的多个合法 `rdf:type` 声明必须保留。

| 用途 | 识别条件 | 身份与边界 |
|---|---|---|
| 概念 | 显式 `rdf:type skos:Concept` | 使用稳定 IRI；不能同时是 `skos:ConceptScheme` 或 `skos:Collection` |
| 分组 | 显式 `rdf:type skos:Collection` | 包括自有领域分组和继承的来源分组；保留来源的合法附加类型，成员关系不是上下位关系 |
| 词表 | 显式 `rdf:type skos:ConceptScheme` | 自有主词表中只有一个自有 ConceptScheme；来源原有 Scheme 在来源图中保留，不能同时是概念或集合 |
| 任务记录 | 当前来源以 `dcterms:type "task"` 标识，且显式声明 `rdfs:Resource` | 使用稳定 IRI；不把所有 `rdfs:Resource` 都识别为任务，也不改造为主题概念 |
| 辅助记录 | 本地说明资源，或保存 `owl:imports` 等文档元数据的资源 | 本地说明按 `rdf:value` 检查；文档元数据按原属性检查。没有 `rdf:type` 不自动构成错误，也不自动补造类型 |

IRI 即本文使用的资源标识形式，包含现有 HTTP URI 和 `urn:`。IRI 是 RDF 节点身份，不是额外的 `id` 文字字段。主节点身份与名称分离；不能因改名或进入另一个领域分组而重新分配概念身份。

当前没有 `skos:OrderedCollection` 实例，不要求给普通集合补顺序。未来引入时需补充 `skos:memberList` 及 RDF 列表约束，不能把文件中的排列顺序解释为集合顺序。SKOS 的类型互斥及集合语义见 [SKOS Reference §3、§4、§9](https://www.w3.org/TR/skos-reference/)。

## 通用约定

### 值与数量

| 写法 | 约定 |
|---|---|
| `1..n` | 至少一个值；其中类型、身份和归属是结构要求，名称的来源缺项按校验分级处理 |
| `0..n` | 可选且允许多个值；缺少时省略该属性 |
| `0..1` | 可选且最多一个值 |
| 标签文字 | 非空 RDF 文字，带合法语言标签；适用中英文范围与同语言数量规则 |
| 普通文字 | RDF 文字；代码、标识、来源类别、版本等不要求语言标签；不得用空字符串表示缺项 |
| 说明值 | 标签文字，或指向说明资源／文献的 IRI；兼容来源中合法的空白节点说明结构 |
| 日期值 | 合法的 `xsd:date` 或 `xsd:dateTime`；不补猜时区，不把日期扩写成虚构的时间精度 |

表中的数量按单个主语和单个属性统计。多值用多条 RDF 三元组表示，不使用逗号拼接字符串。观察到的最大数量不直接成为上限，例如当前上位最多七个，不意味着规范限制为七个。

主节点使用 IRI 是项目约定，不是 SKOS 排斥空白节点。来源说明结构中的空白节点可以保留，不能为了统一主节点身份而丢失嵌套说明。

### 语言范围

生成词表的语言文字仅保留英文与中文：允许 `en`、`zh` 及合法的 `en-*`、`zh-*` 变体。比较语言标签时忽略大小写，但不把不同完整标签强行合并。`en-US` 与 `en-GB` 可以分别有首选名。

其他语言标签的文字不进入生成的 `vocabulary.ttl`、领域分图、组织声明和未归属分图；来源原件与 `sources/` 中的原始字节副本仍完整保留。过滤按 RDF 语言标签执行，不依靠 AI、文字外观或 URI 路径猜测语言。

缺少中文或英文时不填空值、不自动翻译、不自动采纳译名。来源没有语言标签的文字不得默认为英文；保留原值并将需要语种判断的内容文字列为缺项。代码、标识、日期和版本等非语言数据继续保留。

语言过滤不得删除概念身份、关系或整条记录。过滤后没有允许语言名称或本地说明文字的对象保留并报告。构建报告记录每种语言的过滤数量和相关缺项，不能继续宣称全部来源三元组都保留在生成主文件中。

### 名称规则

概念、集合和词表的规范名称以 `skos:prefLabel` 为唯一维护入口。同一主语的每个完整语言标签最多一个首选名；`skos:altLabel` 与 `skos:hiddenLabel` 允许同语言多个值。三种标签属性的值集合两两不相交，不得把同一文字值同时写入两种标签属性。

自有词表的名称由组织配置单独明确；八个领域名称分别用于对应领域 Concept 和独立的 Collection，不能全部成为自有词表的首选名。现有八个领域 Scheme 的标题在结构迁移时用于相应领域分组的名称，不拼成自有词表名称。来源的 `dcterms:title` 原样保留；自有输出确有兼容需要时，可以从首选名派生同值标题，不另设可独立修改的第二份名称。

| 情形 | 名称控制要求 |
|---|---|
| 同一概念有多种表达 | 根据明确的来源或项目规则确定首选形式与其他入口，保留到具体语言、属性和值的依据 |
| 不同概念同语言同名 | 报告歧义，保留独立 IRI，并提供来源或范围以供区分；不自动合并、不强制本轮消重 |
| 名称带有限定说明 | 保留有依据的完整标签，包括括号中的消歧文字；不另造必填 qualifier 字段，不批量删除括号 |
| 拼写、缩写和词形变体 | 保留来源用法与采用依据；不一律改为全称、复数、小写或首字母大写 |
| 近义词与较宽名称承接较细名称 | 记录来源或规则限定的用途，不将这种检索归并解释为跨语境的严格同义 |
| 复合表达指向多个组成词 | 保留组合及来源依据；未明确表达组合条件前，不把多个组成词逐一当作 altLabel，不按空格或 AND 自动拆分 |

概念内的同语言首选名唯一是硬约束；不同概念之间的同名是消歧诊断，两者不能混成同一条“名称唯一”规则。临时展示来源后缀不改变首选标签。限定说明是词的一部分，范围说明另用 `skos:scopeNote`；见[词的范围](概述-词的范围.md#说明区别)。

现有来源的等价处理可以按既定继承规则保留为该来源对象的事实，但不能作为合并其他来源概念的自动依据。USE／UF 的两个显示方向由标签及相应规则表达，不增加一套独立维护的 USE、UF 字段。语义边界见[等价关系](概述-等价关系.md#等价的范围)与[首选词与名称形式](概述-首选词与名称形式.md#名称选择)。

任务仍使用来源的 `rdfs:label`，不为字段外观一致而改成 SKOS 概念名称。首选名语言唯一与标签互斥依据 [SKOS Reference §5](https://www.w3.org/TR/skos-reference/#labels)；非空、语言标签和输出语言范围属于本项目约束。

## 概念字段

本节基数针对自有主词表中的陈述。来源图独立保留原有归属；联合查询时看到额外来源归属，不等于存在多份自有词表，也不能将主图的单一归属约束直接套到合并后的查询图。

| 属性 | 数量 | 值类型 | 字段约定 |
|---|---|---|---|
| `rdf:type` | 1..n | IRI | 必须包含 `skos:Concept`；允许其他不冲突的来源类型 |
| `skos:inScheme` | 1 | 自有 ConceptScheme IRI | 自有主词表中的概念统一属于同一词表；分组成员用 Collection 的 member 表达，层级归属用概念间的 broader 表达，原来源归属在来源图及对账记录中保留 |
| `skos:prefLabel` | 1..n | 标签文字 | 按名称规则；来源缺名保留为警告，项目新增节点必须有名 |
| `skos:altLabel` | 0..n | 标签文字 | 替代名称，不因此建立另一个概念 |
| `skos:hiddenLabel` | 0..n | 标签文字 | 检索用写法，不自动作为显示首选名 |
| `skos:notation` | 0..n | 普通文字 | 来源分类代码；保留数据类型与原值，不当作概念 URI |
| `dcterms:identifier` | 0..n | 普通文字 | 来源或登记标识；不假定跨来源全局唯一 |
| `skos:definition` | 0..n | 说明值 | 定义或定义资源引用，不限定为一个字符串 |
| `skos:scopeNote` | 0..n | 说明值 | 范围及使用说明，不自动升级为定义 |
| `dcterms:description` | 0..n | 标签文字或来源原有文字 | 一般描述；保留其与定义、范围说明的区别 |
| `skos:note` | 0..n | 说明值 | 一般说明，不自动确定更具体的说明类别 |
| `skos:editorialNote` | 0..n | 说明值 | 编辑提醒，不代替历史、具体变更记录或采纳授权 |
| `skos:historyNote` | 0..n | 说明值 | 名称、含义或使用范围的重要历史变化，帮助解释旧内容的标记 |
| `skos:changeNote` | 0..n | 说明值 | 细粒度维护变更；从结构化变更记录生成说明或引用，不重复维护第二份事件历史 |
| `owl:deprecated` | 0..1 | xsd:boolean | 有明确依据时标记停用；缺少该属性不证明已经采纳或经过审查 |
| `dcterms:isReplacedBy` | 0..n | Concept IRI | 旧概念指向替代概念，允许多个目标；不等于概念等价或自动重标引 |
| `dcterms:replaces` | 0..n | Concept IRI | 替代概念指向旧概念的派生反向表达，不单独维护 |
| `skos:broader` | 0..n | Concept IRI | 自有直接层级的主要维护方向，允许多父；来源反向边也须纳入归一与对账 |
| `skos:narrower` | 0..n | Concept IRI | 从上位关系派生的下位表达；编辑反向表达时同步修改同一条上位关系，不允许两套互相独立的值 |
| `skos:related` | 0..n | Concept IRI | 相关关系；不得与同一对概念的层级可达关系重叠 |
| `skos:topConceptOf` | 0..1 | 自有 ConceptScheme IRI | 由 hasTopConcept 派生的顶层归属；不能指向领域集合，不单独维护 |
| `dcterms:isPartOf` | 0..n | IRI | 部分关系；不自动改成 `broader`，不要求目标一定是概念 |
| `dcterms:source` | 0..n | IRI | 引用来源资源；不能代替逐字段、逐关系的生成对账 |
| `prov:wasDerivedFrom` | 0..n | IRI | 派生依据，可关联来源页等资源；保留定位 |
| `dcterms:created` | 0..1 | 日期值 | 所描述概念记录的创建时间；来源与项目记录分别追溯，不以本次生成时间代替 |
| `dcterms:modified` | 0..1 | 日期值 | 所描述概念记录的修改时间；不以构建时间覆盖，也不代替变更原因 |
| `dcterms:type` | 0..n | 普通文字 | 仅兼容保留来源记录类别；不要求自有概念重复写 concept，不替代 RDF 类型或分面分类 |

URI、identifier、notation 分别用于对象身份、来源标识与分类代码；某些来源值相同，不构成全局删除其中一个属性的依据。definition、scopeNote、description 分别用于定义、使用范围与一般描述，也不合并为一个文字字段。

说明值使用文字、资源描述或文献引用均有 SKOS 依据，不能为了单一字符串接口删除说明对象。[SKOS Reference §7](https://www.w3.org/TR/skos-reference/#notes)

## 分组字段

| 属性 | 数量 | 值类型 | 字段约定 |
|---|---|---|---|
| `rdf:type` | 1..n | IRI | 包含 `skos:Collection`；保留来源附加的合法类型 |
| `skos:prefLabel` | 1..n | 标签文字 | 分组名称，按名称规则；来源缺名保留警告 |
| `skos:altLabel` | 0..n | 标签文字 | 分组的替代名称 |
| `skos:hiddenLabel` | 0..n | 标签文字 | 分组的检索写法 |
| `skos:notation` | 0..n | 普通文字 | 来源分组代码 |
| `skos:scopeNote` | 0..n | 说明值 | 分组的用途、纳入范围、排除情况和与相邻分组的区别；可引用明确的组织规则 |
| `skos:historyNote` | 0..n | 说明值 | 分组范围的重要历史变化 |
| `skos:changeNote` | 0..n | 说明值 | 从维护记录派生的成员或结构变更说明 |
| `dcterms:source` | 0..n | IRI | 分组依据的来源资源，仍需在对账中明确采用的范围 |
| `prov:wasDerivedFrom` | 0..n | IRI | 分组或成员选择所依据的具体来源记录、规则或版本 |
| `skos:inScheme` | 0..1 | 自有 ConceptScheme IRI | 自有领域分组必须关联唯一自有词表；继承分组可关联该词表。来源原有归属另行保留，集合使用该属性不应被错误拒绝 |
| `skos:member` | 0..n | Concept 或 Collection IRI | 可以包含概念或嵌套集合，不用于表达上下位语义 |
| `iso-thes:subGroup` | 0..n | Collection IRI | 保留来源表达；自有细分需要输出时由已确定的 superGroup 关系派生，不转成概念层级 |
| `iso-thes:superGroup` | 0..n | Collection IRI | 需要此种分组细分时的主要维护方向；不能仅凭类似名称就认定它与 member 完全相同 |
| `dcterms:modified` | 0..1 | 日期值 | 来源分组的修改时间 |

八个领域分组使用本表同一套字段。分组应能通过范围说明或所引用的结构化规则解释“为何收录这些成员”；不要求为每个成员人工重复填写一段说明。其 `skos:member` 引用本词表概念；需要嵌套分组时，引用的子集合也必须能在本次数据中定位。同一概念可被多个分组引用，不复制概念记录。来源原有集合及其原始成员关系继续保留依据，不能因领域分组同名而自动合并集合。

空集合允许保留并提示没有成员，不自动补成员。集合不得作为 `broader`、`narrower`、`related` 的起点或终点。分组代码与概念代码可能采用不同规则，不合并其身份空间。

| 属性 | 数量 | 值类型 | 字段约定 |
|---|---|---|---|
| `rdf:type` | 1..n | IRI | 包含 skos:ConceptScheme，不同时作为概念或集合 |
| `skos:prefLabel` | 1..n | 标签文字 | 自有词表规范名称的唯一维护入口 |
| `skos:scopeNote` | 1..n | 说明值 | 明确收录范围、排除情况和使用边界；是项目的词表级要求，不强加给每个来源词表 |
| `dcterms:description` | 0..n | 标签文字或来源原有文字 | 补充用途或一般介绍，不重复抄写范围说明 |
| `skos:note` | 0..n | 说明值 | 不适合归入更具体说明属性的其他信息 |
| `skos:historyNote` | 0..n | 说明值 | 自有词表范围或组织原则的重要历史变化 |
| `skos:changeNote` | 0..n | 说明值 | 从版本及维护记录派生的具体变更说明 |
| `skos:hasTopConcept` | 0..n | Concept IRI | 自有顶层概念的主要维护入口，检查本词表成员资格；领域集合不是顶层概念 |
| `dcterms:source` | 0..n | IRI | 自有词表引用的来源资源，逐项采用范围仍由配置和依据记录说明 |
| `dcterms:created` | 0..1 | 日期值 | 自有词表建立时间，不继承为任一来源词表的创建时间 |

| `dcterms:language` | 0..n | IRI | 实际提供的中英文语言标识，与输出配置一致 |
| `owl:versionInfo` | 0..n | 普通文字 | 自有词表版本说明；来源版本和生成工具版本分别记录 |

## 来源兼容字段

以下属性保留在其实际描述的来源对象上，不是所有自有节点都要填写的核心字段。自有词表有独立且明确的相应信息时可以使用，不能从来源集合机械汇总出自有创建者、许可、格式或版本。

| 属性 | 数量 | 值类型 | 保留与转换约定 |
|---|---|---|---|
| `dcterms:title` | 0..n | 标签文字或来源原有文字 | 来源标题保留；自有输出仅在兼容需要时从 prefLabel 派生同值标题，不独立维护 |
| `dcterms:identifier` | 0..n | 普通文字 | 发布者词表标识，不替代 IRI |
| `dc:creator` | 0..n | 普通文字 | 来源创建者名称，不自动成为自有词表创建者 |
| `dc:contributor` | 0..n | 普通文字 | 来源贡献者名称 |
| `dc:publisher` | 0..n | 普通文字 | 来源发布者名称 |
| `dc:subject` | 0..n | 普通文字 | 来源主题描述，不据此创建本地分类关系 |
| `dcterms:conformsTo` | 0..n | IRI；兼容来源原有文字 | 来源遵循标准的声明；自有新增声明须有实际依据 |
| `dcterms:format` | 0..n | IRI | 来源载体或格式的标识，不冒称当前自有输出格式 |
| `dcterms:isRequiredBy` | 0..n | IRI | 依赖该资源的对象，不作为概念层级 |
| `dcterms:license` | 0..n | IRI | 来源许可资源，不因转换擅自变更或当作整个自有词表的许可 |
| `dcterms:replaces` | 0..n | IRI | 来源资源的替代声明，区别于概念级替代，不跨对象种类混用 |
| `dcterms:rights` | 0..n | 普通文字或有依据的权利声明 IRI | 来源权利说明 |
| `dcterms:rightsHolder` | 0..n | IRI；兼容来源原有文字 | 来源权利持有者，不为转换名称而制造实体记录 |
| `dcterms:subject` | 0..n | IRI | 来源明确引用的主题，与文字形式的 dc:subject 分开保留 |
| `dcterms:type` | 0..n | 普通文字 | 来源类别信息，不冒充 RDF 类型或本地分类决定 |

来源的 `dcterms:created`、`dcterms:modified`、`dcterms:language` 和 `owl:versionInfo` 同样保留原对象及含义，不能覆盖自有词表的相应值。原来源语言声明与本次输出的语言范围分别报告；保留源声明不意味着生成文字可以超出中英文范围。

`dc:` 与 `dcterms:` 是不同命名空间，不做全局字符串替换。兼容来源文字不等于认定它满足 DCMI 的全部资源类型语义。[DCMI Metadata Terms](https://www.dublincore.org/specifications/dublin-core/dcmi-terms/)

辅助记录按用途选择约束，不以“未声明类型”建立一个新的 RDF 类。

| 属性 | 数量 | 值类型 | 适用对象与约定 |
|---|---|---|---|
| `rdf:value` | 本地说明为 1..n | 标签文字或来源原有文字 | 本地说明正文，允许多语言；语言过滤后无可用正文时保留记录与引用并报告缺项 |
| `dcterms:created` | 0..1 | 日期值 | 说明记录创建时间 |
| `dcterms:modified` | 0..1 | 日期值 | 说明记录修改时间 |
| `dcterms:source` | 0..n | IRI | 说明或元数据的来源 |
| `owl:imports` | 0..n | IRI | 来源文档的本体引用；读取与校验不得据此自动联网加载其他图 |

`skos:definition` 等指向本地说明资源时，核对该资源的正文及已有元数据；指向外部文献时只检查引用形式与已有定位，不强制远程资源在本文件中具有 `rdf:value` 或 `rdf:type`。RDF 类型、属性、许可和标准等仅作为引用对象出现时，不按缺少字段的词条报错。

## 关系维护

概念通过 inScheme 属于唯一自有词表；领域 Collection 通过 member 收录概念；概念之间表达上下位或相关关系。这三种用途互不替代。

| 关系或表达 | 主要维护入口 | 派生与校验要求 |
|---|---|---|
| 直接层级 | `skos:broader` | 导入时同时识别原 broader 和反向 narrower，归一后对账；需要时生成 narrower，不能只删除源 narrower 导致关系丢失 |
| 顶层归属 | `skos:hasTopConcept` | 确定统一词表顶层后派生 topConceptOf；源中的两个方向均保留依据，不把“无 broader”自动当作顶层 |
| ISO 来源分组细分 | `iso-thes:superGroup` | 在确需此类细分时归一原两向关系，按需派生 subGroup；不和 member 或概念层级混为一谈 |
| 概念替代 | `dcterms:isReplacedBy` | 从旧概念指向新概念，反向 replaces 派生；不将替代关系当成等价映射 |
| 相关关系 | `skos:related` | 同一对概念的联系只作一次决定；双向查询或输出由程序保证，不建立另一种“反向相关”字段 |

这里确定的是维护职责，不限制输出是否同时包含两个方向。反向冗余由程序生成并验证一致，不形成第二套人工维护输入。来源原始记录与变更依据继续完整保留。

层级可能表达种属、实例或符合条件的整体部分。来源已有明确细分时保留其类型和依据；只给出 BT／NT 时不猜测细分类型，也不因现有 dcterms:isPartOf 就自动添加 broader。学科与研究对象、共同出现、目录嵌套都不能单独证明层级成立。依据见[层级关系](概述-层级关系.md#成立条件)与[相关关系](概述-相关关系.md#成立条件)。

related 与层级可达关系互斥。同级概念可以有明确的相关关系，但不能把全部同级节点自动相连。层级环、自相关和集合循环作为质量问题报告，不冒称 SKOS 一概禁止。

## 依据记录

已有来源清单和概念对账继续使用；本节补充其必须能定位的精度，不要求为全部概念人工重写依据。

| 信息 | 记录要求 |
|---|---|
| 所支持的对象 | 概念 IRI；涉及名称、定义或关系时，明确属性及具体值或目标 IRI |
| 文字值身份 | 保留完整文字、语言标签及数据类型，不能只存一个无语种的名称字符串 |
| 来源身份 | 来源记录 IRI 或记录标识、固定版本和文件哈希；已有页码、XML 记录、JSON 定位等同时保留 |
| 处理依据 | 原样继承或转换命中的规则及版本；本地选择或调整需要记录具体理由 |
| 名称采用依据 | 区分来源首选形式与项目选择，说明采用哪个表达及其依据，不把概念整体来源自动当成每个译名的证据 |
| 变更与效力 | 变更前后值、时间及已有的决定或授权记录；来源事实、项目判断和未确定项分别可辨 |

这些信息是配套结构化记录的合同，不要求全部重复写为概念属性。原样继承可以由来源标识、属性和值、快照及继承规则自动证明；每个节点不必同时写同值的 dcterms:source 和 prov:wasDerivedFrom。前者表示来源引用，后者表示派生联系，各自使用时保留含义。[PROV-O](https://www.w3.org/TR/prov-o/)

文献、组织与用户依据可能支持不同选择。不得把词频、字符串相似度或源中出现过自动当作全部采用理由，也不制定无来源支持的统一权重算法。说明见[选词依据](概述-选词依据.md#三类依据)和[首选词与名称形式](概述-首选词与名称形式.md#依据记录)。

## 历史与停用

historyNote 面向概念名称、意义或用法的重要历史；changeNote 面向细粒度维护；editorialNote 是编辑提醒。三者不能互相代替。日期只说明时间，构建哈希只定位版本，都不能代替范围变化的说明。[词的范围](概述-词的范围.md#范围变化)、[SKOS 说明属性](https://www.w3.org/TR/skos-primer/#secdocumentation)

有结构化变更记录时，changeNote 从其派生摘要或指向该记录，不维护两份相互独立的历史。程序可以记录原文字发生变化，但不能仅凭文本差异就断言概念含义已改变。没有依据的历史不补造，也不要求给从未发生过变更的概念填写历史注释。

停用、替代和改名分开处理：

- 原概念保持同一含义的改名通常保持 IRI，并按有依据的规则处理旧名称。
- 明确停用时可写 `owl:deprecated true`，保留原 IRI、原有引用及历史。未写 deprecated 不能推断为“已审核”或“已采纳”。
- 有明确替代对象时使用 isReplacedBy；拆分可有多个目标。替代本身不证明严格等价，也不授权自动迁移旧文章的全部主题标记。
- 没有文章、使用频率为零或尚未归入领域分组，都不是停用或删除概念的依据。

停用与替代是项目维护约定，分别使用已有标准属性，不新增混合所有状态的概念 status 字段。[OWL 停用注释](https://www.w3.org/TR/owl2-syntax/#Annotation_Properties)、[DCMI isReplacedBy](https://www.dublincore.org/specifications/dublin-core/dcmi-terms/terms/isReplacedBy/)

## 映射字段

以下是可选映射合同，不是当前数据已有映射的声明，也不要求先处理全部交叉候选。映射可以保存在独立映射图中；对应状态与依据仍由结构化记录管理。

| 属性 | 数量 | 值类型 | 对应含义 |
|---|---|---|---|
| `skos:exactMatch` | 0..n | Concept IRI | 在广泛检索应用中可高度确信互换的对应；具有传递性，不等于 owl:sameAs，不合并双方全部属性 |
| `skos:closeMatch` | 0..n | Concept IRI | 在部分检索应用中足够接近、可以互换的对应；不是“不确定”的占位值，不作传递推导 |
| `skos:broadMatch` | 0..n | Concept IRI | 本端概念对应另一词表中更宽的概念，方向必须明确 |
| `skos:narrowMatch` | 0..n | Concept IRI | 本端概念对应另一词表中更窄的概念；与 broadMatch 互反，不维护冲突的两套决定 |
| `skos:relatedMatch` | 0..n | Concept IRI | 跨词表的相关对应，不代替等价或宽窄判断 |

目标可以在独立来源图中描述；IRI 必须能够通过明确的来源记录定位，不强制校验器联网补全。原样复用同一个概念 IRI 时，不为凑齐字段制造指向自身的 exactMatch。候选、暂缓、不采用与未确定关系不写成有效映射，已明确的自动规则继续在原授权范围内执行。[SKOS 映射定义](https://www.w3.org/TR/skos-reference/#mapping)

## 扩展边界

分面、数组、划分特征和概念组是不同的组织问题。八个领域分组不自动等于分面分析，也不要求所有概念新增 facet、数组类别或划分特征字段。确有对应结构需要时，再依据源模型扩展，保留分组依据与来源类型；当前不补造这些属性。[分面与分组](概述-分面与分组.md#组织职责)

先组与后组主要规定组合表达和检索时机，不作为每个概念必填的布尔字段。多个词组成的名称不自动等于多个概念，组合参照不能被普通相关关系或多个替代标签替代。[先组与后组](概述-先组与后组.md#拆分边界)、[复合词的处理](概述-复合词的处理.md#整体含义)

文章数量、学习进度、查准率与查全率属于内容关联或评价报告。保留它们与词表的联系，但不写入核心概念记录冒充词表结构。任务兼容字段、说明资源与来源元数据也不能因被读入同一文件就成为每个概念的必备字段。

词表可以支持术语工作，但本规范不因此引入整套术语库结构或为每个标签建立独立 SKOS-XL 对象。具体名称依据先由结构化记录追溯，需要独立词级关系时再扩展。[叙词表与术语库](概述-叙词表与术语库.md#数据共享)

## 校验分级

| 级别 | 检查内容 | 处理要求 |
|---|---|---|
| 结构与语义错误 | 非法主节点身份、不相容类型、关系端点错误、同语言多个首选名、标签互斥冲突、相关与层级冲突 | 本次生成新增时阻止发布，保留旧 `current` |
| 项目合同错误 | 自有词表数量不是一个、概念缺少唯一自有归属、领域集合被用作概念上位或顶层、主要维护方向与派生结果不一致、项目新增节点缺少必需信息、新生成字段为空、生成文字超出允许语言、结构或字段转换没有对账依据 | 对相应生成结果报错；来源兼容问题单独报告，不能假称已经符合新规范 |
| 来源缺项与兼容 | 已有概念或任务缺名、内容文字未标语种、说明引用无本地正文、表中标记的旧值形式 | 保留来源对象并警告，不猜测补齐、不无声丢弃 |
| 消歧与维护提示 | 不同概念同语言同名、分组缺少可解释的范围依据、旧概念有替代目标但未明确旧内容处理方式 | 保留并定位问题，不自动合并、改名、删除或重标引，不触发全量人工审查 |
| 可选信息缺失 | 没有替代名、没有定义、没有中文、没有关系、没有时间信息或没有发生过历史变更 | 本身不构成违规；可作为完整性报告，不能据此阻止正常生成 |

来源已有的错误仍是错误，只是按明确来源版本及具体三元组绑定记录，避免阻塞机械继承；不能笼统将全部首次错误永久豁免。新来源、新规则或相关值变化时应产生新的诊断，不能静默沿用原来的例外。

SHACL 用于身份形式、类型、数量、语言和对象约束；图冲突、来源哈希、完整对账与构建发布仍使用相应工程检查。`sh:uniqueLang` 必须与文字语言要求一起使用，不能拿全属性的 `sh:maxCount 1` 代替同语言唯一。规则保存在 [shapes.ttl](../../../data/inputs/vocabulary/shapes.ttl)，由本地 pySHACL 执行；发布还执行生成对账与图关系门禁。[SHACL](https://www.w3.org/TR/shacl/)

来源图允许保留额外标准属性和发布者属性，不采用全局闭合字段表导致数据被丢弃。项目新生成的属性须有明确字段合同；新出现的字段、值类型或节点类别先报告并补充规范，不通过自造字段绕过约束。语言文字输出限制对所有属性生效，包括扩展属性。

校验结果应定位节点、属性、问题值、规则及来源版本，并区分错误和警告；在对话中直接报告关键结果，文件作为完整记录保留。不将 URI 可达性检查扩展成未授权的联网抓取。

## 结构迁移

目标主文件组织一份自有词表，领域分图仍是它的派生子集；五份来源快照继续独立保存。结构转换由生成器执行，输入配置与输出均应记录版本，不直接修改 `current` 指向的既有文件。

| 对象 | 迁移要求 |
|---|---|
| 自有词表 | 从配置读取稳定身份和中英文名称，统一记录成员与版本；重建不临时分配新身份 |
| 八个旧领域 Scheme | 为对应领域 Collection 明确独立稳定身份，登记旧 Scheme 与新分组的迁移对应；不能将原 IRI 原地改成集合类型或用 exactMatch 表达不同种类对象的替代 |
| 概念与关系 | 保持概念 IRI 和上下位、相关关系；统一自有 inScheme，领域成员改用 Collection 的 member，不要求先消重 |
| 未归属记录 | 全量概念均纳入自有词表；原“未归属”明确改为“未归入领域分组”，记录继续保留 |
| 原顶层声明 | 在来源图和历史版本中保留；自有统一词表的顶层单独确定，不从各领域顶层机械拼接 |
| 元数据与字段依据 | 来源元数据保留原对象和来源版本；自有词表与领域集合的名称、成员和类型转换逐项对账 |
