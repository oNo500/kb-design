# 词表数据规范

本规范集中规定综合词表的资源字段、关系约束、配套管理记录及统一校验。对象和范围见[整体设计](设计-词表整体设计.md)；语言处理、变更和版本行为分别由相应专题规定。本篇的记录要求与这些业务规则共同适用，具体存储和序列化由交付合同落实。

## 适用范围

合同适用于综合概念词表的主图、独立名称记录、映射及配套管理记录。来源图保留原词表及其版本；历史图保留当时描述。三者可以关联查询，但不能无差别合并为同一个待发布版本。

普通实体记录的事实字段按[实体设计](../entities/设计-命名实体词表.md)管理，不为了复用本合同而把实体本身声明为 Concept。概念可以表达关于具体对象的主题；其身份与对应的实体记录分别维护。使用 SKOS 名称属性本身不意味着资源为 Concept。[SKOS §5.6.1](https://www.w3.org/TR/skos-reference/#labels)

辅助资料与词表概念分别识别。来源中的任务、文献、类别或目录节点按其原类型保留，不因有名称就转换成概念；已声明为概念的来源条目也不因其名称是专名就改为实体。任何具体归属变化须核对所描述对象、用途、依据和采纳，不能由序列化或 SHACL 通过推断。

实体的相关主题与主题专指的实体不是同一关系。后者的字段表示未采纳前，不加入本合同或以 exactMatch、sameAs 等属性替代；见[关联语义](../entities/设计-命名实体词表.md#关联语义)。

## 标准与选择

标准定义属性含义及一致性条件，项目依据用途补充完整性要求。以下区分适用于全文，字段表中的必填和数量不能一概称为 SKOS 原生要求。

| 依据层次 | 约束 |
|---|---|
| RDF／SKOS／SKOS-XL | 资源、值、类型、关系语义；按语言的首选名唯一性；标签角色互斥；XL 名称单一文字值；集合及映射一致性 |
| 项目完整性要求 | 主要记录显式类型与稳定 IRI；本地新增概念及概念组有名；一般集合和数组不一律必名；自有词表和自建集合有范围说明；依据、版本与历史可追溯 |
| 项目组织选择 | 一份自有 ConceptScheme；主图概念恰好关联该词表；自有集合关联该词表；名称统一登记；概念名称以 XL 为维护入口 |
| 项目质量要求 | 新增或修改的数据不得引入项目禁止的自关联、层级环及未解释的信息损失；来源原件保留诊断，有效发布图仍须满足标准一致性 |

单一归属服务于一份综合词表的管理，不限制来源概念参加其他词表。SKOS 允许概念属于零个、一个或多个 ConceptScheme；本规范的主图限制不能用于否定来源图。[SKOS §4](https://www.w3.org/TR/skos-reference/#schemes)

## 通用约定

### 标识与类型

概念、词表、名称及需要持久引用的集合使用稳定 IRI。保留适用的来源身份；身份要求与本地分配方案见[名称编辑](设计-词表维护.md#名称编辑)。名称文字、排序及目录位置不决定身份。

主要记录显式声明 `rdf:type`，可以保留其他不冲突的类型。Concept、ConceptScheme、Collection 与 Label 不兼作彼此；OrderedCollection 是 Collection 的子类。采用 SKOS-Thes 分组扩展时，另检查 ConceptGroup 与 ThesaurusArray 的专用类型约束，见[集合字段](#集合字段)。说明和列表可以使用空白节点，不为填满类型字段而新造类。[SKOS 类型](https://www.w3.org/TR/skos-reference/)、[SKOS-XL 类型](https://www.w3.org/TR/skos-reference/#xl)

### 值与数量

| 表示 | 合同 |
|---|---|
| `1`、`1..n` | 恰好一个、至少一个；区分本地完整记录与明确允许缺项的来源记录 |
| `0..1`、`0..n` | 可选单值、可选多值；缺少时省略，不用空字符串占位 |
| 资源引用 | IRI 或来源已有的空白节点；需要持久独立引用的本地记录使用稳定 IRI |
| 标签文字 | 非空文字及明确的语言标签；来源未标语种按缺项保留，不补猜 |
| 普通文字 | 编号、来源类别或版本等文字；保留原数据类型，不强加语言标签 |
| 说明值 | 文字、说明资源或文献引用；来源已有多语与嵌套结构保留 |
| 本地日期值 | `xsd:date` 或 `xsd:dateTime`；有事实依据，不补猜时区或用生成时间代替修改时间 |

多值分别写成陈述，不用逗号拼接。文字、语言标签和数据类型共同确定字面值。字段表中本地记录的单值、日期或表示选择，不自动成为所有来源的限制；来源原值按[来源兼容字段](#来源兼容字段)保存，不能为满足表格而静默截断或强转。

### 语言与名称

语言标记、概念对应及显示选择按[多语言词表](设计-多语言词表.md)。实际启用范围由具体范围决定限定；缺译不删除概念，未标语种不按文字外观推断。

同一资源、同一完整语言标签下，直接普通首选标签与全部 XL 首选名称投影合在一起，最多只能有一个不同的文字值。首选、别名和隐藏名的完整文字值集合仍两两不相交；每个 Label 在同一版本中仍恰好有一个 literalForm。[SKOS S13、S14、S52、S55–S58](https://www.w3.org/TR/skos-reference/)

不同 Label 可以具有相同文字和语言，同时保留各自身份、来源和历史。在所指概念及名称使用关系已有依据时，它们可以共同作为该概念的首选名称记录，首选 Label 资源的数量不另设唯一限制。相同投影只产生一个普通文字值，不能由此推导 Label 同一、合并来源身份或自动建立概念对应。[SKOS-XL §B.2.4](https://www.w3.org/TR/skos-reference/#xl)

若同语言的首选投影变成不同文字，就构成冲突，须明确选择采用的文字和名称角色；不能按记录顺序保留一个或以不同 Label 身份绕过标签互斥。显示可以合并重复文字，但须保留到全部相关名称记录和依据的关联；修改则按具体名称身份定位。

同名概念保持独立身份并诊断歧义。限定文字、缩写、词形与组合表达按依据保留，不统一改写为全称或小写。概念名称以 XL 为维护入口，普通标签由其投影；词表和集合默认直接维护普通标签，需要独立名称身份时按具体用途采用 XL。来源已有 XL 关系、名称身份、文字、说明和依据必须保留，不能只保留投影文字。采用 XL 的同一组名称不得另有独立覆盖它的普通标签输入。

## 词表字段

自有词表的范围说明须能解释用途、收录、排除及未分组数据的处理，不能只给出名称或分组数量。

| 属性 | 数量 | 值类型 | 字段约定 |
|---|---|---|---|
| `rdf:type` | 1..n | IRI | 包含 skos:ConceptScheme，不同时作为概念或集合 |
| `skos:prefLabel` | 1..n | 标签文字 | 自有词表的首选名称；直接维护或由所采用的 XL 名称投影 |
| `skos:altLabel` | 0..n | 标签文字 | 词表的替代名称，遵守同一套语言及角色约束 |
| `skos:hiddenLabel` | 0..n | 标签文字 | 词表的检索写法，不作为默认显示名称 |
| `skos:scopeNote` | 1..n | 说明值 | 明确收录范围、排除情况和使用边界；是项目的词表级要求，不强加给每个来源词表 |
| `dcterms:description` | 0..n | 标签文字或来源原有文字 | 补充用途或一般介绍，不重复抄写范围说明 |
| `skos:note` | 0..n | 说明值 | 不适合归入更具体说明属性的其他信息 |
| `skos:historyNote` | 0..n | 说明值 | 自有词表范围或组织原则的重要历史变化 |
| `skos:changeNote` | 0..n | 说明值 | 从版本及维护记录派生的具体变更说明 |
| `skos:hasTopConcept` | 0..n | Concept IRI | 自有顶层概念的主要维护入口，检查本词表成员资格；领域集合不是顶层概念 |
| `dcterms:source` | 0..n | 资源引用 | 自有词表引用的来源资源，逐项采用范围仍由范围决定和依据记录说明 |
| `dcterms:created` | 0..1 | 本地日期值 | 自有词表建立时间，不继承为任一来源词表的创建时间 |
| `dcterms:modified` | 0..1 | 本地日期值 | 自有词表记录的修改时间，不等同于每次重建时间 |
| `dcterms:language` | 0..n | 语言资源引用或 BCP 47 文字值 | 实际提供的语言，不代替每个名称的语言标签；两种表示均须能解释其所指 |
| `owl:versionInfo` | 0..n | 普通文字 | 自有词表版本说明；来源版本和生成工具版本分别记录 |

DCMI 允许以受控语言资源或 BCP 47 文字值表示资源语言。词表标题与首选名称分别按其用途维护，不要求二者同值；具体输出需要同值标题时，由该交付合同说明转换。[DCMI language](https://www.dublincore.org/specifications/dublin-core/dcmi-terms/terms/language/)、[DCMI title](https://www.dublincore.org/specifications/dublin-core/dcmi-terms/terms/title/)

## 概念字段

下列基数针对自有主图；来源归属独立保留。概念同时适用通用说明、来源与维护属性；本地记录日期与来源日期按[来源与依据](#来源与依据)区分。

| 属性 | 数量 | 值类型 | 字段约定 |
|---|---|---|---|
| `rdf:type` | 1..n | IRI | 必须包含 `skos:Concept`；允许其他不冲突的来源类型 |
| `skos:inScheme` | 1 | 自有 ConceptScheme IRI | 自有主词表中的概念统一属于同一词表；分组成员用 Collection 的 member 表达，层级归属用概念间的 broader 表达，原来源归属在来源图及对账记录中保留 |
| `skosxl:prefLabel` | 1..n | Label IRI | 首选名称的维护入口；本地新增概念必须有名，来源缺名保留警告 |
| `skosxl:altLabel` | 0..n | Label IRI | 替代名称，不因此建立另一个概念 |
| `skosxl:hiddenLabel` | 0..n | Label IRI | 检索用写法，不作为默认显示首选名 |
| `skos:notation` | 0..n | 普通文字 | 来源分类代码；保留数据类型与原值，不当作概念 URI |
| `dcterms:identifier` | 0..n | 普通文字 | 来源或登记标识；不假定跨来源全局唯一 |
| `skos:definition` | 0..n | 说明值 | 定义或定义资源引用，不限定为一个字符串 |
| `skos:scopeNote` | 0..n | 说明值 | 范围及使用说明，不自动升级为定义 |
| `dcterms:description` | 0..n | 标签文字或来源原有文字 | 一般描述；保留其与定义、范围说明的区别 |
| `skos:note` | 0..n | 说明值 | 一般说明，不自动确定更具体的说明类别 |
| `skos:editorialNote` | 0..n | 说明值 | 编辑提醒，不代替历史、具体变更记录或采纳授权 |
| `skos:historyNote` | 0..n | 说明值 | 名称、含义或使用范围的重要历史变化，帮助解释旧内容的标记 |
| `skos:changeNote` | 0..n | 说明值 | 细粒度维护变更；从结构化变更记录生成说明或引用，不重复维护第二份事件历史 |
| `owl:deprecated` | 0..1 | xsd:boolean | 有明确依据时标记停用；缺少该属性不证明已经采纳或经过审查 |
| `dcterms:isReplacedBy` | 0..n | Concept IRI | 旧概念指向替代概念，允许多个目标；不等于概念等价或自动重标引 |
| `dcterms:replaces` | 0..n | Concept IRI | 替代概念指向旧概念的派生反向表达，不单独维护 |
| `skos:broader` | 0..n | Concept IRI | 自有直接层级的主要维护方向，允许多父；来源反向边也须纳入归一与对账 |
| `skos:narrower` | 0..n | Concept IRI | 从上位关系派生的下位表达；编辑反向表达时同步修改同一条上位关系，不允许两套互相独立的值 |
| `skos:related` | 0..n | Concept IRI | 相关关系；不得与同一对概念的层级可达关系重叠 |
| `skos:topConceptOf` | 0..1 | 自有 ConceptScheme IRI | 由 hasTopConcept 派生的顶层归属；不能指向领域集合，不单独维护 |
| `dcterms:isPartOf` | 0..n | 资源引用 | 部分关系；不自动改成 `broader`，不要求目标一定是概念 |
| `dcterms:source` | 0..n | 资源引用 | 引用来源资源；不能代替逐字段、逐关系的生成对账 |
| `prov:wasDerivedFrom` | 0..n | 资源引用 | 派生依据，可关联来源页等资源；保留定位 |
| `dcterms:created` | 本地 0..1；来源按原值 | 本地日期值或来源日期 | 所描述概念记录的创建时间；来源与项目记录分别追溯，不以本次生成时间代替 |
| `dcterms:modified` | 本地 0..1；来源按原值 | 本地日期值或来源日期 | 所描述概念记录的修改时间；不以构建时间覆盖，也不代替变更原因 |

IRI、identifier 与 notation 分别表示对象身份、来源标识和分类代码，不因部分值相同全局合并。definition、scopeNote 与 description 的职责也分别保留；说明可用文字、资源或文献引用，不为了字符串接口删除说明对象。[SKOS 说明属性](https://www.w3.org/TR/skos-reference/#notes)

## 名称字段

| 属性 | 数量 | 值类型 | 字段约定 |
|---|---|---|---|
| `rdf:type` | 1..n | IRI | 包含 `skosxl:Label`，不兼作概念、词表或集合 |
| `skosxl:literalForm` | 1 | 文字值 | 每个版本恰好一个；本地新增名称明确语言，来源未标语种保留诊断 |
| `skosxl:labelRelation` | 0..n | Label IRI | 连接两个名称的对称关系，作为具体名称关系的扩展点 |

角色由资源到名称的 prefLabel、altLabel 或 hiddenLabel 关系表达，不写成名称的全局状态。不同语言表达分别登记身份；同一名称的历史文字不全部并入当前 `literalForm`。名称上的说明、来源和日期保留原附着对象。

`labelRelation` 本身具有对称性，不能直接表达有方向的“缩写对应全称”等具体关系，也不用于填补未确定的关系。来源已有的通用联系可以保留；具体用途采用已核属性或经采用的子属性，检查其独立语义。对称属性的子属性不因此自动具有对称性。[SKOS-XL §B.2–B.4、S62](https://www.w3.org/TR/skos-reference/#xl)

词表和集合采用独立名称时，同样使用上述字段及投影约束。是否采用独立名称依据维护与追溯需求确定，不由旧输入仅有文字标签这一事实决定。

## 集合字段

一般集合、概念组与数组不能因共同使用 Collection 表示就共用全部业务约束。下表适用于主图；来源的原类型、名称和归属另行保留。

| 属性 | 数量 | 值类型 | 字段约定 |
|---|---|---|---|
| `rdf:type` | 1..n | IRI | 包含 Collection 或 OrderedCollection；采用扩展时保留其专用类型 |
| `skos:prefLabel` | 0..n | 标签文字 | 一般集合和数组可缺名；概念组的名称要求见下文，可直接维护或从 XL 投影 |
| `skos:altLabel`、`skos:hiddenLabel` | 各 0..n | 标签文字 | 分别为替代名和检索写法，不改变成员或层级 |
| `rdfs:label` | 0..n | 文字值 | 保留来源的组名称或节点标签；不能据此推断概念首选名 |
| `skos:notation` | 0..n | 普通文字 | 来源分组代码，不与概念代码合并身份 |
| `skos:scopeNote` | 自建 1..n；继承 0..n | 说明值 | 用途、成员纳入与排除、排序依据；可引用明确的组织规则 |
| `skos:historyNote`、`skos:changeNote` | 各 0..n | 说明值 | 范围历史及由维护记录派生的具体变更 |
| `dcterms:source`、`prov:wasDerivedFrom` | 各 0..n | 资源引用 | 来源及实际派生，关联成员选择或转换依据 |
| `skos:inScheme` | 自有 1；继承 0..1 | ConceptScheme IRI | 自有集合关联唯一自有词表；来源图的原归属不受此限 |
| `skos:member` | 0..n | Concept 或 Collection IRI | 普通集合成员；有序集合按列表投影，不表示概念上下位 |
| `skos:memberList` | 有序集合为 1 | RDF 列表 | 有限、完整、无循环，允许空列表；显式列表是项目完整性要求 |
| `iso-thes:subGroup` | 0..n | ConceptGroup IRI | 主体也须为 ConceptGroup；具有传递性，是 superGroup 的逆关系 |
| `iso-thes:superGroup` | 0..n | ConceptGroup IRI | 主体也须为 ConceptGroup；具有传递性，子组成员包含于上组 |
| `dcterms:created`、`dcterms:modified` | 本地各 0..1；来源不统一收紧 | 本地日期值或来源原值 | 本地记录时间与来源时间分别保留，不能只因多个值就任取一个 |

### 集合名称

本地概念组应有至少一个明确名称；可以采用普通首选标签，或独立 XL 名称及其投影。来源概念组使用 rdfs:label 或 XL 标签时保留原方式并明确对应，不因缺少某个输出属性就伪造名称。

数组的节点标签可选，一般集合也不一律必名。应用需要无名集合的导航标题时，由显示规则产生并标明其性质，不冒充已采用的词表名称。该区分参考公开交换模型中的 ConceptGroupLabel 与 NodeLabel；不是 SKOS 对所有 Collection 的必填要求。[ISO 公开 Schema](https://www.niso.org/schemas/iso25964/iso25964-1_v1.4.xsd)

### 分组扩展

采用 SKOS-Thes 时，ConceptGroup 和 ThesaurusArray 均为 Collection 的子类，二者互斥。`superGroup`／`subGroup` 只表达概念组之间的细分，不能用于把数组或任意集合挂到上组，也不等同于把一个子集合列为 member。

若 A 的 superGroup 为 B、B 的 superGroup 为 C，则该关系蕴涵 A 的 superGroup 为 C；子组成员须属于相应上组。校验结合类型、互反、传递与成员包含核对所声明的分组上下文，不能只检查直接边或把扩展当作不带约束的属性名。输出未采用该扩展时，来源声明保留在来源图与转换记录中，不作为普通集合关系混入主图。[SKOS-Thes 分组语义](https://www.dublincore.org/specifications/skos-thes/ns/)

概念组保留纳入依据与组间结构。通用集合视图未投影的信息须能回查；对象的业务用途见[关系与导航](设计-词表整体设计.md#关系与导航)。

自有领域分组的概念成员属于本词表，嵌套子集合须在本次数据中可定位；来源组的成员范围独立保留，不据此扩大自有收录。来源组同名不证明身份相同。

集合不能作为概念上下位、相关或映射关系的端点。空集合保留并提示，不自动补成员；概念可以属于多个组，成员变化不复制概念或改变其身份。

### 数组连接

来源数组保留所属结构、上层连接、成员、节点标签及原顺序，并记录原属性与来源版本。只提供通用 Collection 视图时，转换记录明确哪些连接没有进入主图及其回查位置。

上层连接不等于概念的上下位关系，也不能用概念组的 superGroup 代替。自有数组连接采用何种标准属性、怎样约束两端和校验，尚未形成完整采纳；在此之前不以自定属性填补，也不把通用集合字段宣称为完整数组合同。[待定事项](设计-词表整体设计.md#待定事项)

## 说明字段

说明可以附着于概念、名称、集合或词表，须保持其所描述的对象。定义不因名称指向某概念就自动提升为概念定义；范围说明不自动成为定义。

| 属性 | 数量 | 合同 |
|---|---|---|
| `skos:definition` | 0..n 个说明值 | 定义；来源附着于概念或名称时保留原位置 |
| `skos:scopeNote` | 0..n 个说明值 | 使用范围；词表与自建集合按各自字段表必填 |
| `skos:example` | 0..n 个说明值 | 所解释对象的使用示例 |
| `skos:note` | 0..n 个说明值 | 不适合归入更具体属性的说明 |
| `skos:editorialNote` | 0..n 个说明值 | 编辑提醒，默认保留在管理输出 |
| `skos:historyNote` | 0..n 个说明值 | 名称、含义或使用范围的重要历史 |
| `skos:changeNote` | 0..n 个说明值 | 具体变更，由维护记录派生说明或引用 |
| `dcterms:description` | 0..n 个文字值 | 一般描述，不替代定义或范围说明 |
| `rdf:value` | 本地独立说明为 1 | 一个带语言的正文值；来源已有多语或嵌套结构继续保留 |

需要分别记录来源或版本的说明建立独立记录；不同来源和版本不因文字相同合并。指向外部文献时核对引用和已有定位，不要求该文献在词表中具备 `rdf:value`。说明记录可使用来源与日期属性，不冒充 Concept 或 Label。单条本地说明的单值要求是项目选择。[SKOS 说明属性](https://www.w3.org/TR/skos-reference/#notes)

ISO 公开模型把 Definition 关联到术语记录，SKOS 说明属性未限制只能描述概念。保留原附着位置可避免丢失名称语境；只有核对确实适用于整个概念时，才采用为概念定义。[公开对应表，第 9 页](https://groups.niso.org/higherlogic/ws/public/download/12351/Correspondence%20ISO25964-SKOSXL-MADS-2013-12-11.pdf)

## 关系约束

主要维护方向与派生表达分别确定，不能建立两套互相独立的人工输入。

| 关系或表达 | 主要维护入口 | 派生与校验要求 |
|---|---|---|
| 直接层级 | `skos:broader` | 导入时同时识别原 broader 和反向 narrower，归一后对账；需要时生成 narrower，不能只删除源 narrower 导致关系丢失 |
| 顶层归属 | `skos:hasTopConcept` | 确定统一词表顶层后派生 topConceptOf；源中的两个方向均保留依据，不把“无 broader”自动当作顶层 |
| 概念组细分 | `iso-thes:superGroup` | 仅在采用扩展时使用；检查 ConceptGroup 两端、成员包含、传递及逆向 subGroup，不当作概念层级 |
| 名称通用联系 | `skosxl:labelRelation` | 两端为 Label，按对称语义读取；具体子属性另按其语义处理 |
| 概念替代 | `dcterms:isReplacedBy` | 从旧概念指向新概念，反向 replaces 派生；不将替代关系当成等价映射 |
| 相关关系 | `skos:related` | 同一对概念的联系只作一次决定；双向查询或输出由程序保证，不建立另一种“反向相关”字段 |

导入同时识别原关系的两向表达，归一后保留依据；派生冗余由程序生成并核对。词表归属、集合成员和概念关系的职责互不替代。

### 层级判据

自有分类法与叙词表的概念层级采用 ANSI/NISO Z39.19-2005 (R2010) §8.3 的业务判据。上下位所指概念须能进行同一基本类别内的逻辑比较；例如，学科与其研究对象不能仅因研究联系构成上下位。以下是项目明确采用的业务条件，不冒称 SKOS 的额外形式公理。[标准原文，印刷页 46–50](https://groups.niso.org/higherlogic/ws/public/download/12591/z39-19-2005r2010.pdf)

| 情形 | 采用条件 | 不成立或需区分的情况 |
|---|---|---|
| 种属 | 按所用概念定义，下位全部属于上位；上位涵盖该类成员 | 只有部分重叠、常见共现或在特定场景才成立，不足以形成种属关系 |
| 实例 | 下位是所指一般类别的一个具体实例 | 不能把具体实例当作一种类别，也不凭专名形式就断定是实例 |
| 整体部分 | 下位概念在不依赖临时情境的意义上内在地包含于整体；结合 §8.3.3 的范围与例子核对 | 不能把任意部件、装配关系或一般 isPartOf 自动改成层级 |
| 多上位 | 每条上位联系分别有逻辑依据，可属于不同的层级关系类型 | 上位数量不替代逐条判据，也不构成第四种关系语义 |

§8.3.3.2 以化油器可用于汽车以外机器为例，要求这对词采用相关关系；§8.3.4 又给出有依据的多上位和混合关系类型。两节须连读，不能机械地把“多个整体”或“多个父节点”作为一律拒绝或允许的条件。无法明确对应条款与概念范围时，保留待判断的具体关系，不补造统一阈值。例证见[层级关系](概述-层级关系.md)。

来源已有的细分类型及关系原样保留并注明出处；仅有 BT／NT 时不猜细分。目录位置、研究对象和词形不独自证明关系成立；来源结构的保存与其是否作为自有语义关系采用分别判断。上述业务判据不自动引入新的 RDF 关系属性，也不把概述文章或标准中的实例自动转成项目实体或概念记录。

related 与层级可达关系互斥。同级可以有明确的相关关系，但不能全部自动相连。层级环、自相关和集合循环按适用规则诊断；本地新增与固定来源异常分别处理，不冒称 SKOS 普遍禁止所有环或自关联。[相关关系](概述-相关关系.md#成立条件)

### 派生表达

所采用的 XL 名称按其角色投影为普通 `skos:prefLabel`、`altLabel`、`hiddenLabel`；有序集合按成员列表投影为 `skos:member`。投影由同一维护输入生成并校验，不另行手工覆盖。Turtle 解析本身不执行这些推导。

| 输出属性 | 值与数量 | 维护输入 |
|---|---|---|
| 采用 XL 的资源的 `skos:prefLabel` | 语言文字；数量与相应对象的名称要求一致 | XL 首选名称的文字值 |
| 采用 XL 的资源的 `skos:altLabel`、`skos:hiddenLabel` | 各 `0..n` 个语言文字 | 对应 XL 名称的文字值 |
| 有序集合的 `skos:member` | 概念或集合标识，`0..n` | 成员列表 |

## 映射字段

映射是可选合同，可放在独立图中，依据与采用状态由结构化记录保存。采用范围和应用条件见[映射记录](#映射记录)。

| 属性 | 数量 | 值类型 | 对应含义 |
|---|---|---|---|
| `skos:exactMatch` | 0..n | Concept IRI | 在广泛检索应用中可高度确信互换的对应；具有传递性，不等于 owl:sameAs，不合并双方全部属性 |
| `skos:closeMatch` | 0..n | Concept IRI | 在部分检索应用中足够接近、可以互换的对应；不是“不确定”的占位值，不作传递推导 |
| `skos:broadMatch` | 0..n | Concept IRI | 本端概念对应另一词表中更宽的概念，方向必须明确 |
| `skos:narrowMatch` | 0..n | Concept IRI | 本端概念对应另一词表中更窄的概念；与 broadMatch 互反，不维护冲突的两套决定 |
| `skos:relatedMatch` | 0..n | Concept IRI | 跨词表的相关对应，不代替等价或宽窄判断 |

目标可由独立来源图描述，但 IRI 必须能通过明确的来源记录定位，不要求校验器联网补全。原样复用同一 IRI 不增加自身 exactMatch。候选、暂缓、不采用及未确定关系不作为有效映射输出；明确自动规则只在原授权范围内复用。

映射须同时满足标准语义和项目使用条件。对称、互反及传递推导按[标准一致性](#标准一致性)检查，不由 RDF 关系自动产生跨用途、反向或中转使用许可。[SKOS 映射](https://www.w3.org/TR/skos-reference/#mapping)

## 映射记录

本合同规定两端均为单个概念的简单映射。一个概念可以有多条分别成立的映射记录，但不能因为目标有多个，就把它们擅自解释为共同成立的组合或任选其一。

下表列出必须能够确定的管理信息，复用概念身份、标准映射属性及已有版本、依据和采纳记录，不另行定义组合表达语法或交换本体。

| 信息 | 数量与含义 | 约定 |
|---|---|---|
| 记录标识 | 一个稳定标识 | 引用这项对应及其依据 |
| 源词表、目标词表及版本 | 两端各一组身份和明确版本 | 限定判断所用的上下文 |
| 源概念、目标概念 | 两端各一个概念标识 | 不用未经采用的表达式或虚构概念填充端点 |
| 映射属性 | 一项已明确的标准属性 | 按 exactMatch、closeMatch、broadMatch、narrowMatch 或 relatedMatch 的实际语义判断 |
| 用途、范围及允许方向 | 至少一个明确用途及其条件 | 区分浏览参照、查询转换及标引转换，不由逻辑对称性推导反向使用许可 |
| 适用版本与复核条件 | 明确适用的两端版本及变化条件 | 需要时补充时间范围；超出条件须复核 |
| 依据及采纳 | 相关依据和决定引用 | 保留判断理由与责任，不把候选或未确定关系输出为有效映射 |
| 修订历史 | 前后版本及已有变更记录 | 可共用批次上下文，冲突不能按读取顺序覆盖 |

两端的概念范围、关系语义、版本与采纳条件都成立时，才输出相应关系。仅适用于特定查询的替换不能提升为全局 exactMatch。消费者读不到用途限制时，不据此自动重标引或扩展查询；原标识保持不等于映射一直适用。[SKOS 映射](https://www.w3.org/TR/skos-reference/#mapping)

### 组合材料

跨词表组合映射尚未选定交换表示和完整消费合同，不属于上述简单映射的输入格式。来源已有的组合、运算含义、嵌套或共同使用条件按原表示及来源版本保留；不因本合同暂不支持而删去，也不拆成多条本来不能独立成立的 exactMatch。

词表内的复合等价与跨词表组合映射分别研究。已有扩展中的 CompoundEquivalence 可作为前者的核对对象，但须核对其词表范围、术语类型及与名称复用的相容性后再决定采用；不能直接作为任意跨表组合的编码。未采用的格式不进入自有正式接口，也不通过自定 AND／OR 字段和递归表达式补齐。[SKOS-Thes 复合等价](https://www.dublincore.org/specifications/skos-thes/ns/)

来源中的复合非首选入口及其多个首选词目标保留原义，不改成若干独立别名，也不为填充映射端点新造概念。需要实际交换或消费这类记录时，先完成标准及成熟方案核对，再按相应权限采用。

## 来源与依据

来源依据须能定位谁的哪个版本支持哪条陈述，以及经过什么处理。来源整体身份不能代替名称、定义或关系的具体依据。

| 记录 | 必需信息 | 约定 |
|---|---|---|
| 来源版本 | 来源身份、版本或可区分的快照标识、取得或访问依据 | 缺少上游版本时如实记录；可通过适用的完整性证据区分内容，不强制来源必须是一份文件 |
| 来源版本 | 可定位的内容或描述、已知取得时间、许可信息或未核说明 | 保留原始表示和取得条件；无法取得的内容须明示 |
| 依据 | 主体、属性、完整值及其适用版本 | 保留语言和数据类型，关系值明确目标身份 |
| 依据 | 外部材料及可核对的位置，或明确的本地判断 | 可采用记录标识、片段、查询条件或其他合适定位；不虚构原文位置 |
| 依据 | 处理规则、规则版本、判断理由及相应采用记录 | 区分原样继承、转换、本地判断和模型输出；共同依据可以被多项引用 |

`dcterms:source` 关联来源，`prov:wasDerivedFrom` 表示实际派生；各可多值，保留资源引用和已有定位。模型判断沿用[语言依据结构](../terminology/决定-语言依据结构.md)，不冒充外部资料。原样继承和批次授权按其范围留痕，不重新要求全量逐项审批。[PROV-O](https://www.w3.org/TR/prov-o/)

本地记录的创建时间与最近修改时间各为可选单值，采用有依据的 date 或 dateTime；概念和术语日期的这项选择有公开 ISO 交换模型参照。来源日期按原主体、版本、值及精度保留，可以有多个值；不得用本地单值要求静默取最大值、覆盖或补猜。采用某个来源日期描述本地记录时，必须说明二者对应关系。[ISO 公开 Schema](https://www.niso.org/schemas/iso25964/iso25964-1_v1.4.xsd)

原件路径、存储位置、字节哈希、算法和完整文件清单由适用的交付合同规定；数据模型要求版本可定位、内容可核对，不把这些文件方案当成所有来源的必需形态。

## 名称登记

登记保存来源、编辑或翻译任务与稳定名称身份的对应。名称文字、角色及依据仍由各自记录维护，登记不另设一份可独立覆盖它们的内容源。分配和修订条件见[名称编辑](设计-词表维护.md#名称编辑)。

| 关联信息 | 必须能确定的内容 | 适用条件 |
|---|---|---|
| 名称身份 | 保留的来源 Label IRI，或首次分配的本地名称 IRI | 同一记录的后续导入、重试与生成复用既有分配 |
| 来源对应 | 来源、所指资源及版本；无名称标识时的角色、完整文字及语言 | 初次辨认来源名称，并保留后续连续性的依据 |
| 编辑或翻译对应 | 产生该名称的编辑记录或翻译任务、所指对象与字段或角色 | 本地新增表达及译文；批次共同信息可以引用 |
| 连续性依据 | 同一记录的修订关系及理由，或无法确认连续性的待核原因 | 修改文字、语言或共享用法时，由维护规则判断 |
| 登记版本 | 本次发布或展示实际使用的登记快照及既有分配历史 | 当前名称与历史文字按各自版本读取 |

角色属于资源到名称的用法，登记中的来源角色只用于定位相应记录，不成为名称的全局角色。回退保持分配历史，身份不得转用于另一名称。

## 译文与复核

译文的形成事实和它对某个源版本的适用性分别记录。下表汇集[翻译流程](设计-多语言词表.md#翻译流程)已要求的信息；记录可以独立存放，通过对象、任务及版本明确关联。

| 记录 | 必须能确定的信息 | 关联约束 |
|---|---|---|
| 翻译任务 | 所指对象、字段或名称角色、源表达及版本、实际源语言、目标语言和用途 | 名称或说明保持原附着对象；任务范围不由缺译自动扩大 |
| 译文 | 对应任务、译文或保留原文的结论、材料依据、责任者及时间 | 采用独立名称时关联 Label IRI 和名称登记；文字语言及源表达可回查 |
| 批次依据 | 共用材料、实际模型和执行者、各时间的含义及所属批次 | 单条记录明确所属批次；非模型译文不补造模型信息 |
| 文字修订 | 被修订的记录与版本、修改前后文字、原因和依据 | 沿用变更记录，区分同一名称修订与新增表达 |
| 适用性复核 | 被核对的译文及版本、新源版本、结论、理由及本次核对记录 | 原翻译依据和时间保留；复核时间不冒充翻译时间 |
| 展示关联 | 词表基准、选用译文、名称登记、依据及适用性记录的版本 | 能从所显示名称回查对应记录；待复核提示随名称提供 |

名称登记、译文、复核和展示必须关联同一目标对象及所选表达，不能只按同文匹配。复核记录说明对哪个新源版本作出了何种判断；展示采用哪项结论可回查。复用保留原批次与依据性质，后续核验不改写原翻译事实，也不提升整批依据等级。

## 维护记录

采纳、变更、退出及交付分别记录事实，通过对象和版本关联。下表规定记录内容；触发条件与处理权限见[维护设计](设计-词表维护.md)，版本选择见[词表版本](../../governance/maintenance/设计-词表版本.md)。

| 记录 | 必须能确定的信息 | 关联约束 |
|---|---|---|
| 采纳 | 具体对象或值、依据、适用范围、结果、决定人和时间 | 可引用共同批次决定，效力限于原授权 |
| 变更 | 对象、适用版本、属性、前后值、原因、证据、责任者、时间与授权 | 新增或移除时一侧可空；解决决定固定其所依据的版本和具体值 |
| 退出 | 概念标识、事件与原因、依据及授权、发生版本、最后包含该记录的版本、已知后继对象及直接受影响引用 | 引用范围无法确认时明确记录；事件不合并成一个笼统状态 |
| 发布 | 实际采用的来源、本地数据、名称登记及译文版本、规则、执行信息和发布时间 | 能定位被检查和发布的内容，以及相关变更和采纳记录 |
| 交付 | 输出对象及版本、数据规范与规则版本、采用范围、适用交付合同、校验及转换结果 | 核对完整性、未投影内容和原因；文件表示由交付合同规定 |
| 应用加载 | 消费方实际加载的发布版本及结果 | 与发布记录分别确认，保留失败或版本落后事实 |

维护事件与发布摘要关联同一批实际变更，不维护两套独立事实。来源原样继承、批次共同依据和既有决定可以复用；未发生的历史不得补造。

## 历史与停用

historyNote 解释重要历史，changeNote 从维护事件派生具体变更摘要或引用，editorialNote 保存编辑提醒。日期、哈希和文字差异不能代替含义变化的依据。

停用及替代的属性、数量和含义见[概念字段](#概念字段)。退出事件与相关属性对应，后继对象按原身份引用；替代关系本身不表示概念等价或内容已经迁移。[OWL 停用注释](https://www.w3.org/TR/owl2-syntax/#Annotation_Properties)、[替代属性](https://www.dublincore.org/specifications/dublin-core/dcmi-terms/terms/isReplacedBy/)

停止收录、来源缺失、停用和合并拆分的条件见[概念退出](设计-词表维护.md#概念退出)，旧引用的读取规则见[历史读取](../../governance/maintenance/设计-词表版本.md#历史读取)。

## 来源兼容字段

来源描述保持原主体、属性、文字语言、数据类型与资源引用。下表说明属性用途和应保留的表示，不把某批输入曾使用的值类型当成标准的全部值域。

| 属性 | 数量 | 表示及处理 |
|---|---|---|
| `dcterms:title` | 0..n | 标题文字及原语言；与首选标签可同值也可不同，按实际含义保存，不强制相互派生 |
| `dcterms:identifier` | 0..n | 来源标识文字及原类型，不替代资源 IRI |
| `dc:creator`、`dc:contributor`、`dc:publisher` | 各 0..n | 来源中的文字或资源引用；分别说明创建者、贡献者和发布者，不自动转成自有元数据 |
| `dc:subject`、`dcterms:subject` | 各 0..n | 主题文字或资源引用；优先保留已有受控身份，不据此自动建立本地概念关系 |
| `dcterms:type` | 0..n | 类别资源引用或文字；保留已有受控类型，不用类别字符串代替 rdf:type 或本地分类决定 |
| `dcterms:format` | 0..n | 格式、介质或尺寸的资源引用或文字，如媒体类型字符串；不冒称自有输出的格式 |
| `dcterms:conformsTo` | 0..n | 标准引用及来源原有表述；自有符合性声明须有明确对象和证据 |
| `dcterms:language` | 0..n | 受控语言资源或 BCP 47 文字值；资源级语言声明不代替每条名称的标签 |
| `dcterms:isRequiredBy`、`dcterms:replaces` | 各 0..n | 按属性含义保留所指资源；来源文档替代与概念替代分别解释 |
| `dcterms:license` | 0..n | 优先引用许可文档；无法使用 URI 时可保留能识别许可的文字，不擅自变更许可 |
| `dcterms:rights`、`dcterms:rightsHolder` | 各 0..n | 分别为权利声明和权利持有者；保留资源引用或能识别对象的文字，不为格式统一造实体 |
| `dcterms:created`、`dcterms:modified` | 来源各 0..n | 保留原主体、版本、数量及时间精度；本地记录按独立日期约定处理 |
| `owl:versionInfo` | 0..n | 来源版本说明，不覆盖自有词表或工具版本 |

DCMI 的推荐表示与强制值域分开理解。例如 language 允许语言资源或 BCP 47 文字，subject、license、rightsHolder 等在相应条件下允许文字。不能把“推荐 URI”一律实现为“禁止文字”，也不能把来源的所有任意值都宣称为符合标准；异常保留原值并诊断。[DCMI Metadata Terms](https://www.dublincore.org/specifications/dublin-core/dcmi-terms/)

`dc:` 与 `dcterms:` 不做全局字符串替换。来源语言、创建者、权利和格式仍属于原资源；汇集数据不使自有词表继承这些事实。来源中的空白节点和嵌套结构保留，不因表格写有资源引用就强造 IRI。

`owl:imports` 可以保留为来源声明，读取和校验不据此自动加载其他图。仅作属性、类型、许可或文献引用的资源，不按缺字段的词条处理。任务等辅助对象的来源格式在适配合同中明确，不另设覆盖所有来源的任务类型。

## 校验范围

发布校验同时检查内容及其适用范围。来源原件、有效发布图、受限用途的诊断或保留材料分别标识；保存了原件或没有引入新错误，都不能代替对有效发布图的一致性判断。

| 检查范围 | 必须确定的内容 |
|---|---|
| 来源原件 | 固定版本、原结构、已有异常及转换去向；保留原值不宣称其正确 |
| 有效发布图 | 类型、字段、身份、语言、角色、关系、集合及所采用扩展的一致性 |
| 映射上下文 | 有效映射、两端版本及所需关系；不混入全部历史与未采用判断 |
| 多语言展示 | 语言标签语法、登记有效性与启用范围；任务源语言和目标语言、缺译及回退；词表、译文、名称登记、投影及适用性记录的相容版本 |

导入、编辑、翻译或自动合并可以产生待核结果；只有完成适用的完整性、标准语义与具体采用核对后，才能进入有效发布。各入口采用同一版本的适用规则，局部检查不能替代最终检查。材料不足时报告未完成，不以未发现错误冒充已验证。

### 标准一致性

| 规则 | 校验要求 |
|---|---|
| 核心类型 | 检查 Concept、ConceptScheme、Collection、Label 的互斥及 OrderedCollection 子类关系 |
| 普通及 XL 名称 | Label 单一文字值、标签角色互斥、按完整语言标签的首选文字唯一及 XL 投影；同文不同 Label 分别保留身份，不因资源数量增加而误报首选文字冲突 |
| 层级及相关 | 考虑上下位逆向、层级可达性与 related 互斥；相应映射子属性参与检查 |
| 映射 | 结合 exactMatch 的对称与传递、宽窄映射互反，检查 S46 等冲突，不把蕴涵关系当作新增用途许可 |
| 有序集合 | 成员列表完整性、顺序与 member 投影，不用文件中的语句顺序代替 |
| SKOS-Thes 分组 | 仅在采用扩展时检查 ConceptGroup 两端、与 ThesaurusArray 的互斥、传递、逆向及成员包含 |
| 名称间联系 | labelRelation 两端为 Label 且具有对称性；具体子属性按自身语义核对，不自动继承对称性 |

旧版已有的 exactMatch 与 broadMatch 冲突仍违反 S46；“本次没有新增冲突”不会使它变得一致。原异常可以留在来源或明确隔离的材料中，但不能靠历史豁免把含矛盾的有效图标为已通过标准一致性。[SKOS 关系与 XL](https://www.w3.org/TR/skos-reference/)、[SKOS-Thes](https://www.dublincore.org/specifications/skos-thes/ns/)

检查使用明确的图范围与所选规则所需的推导，不改写来源、编辑输入或采纳记录。不得把直接 broader 当作传递属性，也不自动加载任意本体。SHACL 不要求完整 RDFS 推理，实现可使用明确的校验视图或等价检查，但必须报告实际覆盖。[SHACL 推理说明](https://www.w3.org/TR/shacl/#entailment)

### 校验分级

| 问题 | 处理要求 |
|---|---|
| 有效图的语法或标准语义矛盾 | 无论新旧，未解决时阻止作为有效发布图交付；原件仍保留，不能静默删值使其看似通过 |
| 项目完整性或质量要求 | 按声明的对象和用途检查；来源缺名、未标语种等例外必须明确，不扩大为标准矛盾的豁免 |
| 来源原件异常 | 定位来源版本及具体陈述，保存诊断和处理依据；需要输出受限材料时明确用途与未满足项，不混作有效主图 |
| 歧义、依据不足或检查未完成 | 保留待核事实，不自动生成已采纳名称、关系或映射；发布取舍按明确用途及相应权限决定 |
| 转换损失 | 说明原信息、未投影部分及可回查位置；不能因原件保留而宣称无损 |

完整性例外改变的是项目的适用条件，不改变 SKOS 语义。标准一致性、SHACL 报告、项目是否放行及治理采纳分别报告，不能用一个“通过”掩盖差别。[SKOS 一致性](https://www.w3.org/TR/skos-reference/#conformance)、[SHACL 报告](https://www.w3.org/TR/shacl/#validation-report)

结构校验不证明领域内容正确、授权真实或知识覆盖完整。名称、定义、关系及映射仍须对应依据，实际内容和检索样本按[用途与验收](设计-词表整体设计.md#用途与验收)核对。
