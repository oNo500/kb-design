# 词表生成流程

自有词表从成熟来源取得概念和结构，经来源解析、字段转换、领域组织与自动校验生成。目标是一份可维护、可追溯的知识组织数据，用于内容标引、浏览检索和缺口检查。本文说明当前 RDF／SKOS 工程链路；节点和字段的具体合同见[词表数据规范](设计-词表数据规范.md)。

## 领域与来源

八个领域是自有词表内部的分组，六份来源提供概念和组织依据，两者是多对多关系。

| 领域 | 当前分组采用的来源 |
|---|---|
| 计算机科学 | IEEE、MSC2020 |
| 数学 | MSC2020 |
| 图书馆与信息科学 | UNESCO |
| 写作研究 | ERIC |
| 技术传播 | ERIC；IEEE 的专业传播分支暂仅作参考，不据此形成成员 |
| 学习科学 | ERIC、Cognitive Atlas；部分教学范围暂仅作参考 |
| 认知科学 | Cognitive Atlas、ERIC、PhilPapers |
| 哲学 | PhilPapers |

计算机科学优先填充内容，认知科学、哲学随后，其他领域按需展开。内容优先级不裁剪来源数据，也不决定概念是否保留。当前具体继承范围见[组织配置](../../../data/inputs/vocabulary/knowledge-system.json)。

## 工程阶段

| 阶段 | 工作 | 产物 |
|---|---|---|
| 领域确定 | 明确知识组织范围、用途和内容优先级 | 领域与用途说明 |
| 来源确定 | 比较覆盖范围、概念粒度、关系结构及维护条件 | 来源选择和领域对应 |
| 来源固定 | 保存已取得的原件，记录地址、版本、获取信息和哈希 | 可核对的离线快照 |
| 来源解析 | 读取原有名称、概念、代码、关系及分组，保留定位 | 来源结构化记录 |
| 来源词表生成 | 按各来源的实际含义转换为 RDF／SKOS；原生 Turtle 直接接入 | 六份独立来源词表及各自诊断 |
| 自有词表生成 | 执行字段规范化、语言过滤和领域规则，统一词表成员 | 一份自有词表和八个领域分组 |
| 校验与发布 | 检查字段、关系、身份、来源去向及产物完整性，成功后切换入口 | 构建版本、对账报告及 current |

解析方法随来源格式变化：IEEE 从 PDF 提取结构化记录；MSC2020 读取 TSV；ERIC 读取 ZIP 内的 XML；Cognitive Atlas 读取 API JSON；PhilPapers 读取缓存 JSON；UNESCO 读取原生 Turtle。已有来源词表可以直接进入自有词表生成，不必每次重新解析原件。

## 数据归属

| 对象 | 职责与位置 |
|---|---|
| 来源快照 | 来源事实的 SSoT，由 kb-sources 保存原始取得记录及文件 |
| 来源词表 | 六份来源的 RDF／SKOS 表达，原始身份和问题分别保留 |
| 项目组织输入 | `data/inputs/vocabulary/` 中的组织配置、来源锁定与 SHACL 规则 |
| 明确的项目取舍 | 通过结构化配置或相应采纳记录进入生成过程，不直接修改产物 |
| 自有词表 | 派生产物，版本位于 `output/vocabulary/versions/`，稳定入口为 `output/vocabulary/current/` |
| 实际知识内容 | 单独维护，应用通过概念 IRI 关联；不混入词表节点的定义 |

来源快照说明来源实际提供了什么，项目配置和采纳记录说明如何采用。人工或 AI 的调整均须进入可追溯输入，再由生成器执行，不绕过工程链路改写结果。

主图只保留中英文及其语言变体的文字；未标语言的原值、代码、日期和标识保留，不自动猜测语种。原件和来源 Turtle 的字节副本完整保存，过滤及转换有记录，不能声称规范化主图仍包含全部原始三元组。

## 组织结果

自有主词表包含一个 ConceptScheme。八个领域使用 Collection，通过 member 引用概念；所有概念都通过 inScheme 属于同一自有词表，包括尚未归入领域分组的概念。

同一概念可以属于多个分组。跨来源尚未确认对应的概念保持独立身份，不因名称相同自动合并。现有交叉候选只作按需线索，不是全量生成的前置任务。

概念、分组与来源原有上下位关系分别处理。程序归一已有互反关系，不猜测新的学科层级，不补造译名、历史、停用或替代值。没有内容、没有名称或没有领域分组的来源概念继续保留；可用性问题在报告中明确列出。

## 校验与发布

来源的真实问题与规范化输出的问题分开报告。独立对账器将来源语句、转换记录和实际投影逐条核对：应保留的语句不能丢失，过滤必须符合规则，派生关系必须有原始语句支持；生成器自己的计数不能替代这项检查。输入哈希、概念身份、图约束、SHACL 和 Turtle 往返分别检查其他失败。可继承的来源缺项作为明确警告保留，阻断错误不得成为当前版本。

校验成功后，将新构建保存在版本目录，再原子更新 current。失败时旧入口不变，历史版本保留。应用一次读取多个文件时先解析 current 指向的版本，避免混读两个版本。

从仓库根目录执行全量生成：

```bash
uv run kb-vocab build-system \
  --config data/inputs/vocabulary/knowledge-system.json \
  --output-root output/vocabulary
```

每次使用新的构建版本；不需要手工改日期目录。产物包含完整词表、组织声明、领域分图、未分组数据、来源副本、字段转换记录、迁移记录、校验报告及构建清单。归档同时保存原配置和可重放配置，后者引用包内来源与规则；移动整个版本目录后可独立读取输入重建，归档附带工具代码、依赖版本和环境恢复命令，仍需可用的 Python 与依赖获取条件。ERIC、IEEE 和 Cognitive Atlas 已支持明确来源键的 URI 复用，缺失旧键时停止；发布同时比较上一版概念身份与字段变化。具体命令和文件合同见 [kb-vocab README](../../../packages/kb-vocab/README.md#词表构建)。

## 覆盖检查

```text
[自有词表] + [内容关联记录]
             |
             +--> 哪些已有主题尚无内容？

[自有词表] + [CS2023 等知识覆盖依据]
             |
             +--> 哪些知识尚未被词表覆盖？
```

第一条检查内容填充，第二条检查词表的表达与组织覆盖，两者不能互相代替。CS2023、IFLA、CWPA、tekom 等文献的后续覆盖建模仍暂缓，不将其目录直接当作概念层级。

当前生成链路已跑通，但应用接入、内容填充和知识覆盖验证不是同一项完成状态。部分来源版本或访问渠道仍有待核事项；PhilPapers 当前使用第三方缓存，不能因文件有哈希就宣称已经核实官方版本。

## 当前基线

第 3 版规范的本次全量构建保留 30,352 个概念，其中 14,919 个进入至少一个领域分组，15,433 个尚未分组但仍属于自有词表。输出没有阻断错误，三个来源缺项作为警告保留。更新后的数量以[当前构建报告](../../../output/vocabulary/current/report.json)为准，不手工修改派生统计。

来源选择的持续记录见[项目简报](../../../packages/kb-sources/项目简报.md)，字段与维护规则见[词表数据规范](设计-词表数据规范.md)，当前数据入口见[构建结果](../../../output/vocabulary/current/index.md)。旧 YAML 消费者尚未自动切换，不能把当前词表构建成功视为全部应用已经迁移。
