# 词表维护设计

## 操作场景

来源同步和本地编辑共用生成、校验、发布及应用同步。来源快照保持原样；当前词表由可配置的来源选择与本地编辑共同生成，不直接修改 `vocabulary.ttl`。

| 场景 | 入口 | 行为 |
|---|---|---|
| 来源清单变化 | `kb-vocab sync` | 根据清单纳入或退出整份来源，计算指纹，调整已失效的分组引用并重建 |
| 获取或解析新版 | `kb-vocab sync --refresh-source NAME` | 按该来源登记的获取、提取和导入适配器执行，复用已知身份 |
| 本地增删改 | `kb-vocab edit apply FILE --reason REASON` | 保存批量编辑，再从已归档的来源重建，不下载或重新解析原始资料 |
| 暂存本地编辑 | 编辑命令加 `--record-only` | 只保存编辑意图；随后执行 `sync --local` 批量生成 |
| 失败重试 | `kb-vocab resume` | 复用已完成的来源准备；词表已发布时只重试应用同步 |

`--no-apps` 可明确跳过应用更新。来源名称是稳定的登记键，改名按来源退出和新增处理。当前入口支持既有适配器，不把未知 PDF 或任意网页自动解释成词表。

## 数据职责

| 文件 | 职责 |
|---|---|
| `data/inputs/vocabulary/maintenance.json` | 配置入口、输出位置及应用目标 |
| `sources.json` | 当前希望同步的来源、已有 Turtle 和可选刷新流程；移除条目即表示该来源退出 |
| `knowledge-system.json` | 自有词表和领域分组规则；同步器派生实际来源指纹及有效分组引用 |
| `local-edits.json` | 本地编辑的唯一当前记录，含修订号、编辑前的来源值和修改历史 |
| 构建的 `upstream.ttl` | 本次来源及组织规则形成的未编辑基线 |
| 构建的 `vocabulary.ttl` | 应用本地编辑后的一份当前词表 |
| `local-effects.json` | 本地新增、删除、字段变化与来源退出造成的引用清理 |
| `output/vocabulary/operations/` | 操作请求、输入快照、状态、冲突与应用结果 |

原始文件、旧构建和已退出来源的历史快照不是本地编辑目标。物理清理与停止同步分开；同步器不会因为清单变化直接清空历史目录。

## 来源选择

来源条目可配置 `selection`，其中 `roots` 是准确的来源概念 URI，`descendants` 决定是否包含全部下位概念。未配置时保留该来源的全部概念。根概念不存在时拒绝构建，不按名称猜测替代项。

过滤只作用于该来源进入自有词表的贡献，原始 Turtle 副本保持完整；其他来源仍支持的同一 URI 不随之删除。指向不再收录概念的关系按规则移除，去向写入 `source-selection.json`，再对过滤结果执行正常转换对账。领域成员由完整来源结构与选择范围共同确定。

当前 ERIC 采用[收录范围决定](决定-ERIC收录范围.md)：15 个根概念及全部下位概念，当前共 44 个概念。改变选择范围不会把已经刷新的来源退回旧快照。本地编辑仍在选择结果上应用；引用被排除节点的本地修改会报告冲突。

## 编辑粒度

编辑文件是 JSON 操作数组。概念、集合及其字段使用 RDF URI；值使用 RDF 的 N3 写法，由 RDFLib 解析。支持中英文文字、URI、类型化字面值和批量操作，不使用任意 SPARQL UPDATE。

| 操作 | 对象 | 含义 |
|---|---|---|
| `create` | Concept 或 Collection | 显式创建本地节点，提供稳定 URI、类型和字段 |
| `set` | 属性，可限定语言 | 替换选定属性或语言的全部值 |
| `add` | 属性值 | 增加名称、关系或分组成员等值 |
| `remove` | 属性值 | 移除指定值，保留其他值 |
| `delete` | 节点 | 排除节点及其引用，持久保存删除意图 |

例如从集合中移除成员只删除 `skos:member`，不会删除概念。关系变更同时维护已定义的反向表达。主体 URI 不能通过字段修改；类型和词表归属由创建及生成管理。匿名资源不作为直接编辑身份，复杂说明资源应使用稳定 URI。

编辑记录只说明本地意图和来源，不自动证明术语准入或外部事实成立。界面将本地新增名称标为本地编辑；不会把它标成来源原文、已核外部术语或 AI 翻译。

## 再同步规则

字段编辑保存编辑前的来源值、本地目标值和最新来源值，用三方比较处理后续同步：

- 来源未改变该字段时，保留本地修改。
- 来源与本地得到相同值时直接通过。
- 不同属性、不同语言以及不冲突的值增删可以共同保留。
- 同一字段出现不兼容变化时报告冲突，停止发布；不会静默选择来源或本地值。
- 本地删除记录继续有效；来源重新出现同一身份不会直接使节点复活。节点内容发生变化时可要求明确解决冲突。
- 本地新建节点不会随来源退出被删除。若其关系目标退出，或被修改的来源节点消失，会报告失效引用或目标缺失。

同一 URI 由多份来源提供时，移除其中一份不会删除仍被其他来源支持的身份。相同名称或近似映射不自动视为同一 URI。来源内部无法判断的身份变化仍受现有适配器和身份丢失门禁限制，不自动猜测改名、拆分或合并。

## 冲突处理

失败操作保存 `conflicts.json` 和 `incoming.ttl`。冲突绑定编辑内容指纹，过期的冲突不能覆盖后来修改的编辑。

```bash
uv run kb-vocab edit resolve PATH/TO/conflicts.json \
  --id EDIT_ID --choice local --reason "保留本地修改"
```

`local` 为字段或节点内容冲突更新比较基线，继续保留本地意图；`source` 撤销对应本地编辑。目标或关系已不存在时，不能只选择本地值来制造有效身份，须显式调整关系、建立所需本地节点或撤销该编辑。多项冲突可先用 `--record-only` 处理，随后 `resume` 继续原操作，复用已准备的新版来源。

`edit undo EDIT_ID --reason REASON` 撤销一项当前编辑。`--expected-revision` 提供乐观并发检查；`--dry-run` 只预览批量编辑结果，不写入。

## 发布与恢复

本地编辑的修订原子写入；每次生成保存其完整快照。图校验、SHACL、来源对账和身份检查通过后才切换词表入口。失败不会覆盖当前可用词表，失败的编辑意图仍可检查、修改或撤销。

应用同步在词表发布后执行。应用失败明确记录为 `application-failed`，不声称已同步；重试无需重新下载、解析或发布词表。已经匹配的应用副本通过实时核对后不重复导入。两个应用副本不承诺同时无中断切换。

已有中文展示标签仅在 URI 和英文名称仍适用时沿用。被移除或英文已变的条目不沿用旧译文；新增的待翻译条目明确记录，不自动调用 AI。

归档包含未编辑基线、本地编辑记录、来源、配置和运行材料，可以重放。进程异常退出可能留下写锁；必须确认没有活动写入者再清理，不宣称操作系统崩溃持久性。
