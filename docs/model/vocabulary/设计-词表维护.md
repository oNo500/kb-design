# 词表维护

本专题规定词表怎样收录、编辑、更新及退出对象。每次变更保留稳定身份、修改理由和相应采用依据。记录字段集中在[数据规范](设计-词表数据规范.md)；译文适用性由[多语言词表](设计-多语言词表.md)展开，发布与历史读取由[词表版本](../../governance/maintenance/设计-词表版本.md)规定。

## 维护职责

| 责任 | 输入与职责 | 边界 |
|---|---|---|
| 来源维护 | 固定来源版本，识别身份、内容及组织变化 | 不覆盖原件或冒充来源作出停用决定 |
| 内容编辑 | 提出概念、名称、关系及分组的具体变更，提供依据 | 编辑记录不自动成为已采纳内容 |
| 名称登记 | 维护来源名称与本地名称身份的连续对应 | 不决定译文正确性或接管术语准入 |
| 审核与采纳 | 核对含义、用途、依据和授权，作出具体决定 | 不由生成器、相似度或字段合法性推导采纳 |
| 发布与消费 | 核对完整性、固定版本、交付相容数据并记录加载结果 | 词表发布与应用采用分别确认 |

项目维护流程按[整体采纳](决定-词表整体设计.md)及[维护约束](决定-词表维护约束.md)执行。业务对象参照 ISO 25964 公开模型，表示与一致性采用 SKOS／SKOS-XL；以下职责和流程是项目选择，材料核读边界见[标准依据](设计-词表整体设计.md#标准依据)。

## 变更记录

编辑、语义采纳及发布是不同事实。变更记录定位原对象和基准版本，明确修改意图，并关联具体依据和授权；字段、引用及退出记录的完整要求见[维护记录](设计-词表数据规范.md#维护记录)。

概念含义、名称文字、角色、成员及来源变化分别判断。来源原样继承与批次共同依据可以共用记录，效力仍受原范围限制。维护事件供发布摘要引用，日期或文字差异本身不构成含义变化的结论。

## 来源选择

收录须有明确范围与依据，能够说明采用哪些来源概念、关系及组织信息。按根及下位范围选择时，根须由准确身份确定；补入祖先须有来源中的真实关系，不按名称猜测，也不自动扩展到其他分支。

筛选只改变来源对综合词表的贡献，保留完整来源快照及每项排除的去向。同一身份仍由其他来源支持时，不能仅因某份来源退出就删除；本地新增对象也不随来源退出而消失。关系或编辑依赖的对象不再收录时，须核对失效引用并处理冲突。

具体领域、语言与来源范围由相应决定限定。选择规则可以执行和结果可以计数，不证明语义挂接正确或知识覆盖完整。

## 编辑粒度

| 变更 | 编辑对象 | 要求 |
|---|---|---|
| 建立记录 | 已采用的概念、名称或集合 | 明确类型、稳定身份、字段及依据 |
| 修订字段 | 指定记录的属性及必要的语言范围 | 保留原值、修改意图和版本，核对共享引用 |
| 增减关系 | 概念关系、名称角色或集合成员 | 明确两端及成立依据；派生表达与维护输入保持一致 |
| 调整名称 | 文字、语言或首选角色 | 区分同一记录修订和新增表达，按名称登记处理 |
| 退出或恢复 | 停止收录、停用、合并、拆分或重新收录 | 按事件区别处理历史与旧引用，不能用通用删除掩盖原因 |

移除集合成员不会删除概念。修改关系须维护其语义相关的反向或对称表达；身份不能通过改文字字段隐式替换。RDF 图中仍可保留说明或列表的空白节点，需要持久编辑和引用的本地记录应使用可稳定定位的身份。

### 名称编辑

导入、人工编辑和翻译使用同一名称登记；登记保存身份对应，各来源与编辑入口负责内容。记录及版本关联见[名称登记](设计-词表数据规范.md#名称登记)，角色和值的约束见[语言与名称](设计-词表数据规范.md#语言与名称)。

| 操作 | 编辑责任 | 身份与结果 |
|---|---|---|
| 导入来源名称 | 提交所指资源、角色、完整文字、语言与来源版本 | 保留来源名称身份；没有身份时登记一次，后续按连续性证据复用 |
| 修订已有名称 | 明确名称 URI、基准版本、修改文字及依据 | 同一记录修订保留 URI；共用名称先核对全部引用，必要时分立 |
| 新增表达 | 说明表达、所指资源、语言、角色及依据 | 分配另一名称身份；不同语言表达分别登记，同文不自动合并 |
| 切换首选或别名 | 修改资源到名称的角色关系 | 保留名称 URI，不把角色写成名称的全局状态 |
| 新增或修订译文 | 按[翻译流程](设计-多语言词表.md#翻译流程)提交结果或修订依据 | 沿用同一登记，关联对应任务、译文及适用性记录 |
| 普通标签兼容输入 | 定位资源、角色、完整语言标签及名称 URI | 唯一定位且意图明确时才可处理；同文多记录不得任取或默认全部修改，`zh` 不作为所有 `zh-*` 的批量指令 |

首次分配与来源、编辑或译文记录共同保存；重试和重复生成复用已有分配。确认属于同一记录的拼写或格式修订保留身份，无法确认连续性时保留新旧记录及待核原因，不凭文字相似度裁决。旧写法是否继续作为别名，另按检索需要和具体采纳判断。

词表和集合的普通标签可以直接维护；采用 XL 的名称通过独立记录编辑，普通标签为投影。兼容入口不得独立覆盖 XL 输入；修改后重新核对投影及角色冲突，同文记录分别保留来源和历史。正式术语的准入与编辑权仍按[术语设计](../terminology/设计-术语.md)处理。

### 标识策略

稳定且不依赖可变文字是身份要求；UUIDv4 是本项目已采用的具体分配方案。新增本地名称使用 `urn:uuid:` 加 UUIDv4，使分配不依赖名称、层级或 HTTP 托管位置；按标准生成并由登记检查和持续复用，不重新随机分配。[RFC 9562 §4、§5.4、§6](https://www.rfc-editor.org/rfc/rfc9562.html)

这一方案服务于独立分配与持久引用，不是 SKOS 唯一允许的 URI 形式。来源已有身份和已分配本地身份继续保留；不能因为后来选择另一种发布方式而批量改号。

需要在 Web 上直接取得资源描述时，应另行说明可解析 URI、描述地址或解析服务与既有身份的对应。URN 本身不承诺 HTTP 可解析；W3C 的 HTTP 发布指引与本地标识分配分别适用，不据其中一种方案否定另一种合法身份。[Cool URIs](https://www.w3.org/TR/cooluris/)

## 来源更新

来源更新须同时保存本地修改所依据的描述、来源的新变化及本地意图，使冲突能够解释和复核。目标不限定必须使用三方比较、重放或某种差分算法；所选方法都须满足以下条件。

| 情形 | 处理要求 |
|---|---|
| 来源未改变相关描述 | 保留仍适用的本地修改及原依据 |
| 来源和本地得到相同值 | 可复用该字段结果，但不因此免除名称、关系及依赖的一致性检查 |
| 不同属性、语言或值的变化 | 先形成待核组合，再检查相互约束；不能只因字段不同就认定语义独立 |
| 来源与本地不兼容 | 报告基准、变化、意图和受影响对象，不静默任选一方 |
| 对象缺失或关系端点退出 | 核对其他来源、保留的本地对象及引用；明确解决失效关系 |
| 已明确停止收录的对象重新出现 | 保留退出决定，未经恢复决定不自动重新采用 |

每次协调结果都须重新检查完整输出及必要语义依赖。例如，两个属性分别新增名称，也可能共同造成首选与别名文字冲突；值比较相容不代表标签或映射语义相容。

同一身份仍受其他来源支持时不因一份来源退出就删除，但具体属性和关系仍须按其依据判断。记录连续性不明时保留问题，不猜测改名、拆分或合并。

影响判断以记录中的明确依赖为依据，定位受影响的名称、译文、映射和分组，保存原因与处理结果。定义、范围、关系或成员变化分别核对实际依赖；关系与成员变化还须核对来源选择闭包、领域挂接、导航及依赖其上下文的映射。没有证据的邻接关系不扩大为全部语义邻居重审，依赖资料不足时如实说明。

文字变化不自动证明含义变化。相关内容未变时可以按原条件复用判断，保留原证据版本并另记本次适用性；译文复用、待复核和失效的完整条件见[增量同步](设计-多语言词表.md#增量同步)。停止收录、来源退出及合并拆分转入下节处理。

## 概念退出

退出处理必须说明发生了什么，以及旧引用如何读取。使用现有停用、替代属性和配套变更记录，不把不同事件压成一个无来源说明的删除动作。

| 情形 | 当前词表的处理 | 旧引用与依据 |
|---|---|---|
| 本地停止收录 | 可从主图排除，并清理该次输出中失效的关系和成员 | 保存原标识、退出版本及收录决定；不能声称来源已停用该概念 |
| 来源退出或新版不再提供概念 | 核对其他来源、本地编辑和引用依赖，再决定是否继续收录 | 保存来源版本与缺失事实；缺失原因不明时不自动写 `owl:deprecated`，也不按同名换标识 |
| 已明确停用 | 根据依据保留停用说明；从新标引候选中排除 | 旧标识仍能返回停用记录或历史说明，有替代对象时列明但不自动改标记 |
| 概念合并 | 按具体采纳确定保留或新建的身份，并记录旧身份到后继对象的关系 | 保留原范围与历史；逐项判断旧内容是否适合转移，`exactMatch` 不代替迁移决定 |
| 概念拆分 | 保存原概念与多个后继对象的区别和适用条件 | 旧引用继续指向原历史记录，不能默认任选一个后继，也不能自动扩展为全部后继 |

退出事件按[维护记录](设计-词表数据规范.md#维护记录)关联版本、原因、后继与受影响引用。引用消费者缺失或范围无法确认时明确记录；清理图内引用不等于外部内容已经迁移。

未指定版本和指定版本的读取顺序统一见[历史读取](../../governance/maintenance/设计-词表版本.md#历史读取)。本地排除、来源事实和旧内容迁移分别留痕；恢复收录也须有明确的撤销或恢复决定，不能仅因来源再次出现同一 URI 就恢复已经明确退出的本地对象。

物理清理历史文件另按治理权限决定，不随上述事件执行。当前图可以不再收录对象，但保留的历史描述、退出原因与后继说明必须能被读取；仅保存名称、来源快照或归档不足以满足历史读取要求。

## 冲突处理

冲突须能定位比较基准、最新来源、本地修改、受影响对象及原因。解决决定关联被比较的版本和具体值；过期结论不得覆盖后续修改。

保留本地值、采用来源值或形成新的修订分别说明依据。关系目标消失时，不能仅选择保留本地值就声称引用有效；须明确恢复有依据的对象、调整关系或撤销修改。对象身份、类型或含义不确定时保留问题，不用自动合并掩盖。

编辑提交须能发现并发修改。失败重试只复用内容和依据仍相容的结果，不能重复分配身份或重复采用已经失效的决定。实践中无法满足的要求按问题记录与研究流程处理，不直接降低设计约束。

## 发布交接

编辑和来源协调产生待核结果，经具体采用与[统一校验](设计-词表数据规范.md#校验范围)后，交给版本发布流程。交接结果能够定位来源、本地编辑、名称登记、译文、依据和适用规则；所需记录见[维护记录](设计-词表数据规范.md#维护记录)。

校验或发布失败时保留可用版本，并保留可继续修订的编辑意图和错误原因。发布、切换、加载及回退按[版本合同](../../governance/maintenance/设计-词表版本.md#发布与回退)处理。锁、原子写入、进程恢复和具体同步顺序由实践方案落实，并说明其实际保证范围。
