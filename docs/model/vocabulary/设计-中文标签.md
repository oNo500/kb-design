# 中文标签

## 适用范围

中文展示以 `output/vocabulary/current/vocabulary.ttl` 为翻译的唯一基准（SSoT）。该文件由词表生成器维护，决定对象身份、英文名称、关系和分组；翻译不反向修改基准。基准以英文为主，已有中文保留，不为翻译删除。

当前批量翻译只处理现有 Concept、Collection、ConceptScheme 缺失的中文首选名，不翻译别名、定义、范围说明或任务记录。AI 初译用于展示，暂不要求逐项核对权威中文术语；后续可针对指定对象补充来源或修订译文，不自动取得正式术语准入效力。

## 基准与产物

| 文件 | 职责 |
|---|---|
| `output/vocabulary/current/vocabulary.ttl` | 当前英文基准入口；每次同步固定到具体版本及哈希 |
| 任务目录中的 `tasks.json` | 从基准提取对象 URI、字段、英文原文及任务 ID，不能自行新增词表对象 |
| 批次输入与输出 | 输入提供待译词汇及必要上下文；输出按任务 ID 提供中文或保留原文的结果 |
| `translations.zh.ttl` | 从当前有效译文生成的中文增量，不人工维护第二份译文 |
| `vocabulary.multilingual.ttl` | 当前基准与中文增量合并的双语产物，不覆盖英文基准 |
| `label-provenance.json` | 目标词表、基准哈希、批次元数据及标签到批次的关联 |

对象对应以稳定 URI 为准；字段和目标语言限定具体译文。名称相同不表示对象相同，不按英文名称或文件中的排列位置复用译文。本轮批译结果位于 `packages/kb-vocab/output/translation-run/result/`，这里的“结果”不表示权威术语已核定。

## 增量同步

同步规则是：**删除没有的，翻译增量，已有译文不重译。**

| 当前基准与已有结果的差异 | 同步行为 |
|---|---|
| 对象仍在，且已有中文译文 | 按 URI 复用译文及其原批次元数据，不再次调用模型 |
| 对象仍在，但基准和已有结果中都没有中文译文 | 提取为增量翻译任务；已明确保留原文的处理结果不自动重复尝试 |
| 对象已不在当前基准中 | 从当前中文增量及新双语产物中移除；保留历史版本和批次文件 |
| URI 不变，英文名称、定义或范围变化 | 保留已有中文，可输出变化提示，不自动重译；修订须单独指定 |
| 关系或分组变化 | 使用当前基准的结构，已有中文继续复用，不因结构变化重译 |
| URI 改变 | 按旧对象退出、新对象进入处理；不凭同名推定继承关系 |

基准已有中文时不由 AI 译文自动覆盖。若与历史译文不同，应明确处理该冲突，不以文件读取顺序决定名称。

删除只作用于派生的当前中文和双语产物，不删除英文基准文件、来源材料或历史批次。重新合并应从当前基准生成，不能在旧双语文件上只追加，否则会残留已删除对象或旧关系。

## 批次元数据

每批只保存一份翻译者类型、实际模型标识、agent、时间、输入输出哈希，以及翻译所依据的基准版本；每条中文关联批次，不重复填写模型与时间，不建立逐条审批流程。

模型信息由执行程序按实际调用记录，不让 agent 猜测。多个 agent 或补做批次参与时保留实际归属。时间注明是输出文件写入时间，不把后续合并时间冒充原翻译时间。

复用译文时保留原批次信息；新双语产物另记录本次合并使用的基准，不能把旧译文的来源版本或时间改成最新一次同步。后续权威资料及修订依据关联具体对象和字段，不把整批 AI 译文自动升级为已核实术语。

## 合并与展示

合并前检查基准版本、任务 ID、对象 URI 和待译字段是否对应，检查漏项、标签冲突与明显英文占位。保留原文的项不生成空中文，也不把英文标成 `@zh`。同语言首选名唯一与标签属性互斥继续遵循[词表数据规范](设计-词表数据规范.md#名称规则)。

合并只增加适用的中文标签，节点身份、英文内容及关系均取自当前基准。校验成功后，成套更新中文增量、双语文件、批次元数据和应用展示；失败时继续使用上一套可用产物，不显示半更新结果。

应用读取同一版本的双语数据与元数据，可显示中文、英文或中英对照；缺少中文时回退英文。Skosmos 在名称附近显示 AI 翻译及模型提示，详情提供批次、agent 和时间。界面菜单翻译仍由应用维护。旧 Obsidian YAML 消费者不因双语文件存在而自动迁移或同步。

## 实现状态

已实现固定基准提取、分批翻译、批次合并、中文增量与双语文件生成，以及 Skosmos 的独立中文展示入口。操作命令见[批量翻译脚本](../../../packages/kb-vocab/scripts/README.md)。

上述增量同步规则已确定，**跨基准版本的差异比较、历史译文复用、删除清理及统一切换尚未完整接入脚本**。当前提取器只检查传入基准是否已有中文，不读取历史译文库；不能把重新提取全部缺失中文当作增量同步。本次文档更新不表示这些能力已经实现。

## 兼容接口

原有逐项采纳接口继续保留，但不用于当前快速 AI 批译。它使用 `data/inputs/vocabulary/labels.zh.ttl`、`label-adoptions.json` 和现有书目；组织配置的可选 `labels` 项指定 `file`、`adoptions`、`bibliography` 路径。

该接口中，标签文件是补充中文的编辑源；采纳 JSON 使用 schema_version 1 和 records，每条包含 id、accept、uri、property、language、label、original、basis，可带 reason。只有 accept=true 且与标签具体值一一匹配的记录生效；original 由 `kb-vocab label-context` 生成，绑定对象类型、英文标签和完整本地说明。上下文变化会阻断这个旧接口的构建，**不作为批量增量同步自动重译的规则**。

旧接口按[语言依据结构](../terminology/决定-语言依据结构.md)区分外部第 1–4 级与模型第 5 级。外部 references 使用书目 ID 和定位，第 4 级至少两个不同来源；模型记录 name、date、rationale、approval，并标明外部用法未核实。结构校验不认证授权真实性、语义对应或来源独立性。历史保留为 accept=false，来源已有名称不按读取顺序覆盖。

旧接口的 build-system 在校验前合并标签，领域分图共享结果；manifest 版本 5 保存标签、采纳和书目快照，支持搬动后的重放及版本回滚。其逐项 provenance 与当前批次元数据分开，不把旧接口的空输入状态解释为本轮批译尚无产出。
