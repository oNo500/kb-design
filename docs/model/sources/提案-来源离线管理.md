# 来源离线管理

状态：独立 package 的方向已确定，其余工程合同待采纳。本文规划公开材料获取、受限材料手动导入、离线保存、核对与更新；不表示相应命令、schema、目录或下载已经实施。

## 建设目标

为知识体系建设提供可维护、可核对、可校验的原始材料。Computer Science 是当前内容重点，Cognitive Science 和 Philosophy 是下一阶段内容重点；其他领域按需填充内容。上述优先级不减少已确定领域的来源准备和词表覆盖要求。

来源完整性相对于明确的版本和材料清单判断。PDF 可打开、哈希一致或目录提取成功，不能单独证明领域知识覆盖完整。

## 方案选择

| 方案 | 做法 | 影响 |
|---|---|---|
| 原文直接纳入 Git | 原始文件与代码一起提交 | 获取简单，但大文件、访问权限和再分发条件混入项目历史 |
| 本地持久原文与可追踪清单 | 原文单独持久保存，获取配方、快照清单及选择记录由 Git 管理 | 适合公开与手动取得的材料共存，需要备份和缺失检查 |
| 立即部署资料服务 | 引入独立存储与在线管理服务 | 当前增加部署、认证和运维工作，尚无必要 |

建议采用第二种。先建立仓库内工具与本地文件合同，不新增服务器或资料平台。

## 职责边界

| 对象 | 职责 |
|---|---|
| `kb-sources` | 公开获取、手动导入、离线原文保存、快照核对、差异比较及定位提取 |
| 获取配方 | 准备取得哪些文件、从哪里取得、预期版本与取得方式 |
| 快照清单 | 某次实际取得了哪些原始字节、何时取得、文件位置和完整性证据 |
| 提取结果 | 从指定快照提取的文字、表格、代码与位置，不替代原文 |
| 重新设计的主题生成器 | 按文件合同读取明确快照和采纳输入，建立词表节点与关系 |
| 现行书目、来源用途登记及旧代码 | 保持现状，作为现行系统和重设计的参考，不参与新包的隐式运行依赖 |

新包记录的是材料身份及实际取得事实，不承担现行书目或来源用途的编辑权。若某材料已有书目身份，可在配方中显式关联该标识；关联值不是自动读写旧 schema 的入口，也不要求先在旧系统登记才能测试新包。

观察到的标题、版本和来源位置用于核对，不自动覆盖既有书目事实。离线材料可用性与其是否获准成为正式词表依据分别处理。新生成器需要什么采纳输入，在其合同中另行明确；本包不把旧状态与审批实现直接搬过来。

## 工程归属

创建独立包 `packages/kb-sources/`，Python 模块名为 `kb_sources`，命令入口为 `kb-sources`。它可以作为 uv workspace 成员，也应能够独立安装和运行。

新包自行持有获取、存储和验证实现，以及配方、快照、提取结果的 schema；不依赖 `kb-core`、当前 `kb-topics`、旧迁移器或旧来源校验器。旧实现可以帮助识别风险，但不通过导入或包装旧实现建立新功能。

配方、持久存储和派生输出路径由显式配置传入，不要求依靠旧包的仓库定位函数。开发测试在临时目录中运行，不以旧仓库的特定 Git 历史或正式资料完整存在为前提。

拟议包结构如下：

```text
packages/kb-sources/
  pyproject.toml
  src/kb_sources/
    cli.py                    命令入口
    acquisition.py            公开获取与手动接收
    storage.py                原文对象与快照保存
    validation.py             格式、清单和完整性校验
    extractors/               按格式提取与定位
    schemas/                  随安装包分发的数据合同
  tests/
```

下游通过快照清单和提取文件衔接，不直接调用新包内部函数。包拆分本身不决定是否合并主题与实体，也不决定新词表的关系语义。

本轮方案调整不修改、迁移、删除或回退既有代码。未来实现只新增新包及必要的 workspace 配置；旧生成器与旧来源命令继续保留，新流程达到验收条件后才单独讨论正式切换。

## 存储位置

以下为拟议路径，不是已存在的接口。

```text
data/inputs/source-materials/
  recipes.yaml                 获取配方
  pins.yaml                    离线处理明确选定的快照

data/source-materials/snapshots/
  <material-id>/<snapshot-id>.json
                               不可覆盖的快照清单

output/sources/
  incoming/                    手动文件待接收区
  objects/sha256/<digest>/      按内容哈希保存原始文件

build/source-materials/
  <snapshot-id>/                提取结果、比较报告与临时接收文件
```

`output/` 已被 Git 忽略，原文和人工下载文件不默认进入公开 Git 历史，也不属于 build 清理范围。不可从官网重新取得的材料必须纳入用户的持久备份；清单存在而原文缺失时报告缺失，不声明离线可用。

HTML 的原页面及阅读所需图片等资源分别保存到同一快照清单。为离线浏览改写链接时，只生成派生副本，原始字节保持不变；不保存登录信息、会话 Cookie 或账号口令。

## 获取与导入

公开下载和手动导入共同经过接收、文件验证、原文保存和清单写入。

| 方式 | 责任分工 | 接收规则 |
|---|---|---|
| 公开获取 | 工具按明确配方获取指定官方文件或页面 | 限定地址与跳转，设置超时、大小限制及有限重试；登录页、验证码和错误页面不能作为正文接收 |
| 手动导入 | 用户完成登录、购买或机构访问后取得文件 | 复制用户指定文件，保留原文件；记录实际导入时间，未知的下载日期不补造 |

即使扩展名为 PDF，也需要检查实际文件格式及是否可以解析。标题或版本与预期冲突时进入待核对结果，不自动修改预期以通过检查。

导入同样内容可复用已验证的原始字节；来源、版本与取得记录仍需分别核对。不同内容产生新快照，不覆盖旧快照。

## 配方与清单

| 记录 | 必要信息 |
|---|---|
| 获取配方 | 材料标识；可选的现行书目关联；目标版本或固定版次；用途说明；获取方式；预期文件清单；取得地址；预期格式；版本定位规则；使用条件出处 |
| 文件记录 | 实际请求与最终地址或人工交付说明；取得或导入时间；格式、字节数、SHA-256；本地对象路径；接收错误与限制 |
| 快照清单 | 材料与文件集合；观察到的标题和版本；预期文件的满足情况；清单模式版本；接收工具版本；前一快照引用 |
| 提取记录 | 输入快照及文件哈希；工具与解析器版本；原文代码、标题、章节、页码或 HTML 锚点；提取结果与未能处理的内容 |
| 快照选择 | 下游任务使用哪个具体快照及其清单哈希；选择依据；不与书目版本或来源角色混为一谈 |

抓取日期不是出版版本，HTTP ETag 不是内容哈希。清单自身计算哈希并记录在选择文件中，不能只校验原文而允许清单路径或文件集合被无声替换。

## 格式处理

首期支持已核实主要来源需要的 PDF 和 HTML；后续遇到真实的官方 XML、JSON 或表格数据，再增加对应解析器。

- PDF 保存原件。提取时保留页界、原文编号和章节位置；复杂表格、数学公式、扫描页或乱码明确报出，不以缺内容的文本冒充完整正文。扫描件首期转人工处理，不默认新增 OCR。
- HTML 保存原件与规定的依赖资源，提取正文、标题、原始链接和稳定锚点。动态页面没有正文时报告限制，不把导航页当全文。
- 派生 Markdown、JSON 或文本可重建，不直接作为人工改写的唯一编辑源。

解析成功与内容复核分别记录。词表采用关系、名称或定义时，仍须回到原文位置核对；本阶段不通过标题缩进自动推导 `broader`，不自动合并同名概念。

## 首批材料

下列范围依据已完成的只读获取调查制定。表中的“公开”只说明有公开入口；具体保存和使用条件按材料本身核对。

| 领域 | 拟接收材料 | 获取方式及未决项 |
|---|---|---|
| Computer Science | CS2023 封面与引言、知识模型、完整知识体系正文及其余报告组成文件；HTML 版作对应材料 | 公开；先核对报告组成文件是否属于同一版本，再形成完整清单 |
| Mathematics | MSC2020 完整分类 PDF、官方说明和版本转换资料 | 公开；保留分类代码，抽取后检查遗漏与跨页条目 |
| Library and Information Science | IFLA 2022 英文指南 PDF | 公开；指南可作为基础范围依据，其细度不能自动等同于完整词表 |
| Writing Studies | CWPA 4.0 完整 PDF 及通过日期所在页面 | 公开；保留大学初年写作范围，不声称覆盖整个写作专业 |
| Technical Communication | tekom 2018 Version 1 教学与考试视角 PDF，现行框架页面 | 公开；二者先独立登记，版本及内容对应未核清前不拼接 |
| Learning Sciences | How People Learn II（2018）；剑桥学习科学手册第 3 版（2022） | 前者 PDF 有登录或访客取得流程；后者完整章节需要个人或机构权限，交用户手动取得 |
| Cognitive Science | 完整专业结构来源尚待选定；剑桥认知科学手册（2012）作为候选 | 候选有权限要求，且范围偏基础、理论与哲学；不先要求用户购买，也不声明它已被选为完整基线 |
| Philosophy | SEP 的一个明确固定版，包括预定范围内的条目及索引 | 固定版 HTML 公开，会员 PDF 可选；先形成范围清单，并核对下载及使用条件；百科条目集合不自动形成分类层级 |

来源准备不按内容填充优先级删减。尚未取得或尚未定稿的材料，在总体清单中保留明确缺口；不能用空结构声明领域词表已经完善。

## 手动交付

导入口建成后，再给用户逐项交付单，至少列明书名或报告名、版次、ISBN 或 DOI、所需完整范围及可接受格式。

用户提供合法取得的文件即可，不需要提供账号密码。工具负责复制、识别文件、计算哈希、记录清单并报告缺页、缺章或版本冲突。下载得到的预览、目录、摘要或书目引用不能当作完整正文。

Learning Sciences 两项材料可列入手动交付准备；Cognitive Science 在选源完成前不发出购买要求。SEP 可使用固定版 HTML，不以购买 PDF 会员作为前置条件。

## 更新与恢复

首期更新由显式命令触发，不启动后台抓取。检查远端变化只生成新旧差异及影响报告，不自动替换下游固定的快照。

同一地址出现不同内容时保留两个快照。新版进入本地后先核对新增、删除、改名、范围和关系变化，再决定是否更新选择记录。通过恢复旧选择记录和相应原文对象，可以重现旧输入；不删除旧材料来完成切换。

## 验证门槛

| 要发现的失败 | 后果 | 独有证据与检查 |
|---|---|---|
| 原文或清单被改写、缺失 | 无法重现依据 | 逐文件与清单哈希、受控对象路径；离线重读检查 |
| 登录页、下载截断或错误文件被当作正文 | 后续生成依据错误 | 格式识别、解析结果、标题版次及原文内容核对 |
| 报告缺组成文件、手册缺章 | 用不完整材料声称覆盖完整 | 明确的预期清单与实际文件集合逐项对应；预览与正文区别 |
| 提取丢段、表格错列、编号错接 | 节点或关系错误 | 原文位置映射、代表性复杂页面的人工对照、未解析内容报告 |
| 自动与手动接收路径行为不同 | 手工材料绕过验证 | 两种入口共用接收流程，并用无效材料验证相同拒绝行为 |
| 中断或路径跳转破坏旧快照 | 旧依据丢失或越界写入 | 临时接收后发布、路径限制、失败保留旧快照与选择记录 |
| 已下载被误当作已采纳 | 越过概念与来源用途决定 | 文件有效性与正式使用门槛分开；下游要求明确引用和适用的采纳依据 |

测试只覆盖上述独有风险。schema 负责形状，哈希负责字节；两者都不替代语义核对或人的采纳。

## 实施顺序

以下均为未执行任务。采用顺序实施与阶段验收，先完成 CS2023 样例，再扩展材料批次。

- [ ] 确认合同：明确首批材料、持久存储位置和有限获取范围；列出配方、快照与提取结果的完整字段及验证要求。
- [ ] 建立新包：新增 `packages/kb-sources/`，接入 uv workspace 与统一锁文件；schema 随新包分发，独立安装不依赖旧代码。
- [ ] 实现接收：在新包中实现配方读取、公开获取、手动导入、对象存储及清单写入。
- [ ] 接入命令：通过 `kb-sources` 提供 `fetch`、`import`、`verify`、`diff`；这些是拟定命令，不是当前可执行接口，不加入旧 `kb-core` 命令表。
- [ ] 完成样例：以 CS2023 为首个完整材料包，验证离线读取、预期清单、重复导入、接收中断、错误正文与恢复；验证安装包在仓库外使用显式配置也能工作。
- [ ] 实现提取：按 PDF／HTML 增加提取及位置对应，记录工具版本、输入哈希与失败片段，验证复杂页面不被静默丢弃。
- [ ] 扩展来源：接收其余公开材料及用户手动文件，完成各领域获取与覆盖缺口清单。
- [ ] 对接新生成器：离线材料合同稳定后，为重新设计的主题生成器提供文件接口；旧生成代码保留，正式数据迁移与切换另行设计。

接收与存储能力预计 1–2 个工作日；CS2023 完整材料和定位提取样例预计另需 1–2 个工作日。其余领域按解析难度、取得权限及语义复核情况估算，不以下载完成时间代替全部词表完工时间。

## 采纳边界

独立 package 和保留旧代码的方向已由用户选择。持久接收的具体对象、完整字段合同、写集和实施批次由本提案进一步落实，不因包名确定就声明功能已经实现。

新包的范围是明确材料的离线接收与核对，不扩大为任意网站爬取，不要求用户交出登录凭据，也不把采集结果自动写入现行主题、术语、书目或来源角色。

既有[术语依据范围](../terminology/决定-术语依据范围.md)等规则继续约束旧批次。新包自身的文件合同不依赖旧审批代码；将材料用于正式知识组织时，仍须保留明确来源与人的采纳边界，不能从“已下载”推导“已批准”。
