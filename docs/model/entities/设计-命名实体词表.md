# 命名实体词表

本篇规定实体记录的身份、名称、属性及其与概念词表的关系。实体记录描述需要独立识别的人物、组织、项目、产品等具体对象；概念词表管理用于组织知识的概念、定义、名称、翻译和关系。名称规范服务是实体记录的一项职责，不把对象本身等同于它的名称。

## 对象分工

| 判断 | 概念词表 | 实体记录 |
|---|---|---|
| 要回答的问题 | 这个主题是什么意思，与哪些主题有关 | 这是哪个对象，它有哪些有依据的事实 |
| 主要内容 | 定义、范围、名称、别名、译名、概念关系 | 稳定身份、对象类别、名称、网址、创建者或维护者、适用版本及对象关系 |
| 组织方式 | 概念层级、相关关系和集合，可有多个上位 | 按对象身份维护，按已采用类别和关系查询 |
| 内容引用 | 表达文章讨论的主题 | 表达文章涉及的具体对象 |

决定记录位置的依据是所描述的对象和用途，不是名称是否大写、是否为专名或是否常见于专业文章。项目中的“实体记录”是具体管理范围；不把 RDF 中所有资源或 OWL 中所有个体都归入这里。概念资源本身也是 RDF 资源。

某个人物、语言或产品可以成为文章的主题。为组织这些文章建立的主题概念，与描述该对象事实的实体记录分别承担职责；不因具体名称已出现在概念词表中就删除它，也不为每个概念强制复制一条实体记录。共同边界见[整体设计](../vocabulary/设计-词表整体设计.md#对象分工)。

## 收录判断

| 需要 | 处理 |
|---|---|
| 解释一个主题，组织其名称和相关资料 | 维护概念；引用既有概念身份，不因换成分类或主题用途而复制 |
| 保存某个人物、组织、项目或产品的可核对事实 | 核对具体对象后建立实体记录 |
| 同时需要主题组织和对象事实 | 分别维护概念与实体身份，根据明确含义建立关联 |
| 只有一个名称或不明确的缩写 | 保留待核问题，不据字符串自动认定对象或分配类别 |

例如，记录 MCP 的含义与相关知识时使用主题概念；管理具体规范版本时，还要区分协议与规范文献，文献身份遵循[参考文献目录](../sources/设计-参考文献目录.md)。一个具体 MCP 工具项目有独立的身份与事实需求时，才另行建立实体记录。此例说明判断方法，不批准新类别或具体条目。

来源的“人物”“技术”等分支只是原有组织信息。导入时保留原类型和关系；将其中条目选入实体记录须逐项确认，不能整组改类型或因名称相同合并。

## 实体记录

以下是记录必须能表达的业务信息，不规定数据库表数或强制把所有可选事实填满。

| 信息 | 要求 |
|---|---|
| 身份 | 稳定标识；名称、地址或显示位置变化不自动改变身份 |
| 名称 | 名称及实际语言、适用的别名、依据；同名不证明同一对象 |
| 类别与范围 | 采用类别及依据、对象范围；不能仅从词表所在分支推导类别 |
| 对象事实 | 仅保存与使用有关且有依据的属性和关系；按属性区分组织、项目、产品、版本和文献 |
| 主题关联 | 所关联的概念身份、关系用途及逐项依据 |
| 来源与历史 | 材料、版本、核对时间、判断责任、变更与替代记录 |
| 项目状态 | 项目记录的采用状态，不能与产品维护状态或网站是否可访问混用 |

仅凭同一产品有多个版本，不决定是否拆分身份；先明确描述的是产品、系列还是特定版本。已有稳定身份、具体采纳与历史继续有效，不能由本篇自动重建。

### 归属依据

每项主题关联均须有材料支持或明确的项目判断，并说明实际支持哪些概念。关联多个主题不表示这些主题互为上下位，也不表示实体是这些概念的 RDF 实例。正式状态的既有依据要求不放宽；现行表示见[归属合同](../../practices/vocabulary/设计-实体记录现行合同.md#归属依据)。

### 事实依据

对象事实、名称的语言依据和概念归属分别核对，网站存在或名称一致不能同时证明三者。普通实体直接官方 URL 的既有限定仍只覆盖 label、kind、urls、scope、vendor，不扩展至 subjects、术语、映射或派生；表示及条件见[事实合同](../../practices/vocabulary/设计-实体记录现行合同.md#事实依据)。

### 类别

类别使用已采用的外部类别及其明确含义，不把“实体／术语／专名”设为一组选项：前者在本篇指被描述的对象，后两者涉及名称的用法。现有类别及扩展权限见[类别合同](../../practices/vocabulary/设计-实体记录现行合同.md#类别)。项目、协议等对象的讨论不自动开放新 kind 值。

`person` 只收在相关主题或活动中有显著公开角色、且符合公众人物判断依据的人。已发表作品的作者、公开项目的维护者和方法的提出者只作为可能的收录对象，不因该身份、Wikidata 条目或公开出处自动取得公众人物资格；须分别说明一般公众人物依据，或相关公共争议中的突出角色及适用范围，并提供可引用的公开出处。不收私人、同事或联系人。文献记录用 `creator` 指向已收录人员，软件实体的个人维护者用 `vendor` 指向人。该规则由[人员收录澄清](决定-公众人物边界.md)采纳；不扩大隐私边界，不自动删改现有实体。

### 生命周期

项目的收录、使用、退出与对象在外部的发布、停止维护分别记录。原 candidate、active 等状态的保存与当前能否使用也分别判断：统一 RDF 交付按[实体统一使用](决定-实体统一使用.md)检查基本字段，符合条件即可先用，不以改写原状态为前提。

改名不更换对象身份；停止维护不自动删除记录；已经明确停用的项目记录不自动恢复。替代须确认实际后继对象并保留旧引用。旧 YAML 的状态和值域继续见[生命周期合同](../../practices/vocabulary/设计-实体记录现行合同.md#生命周期)。

## 关联语义

| 关系 | 两端及含义 | 不能代替的关系 |
|---|---|---|
| 实体的相关主题 | 实体与概念；说明与哪些主题有关，现行由 subjects 表达 | 对象类别、概念层级、概念所指对象 |
| 主题所指对象 | 描述某个具体对象的主题概念与该实体；确认此主题围绕哪个对象 | 两端资源同一、两个概念等价 |
| 实体间关系 | 实体与实体；创建、维护、替代等明确采用的关系 | 仅因共同主题产生的关联 |
| 外部身份对应 | 本地实体与外部关于同一对象的身份 | 概念之间的相近或等价映射 |

同一个实体可以关联多个主题；一个一般主题可以涉及多个实体。相关主题不能自动提升为“该概念专指该实体”。若确需后者，记录两端身份、关系含义及依据，具体交换属性须先核对成熟词汇的适用范围；未采纳前不新增机器接口，也不以同名、sameAs 或 SKOS 映射代填。

概念记录与实体记录采用不同身份，是项目为分开维护主题含义与对象事实作出的选择，不是 SKOS 强制规定所有领域对象与概念互斥。[SKOS §3.5.1](https://www.w3.org/TR/skos-reference/#concepts)

`skos:broader`、`skos:related` 及其映射子属性按 SKOS 语义连接概念；不能借它们表达普通实体的厂商、维护者或对象类别。`rdf:type` 表示资源是某个类的实例，与概念的上下位关系不同。[SKOS §8.6.2](https://www.w3.org/TR/skos-reference/#semantic-relations)、[RDF Schema §3.3](https://www.w3.org/TR/rdf-schema/#ch_type)

## 主题职责

内容的 subject 引用概念，entities 引用具体实体，含义见[内容模型](../content/设计-内容模型.md#字段)。两类引用分别判断，不要求每次同时填写，也不从一个字段自动补出另一个。

讨论某语言的资料可以引用相关主题，也可以引用已采用的该语言主题概念；要标明涉及哪个具体语言对象时，引用实体记录。已有概念和实体的具体采纳分别核对，不能在这里凭例子创造身份、规定一条唯一挂接或将具体语言一律排除出概念词表。

概念只维护含义与组织所需的信息，对象属性由实体记录维护；界面需要同时展示时按身份关联读取，不复制成两套可独立改写的事实。不存在专指关系时，只显示已有相关主题，不猜测关联。

## 标准依据

| 依据 | 支持的判断 | 边界 |
|---|---|---|
| [SKOS Primer §2.1–2.2、§3.3](https://www.w3.org/TR/skos-primer/) | 概念、名称及主题标引分别表达 | 不规定本项目必须建几张表 |
| [SKOS Primer §5.1](https://www.w3.org/TR/skos-primer/) | 非概念资源也可使用 SKOS 名称属性 | 有 prefLabel 不证明资源是 Concept |
| [SKOS Reference §8、§10](https://www.w3.org/TR/skos-reference/) | 概念关系及概念映射的语义 | 不代替普通对象之间的事实关系 |
| [RDF Schema §3.3](https://www.w3.org/TR/rdf-schema/#ch_type) | rdf:type 的实例与类语义 | 不规定本项目类别清单或归属事实 |

ISO 25964-2 的名称规范表材料仅按[既有阅读范围](../vocabulary/阅读-ISO%2025964%20叙词表标准.md)使用，不把目录或名称规范表的概括说明当作 §23 正文已经逐条核实的依据。概念与实体分别维护以及收录、采纳权限是项目选择。

## 实施边界

现行编辑源、字段、类别值、依据形状、严格校验及特殊记录的处理集中在[实体记录现行合同](../../practices/vocabulary/设计-实体记录现行合同.md)。本设计不自动迁移数据、开放类别、解除人员限制或启用消费者；历史决定保持原文，范围解释见[分工决定](../vocabulary/决定-概念与实体分工.md)。

## 待定事项

- 主题专指实体的交换属性、两端类型、数量及校验，须在核对成熟表示后单独采纳；现行 subjects 不冒充该接口。
- 未采用的实体类别及更细的项目、产品、版本关系，保留具体需求与依据后决定，不由词表分支推断。
