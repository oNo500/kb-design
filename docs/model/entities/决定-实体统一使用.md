# 实体统一使用

状态：已采纳，2026-09-24。用户要求“实体的话应该放在一张词表里，只要字段够，就先用吧”。本决定统一现有实体交付，并将基本字段条件与原记录状态分开处理。

## 收录范围

当前纳入 CCS 已分流的 302 条实体记录及旧实体导入的 35 条记录，生成一份当前实体词表。它们保留原实体及名称身份，不根据名称相同合并；CCS 的 48 项未决条目尚未确定为实体，不在本次范围内。

来源副本、原状态、未核说明、依据与历史继续保留。不同来源文件是生成输入，应用使用同一份合成的 `entities.ttl`，不再分别选择两份当前实体交付。

## 使用条件

| 条件 | 要求 |
|---|---|
| 身份 | 可稳定引用的绝对 IRI，与原来源记录能够对应 |
| 名称 | 至少一个可用首选名称，普通标签或完整 XL 名称表达均可；文字和语言保持来源原值 |
| 类别 | 使用现有已采用的实体类别及其明确 RDF 类型，不把概念、名称或来源资源当实体 |
| 来源 | 能定位来源记录、固定输入版本及文件摘要 |

满足以上条件的记录可以先用于本项目的实体选择、引用和检索。缺少可选定义、主题归属、厂商、外部映射或完整事实复核不单独阻止使用；缺项及未核事项如实显示，不能补造值来取得通过。

基本字段缺失或相互冲突时明确列出原因。记录保留在统一交付中，不在可用清单中；与其他记录产生无法保真合成的身份或名称冲突时，停止该次生成，保留来源。

## 状态与判断

`candidate`、`active` 等原状态继续作为来源记录保存，统一交付不批量把 candidate 改成 active。candidate 或 `facts_verified=false` 本身不再是本次使用的阻断条件；基本字段通过也不证明事实已经核实或此前审批已经发生。

已明确停用的记录不因字段齐全自动恢复使用，须另有恢复决定。现有对象范围不自动扩大；同名对象的对应、合并和新类别仍需独立判断。本文不表示 SKOS 规定了上述项目使用条件。

## 数据职责

原 YAML、CCS 来源及分流记录保持各自输入职责。统一生成器只组合固定交付并形成一份实体词表，不重命名原身份、不改写来源判断、不推断旧主题到 CCS 的关系。

该使用规则适用于新的统一 RDF 实体交付，不回写旧 YAML 的状态字段，也不改变旧工具的 active 读取合同。后续应用适配以本交付的可用清单和本决定为准，不能再次仅凭 candidate 过滤已满足条件的实体。

## 版本交付

每次交付保存实体 RDF、按实体列出的来源及原状态、基本字段结果、同名提示和完整输入副本。旧版本保留，当前入口只指向核对完整的新版本。

词表维护负责此交付及当前入口；Obsidian 加载仍是独立应用操作，本决定不直接修改应用实例或文章。表示沿用[实体设计](设计-命名实体词表.md)，实现与入口见[词表维护工程](../../practices/vocabulary/设计-词表维护工程.md)。
