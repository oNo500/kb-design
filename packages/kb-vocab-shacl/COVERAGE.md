# 规则覆盖 (Rule Coverage)

本表对应[目标数据规范](../../docs/model/vocabulary/设计-词表数据规范.md)，设计基准为 `50a3598`。它记录检查边界，不重复定义字段，也不表示一次运行已经取得全部上下文或完成所有内容判断。

## 结构与统计

`structure.ttl` 按词表、概念、名称、集合及其子类型、独立说明列出 RDF 字段；共同字段通过 `sh:node` 组合，字段约束通过 `sh:property` 复用。字段覆盖测试逐项核对本规范的 RDF 字段表，含可选字段；正文允许的 `owl:imports` 也列入，但不执行外部加载。

`inventory` 从同一组 Shape 的直接 `sh:path` 读取字段，合并同一资源下的重复引用，再统计已有值和无字段对象。声明的类、输入中的子类关系，以及结构列出的 `targetSubjectsOf`／`targetObjectsOf` 用于选择对象。例如 literalForm 主体按名称检查，member 主体按集合检查，漏写类型不能避开统计和结构校验；普通标签本身不用于推断概念身份。无类型或未归类主体仍单列。全图字段表保留辅助资源上的属性出现情况，不将这些资源强归入概念。

`structure` 是可交给校验器的字段结构视图；它加载已有共享约束，并移除共享规则原先独立执行的目标，避免带入无关的旧校验。原 `standard`、`target` 的行为保持，未与新视图强制合并。统计不执行其中的校验条件，也不产生 `conforms` 结论。

独立说明没有通用类型，`resource:Note` 未设置默认目标；调用方可向所加载的图添加 `sh:targetNode`。`dcterms:relation` 指向相关条件规则，只作关联，不自动启用。本地条件尚未确定时保留字段及其说明，不给所有来源强加本地约束。

统计报告从这些关联中列出条件规则，包括由集合继承的规则；分别记录范围未指定、范围已指定或规则已停用，以及所选对象数。无论是否指定范围，`inventory` 都不执行校验，JSON 的 `validation_executed` 固定为 false，不能据此认定条件满足。

名称登记、映射管理、译文、采纳、版本和交付等配套记录没有在本次 TTL 中统一绑定为资源字段，仍明确列为外部记录，不假称它们缺失或已满足。完整 RDF 字段清单也不等于所有语义、管理及交付要求都已实现自动校验。

## 已有规则

| 设计范围 | 本包覆盖 | 条件与边界 |
|---|---|---|
| 核心类型 | 概念、概念体系、集合与 Label 的类型互斥；已知集合子类型 | 纳入已声明类型及所列标准属性的定义域、值域含义，不是任意 OWL 本体的一致性证明 |
| 普通及 XL 名称 | 文字值类型、Label 单值、同语言首选文字唯一、角色互斥、同文多记录 | 取普通标签与 XL 路径的值集合；不合并名称身份，不要求首选 Label 资源唯一 |
| 自有表示 | 一份 ConceptScheme、概念归属、主要身份与显式类型、词表名称和范围、XL 记录及普通投影 | `target` 用于自有主图；子类推导不替代显式类型字段；不能套用到所有来源的混合图 |
| 关系一致性 | 层级可达与相关互斥；精确映射对称、传递闭包与宽窄、相关映射冲突 | 路径纳入明确列出的逆关系和映射子属性；不任意推导 closeMatch 或加载外部本体 |
| 集合 | 成员类型、有序列表数量、完整性、终止、环与 member 投影 | 显式单列表及列表完整性由 `target` 检查；普通及空集合可缺名；列表顺序不从语句顺序推断 |
| 分组扩展 | ConceptGroup／ThesaurusArray 互斥、组关系端点、项目显式成员包含检查 | 输入采用这些扩展时适用；传递与逆向关系参与成员核对；显式成员要求位于项目 profile |
| 元数据 | 文字字段、来源与派生引用、停用布尔值；条件性本地说明正文 | 来源说明允许合法 RDF 值，包括 XML 字面值和资源；不对所有日期或说明强加单值 |
| 来源缺项 | 缺少首选名、未标语言的 Warning，空集合的 Info | 不删除概念，不补语言，不强制所有概念具备中文 |
| 质量诊断 | 自相关、层级环、集合循环 | 单张图不能证明是新引入；新旧差异及实际处置另行判断 |

具体规则以稳定 IRI 标识；`sh:name`、`sh:message`、`sh:severity` 分别保存名称、报错说明和严重程度，`dcterms:source` 关联标准，`rdfs:comment` 指向设计章节。执行记录应保存包版本及实际规则文本的摘要值。

`standard` 只包含本包已实现的标准检查，不代表全部 SKOS／OWL 公理的一致性判定。SHACL 检查所提供的数据及所选规则；检查记录是否缺字段，不等于仅凭缺失陈述就能证明本体矛盾。规则解析或引擎异常属于检查失败，不能当作通过。

## 条件检查

仅凭最终数据，不能确定记录是否本地新建。以下 Shape 已定义约束，但没有默认检查对象；调用方根据来源或采纳记录，明确指定对象后执行。

| Shape | 适用对象及要求 |
|---|---|
| `LocalConcept` | 本地新增概念，要求 XL 首选名称 |
| `LocalCollection` | 自建集合，要求范围说明和词表归属 |
| `LocalConceptGroup` | 本地概念组，要求名称 |
| `LocalLabel` | 本地新增名称，要求语言标签 |
| `LocalNote` | 本地独立说明，要求一个带语言的正文 |
| `LocalDates` | 本地记录的创建、修改日期，各为可选单值 date 或 dateTime |

例如，已确认某个概念为本地新增对象时，在调用 `validate` 前将它指定为 `LocalConcept` 的检查对象。以下代码沿用 README 中的 `rules` 变量；可用于 `structure` 或含相应定义的 `target` 视图：

```python
from rdflib import Namespace, URIRef
from rdflib.namespace import SH

shapes = Namespace("urn:kb-vocab-shacl:")
rules.add((shapes.LocalConcept, SH.targetNode, URIRef("https://example.org/new-concept")))
```

未指定对象时，这些条件检查没有执行；其他规则通过不能证明它们已满足。不能把来源缺项全部当成本地完整性错误，也不能通过 URI 命名猜测记录来源。

外部映射端点检查 IRI 及已知不相容类型；历史替代引用目前只检查 IRI。完整类型、可定位描述、依据和版本，须在明确的来源或历史上下文中核对。不能自动联网补全，也不能因为来源与历史图没有混入主图就直接断言引用错误。

## 其他检查

以下要求没有被当前 SHACL 包完整实现，不能因其他规则通过而标为已检查：

| 范围 | 原因及所需证据 |
|---|---|
| 语言标签语法、IANA 登记及启用范围 | 本包检查语言字面值及按完整标签的角色约束，不内置语法解析器或注册表，也不固定为 en／zh；须使用适用库、明确注册表和语言策略 |
| 名称登记与身份连续性 | 要比较登记快照、来源、修改及历史，最终图中的 IRI 存在不能证明这些事实 |
| 译文与适用性复核 | 需要任务、依据、复核及版本记录；译文更新和重译不在本轮范围 |
| 映射管理信息 | 两端版本、用途、方向、依据、采用和复核条件的存储表示须由相应记录合同落实；本包不自造 RDF 类或属性填空 |
| 采纳、退出及交付记录 | 责任者、授权、前后版本、历史读取、加载结果及文件完整性需要配套记录和程序检查 |
| 本次新增的质量问题 | 是否引入环、自关联或信息损失需要基准及变更证据，不能只根据最终图直接定性 |
| 任意自定义类与子属性 | 必须先明确采用的本体和推导范围；本包只支持列明的标准类、属性路径及输入中已有的类匹配 |

这些是本包的覆盖边界，不撤销设计要求。JSON 管理记录的结构、跨文件关联和版本证明可以由相应验证器处理。

## 人工判断

概念含义、名称对应、NISO 层级业务判据、范围说明是否充分、依据是否支持具体断言及知识覆盖，需要内容审查。SHACL 不根据“科学”“过程”等名称片段自动建立分类，也不产生语义采纳决定。

## 未决表示

自有数组上层连接、词表内复合等价、跨词表组合交换及未核 ISO 权威正文，沿用[整体设计的待定事项](../../docs/model/vocabulary/设计-词表整体设计.md#待定事项)。本包不自动采用这些格式、类型或属性。
